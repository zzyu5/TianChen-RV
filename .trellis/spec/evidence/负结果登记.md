## 一、五条登记

### N-1 · [C3′-KQUANT-DECODE-BOUNDARY]

**结论（现行法）**：K-quant super-block repack-GEVM decode@M=1 = **format-keyed 适用边界**；fold epilogue 在 M=1 不 amortize。**同族某格的 win 不泛化到该族 decode。**

**判别键 / 机制**：

- **★在册判别键「sub-block 数」已被证伪** → 挂 [issues](../issues/index.md) **ISSUE-048**（同族内同 sub-block 数而 verdict 相反）。**该键不得再被引作解释。**
- 墙记「fold@M=1 不 amortize」= **档成立，但内禀驱动项不是 fold**；**成本中心 = 未证 · 留白** → 挂 **ISSUE-014**。**禁写"成本中心 = 权重位重建"。**

**部署含义**：front-door 应 **DECLINE** K-quant repack@decode。

### N-2 · [IME-VENDOR-NEGATIVE]（**最锋利**）

**结论（现行法）**：首个 kernel-sym 对真硬件 SpacemiT **vendor 手调 IME 核**的正面度量 = **输**；**gap 随格式复杂度扩张** = [PAT-1] format-keyed 边界最锋利的证据。

**判别键 / 机制**：我方 fold 随 super-block 暴涨，vendor 单核塞所有格式而**近乎平坦**——两条曲线的斜率差就是边界本身。

**随行事实**：`q8_0@ime` **结构 void**（该板无合法 IME 对手）→ 坐实 e2e "q8_0 beat" = **赢 RVV-repack、非赢 IME** → 锁定写法挂 **ISSUE-029**。

**部署含义**：front-door 应 **DECLINE** IME@复杂格式。

### N-3 · iq/tq gemm gcc-death

**结论（现行法）**：prefill rvv-gcc（deploy MAIN）**输纯标量 ref**；[CASE-KQUANT-GCC-CODEGEN] 扩展到 iq/tq repack-GEMM。

**判别键 / 机制**：**宿主编译器 codegen 轴**（同格 clang 显著快于 gcc）——**非** kernel 质量轴。与 [DISCRIMINATOR-OPPONENT-BOUND-TYPE]（对手 bound-type 轴，见 [三贡献证据地图 §4.4](./三贡献证据地图.md#44-discriminator-opponent-bound-type)）**正交**。

**部署含义**：front-door 应 **DECLINE** gcc-death 路。

### N-4 · [GAP-IQ1S]-RESOLVED-HOLISTIC

**结论（现行法）**：iq1_s emitter-maturity = **holistic micro-scheduling**，**非单一可隔离轴**：三条 byte-exact 杠杆（gather-widen / vector-index / deferred-scale）逐一**精确追平**对手的单一优势轴，**ratio 恒不动**。**翻正门 = 结构级重写，超单旋钮。**

**判别键 / 机制**：**真-fixable ≠ 保证翻正**——诚实案例：完整环 byte-exact、结构靶命中，但**未翻正双板确认**。

### N-5 · dequant / product_reduce emitter-maturity 墙

**结论（现行法）**：iq3 gather-bound（`vrgather`）+ nvfp4 `ldexpf` + product_reduce offbin **被 scalar 追平**。

**判别键 / 机制**：**emitter 成熟度墙**——**非**能力键控可键控项。

**随行争议**：dequant 族另有「向量内容由宿主 codegen 产生」之争（该族计入构造轴的强义存疑，[canon · 成色与措辞](../canon/成色与措辞.md) [L-8]）→ 挂 **ISSUE-001** / **ISSUE-002**。
