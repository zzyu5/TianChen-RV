# 公式层与覆盖

本文定义 Weft operator compiler 的横向 formula/construction layer、formula catalog、`g/c/ω` 消费和覆盖要求。主公式与 selector 数学语义仍以 [变体流水线](./变体流水线.md) 为唯一正本；本文回答所有 operator/family 如何进入同一工程路径，以及怎样判定公式层已经完整建立。

## 【定法】系统级义务

每条 production operator construction path 都必须经过公式/构造阶段：

```text
canonical operator problem P=(S,g,ω)
  → target/profile binds construction family f
  → family capability projection c_f
  → family-local formula/construction
  → typed candidate/plan/body parameters + requirements + analytic prior
  → legality
  → optional bounded selection
  → selected typed body
  → family-local realization / artifact lowering
```

这条义务覆盖：

- 所有已注册 production source front door；
- 所有绕过 source front door、但能进入 production conversion/artifact 的 direct route；
- quantize、dequantize、contraction/vec-dot、GEMV/GEMM、elementwise、reduction/product 及当前其它 operator family；
- 所有进入 production registry、默认 pipeline 或公开 direct route 的 plugin family。RVV、IME、Scalar、Offload、Demo、Toy、Template、TensorExtLite 等目录是 census 候选集，是 production、test-only 还是 template-only 由可达入口决定，不由名字推断。

production entry 指安装后的正式 pipeline 中，在受支持配置下可达的 source front door、conversion、direct route 或 fallback route。某条路径只有一个确定实现，不构成绕过理由。它可以使用 single-candidate deterministic construction，并把没有物理作用的输入轴标为 honest-null；不能由 builder/emitter 中的隐式默认替代公式阶段。

测试专用 fixture、隔离 oracle 和未注册实验入口可以不进入 production coverage 分母，但必须结构上不能成为 production fallback。

## 【定法】什么是 formula

Formula 是从 typed `g/c/ω` 与已声明 mechanisms 构造以下至少一项的解析知识：

- candidate 或 mechanism composition；
- typed plan/body 参数 `θ`；
- resource/layout/schedule requirements；
- legality 所需的解析要求；
- 有限合法候选上的 analytic prior；
- single-candidate deterministic typed construction。

Formula 不是：

- format/board 名到完整实现的字符串分派；
- measurement winner lookup；
- 只搬运字段的 stamp/materializer/reader；
- reason、provenance 或 dashboard；
- verifier 中对同一公式的重放；
- emitter 内的二次算法、LMUL、tile、loop-order 或 mechanism 选择；
- 为增加公式数量包装常数或未消费 optional 字段。

真正不可复用的新语义可以成为 family-local 最小 mechanism。完整 point implementation 不得作为已有 mechanisms 可表达组合的默认扩展单位。

### 构造充分性与诚实分类

除显式列入 mechanism basis 的不可再分、可独立复用原语外，稳定目标判据是：删除任一按 format/shape/capability point 手写的完整实现 leaf 后，`g/c/ω + mechanisms + family-local formula` 仍能重建同一 typed candidate/body/plan。Formula 只返回 leaf id、旧 builder 名、完整 plan-row key 或 selector token，再由后层取回原实现，不算强义构造。

这是目标态，不是对当前代码的虚假描述。本次横向 formula-layer rebase 必须把每条 production path 纳入唯一公式/构造权威链，同时诚实区分：

- 已能通过上述删 leaf 重建判据的 strong construction；
- 仍依赖完整逐点 leaf，但已无隐藏决策、无双 authority 的 deterministic
  constructed-weak path。旧 dispatch-wired 只是一种待退役诊断，不是允许保留的
  production fallback。

后者必须进入 catalog 和 production-entry 检查，不得继续藏在 builder/emitter；但
catalog completeness 不得被当作 strong construction 或删-leaf 重建已完成。强义
reconstruction 与直接发射器边界见 [发射与降级](./发射与降级.md)。

## 【定法】轻量公共契约，family-local typed 实现

公式层只共享最小语义，不建立通用 Formula IR、表达式 DSL、动态字符串分派、global provider service 或通用 mechanism AST。

每个 formula 必须具有稳定、可枚举的 descriptor：

```text
formula id
owner plugin / module
operator domain
typed g type and consumed fields
typed c projection and consumed fields
bounded ω type and consumed fields
result kind
applicability / fallback class
production construction entry
```

具体 `g/c/ω` 类型、candidate、plan 与 evaluator 由 family-local C++/MLIR 代码拥有。公共层只提供：

- formula descriptor 的值类型；
- axis-use 与 result-kind 的小型枚举；
- plugin registry 收集 catalog 的接口；
- 测试/诊断所需的只读枚举。

Catalog 不是 compute authority。production caller 直接调用 typed family-local formula；catalog 与 evaluator declaration 必须同源，不能手写第二份公式表。Catalog 不按 formula id 做动态求值，不提供 untyped/`Any` 输入或大一统 result；它只为发现、扩展导航和测试枚举服务。

## 【定法】`g/c/ω` 解耦与消费

### S

承载稳定 operator semantics、operand roles 与结果语义。`S` 在进入具名 operator formula
时已经由 source op/domain 固定，因此不增加到既有 `θ=f^A(g,c,ω)` 的显式参数中。Source
adapter 不得把 family schedule、winner 或 artifact route 写入 S。

### g

承载 format/encoding/packing、layout、shape/geometry 与 representation facts。不得包含
capability、board winner、measurement、完整 body id 或已选 LMUL/tile/warp 等 family
schedule。Family execution mechanisms 由 formula 组合，不是 source g 已经做出的决定。

### c

只从 canonical `TargetCapabilitySet` 及 plugin-owned typed projection `c_f` 获得。Formula
不得重解析 march/board/device 字符串、环境变量或全局 target singleton，也不得建立跨
RVV/GPU/IME 的 giant optional capability。

### ω

承载 bounded、runtime-independent 的 operation regime、policy、必要 shape bucket 或静态 context。Measurement winner memory 不属于公式输入；它由 formula 构造候选与 legality 后的 selector 单独消费。

每个 descriptor 只声明真实消费的依赖边。一个轴无物理分叉时使用 typed honest-null 或从 evaluator 签名中消失；不得传入后 `(void)` 丢弃。每条 decisive 依赖边必须通过独立扰动证明进入 typed result、legal set 或 emitted IR/code；每条 honest-null 也要证明变化不应被虚构为 code effect。Honest-null 不是兼容逃生口：它不得在 null 后回到旧 builder/emitter 重建同一实现。

## 【定法】公式 catalog

所有 current production formulas 必须出现在由 plugin registry 可枚举的唯一 catalog 中：

```text
core formula catalog
  ← plugin-local formula descriptor ranges
       ← family-local typed evaluator declarations
```

稳定要求：

- formula id 全局唯一且不携带 board/measurement winner；
- 每个 catalog entry 恰有一个 typed evaluator/constructor owner；
- 每个 production construction entry 恰有一个公式 owner；
- deterministic construction 也必须具名；
- 不适用与 unsupported/reject 必须可区分；
- catalog 只读，不允许按 formula id 动态重建 compute；
- 删除 formula 时同步删除所有 production caller、coverage case 和旧 authority。

Formula id 只用于 inventory 和精确关联，不是进度分母。拆分、合并或重命名 formula id 不得改变覆盖结论；覆盖对象是 production authority、可达 entry、声明依赖和语义分区。

新增 operator、format、capability、formula 或 backend 时，维护者应能从 architecture/plugin 文档直接找到 family-local formula 位置与 catalog registration；不得修改 core family-name control flow。

## 【定法】覆盖怎样判断

公式覆盖不是源码行覆盖、formula id 数量或“已经实现几个公式”。它直接回答四个
代码问题，不要求维护手填百分比、长期 census ledger 或引用格式：

1. **Authority**：当前 production analytic/construction authority 是否都能从唯一
   catalog 找到 family-local typed owner？
2. **Entry**：每个 registered/direct production entry 是否真实调用该 owner，并消费其
   完整结果？
3. **Causality**：descriptor 声明为 decisive 的 `g/c/ω` 字段是否有行为测试证明会改变
   typed result、legal set 或 emitted code；honest-null 轴是否保持无虚假作用？
4. **Semantics**：适用、边界、unsupported/reject 与合法 fallback 是否由真实入口测试？

Catalog/registry 测试应从当前代码枚举这些对象并在出现遗漏时失败。它可以打印数量来
帮助定位，但数量不是科研结论，也不需要复制到稳定 spec、task 或人工表格。只批量注册
descriptor、只枚举 semantic case 名称，或只让测试手写 selected body，都不算覆盖。

一条 entry 只有同时满足以下条件才算进入统一构造路径：关联唯一 family-owned typed
construction；从实际 typed 输入构造完整决定结果；结果字段被 downstream 直接消费而
非忽略、覆盖或重算；原 builder/emitter/route 中的重叠 compute authority 与兼容旁路已
删除。

横向公式层 authority cutover 的代码事实应满足：

```text
unclassified production analytic authority = 0
legacy formula entry/caller = 0
compatibility formula adapter = 0
emitter-side redecision = 0
verifier/planner formula replay = 0
selector-created candidate = 0
hidden target/global read = 0
ignored/overridden formula result = 0
```

这些条件证明 authority 与入口收敛；它们仍不证明 `ConstructedWeak` leaf 已通过
delete-leaf reconstruction。后者必须由删除实验、等价生成测试或其它直接构造证据
单独证明，不能从 catalog 输出推导。

## 【定法】横向 cutover

建立 formula layer 是一次 project-wide horizontal rebase，不按五个 dequant plan、单个 q5_1、单个 backend 或少数 vertical slice 分期结项。

横向切换直接以当前注册表、production call graph 和代码中的 typed owner 为全集：

1. 全部 production formula/analytic construction authorities；
2. 全部 production operator entries 与 callers；
3. 全部 declared `g/c/ω` dependency edges；
4. 全部与公式同义的旧 decision provider/helper/materializer/reader/planner replay 和 emitter-side decisions；
5. 全部 catalog/behavior/negative coverage cases。

施工可以在未提交 worktree 中按依赖顺序进行，但最终合入必须一次完成：所有 current
production entries 统一进入新层，全部旧 authority 和 compatibility bridge 同时删除。
不得以“其余公式以后迁”“第二 family 后补”或“当前硬件不支持”为由保留双轨。

不含解析选择的 family 仍须提供 deterministic construction descriptor 和真实 typed construction entry；未实现的输入必须显式 unsupported/reject，不能保留隐藏旧路径。

横向退役规则见 [退役与原子合入](./退役与原子合入.md) `[RET-F]`。

## 【实现基线】2026-07-23 横向 authority cutover

当前 registry、公开 pass、direct backend、selected-body owner 与 production EmitC caller
已经按同一次横向迁移收口。这里记录的是单一 authority 的代码事实，不用 formula 数量、
测试总数或历史 census 代替 dataflow 证据。

| 对象 | 当前唯一 construction authority | downstream 约束 |
|---|---|---|
| builtin plugin proposal/cost/front door | plugin-local descriptor、evaluator 与 registration 由 live registry 枚举；catalog 只读 | core 不按 family name 动态求值 |
| RVV quantize/dequantize row | lifecycle 与显式 front door 复用 `RVVFormulaConstruction` 的 domain construction owner | unknown leaf 拒绝；emitter 只消费 typed body |
| RVV repack/contraction | contraction、repack 与 resource formula 先构造完整合法结果；lower-quant 成功返回前构造或验证 final schedule | measurement 只能选择已有合法 candidate；reason/key mirror 不参与 IR |
| generic RVV schedule | `Construction/RVVScheduleFormula.cpp` 是 candidate、legality、prior 与 bounded winner 的唯一 owner，并进入 project lifecycle | Q40/GEMM subset compatibility pass 已删除；partial/illegal tuple fail closed |
| RVV source front doors | `RVVSourceScheduleFormula` 返回 typed schedule result | front door builder 不再直接调用 gearbox selector 或重选 LMUL |
| low-precision/dot-reduce selected body | resource/dot/dequant formula result 在 selected-body owner 同一调用链内产生 | realization、route 与 emitter 不从 metadata 重建 primitive/resource 决定 |
| composite gather–MAcc–scatter | composite formula result由真实 selected-body registry owner 消费 | dispatcher 只查 registry；catalog 不再手工 `+1` |

| flat block-dot compute | `RVVFlatBlockDotFormula` 从 typed mechanism body 产生完整 `flat_*` final plan | emitter 只解析闭集 plan、投影 raw typed geometry；不得查 `kind`/`format`/旧 `fold_model` 重选 |
| artifact-neutral family seam | target/profile 绑定 origin family 与 typed `c_f` 后，以 variant-scoped `FamilyConstructionRequest` 调用 `constructFormulaPlans`，family 返回 exact `FamilyConstructionResult` typed operation/root；base implementation fail closed | common 只检查 exact result 存在且属于绑定 kernel/variant；completion 不依赖 artifact dialect、module scan 或 metadata/string route |

| Scalar direct compute | Scalar family 从 typed geometry 与 canonical `scalar.fallback` 构造 conversion-local final plan；q2 block-dot 与 q4_0 dequant 对称进入同一 family lifecycle | emitter 只读取完整 plan；unsupported geometry、缺 capability、partial/冲突预置 plan 均拒绝 |

| deterministic typed-body families | Demo、Toy、Template 与 TensorExtLite 由各自 family construction owner 校验 canonical capability、selected variant 与 legality，并直接构造/返回 exact family-local typed body/root | construction manifest、typed-role replay、route provider、通用 readiness verifier、字符串 role/status/interface 镜像与 metadata-only boundary 已删除；固定 callee/ABI 只是 artifact projection，不是第二 compute authority |
| unsupported family | Offload 不注册 backend emitter | 明确 unsupported/reject，不以空 driver 或 fallback 冒充 coverage |

flat block-dot 当前 live 语义域为 `Q80Q80`、`Q40Q80`、`Q41Q81`、`Q50Q80`、
`Q51Q81`、`IQ4NLQ80`、`MXFP4Q80`、`Q10Q80` 与 `NVFP4Q80`。这份集合用于保护
机制差异和 negative boundary，不按 leaf 数量计算科研进度。formula 原子产生 body family、
decode primitive、fold、block length、activation offset、scale source、真实存在的 table
identity 与 bias；缺失、partial、未知、与 typed mechanism 冲突的 plan 一律拒绝。测试骨架
不能再靠旧 `fold_model` 被猜成 production leaf。

Catalog 的 `construction:*` production-entry inventory 与 live family construction owner
必须同源、entry 与 owner 唯一；EmitC backend inventory 单独枚举 artifact consumer，不能与
construction inventory 合并或要求所有 future family 进入同一表。这些只是防止死登记和漏
登记的结构门，不替代实际 construction/negative 行为证据。

当前 construction-entry inventory 与 artifact inventory 已分开：family formula/construction
在 artifact class 之前完成；EmitC、native object、future NVVM/ROCDL 只是不同 artifact
consumer。`emitc.func` 完成门只属于 current EmitC artifact，不能被提升为跨 family
construction contract。所有 current family 先经过 artifact-neutral construction lifecycle，
再把 exact typed result 交给对应 artifact driver；不新增 universal
provider/verifier/Formula IR，也不以 module-wide body scan 代替 construction return value。

入口完整性还要求从 conversion 根反向封口：raw family pattern/type population 只能是
backend 实现细节，不能成为 public caller 可自行拼装的第二 lowering API；所有实际
`apply*Conversion` 必须由 constructed-only shared harness 持有，而它的 production caller
必须先完成 family construction。一次 standalone
EmitC materialization 只能有一个 backend owner；混合 family body 必须在任何 cleanup 前
fail closed。family-specific public pass 对“不含本 family body”可以 no-op，但对“含 body 而
不能完整转换”不得成功保留原 IR。

因此 `[RET-F]` 对当前 registered/direct production authority/caller 集合已经闭合：旧兼容
入口、registry special branch、front-door 双编排、emitter compute replay 与非语义镜像均
不再构成第二生产路径。这个结论只说明 authority convergence；它不改变主公式、薄 selector、两柱或
六律，也不把下面的构造充分性债务写成完成。

当前仍有 `ConstructedWeak` leaf：它们已经在唯一公式路径内，但仍依赖完整机械 leaf。
“删除某个逐点手写 leaf 后，`g/c/ω + mechanisms + formula` 能重建同一实例”的 strong
reconstruction 继续作为下一层准入标准，必须由删除实验或等价构造证据单独证明。

## 【定法】测试要求

### Catalog/static integrity

- formula id、owner、operator domain 唯一；
- catalog entry 与 typed evaluator declaration 同源；
- 每个 production entry 有且只有一个 formula/construction owner；
- denylist 中旧 symbol/include/adapter/caller 为零；
- core/common 无 family-name formula dispatch；
- formula module 不读取 emitter state、measurement winner 或隐藏 target global。

### Formula unit behavior

- baseline applicable case；
- 每个 decisive `g`、`c`、`ω` edge 的独立变化；
- unrelated/honest-null 轴的不变性；
- 每个分段边界、unsupported 与 fallback；
- deterministic result 与 typed invariants。

### Production integration

- 从真实 source/direct production entry 执行，不由测试手写 selected body；
- formula result 改变真实 typed IR、candidate/legal set 或 code shape；
- legality 只缩小公式候选；
- selector 不创造候选或改变 `θ`；
- typed body 消费 selected result；
- emitter 不重算公式决定；
- 每个 current production plugin/operator domain 至少执行一条路径。

### Regression

- 既定 byte-exact/ULP correctness；
- plugin/registry/route/bundle/ABI tests；
- 与触及面相称的 clean build 和 full `check-weft`；
- 性能主张另走真实硬件 measurement，不由本次本地重构测试代替。

## 非目标

- 新高层 tensor/tile IR；
- 通用 Formula dialect、AST 或在线 autotuner；
- 一个包含所有 family optional 字段的 giant context/result；
- 把 GPU 注册为 current EmitC emitter，或让 artifact registry 兼任 family construction；
- universal verifier 或 formula provenance 治理系统；
- 强迫每个公式同时依赖 g、c、ω；
- 用 catalog 数量、coverage 字符串或 reason 冒充 construction；
- 允许 production 旧路径作为迁移 fallback。
