# 家族现状（extension families）

本文答两件事：**哪些家族的根在不在**（现状，可实核），以及**一个家族凭什么正当进入本机器**（定法）。各家族的接入协议本身住 [插件协议](./插件协议.md)。

读法口径见 [本层 index](./index.md#读法口径落笔前必读--四条)。硬规则全文住 [canon · 核心不变量](../canon/核心不变量.md)。

> RVV / IME / TensorExt / Offload / Scalar / future NVIDIA/AMD/vendor·custom 家族属于
> **同一个 Weft MLIR operator compiler / execution-layer stack**，不是互不相关的 backend
> 集合。RISC-V 是当前旗舰 realization 与压力域；GPU 是 V2 的第二 execution paradigm
> 目标，不在当前家族册中（见 [执行问题与家族边界](./执行问题与家族边界.md)）。

---

## 【现状】家族册

**extension family 实存 8 个**：RVV · IME · Offload · Scalar · Template · TensorExtLite · Toy · Demo。

另有 **`Exec` = core envelope dialect**（非家族）· **`Builtin`**（`lib/Plugin/Builtin` 注册表 + `lib/Target/Builtin`）· **`Construction`**（`lib/Plugin/Construction` 构造协议）两根**非家族基建**。

### 三根完整度（实核）

| Family | `lib/Dialect/` | `lib/Plugin/` | `lib/Target/` |
|---|---|---|---|
| RVV | ✓ | ✓ | ✓ |
| Scalar | ✓ | ✓ | ✓ |
| Template | ✓ | ✓ | ✓ |
| TensorExtLite | ✓ | ✓ | ✓ |
| Toy | ✓ | ✓ | ✓ |
| Demo | ✓ | ✓ | ✓ |
| **IME** | ✓ | ✓ | **—** |
| **Offload** | ✓ | ✓ | **—** |

> 复核谓词：
> `for f in RVV IME Offload Scalar Template TensorExtLite Toy Demo; do echo "$f $([ -d lib/Dialect/$f ] && echo Y || echo -) $([ -d lib/Plugin/$f ] && echo Y || echo -) $([ -d lib/Target/$f ] && echo Y || echo -)"; done`

**IME 无 `lib/Target/` 根但有发射驱动**（`lib/Plugin/IME/IMEBackendEmissionDriver.cpp`，经共享 `BackendEmissionRegistry` 接入）；**Offload 两者皆无**。

### 注册事实（实核 · 两张表）

- 插件发现目录 `kBuiltinExtensionBundles[]`（`lib/Plugin/Builtin/BuiltinExtensionPlugins.cpp`）→ **8 项**（全部 8 家族）。
- 后端发射器目录 `kBuiltinBackendEmitters[]`（`lib/Conversion/EmitC/Builtin/BuiltinBackendEmitters.cpp`）→ **7 项**：RVV · Demo · Toy · Template · TensorExtLite · IME · Scalar。**表内无**：Offload。

> 复核谓词（语法边界抽表体，不用有界窗口）：
> `awk '/kBuiltinExtensionBundles\[\] = \{/,/^\};/' lib/Plugin/Builtin/BuiltinExtensionPlugins.cpp`
> `awk '/kBuiltinBackendEmitters\[\] = \{/,/^\};/' lib/Conversion/EmitC/Builtin/BuiltinBackendEmitters.cpp`

### 【现状】零 core family-name 分支（I3）

**I3 在 core pass 层是【现状】，不只是目标**——逐文件实核 `lib/Transforms/` 的 12 个 `.cpp`：11 个对 `{RVV|IME|Offload|Scalar|TensorExtLite|Toy|Demo|Template}` **0 命中**；唯一有命中的 `EmitCLowerableMaterialization.cpp` 的 2 处**均在注释散文**（说明 registry 遍历已注册 backend 的表驱动机制），**非分支**。

> 复核谓词：
> `for f in lib/Transforms/*.cpp; do echo "$(grep -cE '\b(RVV|IME|Offload|Scalar|TensorExtLite|Toy|Demo|Template)\b' "$f")  $f"; done`
> 命中文件须逐个人工判「分支 vs 注释」，**禁只看计数**。

> ★ **措辞订正**：spec 前版称 IME 的零分支是「grep-clean proven: 0 hits over lib/ minus IME dir」。**该断言按字面不成立**——`lib/` 内 IME 名在 IME 目录外另有命中：2 处在 RVV 插件文件内的**注释**（`RVVExtensionPlugin.cpp` · `FrontDoor/RVVLowerQuantContraction.cpp`），加上两张**注册表的数据行**。**不变量仍成立，但其正确表述是**：零分支性质的辖域 = **core/common pass**（`lib/Transforms/`，逐文件实核如上）；家族名出现在**另一家族的插件注释**与**family-agnostic 的注册表数据行**内，二者都不是 core 分支。
> 复核谓词：`grep -rnE '\bIME\b' lib/ --include='*.cpp' --include='*.h' --include='*.td' | grep -v '/IME/'`

## 【定法】三根表的判读注

**「三根齐」不是成熟度判据**——三根齐的家族里既有主力也有脚手架 / 对照家族。**禁以目录存在推断家族成色**（[L-6] wiring ≠ construction）。**本表只答「根在不在」，不答「成色如何」。**

> 本节**不断言「今日有几个 / 没有家族满足 [F-6]」**——那是**进度状态**，住 [issues](../issues/index.md)。
> **两类计数别混**：**结构事实的计数**（几个桶 / 几个家族根 / 几个 pass）附谓词可实核，**入【现状】栏**；**进度 / 覆盖度状态的计数**（几格达标 / 还缺几个 plan）会随工作漂移，**不入 spec**。

## 【定法】[F-6] Weft-RV 独立/集成判据

在 Weft-RV realization 内声称 **independent** 的家族，须**同时**满足：

1. 其全部变体的能力谓词 `implies` 传递闭包 ∩ `{rvv.*}` = ∅（**脚本化机检**）；
2. **存在向量缺席实例**使其变体 `only_feasible` 并**被真实选中**。

术语用 **independent-attached**，**不与 integrated（复用向量寄存器堆）混用**。
该判据不用于判断 future GPU 是否可作为 Weft construction family；general admission 见下
[家族准入边界](#定法家族准入边界)。

## 【目标】[F-6] 的机检落地

判据已定法，但其两项条件的**机检脚本**与**被真实选中的向量缺席实例**是待建工件。任何 independent 主张须先过该机检——**在机检存在前，禁以目录存在或设计意图代替**。

## 【定法】家族准入边界

一个 family 正当进入 Weft，当且仅当它能作为 execution-layer typed construction family
接入同一 operator compiler 主链，而不要求 core/common 按 family 名解释 compute：

- canonical source/problem 明确 `S/g/ω`，且不携带 family schedule；
- target/profile 在 construction 前绑定 family，target 能力形成 typed `c_f` projection，
  不从 route/artifact/device 名反推；
- bounded `ω`、formula construction、legality 与 optional selector 在 family 内产生 final
  typed body/plan；
- artifact driver 通过共同 registry/interface 接入，但 lowering、ABI、runtime 与 artifact
  语义仍由 family owner 负责；
- unsupported 能力、缺 runtime/toolchain 或空合法集显式拒绝；
- runtime、correctness 与 performance 主张有对应真实平台证据。

因此，复用一条 dispatch pipeline 还不够；必须复用 capability-driven typed construction
契约，并证明新增 family 的变化主要局部化。反过来，也不能把“必须属于 RISC-V ISA”写成
系统类型限制：Weft 的身份是 post-graph、pre-schedule operator compiler，RISC-V 量化推理是
当前旗舰实例与论文主要验证域。独立 GPU/NPU/offload family 当前没有实现，也不能从空
placeholder 推导通用性；未来若接入，必须先给出自己的 problem applicability、capability、
mechanism/formula、typed body、artifact/runtime、legality 与 evidence，而不是仅增加设备名
分派或 current EmitC emitter。

当前 Offload 仍是 explicit unsupported；这表示尚无该 realization，不表示研究主线把
所有非 RISC-V execution family 永久排除。

> 家族语义（family = 能力声明 + 所有权边界，不是指令密度；「能力门家族」合法）见 [能力模型 §[S-8]](./能力模型.md#定法s-8-家族语义--能力声明--所有权)。

# RVV 家族

RVV 是 Weft-RV 当前的主真实硬件 family，也是第一个走通 typed-body → plugin-owned route → 公共 EmitC → 真板证据的完整 family。**RVV-first ≠ RVV-only**：同一套 plugin 协议要能让 IME / offload 复用。

**durable 路径（authority chain，全项目唯一权威版本）**：

```text
weft.exec envelope
  -> selected RVV variant
  -> typed low-level weft_rvv vector-level body
  -> RVV plugin-owned legality / selected-body realization(Gearbox) / route provider
  -> WEFTEmitCLowerableRoute
  -> 公共 EmitC materializer
  -> RVV intrinsic C/C++
  -> target artifact
  -> 真板 evidence（当 runtime/correctness/performance 被主张时）
```

> 本节只描述 RVV 插件的**稳定边界**。具体覆盖到第几个算子、哪个候选在调、measurement 跑成什么样——是状态，进 task/journal，不进这里。

## 【定法】Authority Placement

谁拥有什么。这是 RVV 线最容易被 AI 搞错的地方（从 ABI 名/route id/artifact 名反推 compute）。底层规则见 [canon · 核心不变量](../canon/核心不变量.md) I2/I3/I5；下面是 RVV 的具体落点。

**`weft.exec`** 只拥有 execution envelope：kernel、capability scope、selected variants、requires、dispatch/fallback、diagnostics、`mem_window`/`runtime_param` 的 ABI 角色声明。它**不**拥有 RVV compute 语义、dtype、schedule、intrinsic 拼写或 selected route authority。

**selected `weft_rvv` body** 拥有 typed vector-level 执行结构：typed vector 值与 element dtype、SEW/LMUL/vtype policy、VL/AVL/setvl、load/store 与 memory form、arithmetic/compare/select/FMA、reduction/accumulator、mask/tail、movement/layout/conversion、runtime ABI 值消费。dtype/config/operation 事实**只**经 typed 值、config、body 结构进入——不从 route id、C ABI 串、参数名、artifact 名、test 名、`__riscv_*_i32m1` 拼写、旧 `!weft_rvv.i32m1` helper 名推断（I5）。

期望的 typed 形态：

```mlir
!weft_rvv.vector<elem = i32, lmul = m1>
%vl = weft_rvv.setvl %remaining {sew = 32, lmul = m1, policy = ...}
%a  = weft_rvv.load %lhs[%i], %vl
%c  = weft_rvv.binary {kind = add} %a, %b, %vl
weft_rvv.store %out[%i], %c, %vl
```

**RVV 插件** 拥有：RVV body/config/control/dataflow 的 legality；hints/config/profile 影响生成代码时的 selected-body realization；route 支持与 route provider 输出；intrinsic 映射；C/RVV 向量类型映射；ABI 映射；fail-closed 诊断。Common/core 只调插件 interface + 校验通用结构，**不**按 RVV 语义分支、不选 intrinsic、不推 dtype、不建 schedule、不合成 body（I3）。

**公共 EmitC/export** 只做中性 materialization 与打包，materialize provider 建好的 `WEFTEmitCLowerableRoute`。它**不**发明 RVV compute、dtype、SEW/LMUL、schedule、intrinsic 选择或 ABI 角色语义。

## 【定法】Parameter Flow

`mem_window` / `runtime_param` 声明 ABI/runtime 角色（lhs/rhs/out/n、buffer/scalar、runtime count、C ABI 拼写/provenance）。selected `weft_rvv` body 必须显式 bind/import 这些值，再经 typed control/dataflow 消费：

```mlir
%lhs = weft_rvv.runtime_abi_value @lhs
%n   = weft_rvv.runtime_abi_value @n
```

然后经 `setvl`、load/store、compute、mask、reduction、movement 使用。`weft.exec` 不从 ABI 角色名 / C 类型串 / artifact metadata 推断 add/mul/reduce/dtype。

## 【定法】Route Provider —— 一个通用契约

RVV 路线历史上为每个算子族重复抄了大量同结构契约。它们其实是**同一条通用契约**反复套用。这里写一次：

RVV route provider 从 typed body 事实派生 route，事实包括：operation kind、element type、SEW、LMUL、tail/mask policy、operand form、memory form、runtime ABI binding、target capability。由这些派生 intrinsic/backend 拼写、C 类型、header、operand binding。

通用规则（对所有算子族一致，不需要每族再写一遍）：

- route 事实**结构性来自 typed body**或被 realize 进 body；metadata 镜像可有，但不是 authority（I4/I5）。
- 缺合法 typed body / 缺必要 capability / 只有 metadata → **fail closed** 给 bounded 诊断，绝不从 metadata 合成 C body（I7）。
- provider 输出先于公共 EmitC；公共 EmitC 不补 RVV 语义。
- runtime/correctness/performance 主张 → 真板证据（I8）。

新增一个算子族 = 让它满足上面这条通用契约 + 进下面的覆盖表，**不是**再抄一份 7 段模板。

## 【定法】Selected-Body Realization

RVV 的 selected-body realization 是 family-local typed construction 的一部分。它把合法且
已选的 candidate/plan 具体化为 `weft_rvv` body，可决定 dynamic VL/setvl 放置、合法
SEW/LMUL/policy、memory form、mask/tail、register-pressure-safe unroll、prefetch/
software-pipeline 与 accumulator/reduction layout。

候选、resource/legality、analytic prior 与 bounded measurement selection 的唯一契约在
[变体流水线](./变体流水线.md)。旧 Gearbox candidate/resource stamp、公开兼容 pass 或
pre-realized-body 二次解释都不是当前 authority。影响生成代码的决定必须在 route 构造前
进入 final typed body/plan，不外溢到公共 EmitC、provider 或 artifact metadata。

## 计算类契约面（coverage surface，按结构化计算类）

RVV provider 按 route 契约要支持的算子族。这是**广度清单**，不是契约阶梯——每族都走上面那条通用 provider 契约（**当前覆盖到哪些族是状态，进 task/journal**）：

| 计算类 | 算子族 |
|---|---|
| elementwise / arithmetic | binary 算术、compare、select、math |
| broadcast | scalar-broadcast 算术、splat-store |
| reduction / accumulation | standalone reduction、MAcc（plain + scalar-broadcast）|
| contraction-like | widening dot/product-reduce、widening MAcc |
| 低精度 contraction | i8/u8 widening product → widening reduction → dequant(i32→f32)[+clamp/select]、packed-i4 |
| movement / layout | unit-stride load/store、strided、indexed gather/scatter、segment2 deinterleave/interleave（plain + computed-mask）|
| dtype conversion | widening / narrowing conversion |
| mask / tail | computed-mask 各 memory/compute 形态、tail policy |
| runtime shape / control | `setvl` / `with_vl`、runtime AVL/VL、runtime-scalar 形态 |

低精度 contraction（i8/u8/packed-i4 widening-product-reduce-dequant）是 RVV **性能轴**证据点。它必须按 formula 构造的 typed body 与机械 route/emitter 推进，**不被 q8/q4/llama 之类工作负载名当 route authority**（I9）。其 body 是否达到 strong construction，要看 widening dot-product-reduce、dequant-LUT、宽钳位等 mechanisms 能否在删除完整 point leaf 后重建同一 body/legal domain；provenance 只能辅助定位。统一契约见 [发射与降级 §发射与构造纪律](./发射与降级.md#定法发射与构造纪律construction-discipline)（[K-0]/[K-2]/[K-6]），此处不重述。

## 【定法】Fail-closed invalid paths

`i32m1`-as-route-authority、`RVVI32M1*` route spec、descriptor/microkernel/direct-C
反向构造、source-front-door 合成 route 都不是有效 production authority（I7）。这些输入
只能 fail closed，不能作为兼容 positive route。新可执行工作一律走 formula/construction
→ final typed body/plan → mechanical route/EmitC。

## 给 agent 的判断点（不是 gate）

- 在写"第 N 个 route 契约"之前：它真满足上面的通用契约吗？若是，进覆盖表即可，别抄模板。
- 在做"又一个 artifact/ABI evidence closeout"之前：读 [governance · 思维准则](../governance/思维准则.md#一主干纪律) §一 主干纪律——大概率该转主干了。
- 性能主张落地前：Gearbox 真的枚举/剪枝候选了吗？真的对**框架出厂同-ISA kernel**胜出/打平了吗（**不是**赢 scalar）？没有就如实说，别用 metadata 包装成"成熟"。

# IME 家族

## 【定法】Role

IME plugin 是统一 WEFT 系统内 IME（`spacemit.ime`）extension family 的路径。它是**第二个非-RVV extension family**，经同一 capability model / registry / common pipeline 消费，**零 core family-name 分支**（I3）——**不是**一个独立 backend。

零-core-branch 泛化的行为形态：

```text
existing system supports RVV
add IME plugin
same validated scenario may gain an IME execution variant
core pass does not hard-code IME
admission cost is local-not-zero（注册行 + family-local LOC），NOT "zero core edits"
```

> 零分支性质的**辖域与实核谓词**见上 [§零 core family-name 分支](./家族现状.md#现状零-core-family-name-分支i3)。

## 【定法】Positioning

IME 不是普通的 runtime offload。它更接近：

```text
ISA-level matrix-like extension
vector-register-backed matrix execution
RVV-resource-related matrix/dot execution
```

IME 的 runtime/correctness/performance 主张需要真实硬件/toolchain 证据（I8）。下面更宽的 op 类是该家族的**设计契约证据场景**，不是当前 source-front-door 或 high-level frontend 工作。

IME plugin 必须理解：IME 矩阵/dot 指令；RVV 向量寄存器资源；VLEN 对 fragment shape 的影响；dtype 与 accumulator policy；到 IME/vendor intrinsic C/C++ 的 EmitC 映射与所需 toolchain 路径。

## 【定法】Capability Fields

```text
spacemit.ime or target-specific IME capability
ime.version
ime.supported_dtype
ime.vector_register_backed
ime.vlen_range
ime.fragment_shapes
ime.accumulator_types
ime.toolchain_path
```

参考 attribute：

```mlir
#weft.ext<"spacemit.ime",
          kind = "isa_ext",                          // [S-1] 闭合枚举值
          subclass = "isa-matrix-vector-backed",     // 子分类标签（[S-5]①），非 kind 值
          status = "available",
          register_model = "rvv-vector-register-backed",
          dtype = ["int8", "fp16", "bf16"],
          vlen_dependent = true>
```

## 【定法】Extension Family

架构家族名 `weft.ime`。

Types：

```text
!weft.ime.frag<dtype, shape, layout>
!weft.ime.accfrag<dtype, shape>
!weft.ime.config<...>
```

类型设计必须表达与 RVV 资源的关系：

```text
register_model = rvv-vector-register-backed
vlen_dependent = true
```

Ops：

```text
weft.ime.config
weft.ime.load_frag
weft.ime.store_frag
weft.ime.pack
weft.ime.unpack
weft.ime.mma
weft.ime.dot
weft.ime.accumulate
weft.ime.convert
```

这些是 **IME 执行 op，不是 high-level matmul op**。

## 【定法】Variant Generation Scope

IME plugin 的变体生成范围可覆盖：

```text
matmul
batched matmul
attention qk/av matrix block
MLP dense block
int8/fp16/bf16 dot-like kernels
```

它**不需要**覆盖每个算子。它应覆盖**能体现矩阵扩展价值**的算子。

## 【定法】Legality Rules

IME plugin 检查：target 声明了 IME capability；RVV/vector-register-backed 前提被满足；dtype 被 IME 支持；fragment shape 匹配 VLEN 与指令限制；accumulator 类型被支持；layout 与 packing 要求被满足；toolchain 支持选中的 IME 发射路径；需要时 IME/vendor intrinsic C/C++ route 可用。Inline asm 或 backend adapter route 是可选的未来兼容路径，**不是当前默认**。

## 【定法】Tuning Space

```text
fragment shape
K blocking
accumulator residency
packing format
register pressure
thread partition
IME instruction selection
fallback to RVV for unsupported shapes or dtype
```

Tuning metadata 必须**留在 variant-local**，不得污染 high-level 语义。

## 【定法】Emission Paths

```text
WEFT IME family ops
  -> EmitC
  -> IME/vendor intrinsic C/C++
```

全部 IME-specific 发射逻辑属 IME plugin 内部。Compiler builtin、inline asm、external assembly stub 或 patched backend adapter route 是**未来可选兼容路径**。

## 【定法】Plugin Evaluation

一个家族的零-core-branch 泛化主张为 **TRUE**，当：

- 同一个已验证的 high-level 场景**无需 core/common pass 改动**即获得一个 IME execution variant；
- IME 与 RVV 变体在**同一套 selection/dispatch 逻辑**下共存，无 family-name 分支（I3）；
- selection / dispatch / emission 复用 common pipeline，IME-specific 逻辑留在 plugin-local；
- 任何新 capability / ops / types 由插件**局部**贡献，而非编辑 core。

（IME 的 runtime/performance 是**独立的性能主张**，需要真实 K1/IME 硬件证据，I8。）

# Scalar Fallback 家族

## 【定法】Role

scalar fallback plugin 为 Weft-RV execution variant 提供**可移植兜底槽**。它是一条**覆盖与正确性导向**的路径，在 target profile 显式暴露 fallback capability 时使用。

**它不是主性能路径**，不得被报作 RVV / IME / offload / 硬件特定证据。

## 【定法】与向量缺席独立标量家族的边界（勿混 —— 同名 "scalar"，实为两物）

**本 fallback 插件 ≠ 向量缺席的独立标量性能家族。** 后者是**向量缺席的独立性能家族**（owned 内核 = 低比特 `vec_dot` 热性能路径；须过 [F-6] 独立性 = 向量缺席实例下 `only_feasible` 且真实被选中）。本 fallback 插件是**可移植兜底覆盖槽**（correctness-only、非性能路径）。

**不得把 owned 性能内核塞进本 fallback 槽**：`weft_scalar` 命名空间保留的 "later scalar rebuild" **可作独立标量家族的落点，但那是一个新的独立家族插件**（带 owned 内核 + 能力事实 + [P-2] 五件套），不是给本 fallback 槽加性能路径。

**设计护栏（耐久约束，非任务选择）：低比特量化点积数学不走 XOR-popcount** —— 三值/低比特走位域抽取 / base-3 拆包 / 查表 gather，`zbb` 的 `cpop` 在这些内核**无处落地**；owned 内核**不得按 popcount 模板设计**、不为其造 popcount 语料。

> 家族语义（「能力门家族」合法；`zbb`/`zba`/`zbs` 作标量家族的 `sub_ext` 子事实）见 [能力模型 §[S-8]](./能力模型.md#定法s-8-家族语义--能力声明--所有权)。

## 【现状】First C++ Plugin Slice

第一个 scalar fallback C++ slice 是**刻意有界**的。它证明一个 fallback 实现能经与 RVV 同一套 plugin 协议参与，而**不向 core 编排添加 extension-specific 分支**。Legacy descriptor 形态的字段名是删除残留或 fail-closed 实现债，**不是**添加新计算的架构。

稳定的 first-slice 名字：

```text
plugin name: scalar-plugin
plugin version: 0.1.0
plugin capability id: scalar.fallback
plugin capability kind: policy          # [S-1] 闭合枚举值（可用性/兜底门），不是裸 "fallback"
plugin capability subclass: fallback    # 原始类目保留（[S-5]① subclass，信息不丢）
preferred kernel capability symbol: @scalar_fallback
first-slice proposal / variant symbol: @scalar_fallback_first_slice
variant origin: scalar-plugin
required capability id: scalar.fallback
materialized requires form: requires = [@scalar_fallback] for an exact scalar
  fallback capability, or a relation-provider symbol such as
  [@module_fallback_profile] when that capability structurally `provides` or
  `implies` id `scalar.fallback`
generic policy: portable_scalar_fallback_first_slice
generic fallback role: fallback_role = "conservative"
deleted legacy selected-path element attr: weft_scalar.element_count
```

> 复核谓词：`grep -rn 'scalar.fallback' lib/Plugin/Scalar/*.cpp`

## 【定法】提议规则

first-slice scalar plugin 只有在请求含**一个真实 high-level MLIR operation**、**一个 `weft.exec.kernel`**、且 `TargetCapabilitySet` 内 capability id `scalar.fallback` 可用（作为 exact capability id，或经显式结构化 relation-provider capability 的 `provides`/`implies` 满足）时，才可提议 `@scalar_fallback_first_slice`。**缺失或不可用的 fallback capability 必须产出"无提议"，而不是一个隐式恒可用的 variant。**

scalar fallback source slice 的默认提议是 **descriptorless** 的，**不得**从 frontend metadata、bridge metadata、默认 family 表、缺席 body 状态或手写 microkernel 名派生出有限的 i32/i64 add/sub/mul 族。**当前不存在 typed scalar selected-path compute authority。** 历史标记（如 `weft_frontend_lowering`、`weft_scalar.element_count`）只是删除残留；活跃的 scalar plugin **不**把它们当提议、legality、selection 或 boundary authority 消费。

## 【定法】Capability And Legality

scalar fallback 仍是 capability-driven 的：

- target profile 必须把 `scalar.fallback` 声明为结构化的 exact `weft.exec.capability`，或从结构化 capability-provider `weft.exec.target` 显式 provide/imply 它；
- 生成的 variant 必须经 `requires` 要求该 capability；
- plugin legality 必须拒绝缺 origin、缺 fallback capability 要求、或 fallback capability 不可用的 variant；
- **core pass 不得按名 special-case scalar fallback**（I3）。

## 【定法】Cost And Selection

first slice 用 plugin-owned 的 preference/cost metadata 把 scalar fallback 标为保守覆盖路径。其显式 preference **刻意弱于** RVV 等 plugin-specific 合法变体，故它只在无更好的合法 plugin-owned 路径被选中时胜出。**不得**把它当性能基线，除非后续任务加入真实 lowering、runtime、输入 metadata 与实测证据。

selection 与 dispatch 必须复用既有的通用 variant-selection 协议。**scalar fallback 不引入新的 core fallback selector**：插件用抽象的 conservative fallback 角色标注 proposal/cost estimate，core 只消费那个**通用角色**。

## 【定法】Unsupported Emission Boundary

scalar fallback 当前是一条 **fail-closed 的编译器规划路径**。一个被选中的 scalar fallback proposal 可对通用 selection、dispatch 与 coherence 检查保持可见，但**不得**变成 scalar compute、metadata-only 发射路、runtime ABI 或 target artifact authority：

```text
diagnostic result: unsupported
emission kind: scalar-fallback-unsupported-emission
lowering pipeline: scalar-fallback-no-materialized-emitc-route
runtime ABI: scalar-fallback-no-runtime-abi
runtime ABI kind: unsupported-plugin-runtime-abi
runtime ABI name: unsupported-emission-runtime-abi
runtime glue role: no-runtime-glue-unsupported
required capabilities: selected scalar fallback variant required capability refs
artifact kind: unsupported-emission-diagnostic
```

该 unsupported 诊断/结果**只记录一条缺失的重建路径**。它**不**意味着 Weft-RV 发了 LLVM IR、生成了 object、链了 runtime、跑了 scalar kernel、证了正确性或测了性能。它也**不**授权 metadata-alone 的 selected lowering-boundary 物化。

scalar fallback **不是**把未建的家族泛化工作提前的载体（见 [governance · 思维准则](../governance/思维准则.md#一主干纪律) §一 主干纪律）。在后续 plugin-local 重建创造出真实 typed scalar body 与 EmitC route 之前，它只是一个保守的 selection/fallback 诊断面。

## 【定法】Selected Lowering Boundary

scalar fallback 当前**没有活跃的 selected lowering-boundary operation**。通用 fallback-only 与 dispatch-fallback 路径可保留 selected `weft.exec` metadata，但**不得**要求 scalar plugin 从 descriptorless 无-body 状态、kernel frontend 标记、bridge metadata 或默认 family **合成**一个 scalar plugin-local boundary、runtime ABI operation 或 typed scalar microkernel。

架构家族：`weft.scalar`。保留 MLIR 命名空间：`weft_scalar`。

保留的命名空间是**给后续 scalar 重建 slice 用的**。它**不是**当前 boundary 面，不得被当作可执行 lowering、metadata-only 发射、runtime ABI glue、object 生成、正确性证据或性能证据。通用 fallback-only 与 dispatch-fallback 路径**不得**仅因为没有 scalar boundary 被物化就产生 missing-plugin 诊断。

scalar plugin **不得**从默认值、RVV-scalar bridge metadata、手写的已删除 op 语法或任何等价 metadata selector 创造任何有限族 scalar microkernel。**body 的缺席是一个 unsupported fallback 状态，不是 compute authority。**

下游 emission planning 对被选中的 scalar fallback **只能**发出上述 unsupported 诊断。它**不得**把 scalar boundary 当 route authority 消费，因为不存在活跃的 scalar boundary route。

真正的 scalar fallback lowering 必须由后续 plugin-local 重建 slice 经 extension-family ops + 一条物化的 MLIR EmitC route 添加，然后用编译器生成的工件与该路径相称的 runtime 证据验证。

## 【定法】Deleted Finite-Family Scalar Microkernel Ops

历史的 scalar extension-dialect microkernel source-export 面**已删除**。其旧的有限 dtype/算术拼写集**不得**作为活跃 dialect op、EmitC-lowerable op、惰性未来-route IR、selected-boundary authority、runtime ABI authority、generated-artifact authority、正确性证据或性能证据留存。

scalar fallback 的直接 runtime-callable C 源/header/object route 是**已删除的生产路径**。通用 target artifact 前门对历史 scalar 直接 route id **必须 fail closed**，直到重建路径物化出真实 MLIR EmitC module 并经 MLIR emitter 发出 C/C++。

# Offload 家族

## 【定法】Role

runtime offload plugin 代表 Offload extension family：统一 WEFT 系统内的 **RISC-V host + 外部或 SoC accelerator 执行**。

对 Sophgo 类环境，执行通常用：

```text
vendor runtime
C API
PCIe or SoC data transfer
compiled accelerator model or kernel
async execution queue
host-device synchronization
```

这是一个 **`runtime-offload capability`，不是 custom RISC-V ISA 扩展**（准入判据见上 [§家族准入边界](./家族现状.md#定法家族准入边界)）。

## 【现状】First C++ Plugin Slice

第一个具体的 C++ runtime-offload slice 是**刻意有界**的，且当前**仅为 stale/no-active-route 验证**。可执行的 Offload 集成是**未来工作，尚未构建**。当前 slice 可证明 plugin identity、显式 capability gating、proposal metadata、legality routing、conservative preference metadata 与 descriptor 工件删除后的 unsupported 诊断；它**不得**发布 target artifact/export route。

> **实核佐证**：Offload **在 `kBuiltinExtensionBundles[]` 内**（插件可发现），但**不在 `kBuiltinBackendEmitters[]` 内**，且**无 `lib/Target/Offload` 根**（见上 [§家族册](./家族现状.md#现状家族册)）——与"无可执行发射路"一致。

稳定的 first-slice 名字：

```text
plugin name: offload-plugin
plugin version: 0.1.0
plugin capability id: offload.runtime
plugin capability kind: policy (subclass: runtime-offload)
preferred kernel capability symbol: @offload_runtime
first-slice proposal / variant symbol: @offload_runtime_first_slice
variant origin: offload-plugin
required capability id: offload.runtime
materialized requires form: requires = [@offload_runtime] for an exact
  runtime-offload capability, or a relation-provider symbol such as
  [@module_offload_profile] when that capability structurally `provides` or
  `implies` id `offload.runtime`
runtime ABI handoff id: generic-runtime-offload-c-abi-handoff.v1
handoff kind: runtime-offload
```

## 【定法】提议与 legality 规则

先前的 descriptor 工件 route **已删除**。当前 first slice 仍可物化 capability-gated metadata 与一个 selected `weft_offload.lowering_boundary`，但 emission planning **必须 fail closed 为 unsupported**，直到未来可执行的 Offload lowering 经 common extension family ops → EmitC → runtime C ABI route 重建。

first slice 只有在 kernel 为 id `offload.runtime` 声明了**可用的结构化 capability provider** 时才可提议 `@offload_runtime_first_slice`。该 provider 可以是 id 为 `offload.runtime`、kind `policy`（subclass `runtime-offload`）的 exact capability，或其 `provides`/`implies` 列表满足 id `offload.runtime` 的显式 relation-provider profile。provider 必须携带 bounded 通用属性：

```text
runtime_abi = "generic-runtime-offload-c-abi-handoff.v1"
handoff_kind = "runtime-offload"
```

若 capability 缺失或通用地不可用，插件**不提议任何 variant**。若显式 offload capability 在场但所需通用 handoff metadata 缺失、畸形、无界、疑似机密或不是通用 first-slice handoff 契约，则 proposal collection 记录一次可恢复的 plugin-local decline 并**不产出** offload proposal。**Vendor 名、Sophgo 串、RVV probe 事实、架构名与无关的 runtime-offload capability 不得启用**通用 offload slice，除非它们显式 provide 或 imply `offload.runtime` 并保留所需的通用 handoff 属性。

first slice 在物化的 variant 上携带通用决策 metadata（`condition`、`guard`、`policy`）与 plugin-owned 可丢弃字符串 metadata `weft_offload.runtime_abi` 加 `weft_offload.handoff_kind`。Plugin legality 检查：selected variant 要求一个满足 `offload.runtime` 的 exact 或 relation-provider capability；该 provider 仍可用；plugin-owned 的 variant metadata 与保留的 capability 属性匹配。**这些 metadata 只是编译器 handoff metadata；它不是可执行 runtime glue。**

first-slice 的 emission plan 当前是 **unsupported**。它**不得**发布 route id、artifact kind、selected-plan export metadata、ABI role mirror 或 target exporter bundle 贡献。因此当 selected 路径是 Offload-only 时，公共 artifact 与 bundle 前门 **fail closed**。**这是一个有意的删除缺口，不是恢复 metadata artifact 路的许可。**

## 【定法】Capability Fields

```text
accelerator name
runtime availability
C ABI availability
PCIe or SoC mode
supported operator set
supported dtype
supported shape constraints
async execution support
transfer model
compiled artifact format
```

参考 attribute：

```mlir
#weft.accel<"sophgo.runtime",
            kind = "policy",
            subclass = "runtime-offload",
            mode = "pcie",
            abi = "c",
            async = true,
            supported_ops = ["matmul", "conv", "transformer_block"]>
```

## 【定法】Dialect

架构家族：`weft.offload`。具体 MLIR 命名空间：`weft_offload`。

Legacy/no-active-route 的 first-slice op 形态，**仅供 stale 输入验证**：

```mlir
weft_offload.lowering_boundary {
  source_kernel = "kernel_symbol",
  selected_variant = @offload_runtime_first_slice,
  origin = "offload-plugin",
  role = "dispatch case",
  status = "no-active-route",
  required_capabilities = [@offload_runtime],
  runtime_abi = "generic-runtime-offload-c-abi-handoff.v1",
  handoff_kind = "runtime-offload",
  handoff_reason = "runtime-offload boundary records no active route"
}
```

生产的插件物化当前对 Offload **不返回 boundary**，因为不存在物化的 EmitC/runtime/artifact route。若此 op 出现在输入中，它是一个 no-active-route 验证面。它**不是** high-level compute op、custom RISC-V ISA op、vendor runtime call、DMA operation、accelerator kernel、object 生成步骤、正确性结果或性能结果。

当被选中的 offload 路径有这个匹配的 lowering boundary 时，当前编译器可报告 selected metadata 面与一个 unsupported 诊断镜像。**它不得**为 Offload 发出 target artifact 或 bundle 记录，直到未来的 runtime C ABI lowering 路径被规定并实现。

未来 types 可能含：

```text
!weft.offload.buffer<device, dtype, shape>
!weft.offload.event
!weft.offload.handle
!weft.offload.runtime
```

未来 ops 可能含：

```text
weft.offload.bind
weft.offload.alloc
weft.offload.copy_to_device
weft.offload.copy_from_device
weft.offload.async_call
weft.offload.call
weft.offload.wait
weft.offload.release
weft.offload.shape_guard
```

## 【定法】Variant Generation Scope

未来验证可优先粗粒度算子：

```text
matmul / batched matmul
conv
large transformer subgraph
attention block if runtime supports
MLP block
```

**细粒度 elementwise offload 不应作主线**，因为传输与 launch 开销可能主导。

## 【定法】Legality Rules

Offload plugin 检查：runtime 可用；C ABI 或 vendor API 可链接；输入/输出 dtype 被支持；shape 满足 runtime/算子约束；buffer 所有权显式；同步边界完整；host-device copy 需求被表示；fallback variant 存在；使用 async call 时其被允许。

## 【定法】Cost Model

```text
host-device transfer cost
runtime launch overhead
device compute cost
sync/wait cost
buffer reuse benefit
batching benefit
RVV fallback cost
```

selection 取决于：shape size · dtype · operator type · 数据是否已在 device 上 · runtime 可用性 · batching 机会。

## 【定法】Tuning Space

```text
offload threshold
batch size
transfer granularity
async overlap
buffer reuse policy
host fallback threshold
```

这是 **runtime/offload 决策调优，不是普通的 tile-size 调优**。

## 【定法】与 Custom ISA Plugin 的区别

Custom ISA plugin：

```text
custom intrinsic / inline asm / backend patch / object stub
```

Runtime offload plugin：

```text
C ABI / runtime library / driver call
```

两者都可被 capability 管理，但**不得混为一谈**。

## 【定法】Sophgo Role

Sophgo route 可以证明：RISC-V host + accelerator runtime 可被 capability 管理；offload 可被表示为 execution variant；RVV CPU 与 offload 变体可在 dispatch 下共存；runtime capability 适配统一 capability model。

**它不证明 RISC-V custom ISA 支持。**

# Future 家族槽位

## 【定法】Scope

未来插件可能包括：

```text
AME
future custom ISA
NVIDIA-GPU / AMD-GPU construction families
other matrix extensions
vendor-specific custom instructions
sparse / DMA / cluster / accelerator runtime variants
```

这些是**未来扩展槽位**，不是当前 supported hardware path，也不是当前 source-front-door
authority。H100/5090D 只是 future NVIDIA-GPU capability profiles，不进入本页当前 8
family census。

## 【定法】Required Rule

**不要**把未来扩展硬塞进现有 RVV / IME / Offload 家族，除非其语义确实匹配。一个新扩展
仍是向统一 Weft 系统贡献一个 construction family，不是只在 emission 末端增加独立
backend。GPU 尤其不能读取 RVV body/`flat_*` plan 后换目标发射。

Correct:

```text
new vendor custom opcode path -> new custom ISA plugin
new matrix extension with different register model -> new matrix plugin
new runtime accelerator path -> runtime-offload plugin or new runtime plugin
```

Wrong:

```text
reuse weft.ime for all future matrix/custom extensions
call all vendor accelerator paths custom ISA
make AME a current primary target without hardware evidence
```

## 【定法】Extension Admission Checklist

加一个未来插件**之前**，定义：

- capability kind 与字段；
- canonical problem applicability 与 `S/g/ω` projection；
- extension family 名与具体 MLIR 命名空间；
- 所需的 WEFT common interface；
- types 与 ops；
- 所需 toolchain/runtime；
- 支持的 high-level op 类——**仅作证据/覆盖规划，不是当前 frontend 或 route authority**；
- variant 生成契约；
- legality verifier；
- tuning space；
- cost model；
- family construction completion、artifact class 与 lowering/runtime 路径；current EmitC
  只适用于真正采用该 artifact class 的 family；
- fallback 关系；
- 既有 core interface 是否够用。

> 准入的**边界判据**（正当 vs 越界）见上 [§家族准入边界](./家族现状.md#定法家族准入边界)。**未来插件是未来槽位：只在真实 target 事实与显式任务使它成真时才加一个。**
