# Artifact、发射与降级（工位 4）

final typed body/plan → family artifact driver → target artifact/runtime。本文定义这条链的
**权威方向**、**non-authority 律**、当前 EmitC realization，以及发射与构造纪律。
历史字符串 carrier `WEFTEmitCLowerableRoute` 及其 build-and-discard route machinery 已
退役；当前 artifact driver 直接消费 exact typed body/result。未来 family 可以定义自己的
typed artifact handoff，但不得在 construction 与 lowering 之间再插入 compute provider。

读法口径见 [本层 index](./index.md#读法口径落笔前必读--四条)。硬规则全文住 [canon · 核心不变量](../canon/核心不变量.md)。

---

## 【现状】

- current EmitC artifact class 住在 `lib/Conversion/EmitC/`，family driver 经
  `BackendEmissionRegistry` 表驱动接入；
- RVV、IME、Scalar 与当前确定性 family 都先返回 exact `FamilyConstructionResult`，再进入
  construction-blind artifact driver；Offload 显式 unsupported；
- `emitc.func` 是 current EmitC 完整 legalization gate，不是 construction completion；
- RVV artifact lowering 直接消费 exact `weft_rvv` body/plan。旧
  `lib/Plugin/RVV/EmitC` route-provider、`RVVConstructionProtocol`、route identity/
  plan-owner mirrors 与 provider target 已删除；
- future GPU construction 不注册为这里的另一个 emitter，而是拥有自己的 artifact class。

## 【定法】Artifact-neutral 上层契约

construction-qualified final typed body 必须先于 artifact lowering 存在。通用层只可编排：

```text
final typed body ownership
  → family artifact driver lookup
  → typed handoff + ABI/runtime contract
  → artifact-specific completion gate
```

construction completion 不以 `emitc.func`、NVVM module、C symbol 或 artifact metadata
定义。EmitC/NVVM/ROCDL 各自的完整 legalization 门属于各自 artifact backend。Artifact
driver 不得绑定 selection/deployment domain、选择 construction owner、构造 candidate、调用 selector 或重新解释
`kind/format/fold_model`、LMUL、tile、warp、stage、MMA 等决定。

详细边界见 [执行问题与家族边界](./执行问题与家族边界.md)。

## 适用硬规则

I3（注册表遍历，非 family 分支）· I4 · I5 · I7（fail closed，禁从 metadata 合成 kernel C 源 / header / object / artifact bundle）。

# 【定法】Current Weft-RV EmitC Runtime Contract

## Scope

本契约定义 current selected Weft-RV variant 如何变成 EmitC/native code、runtime ABI
surface、target artifact 与证据。它对当前 EmitC family 一视同仁——RVV、IME、
TensorExtLite、Template/Toy、Scalar；Offload 明确 unsupported。Future non-EmitC family
遵守上层 artifact-neutral authority，但不经过本节的 EmitC artifact class。

Emission is not a metadata state machine. The executable authority chain is:

```text
weft.exec envelope
  -> typed g/c/ω and family construction
  -> legality / optional bounded selection
  -> final typed extension-family body or final plan
  -> family backend driver directly consumes exact typed result
  -> common typed-emission harness / EmitC materializer
  -> C/C++ or equivalent backend representation
  -> target artifact
  -> runtime / hardware evidence when claimed
```

For the current RVV mainline, the selected body is a typed low-level `weft_rvv` body and the origin plugin is the RVV plugin.

## Non-Authority Rule

The following surfaces are diagnostic/handoff mirrors only:

```text
emission_plan diagnostics
diagnostic result/status fields
route ids
artifact kind/name metadata
manifests
semantic role graphs
construction templates
source-front-door markers
selected-path metadata
test names
```

They must not define artifact support, dtype, compute semantics, schedule, intrinsic spelling, ABI
value use, target artifact authority, correctness, runtime, performance, or progress.

## RVV Emission Authority

RVV target export may consume only construction-qualified final typed body/plan state:

```text
selected RVV variant
  -> RVV formula construction + legality + optional bounded selection
  -> final typed weft_rvv body / final plan
  -> RVV family backend emission
  -> common EmitC / target materialization
  -> target export packaging
```

RVV dtype/config/operation facts must be structural in the typed `weft_rvv` body or consumed into
the realized body before artifact lowering. They must not be recovered from `RVVI32M1*` metadata,
`rvv-i32m1` route ids, `weft_rvv.i32_*` helper names, C ABI spellings, exact
`__riscv_*_i32m1` spellings, source-front-door patterns, descriptor residue, artifact names, or
test names.

## Legacy i32m1 Route-Table Policy

There is no supported explicit typed RVV `i32m1` legacy route-table object plan. All legacy `i32m1` route-table cases must be unsupported/fail-closed unless already rewritten onto the corrected generic typed `weft_rvv` surface.

Forbidden current-positive outputs include:

```text
rvv-i32m1-* materialized EmitC object/header/bundle plans
RVVI32M1* route tables as executable compatibility route
artifact kind: riscv-elf-relocatable-object for legacy i32m1 route-table cases
positive target export from !weft_rvv.i32m1 or weft_rvv.i32_* helper families
```

Legacy terms may remain only in clearly labeled fail-closed inventory, negative tests, parser/verifier fixtures without artifact generation, or migration notes.

## Emission Diagnostics

`weft.exec.diagnostic {reason = "emission_plan"}` is emitted as a non-authoritative mirror after
family construction and artifact planning. It is never a construction or artifact INPUT; but when
target-artifact export runs, exactly one emission-plan diagnostic per selected path is a REQUIRED
deterministic mirror (见 Candidate Gate below).

Allowed purpose:

- explain why a selected path is unsupported;
- mirror the family-built artifact projection and materialized EmitC handoff;
- carry deterministic provenance for reproducibility;
- help target export report failure reasons.

Forbidden purpose:

- deciding artifact lowering or selected compute;
- deciding dtype/config/body shape;
- proving executable generation;
- acting as readiness/progress state;
- substituting for plugin legality, exact typed result or artifact-driver output;
- authorizing target artifacts without successful typed-body lowering and complete legalization.

If a diagnostic mirror exists, fields such as `result`, `origin`, `role`, `lowering_boundary`, `runtime_abi`, `required_capabilities`, `artifact_kind`, and `lowering_pipeline` must exactly mirror already-made plugin decisions.

## Current EmitC Target Artifact Export

Target artifact export consumes materialized EmitC produced by the current typed-emission harness
directly from a construction-qualified final typed body/result. Metadata is an exact mirror of the
body, mechanical handoff and selected variant；it never substitutes for the typed result。

Export must fail closed when:

- no selected extension variant exists;
- no typed/selected extension body exists;
- plugin legality rejects the body;
- registered family backend cannot construct and fully legalize the final typed body/plan；
- common EmitC materialization fails;
- only emission-plan metadata, selected-path metadata, route ids, or manifests exist;
- legacy RVV i32m1 route-table data is the only route authority;
- source-front-door/source-artifact markers are the only RVV input (these routes fail closed, 见 I7).

Target export must not synthesize C bodies, headers, objects, bundles, runtime ABI, dispatch source, or self-checks from descriptors, route ids, selected metadata, artifact names, or family records.

## Selected Path Artifact Candidate Gate

### 1. Scope / Trigger

Use this contract when target artifact export consumes selected-path `weft.exec` surfaces and their emission-plan diagnostics. It applies to static selected variants, selected dispatch cases, dispatch fallbacks, and fallback-only selections.

### 2. Signatures

The target export collector consumes:

```text
weft.exec.dispatch / selected diagnostic marker
emission_plan diagnostic keyed by selected variant symbol + selected path role
status = supported | unsupported
origin
role = direct variant | dispatch case | dispatch fallback
emission_kind
artifact_kind
```

It produces `TargetArtifactCandidate` values only for selected paths whose construction-qualified backend result and materialized EmitC exist; `status = supported` is a faithful mirror of that result, validated before packaging (见 Validation & Error Matrix below), not the gating authority (I4).

### 3. Contracts

- Every selected path must have exactly one emission-plan diagnostic before target artifact export.
- A selected kernel must produce at least one supported executable target artifact candidate before export can continue.
- Unsupported selected paths are diagnostics only. They must not become target candidates, runtime ABI authority, headers, objects, bundles, or executable fallback evidence.
- If a selected dispatch case is unsupported and the dispatch fallback is also unsupported, export must fail closed at candidate collection and report the unsupported selected paths.
- If a selected dispatch case is supported and a selected fallback is unsupported in that kernel, export may continue for the supported selected case only. The unsupported fallback remains a mirror/diagnostic boundary, not executable fallback evidence.

### 4. Validation & Error Matrix

- Missing selected-path emission-plan diagnostic -> fail before target artifact candidate construction.
- Selected kernel has no supported candidates -> fail with the selected variant symbols, path roles, statuses, origins, emission kinds, and artifact kinds for the unsupported paths.
- An unsupported fallback diagnostic attempts to produce a header/object -> fail; a diagnostic alone cannot become an executable fallback.
- Supported candidate has stale origin, role, runtime ABI or artifact metadata -> fail in target artifact validation before packaging.

### 5. Good/Base/Bad Cases

- Good: selected execution case supported, named fallback unsupported for that kernel -> export the supported artifact; record the fallback only as validated mirror metadata.
- Base: fallback-only selection whose family construction/emission is unsupported -> export fails with an unsupported selected-path diagnostic.
- Bad: every selected case and fallback is unsupported -> empty bundle or generic "found none" result.

### 6. Tests Required

- Add lit/FileCheck coverage for at least one selected dispatch route where all selected paths are unsupported and export rejects the executable artifact claim.
- Keep positive selected-case artifact tests proving that an unsupported fallback mirror does not block a supported selected case.
- Use C++ target artifact tests when the behavior is not visible through MLIR diagnostics.

### 7. Wrong vs Correct

Wrong:

```text
selected dispatch case unsupported
  + named fallback unsupported
  -> target export returns no candidates or an empty artifact result
```

Correct:

```text
selected paths all unsupported
  -> target export rejects the kernel
  -> diagnostic lists @variant, role, status, origin, emission_kind, artifact_kind
```

## Runtime ABI Boundary

`weft.exec.mem_window` and `weft.exec.runtime_param` declare ABI roles and C export spelling. The selected extension body must explicitly import and consume those values.

Correct:

```text
mem_window/runtime_param declare lhs/rhs/out/n roles
-> weft_rvv body imports those ABI values
-> typed loads/stores/control/dataflow consume them
-> RVV artifact driver maps body + ABI roles to emitted C/C++
```

Wrong:

```text
c_name/c_type/abi_role/artifact name -> infer dtype/operation/route
```

## Source Front Doors

Registered source front doors are valid production entries only when they invoke the same family formula/construction owner and materialize a final typed body/plan before emission. A source marker, descriptor, route id or artifact request by itself must fail closed (I7).

Positive source-to-artifact paths may start from a registered front door, but their evidence must
show the constructed typed body and the same family construction lifecycle used by direct
conversion。当前实现由 target/profile binding 后的 plugin family lifecycle 完成 construction，
再进入 construction-blind artifact driver。不得从 source metadata 合成 C/ABI/artifact，也
不得保留 parallel direct-C implementation。

## Family Export Gate

A family exports only via a construction-qualified final typed body/plan and its registered family
artifact driver. Construction family 与 artifact class 都必须在 typed registry/interface 中显式
拥有，不能由 metadata 反推；artifact driver 只能机械消费 final body。

当前 EmitC family 通过 shared typed-emission harness 从 exact result 构造 EmitC；route
metadata 或诊断不能替代 final body/plan。Absent a fully legalizing backend result, export
fails closed (I7)。一次
standalone materialization 只有一个 owner；mixed body 在 conversion 前拒绝。Raw
type/pattern population 是 artifact backend 私有实现，public pass、translate、materialization
与 artifact caller 不得绕过 shared construction-before-artifact seam。RVV 是最广的 current
realization；Scalar、Demo/Toy/Template/TensorExtLite 与 IME 有当前 bounded path，Offload
explicit unsupported。Future GPU 不进入该 EmitC table。

# 【定法】Current 公共 typed-emission / EmitC materialization

公共层只在 origin family 已完成 formula construction、legality、optional selection 与 final
typed body/plan 后工作。它调用 family driver 从 exact typed result 直接构造 EmitC，不要求
独立 route carrier/provider。

【现状】family construction 已位于本 EmitC 层之前：caller 先按 selected variant 的 origin
绑定 family 与 typed capability，再调用 variant-scoped `constructFormulaPlans` 并取得 exact
`FamilyConstructionResult` typed operation/root。公共层只检查 ownership/existence，不扫描
module 重发现 body。`TypedBackendEmissionDriver` 没有 construction hook；
`convertConstructedModuleWithBackendEmitter` 与
`tryConvertConstructedModuleWithRegisteredBackend` 只接收 constructed result。
`emitc.func` 只作为本 artifact class 的完整 legalization gate。

```text
final typed extension body/plan
  -> registered family backend driver
  -> direct typed EmitC construction
  -> 公共 typed-emission harness / EmitC materializer
  -> MLIR EmitC ops -> C/C++ emitter
  -> target artifact
```

> 本节描述公共侧的**稳定边界**。具体支持到哪些 route family、哪个在调——是状态，进 task/journal。

## Common Responsibility

公共 EmitC 只做中性 materialization：

- 调用通用 backend interface 与 family-owned lowering patterns；
- 从 family driver 对 exact body 的机械投影生成 MLIR EmitC ops；
- 保留 family final plan/body 给出的确定性符号名与打包结构；
- 把 materialized EmitC 交给 C/C++ emission 与 target export；
- construction result 缺失或 artifact 不能完整 legalization 时诊断并 fail closed。

公共 EmitC **不**做（I3/I4/I5）：选 intrinsic；推 dtype/SEW/LMUL/mask-tail/operation kind；建 schedule 或 body shape；从参数名合成 runtime ABI；按 family 语义分支；把 route id / emission-plan status / manifest / artifact metadata 当 route authority。

对 RVV：C 向量类型串、intrinsic 名、header、ABI 映射、route payload、legality 全部 RVV-plugin-owned。公共代码可携带 plugin 预计算的串/payload 片段，但**不派生**它们。

## 【定法】Typed Artifact Projection

family artifact driver 可以从 exact typed body 派生 operand binding、header/type summary、
intrinsic spelling、memory form、mask/tail 与 runtime AVL/VL binding。这些只是 lowerer 内部的
机械投影值：它们不持久化成通用 provider/manifest，不参与 candidate、legality、selector
或 construction completion。

公共侧逐字 materialize family driver 的 typed lowering result，不按 family 名推断 compute；
typed result 缺失、畸形或不能完整 legalize 时 fail closed。新增 family 直接实现自己的
artifact class/driver，不复制旧 operand-binding + fact-surface + provider-validation 协议。

## 给 agent 的判断点（不是 gate）

- 在写新的 artifact projection helper 前：它是否只机械消费 exact typed body？若它开始
  选择 mechanism、schedule 或 body，职责已经放错。
- Current IME/Scalar/其它 EmitC family 复用同一公共 EmitC seam；future non-EmitC family
  复用 artifact-neutral construction/artifact ownership contract，再接自己的 artifact class。
  若公共侧要按 family 名决定 compute，说明设计破了。

# 【定法】[K-10] 结构级 / 参数级判据

全文见 [canon · 核心不变量](../canon/核心不变量.md) 与其去向表所指各 canon 家，本文只钉判据形状：

- 变体差异改变 **{迭代空间拓扑 | 数据/布局消费契约 | 优化目标}** 之任一 →
  **结构级**，formula 构造分立 typed candidate/body/plan。
- 仅在固定结构内调宽窄（VLEN / LMUL / tile 尺寸 / 展开因子 / lane-width）→
  **参数级**，由 typed `g/c/ω` 推导，不为形式对称增加新 plan。
- **硬禁：结构级差异禁实现为 plan 内旋钮。**

**选择层职责**：selector 在 **plan 集内**按 **{形状事实 ∧ 能力事实}** 选择；**M\* 为实测标定事实写回 schema，禁 `if(M==1)` 硬编码**（见 [变体流水线](./变体流水线.md)）。

**问题措辞**：不要用“发射器不成熟”概括所有缺口。应说明是缺 mechanism、formula
未参数化、capability 未消费、仍依赖 point leaf、selector 错误，还是机械 emitter 的
code-shape/ABI/toolchain 问题。

> **具体缺口逐条住 [issues](../issues/index.md)，本文不清点**（spec 不写计数与状态）。

# 【定法】发射与构造纪律（Construction Discipline）

本节定义 selected body 如何变成 emitted code，以及何时可以声称**强义构造**。它对
RVV、IME、Scalar 和未来 family 使用同一判断；构造强度与 typed mechanism 的正本见
[canon · 构造强度、mechanism 与选择归因](../canon/覆盖状态机与选择归因.md)。

## [K-0] Authority cutover 与 reconstruction 是两件事

所有 production entry 都必须先经过统一 formula/construction authority，并在 emission
前形成 final typed body。一个 body 内仍调用完整手写 leaf 时，它可以诚实标为
`constructed-weak`；这不授权 source/descriptor 直接绕过 typed construction 进入旧
emitter，也不允许同一输入同时命中新旧 compute authority。

强义 reconstruction 的判断不按“经过前门”或“存在 descriptor”决定，而按删除实验：

```text
remove one complete point leaf
  + keep typed g/c/ω, reusable mechanisms and family-local formula
  → reconstruct the same typed body/plan and legal domain
```

做不到就继续是 `ConstructedWeak`。Authority 横向切换必须一次覆盖当前 production
domain；strong reconstruction 可以在统一底座上按真实 mechanism 继续增强。两者不得
互相冒充。单一生产路径见 [退役与单一生产路径](./退役与原子合入.md) [RET-1]/[RET-F]。

## [G3] 成熟目标：强构造、专家质量与完整软件链

成熟度不能由固定百分比、bypass whitelist、provenance 字段或六态表定义。目标是三个
彼此独立的代码/证据事实：

1. 受支持 point implementation 尽可能由 `g/c/ω + mechanisms + formula` 重建，完整
   point leaf 不再是默认扩展单位；
2. final typed body 到 route/emitter 只有机械 realization，旧 direct construction
   authority 不可达；
3. correctness、代表性强对手、deployed ggml 与 e2e 由相应真硬件证据判断，不能从
   construction 结构外推性能。

历史 `emit-bypass-whitelist`、coverage-sixstate 与 provenance 工件可用于查找旧路径，
但不是当前 formula authority、研发进度或 strong reconstruction 的正本。是否完成直接
看当前 call graph、typed construction、行为测试和 delete-leaf reconstruction，不为旧表
维护兼容代码。

## [K-2] 可复用 mechanism 作为构造原语

强义 `constructed` body（[K-4]）由 family-local formula 组合并参数化可复用 typed
mechanism，而不是选择一个不透明的完整 point helper。当前典型 mechanism 包括：

```text
widening dot-product-reduce
dequant LUT / bit-unpack
repack / blocking
reduction tree
masked tail handling
[K-2b] wide-clamp / dual-zone body (widen-clamp-narrow)
```

并非每个 mechanism 都必须进入统一 registry、DSL 或 provenance schema；它可以是 typed
op、family-local builder、参数化算法模块或其组合。判断它是否真正可复用，仍看能否在
删除完整 point leaf 后由不同 `g/c/ω` 组合重建 body。残留完整手写 point helper 时，该
body 只能标为 `constructed-weak`。

## 构造 provenance 的地位

可选 provenance 可以帮助开发者定位使用了哪些 mechanism，但它只是 diagnostic mirror：
既不是强构造的必要条件，也不是充分条件，更不能成为 route、dtype、compute 或进度
authority。强义结论由真实 producer/consumer、参数因果和 reconstruction 测试给出。

## [K-6] 构造缺口关闭闭环

对**同-ISA 代表性框架内核**的性能落败或持平，应回到真实因果链检查：格式/语义事实、
capability、mechanism、资源与场景参数、selector residual、compiler/toolchain、memory/ABI
和物理硬件墙。这里不预设穷尽分类，也不要求为每次诊断增加 registry row 或 gap-ID。

若结论是缺 mechanism 或缺 capability fact，应把可复用知识放回对应 typed owner，让
formula 重新构造 body，再以相同 kernel、板、工具链和对手做 paired 测量。不得用一次性
format×board helper 或 measurement winner 直接修补 production compute。反汇编和真板
证据用于性能归因；compile/lit 只证明编译器结构与产物形态。

## Good / Bad Cases

Good:

```text
canonical problem + bound family capability
  -> family construction-qualified final body
  -> matching family artifact driver
  -> artifact-specific complete legalization
```

Good (current EmitC):

```text
typed weft_rvv body
  -> RVV legality
  -> realized body if needed
  -> family artifact projection
  -> common EmitC
  -> target artifact mirror
```

Good:

```text
typed g/c/ω + reusable mechanisms + formula
  -> final typed body
  -> remove one complete point leaf and reconstruct the same body/legal domain
  -> labeled constructed (strong, [K-4])
```

Bad:

```text
source/RVV final body
  -> choose GPU in emitter
  -> reconstruct warp/tile/MMA from format metadata
```

Bad:

```text
flat body emitter picks a descriptor
  -> body arithmetic is a selected handwritten helper
  -> reported as constructed (strong)   # 违宪 [L-8]; this is constructed-weak
```

Good:

```text
legacy RVVI32M1 route-table input
  -> unsupported diagnostic
  -> no EmitC object/header/bundle
```

Bad:

```text
emission_plan metadata + route id
  -> target object
```

Bad:

```text
source-artifact marker
  -> positive RVV artifact
```

Bad:

```text
manifest / semantic role graph / construction template
  -> executable route authority
```

## Required Tests

Production-path changes require tests attached to the changed compiler behavior:

- MLIR/lit/FileCheck for typed body legality, artifact-projection consumption, and fail-closed diagnostics;
- C++ tests for exact construction-result / artifact registry APIs where textual MLIR is not sufficient;
- negative coverage for legacy `RVVI32M1*`, `rvv-i32m1`, source-front-door, and metadata-only target export paths;
- 真板 run output for runtime/correctness/performance claims（I8）。

Broad dashboard, report, ledger, manifest-only, or test-only changes are not emission/runtime progress unless a production compiler path changed.
