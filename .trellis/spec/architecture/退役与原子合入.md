# 退役与原子合入

本文是 active compiler path 退役、兼容边界和多 worktree 合入纪律的唯一工程正本。规范性摘要见 [canon · 核心不变量](../canon/核心不变量.md) I7；公式、选择与发射文件只引用本文，不另立一套退役规则。

> **[RET-1] Evolvable operator compiler, not compatibility museum**：Weft 当前目标是清晰、可验证、可扩展的 MLIR operator compiler / execution-layer software stack，不承担成熟通用 compiler 对历史内部 API、旧 pass pipeline、错误 dispatch 或实验性实现的长期兼容义务。RISC-V 量化推理是当前旗舰实现，不是该兼容边界或系统类别的定义。

## 1. Scope / Trigger

以下任一变化触发本契约：

- 新 authority 替代旧 provider、selector、verifier、emitter、reader、writer 或 dispatcher；
- scalar/string/metadata 接口迁到 typed decision/body；
- monolith/direct emitter 迁到 constructed typed path；
- measurement source、schema、winner view 或 deployed route 收口；
- 修复错误路径、零消费字段、silent default 或 dormant strategy；
- 多 agent/worktree 分别实现同一 campaign 的独立 slice。

本文中的 **declared dispatch slice** 是一个可闭合验证且判定域不含糊的决策或执行单元，至少由以下 tuple 定界：

```text
(operation/kernel family,
 typed input/body schema,
 target/capability domain,
 dispatch key/predicate)
```

它可以进一步绑定 mechanism×consumer、writer/read contract 或 deployed cell。两个 predicate 有重叠时不得靠改名伪装成不同 slice。slice 可以按模块逐个迁移，但已迁移 slice 的合入必须原子。

### [RET-F] 横向 formula-layer rebase

当任务目标是建立全项目共享的 formula/construction stage 时，迁移单位不是单个 format、operator 或 backend slice，而是 task 开始时 census 的完整 current production formula domain：

```text
all registered/direct production operator entries
+ all production analytic/construction authorities
+ all production callers
+ all g/c/ω dependency edges
+ all superseded formula/provider/replay/emitter authorities
```

该 domain 必须一次性原子 cutover。施工顺序可以按模块展开，但最终合入不得出现：

- 五个公式迁入、新旧其余公式并存；
- quantize 进入公式层而 dequantize/contraction 仍绕过，或反之；
- RVV 进入新层而当前其它 production-capable family 后补；
- deterministic path 以“没有选择”为由绕过 construction descriptor；
- catalog/coverage 排除难迁 operator、direct route 或 unsupported input；
- 未迁路径被改名为 fallback、legacy 或 future。

无法完成整个 census 时，task 保持 in-progress 或整笔回滚，不得把局部完成态合入后再创建后续迁移 task。

**唯一的是一个 declared decision/dispatch 的 authority，不是候选数量。** 同一 slice 可以有多个 typed candidate，由唯一 candidate construction、legality 与 selector 选择；不相交 slice 也可以各自拥有唯一 authority。

## 2. Cutover Record

每个触发 RET-1 的 slice 必须能给出以下可审计字段；它们可以住 task PRD、commit message、测试或既有 ledger，不要求新增运行时对象：

```text
slice_id
slice_tuple / predicate / overlap proof
old_authority / old_entry_symbols
new_authority / selected representation
production_callers_before / production_callers_after
semantic_fallbacks_kept
compatibility_paths_removed
tests_or_gates_rewritten
evidence_or_history_destination
```

`production_callers_after` 对已退役旧入口必须为 0。仅 definition、退役索引、负例 fixture 或历史引用不算 production caller，但必须与 active build/dispatch 隔离。

## 3. Contracts

### 3.1 渐进施工，原子合入

- 不同 slice 可以分批迁移；尚未开始的 slice 可以继续使用其当前唯一路径。
- 上条只适用于彼此独立的普通局部迁移；`[RET-F]` 声明的共享 formula-layer rebase 把 census 中全部 current production entries 视为一个横向迁移域，不适用“其它 slice 后补”。
- 同一 slice 一旦完成，新 authority、全部 caller 切换、旧入口删除、测试改写和索引同步必须作为一个可审查合入单元。
- task 启动时登记 slice tuple、旧 authority、已知 caller 集与删除判据；不得在施工后缩小 predicate/caller 集逃避 cutover。
- 开发分支或未完成 worktree 内可以短暂出现中间态；它不得作为 completed task 合入受保护主干或发布分支。多个互不重叠、各自完成原子 cutover 的 slice 可以逐个合入。
- 无法完成 cutover 时，task 保持进行中或整笔 Git 回滚。已完成 slice 的 production rollback 只能通过 source revision revert/redeploy，不得靠同时发布两套 authority、runtime 兼容开关或失败后切旧路；test-only variant forcing 不属于 production rollback。

### 3.2 必须退役

- `compat` / `legacy` / `deprecated` alias、adapter、old→new 或 new→old bridge；
- 对同一 canonical fact/key 的兼容性 dual-write、相互竞争的 authoritative reader，以及对同一 declared decision 的第二 compute-authoritative registry/dispatcher/selector；只读 observer 与职责不重叠的分层 dispatch 不属于双 authority；
- selected stamp 缺失后回旧 selector，或新 emitter 失败后回旧 emitter；
- code-affecting 字段通过 `value_or`、board/march/format 名或环境开关恢复历史默认；
- 零消费 capability/fact、无 caller placeholder、已被正式路径取代的 monolith/direct emitter；
- campaign 关闭后，既无合法目标 cell、又不承担已登记生产/正确性/负对照职责的 variant、debug strategy 与 dormant branch；研究中实现只能留在任务 worktree，不能以默认关闭的 dispatcher arm 或环境开关进入主干；
- 守护对象已经不存在的 test/gate/golden/helper。

失败实验、负边界和历史实现可以留在正式 run lineage、ledger、issue、retired index 或 Git history；它们不得继续参与 active selection、dispatch、build authority 或性能汇总。

### 3.3 可以保留

- canon 允许、正式注册、legality 与正确性成立的语义 fallback；
- 空合法集时的具名 reject/fail-closed；
- 服务于与已迁移 slice **不重叠**的已声明输入域、执行语义、target domain 或 dispatch key，并且同时具有正确性证据、明确 owner 和真实 production caller 的另一条 active path；
- 与 active production registry/default dispatch/fallback/安装 ABI 隔离，且有明确研究职责与测试的负对照；
- 版本化的公共或准 ABI 当前版本。

“旧”“monolith”“仍有 caller”或“不是 winner”本身不是保留/删除判据。落在已接管 slice 内的 caller 必须迁移；保留项必须满足上面的合取条件，不能用“未来也许有用”辩护。负对照若拥有普通 production caller，就不能再使用负对照例外。

### 3.4 Semantic fallback ≠ compatibility fallback

| 类别 | 判据 | 处置 |
|---|---|---|
| 语义 fallback | 输入在正式语义中有另一个具名合法实现；具备 typed candidate/body、legality、reason、正常 selection/stamp 与正确性 | 保留并测试 |
| reject | 当前输入没有合法实现 | fail-closed，保留诊断 |
| 兼容 fallback | 新架构没接完、缺字段、缺 stamp 或新路失败，于是调用旧实现或猜历史默认 | 删除；存在即 slice 未完成 |

fallback 的性质由进入路径决定，不由代码年代决定。旧 scalar/generic body 若成为正式 typed candidate，并经过相同 legality、selection、stamp 与 correctness，可以保留；只有在缺字段、缺 stamp、reject 或新路径失败后旁路进入它，才是必须删除的 compatibility fallback。空合法域必须在 emission 前产生结构化 reject，不得捕获 reject 后进入旧实现。

公共或准 ABI 确需变更时走 RFC/版本化，并原子迁移所有 in-tree consumer。当前项目默认采用 breaking cutover：旧 ABI 不保留 production forwarder，外部使用者迁移到新版本；版本化不授权两套 compute/dispatch authority 或兼容窗口。

### 3.5 单一分发世界

同一 slice 合入后只能有：

```text
one canonical fact/capability owner
one decision authority over a finite typed candidate set
one selected typed representation per selection
one route/dispatch authority for the declared slice
one canonical measurement writer + authoritative read contract
```

可以有多个只读分析 observer，也可以有职责不重叠的分层 dispatch；它们不得写回或竞争上述 authority。benchmark、deployed ggml 与 e2e 可以是不同证据 lane，但它们必须追到同一 selected decision/route；benchmark-only direct kernel 不得伪装为 deployed path。

### 3.6 RET-1 生效前的混合状态

已经存在的“typed path 接管、旧 op-def/emitter/verifier 仍残留”只能登记为 **RET-1 violation/debt**，并绑定 retirement task、owner、精确 caller 集和删除条件。登记与 whitelist 不使其合规，不得新增 caller、扩大 predicate 或宣称 slice 完成。RET-1 生效后的新迁移不得新增此类债务。

## 4. Validation & Error Matrix

| 条件 | 必须结果 |
|---|---|
| 旧 production caller 仍大于 0 | slice 未完成、不得合入 |
| 新旧 selector/dispatcher 都可命中同一输入 | fail；删除其中旧 authority |
| 以两个名字声明 predicate 重叠的 slice | fail；先合并判定域并确定唯一 authority |
| 缺 selected stamp | fail-closed；不得重算或回旧路 |
| 新 reader 无法读取旧 schema | 离线迁移或任务未完成；不得增加长期双 reader |
| capability/fact 无真实 consumer | 删除，或显式从 active decision contract 排除；只读 provenance 另按 I8 归类 |
| 某 candidate 当前未胜但仍有合法 cell | 可保留，不按单次输赢删除 |
| campaign 已关闭，strategy 无合法 cell 且无登记职责 | 证据归档，production 实现与开关删除 |
| 历史 test 只保护已删旧 authority | 改写为新 authority 测试或删除 |
| worktree 只完成半个 cutover | 不合并；继续施工或整笔回滚 |

## 5. Good / Base / Bad Cases

- **Good**：一个 codebook slice 的所有 caller 改读 selected typed plan；emitter 旧 lookup 删除；missing stamp 负例变红；正常 fixture byte-exact。
- **Base（普通局部迁移）**：另一个不在 declared domain 的 mechanism 仍走其原有唯一路径；`[RET-F]` 公式层重构中不存在“当前 production formula 不在 declared domain”的例外。
- **Good**：向量候选非法时选择正式注册的 scalar candidate，trace 带 legality 与 fallback reason。
- **Good**：同一 slice 有多个合法 typed candidate，由唯一 selector 选择；这不是多 authority。
- **Bad**：typed contract 已接两个 caller，但其余同 slice caller继续调用旧 overload，并把旧入口标 `deprecated`。
- **Bad**：新 winner view miss 后读取旧 JSON 表，或新 emitter缺字段后 `value_or` 历史板值。
- **Bad**：性能攻击 no-flip 后保留环境变量和 dormant production branch，只在文档标“暂不用”。

## 6. Tests Required

每个 cutover 按触及面至少包含：

- caller/reachability census：旧 production symbol、registry row、dispatch alias 或 writer 为 0；
- slice predicate overlap 检查：旧、新 route 的判定域无重叠残留，或旧 route 已删除；
- decisive/mutation test：绕过新 authority、删除 consumer 或伪造 stamp 时测试必须变红；
- missing/unknown/illegal 负例 fail-closed；
- 正常输入的 byte-exact/ULP 或既定行为回归；
- dispatch/route trace 证明只选择一次并执行预期 selected body；
- 删除旧 test/golden/helper 后，新增测试直接保护新 authority；
- 同时删除旧 config/env flag、spec 正路描述并同步 whitelist/issue/generated retired index；
- 修改 emitter/verifier 后按 [governance · 思维准则](../governance/思维准则.md) 的重链纪律验证；修改共享 layout 时 clean rebuild。

退役记录和 grep 计数不是测试的替代物；至少一个负控必须证明 gate 能变红。

## 7. Wrong vs Correct

Wrong:

```text
new decision contract
  -> some migrated callers
  -> compatibility adapter
  -> old selector/emitter remains reachable
```

Correct:

```text
new decision contract
  -> all callers in the declared slice
  -> selected typed result
  -> mechanical emitter
old entry / adapter / caller = 0
```

Wrong:

```text
worktree A adds new writer
worktree B still updates old writer
merge both and document precedence
```

Correct:

```text
integrator chooses the single writer contract
each worktree rebases to that contract
merge only after the superseded writer and reader are removed
```
