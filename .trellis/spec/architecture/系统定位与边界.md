# 系统定位与边界

## 【定法】定位

Weft 是 post-graph、pre-schedule 的、可扩展 MLIR automatic operator-to-kernel compiler / execution-layer software stack。

它接收图级处理后语义充分、但尚未决定 family execution mapping 的 canonical operator
problem `P=(S,g,ω)`，依据显式 target/profile 绑定 construction family 与 typed capability，
再由 family-local executable knowledge 构造、选择并实现低层执行路径。RISC-V 量化推理是
当前旗舰实现与主要压力域；GPU 是 V2 的第二 execution paradigm 目标，尚未实现。RVV、GPU、
GGML 或任一现有 format/device 不得进入 core/common 作为系统类别判定。

common abstraction 是：

> capability-scoped, typed extension execution

沿 operator/format、capability、mechanism 与 bounded context 分离知识，再在编译期由
family-local formula 重新组合，是连接两柱的设计桥梁：它一面保持变化局部性，一面恢复
专家级专化。它不是 Weft 的系统身份、第三根柱或独立知识语言；构造公式是完整 compiler
主链中的核心工位，不是对 dialect、plugin、typed body、backend、ABI 与 deployment 的
替代定义。

不是：

- 新 tensor/tile IR；
- 完整模型图 compiler 或要求用户手写 schedule 的 kernel DSL；
- 通用算法选择器；
- 每硬件一套孤立 backend；
- descriptor-driven code template；
- 通用 runtime autotuner；
- 把 GPU 作为现有 EmitC backend 的末端分支。

旗舰负载域与论文评价范围见 [canon · 暂定科研主张](../canon/暂定-科研主张.md)。

## 【定法】主链

~~~text
canonical operator problem P=(S,g,ω)
  │
  ▼
typed target/profile binding
  ├─ construction family f
  └─ family capability c_f
  │
  ▼
catalogued plugin-local formula / construction
  ├─ typed candidate or plan
  ├─ legality/resource bounds
  ├─ analytic prior
  └─ optional measurement key
  │
  ▼
bounded selector
  ├─ qualified measured winner if still legal
  └─ otherwise analytic prior / named fallback
  │
  ▼
selected typed extension body
  │
  ▼
family artifact driver
  │
  ▼
EmitC/native object or future family-specific artifact
  │
  ▼
real hardware evidence when runtime/correctness/performance is claimed
~~~

公式与 selector 的精确定义见 [变体流水线](./变体流水线.md)。
problem、family binding 与 artifact-neutral 边界见 [执行问题与家族边界](./执行问题与家族边界.md)。
所有 production entry、公式 catalog 与覆盖要求见 [公式层与覆盖](./公式层与覆盖.md)。

## 【定法】S/g/ω 与 c_f 解耦

“解耦”不表示 problem 与 capability 永不相遇。性能构造必须同时消费 representation/context
事实和 family capability。

正确边界：

- S、g、ω、c_f 来源、类型和 owner 分离；
- `S/g/ω` 在 source/problem 层不含 family schedule，target/profile 先绑定 `f/c_f`；
- 在 catalogued plugin-local formula/construction 中受控汇合，随后由 legality、selector
  消费完整 candidate，最终结果直接构造成 typed body；不存在独立 selected-stamp
  生命周期；
- typed plan/body 一旦产生，后续 emitter 不重新解析格式名、板名、march 或 measurement；
- 每个 decision 只消费所需 capability projection；
- 不建立全局 giant optional descriptor，也不把 family binding 推迟到 artifact emitter。

## 【定法】主要工位

| 工位 | 稳定职责 | 不得承担 |
|---|---|---|
| Source problem | operator semantics S、representation g、regime/必要 shape ω | LMUL/tile/warp、winner、artifact route |
| Family binding/capability | target profile、family applicability、`c_f` projection | candidate、point leaf、measurement winner |
| weft.exec | execution envelope、variant、requires、dispatch、fallback、ABI | selected family compute、dtype、schedule |
| Formula/construction | candidate/plan、mechanism 参数、resource requirement、legality 输入、prior | 输出 C/intrinsic 字符串、查 measurement winner |
| Selector | 在合法候选内选 winner，miss 时 prior/fallback | 创造 candidate 或绕过 legality |
| Typed body | 执行结构与已选参数 authority | 查 measurement、按板再选择 |
| Artifact driver/lowerer | 机械实现 typed body，管理 target handoff/ABI/runtime | 重新决定 mechanism、LMUL、loop-order、warp/tile |
| Evidence | 验证正确性、部署与性能 | 反向定义 compute |

这些是职责，不要求一一对应独立目录或 class。

## 【现状】公共底座、横向 authority 与剩余强度边界

当前代码已经完成公共底座以及 quantize/dequantize、repack、通用 tunable schedule、
low-precision selected-body 与 composite direct route 的 authority 切换：

- plugin registry 可枚举 formula descriptor，并把 production entry 关联到唯一
  family-local typed owner；catalog 不保存 evaluator，也不动态执行 compute；
- RVV quantize 的 q8_0、q8_1、q8_K 由 typed formula 构造
  `QuantizeRowLeaf` 与 layout；`encode_model` 只保留来源语义；
- RVV dequant 的 Int8Scale、NibbleDecode、BinarySign、KQuantScaleMin、
  CodebookGather、GridLookup 与 TernaryDecode 由统一 closed construction 构造；
  只有 CodebookGather 的当前公式真实消费 capability projection，其余轴诚实为空；
- 在 quantize/dequantize 域，formula 在 emission 前求值并直接创建 final typed body；
  不存在 none/partial/forged stamp 或事后扫描、补写、重放公式的 materializer；
- 这些域的 emitter 只按 final typed leaf/plan 机械实现，不从 format、encode/decode
  model、measurement 或 provider 重新决定算法；verifier 只保护结构、类型、闭集和
  ABI/ISA 不变量；
- repack accumulator-LMUL 与 contraction algorithm 已分离 analytic construction、
  legal set、prior 和受限 measurement winner；measurement 不进入 formula 输入；
- repack 的真实 loop-order 与 main-term schedule 由 `RVVRepackScheduleFormula` 构造
  candidate、prior 与合法域，受限 winner 只能在该域内选择；只有一个 realization 的
  SP4 伪轴、reason/record/replay 链与 emitter default 已退出；
- 通用 RVV schedule 通过 `TunableScheduleOpInterface` 自动发现，formula 构造完整 final
  knob tuple；完整 tuple 必须仍是当前合法 candidate，partial/illegal tuple fail-closed，
  production IR 不保存 candidate count、cost、reason 或 measured time 等审计镜像；
- 旧 `weft-rvv-materialize-repack-strip-width` 公开 pass 已退出，因为它重复当前公式且无
  production constructor caller；
- low-precision 的旧 Gearbox/pre-realized-body 构造面已经完成退役/收口：旧 pass、候选/资源
  选择镜像、remediation/audit attrs、cross-region handoff 与 region marker 不再是公共
  dialect 或 production authority；`RVVLowPrecisionResourceFormula` 与 typed body owner
  直接产生并消费最终 resource/schedule/body 结果。
- composite gather–MAcc–scatter 的旧 resource-selection reader/replay 同样已经删除；
  保留的 route-family plan、typed compute-chain 与 ABI metadata 只描述最终 artifact，不能
  创造 candidate 或反向定义 compute；
- `ExtensionPlugin::constructFormulaPlans(FamilyConstructionRequest,
  FamilyConstructionResult)` 已成为 live family 显式 artifact-neutral lifecycle，base
  construction fail closed。Target/profile 在调用前绑定 origin family 与 typed `c_f`；
  family 返回 exact typed operation/root，公共层只检查 ownership/existence。RVV、IME、
  Scalar、Demo、Toy、Template、TensorExtLite 均有对应 owner，Offload 保持显式 unsupported；
- shared `TypedBackendEmissionDriver` 已退回 construction-blind artifact interface；
  `convertConstructedModuleWithBackendEmitter` 与
  `tryConvertConstructedModuleWithRegisteredBackend` 只消费 constructed body/plan，
  `emitc.func` 仅是 EmitC legalization gate；
- RVV flat block-dot 的 `flat_*` 是 formula 产生的最终计算 plan，emitter 不再用
  `kind`、`format` 或旧 `fold_model` 重选。Scalar q2/dequant 和 IME MAC/tile 也在各自
  family construction 中形成 conversion-local final plan；其余确定性 family 直接返回 exact
  final typed body/root，并以纯 artifact ABI/callee contract 机械物化，不引入 universal
  verifier/provider。其旧 manifest/typed-role replay、route provider 与 metadata-only boundary
  已退出 production。

这组事实证明统一结构已经可用且当前 registered/direct production path 的 authority 已
收敛；它不证明知识因式分解已经完成，也不把 catalog 或全量 lit 通过改写成强重建证据。
当前若干 quantize/dequantize 与逐格式 body 仍是 `ConstructedWeak`：formula 可以构造
其最终 typed leaf/plan，但 leaf 内仍保存完整手写算术。Catalog/front-door 覆盖不能
推出删除该 leaf 后可由 `g/c/ω + mechanisms + formula` 重建同一实例，也不能推出
IME 已达到 RVV 的公式或性能成熟度、measurement 已完全单源，或任何性能胜出。

## 【现状】Artifact-neutral construction cutover

当前 authority 已从 EmitC artifact driver 横向迁出：family plugin 在 artifact 之前构造或
资格化 final typed body/plan，EmitC registry 只完成本 artifact class 的 clone、conversion
与完整 legalization。Canonical problem 的 `S/g/ω` ownership 仍需继续类型化和枚举，但这
不再通过恢复 backend construction hook 解决。

后续 GPU family 必须建立在 [执行问题与家族边界](./执行问题与家族边界.md) 规定的这条
artifact-neutral lifecycle 上。GPU 不注册为 current EmitC emitter，不读取 RVV body/
`flat_*` plan，也不通过外部 kernel metadata 冒充 construction。

## 【目标】强 construction 与生态扩展

每个承重 decision 应能列出：

~~~text
decision id
typed g/c/ω inputs
candidate or typed plan
legality/resource verdict
analytic prior
consumed fields
reason/domain/fallback
optional measurement key
selected typed result
consumer
~~~

它由 family-local typed C++/MLIR evaluator 实现，并通过公共只读 catalog 枚举；
不需要表达式 DSL。统一 authority 是底座，后续目标是把已有机制能够表达的完整
point leaf 继续因式分解，使受支持实例逐步通过 delete-leaf reconstruction；真正新的
不可约语义仍可增加新的最小 mechanism。

## 【定法】一个统一系统

RVV、IME、Scalar、Offload 和 future NVIDIA/AMD/vendor extension 是同一 Weft suite 内的 construction family：

- 共享 capability 语义、plugin lifecycle、core orchestration 和 measurement 规则；
- 保持 family-local capability、mechanisms、plans、legality、typed body 与 artifact driver；
- core 只经 interface/registry 调用；
- 每个 production family 都注册 formula/construction descriptor，并通过 typed evaluator 构造 body；
- 只抽 catalog、axis-use、result-kind 和 orchestration 等真正共同的最小 contract，不抽 family compute。

## 【定法】前端与后端边界

source/problem 层负责 `S/g/ω`，不携带 family schedule。进入已绑定 family 后，以下属于
execution construction：

属于 execution-layer formula/realization：

- 固定 op+layout 下的 LMUL/SEW/VL policy；
- load/strip/unroll/accumulator/reduction layout；
- legality/resource pruning；
- family-local candidate selection。

不属于当前 construction novelty：

- 改写高层算法；
- 选择完全不同的模型/算子语义；
- 修改框架持久化权重布局；
- 图级融合和调度搜索。

## 【定法】runtime 边界

当前系统是 static/AOT target binding + family construction，加 offline-qualified selection。

sparse、gather/scatter 或 MoE 的运行时数据分布若未来进入，必须先具备：

- typed observer；
- bounded profile；
- 预构造且静态合法的候选；
- observation/dispatch/switch 开销；
- 稳定策略与反抖动；
- 真实 workload 与归因。

缺少上述实现时，只能写 future，不得把 runtime 当当前第三层或缺失实验。
同理，CPU/GPU 跨设备 dispatch 在 transfer、artifact 共存、observer 与成本模型缺失时
不得接入当前 selector。

## 【定法】禁止结构

- core family-name branch；
- metadata/reason/artifact 反向定义 compute；
- measurement row 创造 route、dtype 或 mechanism；
- emitter 重做 selector 决定；
- GPU 作为 EmitC emitter，或 artifact code 在 emission 时才绑定 family；
- RVV body/`flat_*` plan 作为 GPU 的输入；
- Formula IR 或 giant optional plan；
- descriptor-driven computation；
- runtime profile 在当前热路径提前接线；
- 为覆盖率制造不被 consumer 使用的 g/c/θ。
- 某些 operator 走公式层、另一些 production operator 继续在 builder/emitter 隐式决定；
- catalog 只登记少数“代表公式”，其余 production analytic authority 不入分母。
