# 变体流水线：公式构造、合法域、有界选择与 realization

本文是项目公式/selection 的唯一工程正本。

## 【定法】输入域

### g：Typed Mechanism Facts

描述格式、编码、布局和 mechanism 事实，例如 qk、stride、plane、entry width/count、scale/min/sign/grid/ternary 结构。

不得承载：

- board-specific winner；
- VLEN-specific 性能结论；
- C/intrinsic spelling；
- 完整实现模板。

### c：Canonical Capability

描述 ISA、VLEN/ELEN、SEW、vreg_count、fractional LMUL、cacheline、IME tile、toolchain/runtime availability 等目标事实。

每个字段需要唯一值、provenance、missing/default/conflict 策略。未被真实消费的字段不算 load-bearing capability。

### ω：Bounded Static Context

只承载真实静态选择依赖：

- op；
- layout/memory form；
- decode/prefill regime；
- 必要 shape bucket；
- 只有确实承重时才存在的 policy/toolchain class。

ω 不是任意 context bag，数据值和运行时分布不进入 ω。

## 【定法】候选构造主公式

\[
\boxed{
K_{v,\omega}(g,c)
=
Emit_v(c)\circ
\bigoplus_i
\left\{
m_{i,v}(g,\omega)
\;\text{with}\;
\theta_{i,v}=f^A_{i,v}(g,c,\omega)
\right\}}
\]

其中：

- v 是有限、具名 candidate；
- m 是 typed mechanism/component；
- fA 是解析规则；
- θ 是 typed plan parameter；
- K 是可由 typed body 与 emitter 实现的候选。

Emit 是机械投影。所有 code-affecting 选择必须已经体现在 v、θ 和 selected typed body 中；Emit 不得重新决定 candidate、LMUL、loop-order 或 mechanism。

一个字段只有在以下条件满足时才算真实 θ：

1. 有多个合法取值，或真实决定合法性/资源；
2. 输入来自 typed g/c/ω；
3. 输出进入 typed plan/body；
4. consumer 真读取；
5. 有决定性测试、正确性或性能 disposition；
6. 不适用时有 structural constant、honest-null 或 fail-closed。

## 【定法】合法域

\[
\mathcal V(g,c;\omega)
=
\left\{
v\in\mathcal A(g,c;\omega)
\;\middle|\;
L_v(g,c,\omega)=1
\right\}
\]

- A 由公式/机制层构造；
- L 是解析 legality/resource predicate；
- unknown capability 按 fail-closed 处理；
- measurement 不能向 A 增加候选；
- measurement 不能让 L=0 的候选合法。

## 【定法】薄选择器

令 κ=k(g,c,ω) 为有限、类型化的 measurement key。

\[
\operatorname{Usable}_M(\kappa,\mathcal V)
=
Hit_M(\kappa)
\land Qualified_M(\kappa)
\land Fresh_M(\kappa)
\land SelectionValid_M(\kappa)
\land Winner_M(\kappa)\in\mathcal V
\]

\[
\boxed{
\sigma_M(g,c;\omega)=
\begin{cases}
\operatorname{Winner}_M(\kappa),
& \operatorname{Usable}_M(\kappa,\mathcal V)
\\[4pt]
\pi(\mathcal V;g,c,\omega),
& \neg\operatorname{Usable}_M(\kappa,\mathcal V)
\land \mathcal V\neq\varnothing
\\[4pt]
\bot,
& \mathcal V=\varnothing
\end{cases}}
\]

\[
\pi(\mathcal V;g,c,\omega)\in\mathcal V
\]

最终执行：

\[
K^*(g,c;\omega,M)=
\begin{cases}
K_{\sigma_M(g,c;\omega),\omega}(g,c),
& \sigma_M(g,c;\omega)\neq\bot
\\[4pt]
\operatorname{FallbackOrReject}(g,c,\omega),
& \sigma_M(g,c;\omega)=\bot
\end{cases}
\]

FallbackOrReject 必须是 canon 允许的具名合法 fallback，否则 reject/fail-closed。

## 【定法】为什么不是 MemoArgmin

当前 compiled measurement view 保存 offline profiling 已经确定的 winner token，不保存完整候选代价向量，也不在编译期重新求 argmin。

因此：

- 当前语义是 qualified winner lookup；
- 普通 argmin 不是 novelty；
- 只有未来数据平面真实保存并消费完整 T(κ,v) 时，才可写合法集上的 argmin；
- 静态 cost 可以帮助候选构造、剪枝或 prior，但不得伪装为已验证全局最优。

## 【定法】知识类型

| 类型 | 负责 | 不得负责 |
|---|---|---|
| Analytic | candidate、typed θ、legality、resource boundary、prior | 虚构所有板上全局最优 |
| Measured | 特定 typed key 下合法候选的 winner | candidate、dtype、route、compute、legality |
| Boundary | unsupported、physical absence、compiler/HW wall、wash | 被隐藏或改写为 PASS |
| Runtime-profiled | 未来对数据分布敏感的动态选择 | 在 observer/开销/策略缺席时写成现状 |

解析知识具有构成性，测量知识只有判别性。

## 【定法】最小 decision contract

每个承重 decision 至少可观察：

~~~text
decision id
typed g/c/ω inputs
candidate or plan
legality/resource verdict
analytic prior
consumed fields
reason/domain/fallback
optional measurement key
selected typed result
consumer
~~~

不要求每个字段成为独立 class/API，也不要求所有 decision 使用 measurement。

## 【定法】authority 顺序

~~~text
facts / capability / context
  → formula constructs candidates/plans
  → legality
  → bounded selector
  → stamp selected typed body
  → body realization
  → plugin route provider
  → mechanical emitter
~~~

禁止回流：

- emitter 查 format/board/march/measurement 再选择；
- selector 在 emission 后改变 code；
- reason/provenance 重建 compute；
- measurement 绕过 legality；
- verifier 与 provider 各自维护不一致公式。

## 【定法】measurement data plane

稳定数据流：

~~~text
measurement schema
  → qualification
  → generated or hash-equivalent compiled winner view
  → selector
~~~

每个 selection-valid row 至少绑定：

- declared capability instance；
- op/regime/shape/context key；
- variant axis 与 candidate set；
- byte-exact；
- paired comparison 与 compiler symmetry；
- run lineage；
- freshness/expiry；
- positive 或 negative disposition。

schema、独立 registry 和 compiled view 不得长期作为三个手工事实源。

## 【现状】实现映射

已存在：

- RVVGearboxSchedule.h 的解析规则；
- 五类 dequant plan/provider；
- VLEN、version、vreg_count 的部分 decisive consumption；
- LMUL、SP4、loop-order 的 measured selection；
- winner hit、miss→prior、部分 winner feasibility revalidation；
- typed reason 与 typed body；
- plugin route provider 和 EmitC。

仍需：

- 把散落 decision 统一到最小 contract；
- plan 字段按 analytic/measured/constant/null 分类；
- 清除 selector/emitter authority inversion；
- 修 GridLookup provider/verifier 双头；
- measurement schema、registry、compiled view 单源；
- 补 capability fields 与 per-board instances；
- 第二 family 复用同一 contract。

当前状态的具体进度与数字住 formula-layer migration ledger、issues 和实验主表，不在本 spec 转抄。

## 【目标】runtime observer

只有出现真实数据分布依赖时，才可在静态合法候选之前增加 typed runtime observer ρ(x)。

启用条件：

- observer 与 profile schema；
- observation/dispatch/switch cost；
- 预构造候选全部静态合法；
- 反抖动、缓存失效和 fallback；
- 可归因；
- 收益覆盖开销；
- 真实 sparse/MoE workload。

当前没有该层，不属于当前必补实验。

## Tests Required

### Formula/legality

- typed inputs 改变时 plan/legal set 的决定性变化；
- unused capability 诚实 no-op/honest-null；
- unknown/unsupported fail-closed；
- formula 与 verifier 不出现第二 authority。

### Selector

- qualified hit；
- no-flip；
- miss→prior；
- stale/unqualified/key-mismatch→prior；
- winner-infeasible→prior/fallback；
- empty legal set→FallbackOrReject。

### Authority

- selected result 在 emission 前 stamp；
- emitter no-redecision；
- measurement 不能增加 candidate；
- metadata/reason 不影响 compute。

### Correctness/performance

- byte-exact 或规定 ULP；
- deployed ggml 回归；
- representative strong opponent；
- 有明确 kernel 增益时选择性 e2e；
- 正负结果均保留。

## 非目标

- 新 Formula dialect；
- 通用表达式 AST；
- giant optional candidate descriptor；
- 每个职责一个强制软件子系统；
- 通用 online cost model；
- runtime sparse/MoE 提前接线；
- 为了公式覆盖率制造伪 c/θ；
- measurement lookup 被包装成新的闭式公式。
