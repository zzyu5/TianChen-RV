# 变体流水线：公式构造、合法域、有界选择与 realization

本文是项目公式/selection 数学语义与 authority 顺序的唯一工程正本。全项目 formula catalog、production-entry obligation、覆盖与横向 cutover 见 [公式层与覆盖](./公式层与覆盖.md)。

## 【定法】输入域

### g：Typed Mechanism Facts

描述格式、编码、布局和 mechanism 事实，例如 qk、stride、plane、entry width/count、scale/min/sign/grid/ternary 结构。

不得承载：

- board-specific winner；
- VLEN-specific 性能结论；
- C/intrinsic spelling；
- 完整实现模板。

### c：Canonical Capability

描述 ISA、VLEN/ELEN、SEW、vreg_count、fractional LMUL、cacheline、IME tile、toolchain/runtime availability 等目标事实。

每个字段需要唯一值、provenance、missing/default/conflict 策略。未被真实消费的字段不算 load-bearing capability。

### ω：Bounded Static Context

只承载真实静态选择依赖：

- op；
- layout/memory form；
- decode/prefill regime；
- 必要 shape bucket；
- 只有确实承重时才存在的 policy/toolchain class。

ω 不是任意 context bag，数据值和运行时分布不进入 ω。

## 【定法】候选构造主公式

\[
\boxed{
\theta_{i,v}=f^A_{i,v}(g,c,\omega)
}
\]

\[
\boxed{
K_{v,\omega}(g,c)
=
Emit_v(c)\circ
\bigoplus_i
\left\{
m_{i,v}(g,\omega)
\;\text{with}\;
\theta_{i,v}
\right\}}
\]

其中：

- v 是有限、具名 candidate；
- m 是 typed mechanism/component；
- fA 是解析规则；
- θ 是 typed plan parameter；
- K 是可由 typed body 与 emitter 实现的候选。

Emit 是机械投影。所有 code-affecting 选择必须已经体现在 v、θ 和 selected typed body 中；Emit 不得重新决定 candidate、LMUL、loop-order 或 mechanism。

一个字段只有在以下条件满足时才算真实 θ：

1. 有多个合法取值，或真实决定合法性/资源；
2. 输入来自 typed g/c/ω；
3. 输出进入 typed plan/body；
4. consumer 真读取；
5. 有决定性测试、正确性或性能 disposition；
6. 不适用时有 structural constant、honest-null 或 fail-closed。

## 【定法】合法域

\[
\mathcal V(g,c;\omega)
=
\left\{
v\in\mathcal A(g,c;\omega)
\;\middle|\;
L_v(g,c,\omega)=1
\right\}
\]

- A 由公式/机制层构造；
- L 是解析 legality/resource predicate；
- unknown capability 按 fail-closed 处理；
- measurement 不能向 A 增加候选；
- measurement 不能让 L=0 的候选合法。

## 【定法】薄选择器

令 κ=k(g,c,ω) 为有限、类型化的 measurement key。

\[
\operatorname{Usable}_M(\kappa,\mathcal V)
=
Hit_M(\kappa)
\land Qualified_M(\kappa)
\land Fresh_M(\kappa)
\land SelectionValid_M(\kappa)
\land Winner_M(\kappa)\in\mathcal V
\]

\[
\boxed{
\sigma_M(g,c;\omega)=
\begin{cases}
\operatorname{Winner}_M(\kappa),
& \operatorname{Usable}_M(\kappa,\mathcal V)
\\[4pt]
\pi(\mathcal V;g,c,\omega),
& \neg\operatorname{Usable}_M(\kappa,\mathcal V)
\land \mathcal V\neq\varnothing
\\[4pt]
\bot,
& \mathcal V=\varnothing
\end{cases}}
\]

\[
\pi(\mathcal V;g,c,\omega)\in\mathcal V
\]

最终执行：

\[
K^*(g,c;\omega,M)=
\begin{cases}
K_{\sigma_M(g,c;\omega),\omega}(g,c),
& \sigma_M(g,c;\omega)\neq\bot
\\[4pt]
\operatorname{FallbackOrReject}(g,c,\omega),
& \sigma_M(g,c;\omega)=\bot
\end{cases}
\]

FallbackOrReject 必须是 canon 允许的具名合法 fallback，否则 reject/fail-closed。

Selector 接收的是 formula 已完成语义构造、且经 legality 资格化的完整 candidate。它只能返回其中一个 candidate identity 或 `⊥`；返回 leaf/body/formula id 供 downstream 重新解释，或修改 `θ`、mechanism composition、typed body，都属于 selector 创造实现。Measurement winner 也只能在这些完整合法 candidate 之间作受限残差修正。

## 【定法】为什么不是 MemoArgmin

当前 compiled measurement view 保存 offline profiling 已经确定的 winner token，不保存完整候选代价向量，也不在编译期重新求 argmin。

因此：

- 当前语义是 qualified winner lookup；
- 普通 argmin 不是 novelty；
- 只有未来数据平面真实保存并消费完整 T(κ,v) 时，才可写合法集上的 argmin；
- 静态 cost 可以帮助候选构造、剪枝或 prior，但不得伪装为已验证全局最优。

## 【定法】知识类型

| 类型 | 负责 | 不得负责 |
|---|---|---|
| Analytic | candidate、typed θ、legality、resource boundary、prior | 虚构所有板上全局最优 |
| Measured | 特定 typed key 下合法候选的 winner | candidate、dtype、route、compute、legality |
| Boundary | unsupported、physical absence、compiler/HW wall、wash | 被隐藏或改写为 PASS |
| Runtime-profiled | 未来对数据分布敏感的动态选择 | 在 observer/开销/策略缺席时写成现状 |

解析知识具有构成性，测量知识只有判别性。

## 【定法】最小 decision contract

每个承重 decision 至少可观察：

~~~text
decision id
typed g/c/ω inputs
candidate or plan
legality/resource verdict
analytic prior
consumed fields
reason/domain/fallback
optional measurement key
selected typed result
consumer
~~~

不要求每个字段成为独立 class/API，也不要求所有 decision 使用 measurement。

## 【定法】authority 顺序

~~~text
facts / capability / context
  → formula constructs candidates/plans
  → legality
  → bounded selector
  → construct selected typed body
  → body realization
  → plugin route provider
  → mechanical emitter
~~~

禁止回流：

- emitter 查 format/board/march/measurement 再选择；
- selector 在 emission 后改变 code；
- reason/provenance 重建 compute；
- measurement 绕过 legality；
- verifier 与 provider 各自维护不一致公式。

普通局部 decision 变更必须在同一可审查合入单元内迁移其全部 production caller，并删除旧入口、旧 overload、兼容 mirror 与 emitter/selector 旁路。

建立 formula/construction layer 属于 project-wide horizontal rebase：迁移域由当前
registry、production call graph 和 typed owners 直接给出，覆盖全部 current production
operator entries、formula/analytic authorities 与 callers。最终合入时其它
operator/family 不能继续走旧公式或隐式 builder/emitter 决策；中间状态只能存在于未完成
worktree。完整 cutover 与 fallback 分类见 [退役与单一生产路径](./退役与原子合入.md)
`[RET-F]`。

## 【定法】measurement data plane

稳定数据流：

~~~text
measurement schema
  → qualification
  → generated or hash-equivalent compiled winner view
  → selector
~~~

每个 selection-valid row 至少绑定：

- declared capability instance；
- op/regime/shape/context key；
- variant axis 与 candidate set；
- byte-exact；
- paired comparison 与 compiler symmetry；
- run lineage；
- freshness/expiry；
- positive 或 negative disposition。

schema、独立 registry 和 compiled view 不得长期作为三个手工事实源。

## 【实现基线】2026-07-22 横向 authority cutover

当前 production call graph 已按同一次横向迁移收口到 family-local construction owners。
RVV 的 `ExtensionPlugin::constructFormulaPlans(ModuleOp)`、所有 backend 的强制
`prepareForConversion(ModuleOp)`、live registry 与 catalog 现在由真实 caller/dataflow
共同支撑；旧 task、历史 census 和测试 fixture 不再作为完成依据。

已闭合的单向链为：

1. quantize/dequantize lifecycle 与显式 front door 复用同一 domain construction owner；
2. generic schedule 的 candidate、legality、analytic prior 与 bounded winner 由
   `Construction/RVVScheduleFormula.cpp` 统一构造，project lifecycle 在成功输出前完成/验证
   final schedule；旧 Q40/GEMM subset compatibility pass、缺字段补全与 schedule mirror 已删除；
3. contraction、repack、low-precision/dot-reduce 和 source front door 均消费 typed formula
   result，不再直接调用 gearbox helper 或靠 reason/record 关联；
4. composite gather–MAcc–scatter 是真实 selected-body registry owner，dispatcher 不再有
   special branch 或手工 catalog `+1`；
5. EmitC 的 flat block-dot 路径首先读取 formula 产生的完整 `flat_*` plan。plan 的 body
   family、decode primitive、fold、block length、activation offset、scale source、table
   identity 与 bias 是最终计算决定；emitter 只做闭集读取、typed geometry 投影和机械发射。
   `kind`、`format` 与旧 `fold_model` 不得在 emitter 中形成第二决策权威；缺失/partial/
   unknown/conflicting plan fail closed；
6. shared backend interface 不再提供成功 no-op；registry clone、公开 EmitC
   materialization、translate/artifact 与 direct RVV conversion 都在 emitter pattern 之前
   执行 family construction，未完整 legalize 时直接拒绝，不转 string/metadata route；
7. Scalar q2 block-dot 与 q4_0 dequant 对称地从 typed geometry 和 canonical capability 构造
   conversion-local final plan；emitter 只读 plan 中的 geometry/decode 常量，不能从原 op
   重算 `qk/2`、plane 或 mask；
8. IME 的 MAC leaf、wide-tiling disposition、VLEN 依赖、helper 与 final dimensions 在
   family construction 中确定；emitter 只消费结果，不再调用 selector 或读 target capability；
9. Demo、Toy、Template 与 TensorExtLite 的确定性路径由 family owner 资格化完整 selected
   typed body，再由固定 family route 机械映射 callee/ABI/role order。这里的 typed body 是
   `ConstructedWeak` final result，不需要通用 Formula IR 或持久化 plan；
10. Offload 没有受支持 emission implementation，保持显式 unsupported 且不注册空 backend。

当前 flat block-dot 的 live mechanism leaf 是：
`Q80Q80`、`Q40Q80`、`Q41Q81`、`Q50Q80`、`Q51Q81`、`IQ4NLQ80`、`MXFP4Q80`、
`Q10Q80`、`NVFP4Q80`。集合用于语义 coverage 与负例保护，不按数量主张 novelty。q5_0/q5_1
的 bias/fold、IQ4NL/MXFP4 的 table/scale-source、Q10/NVFP4 的 special body family 都
由 formula 直接落入 final plan；测试骨架不能再借旧字段猜出 leaf。

这表示当前 registered/direct production authority/caller 的 `[RET-F]` 已闭合：compatibility bridge、
emitter compute replay、registry bypass、双编排和非语义 reason/measurement mirror 均退出
生产路径。verifier 仍只做结构、闭集、ABI 与 parent/core 一致性检查，不重放公式；不新增
universal verifier/provider 层，也不把 route metadata 提升为 compute authority。

边界仍然明确：`ConstructedWeak` 只表示“已进入唯一 construction authority、但仍依赖完整
机械 leaf”。删除某个逐点 leaf 后，仅凭 `g/c/ω + mechanisms + formula` 重建同一实例的
strong reconstruction 尚未由本次 cutover 证明，必须另行用删除实验或等价构造证据审计。

## 【目标】runtime observer

只有出现真实数据分布依赖时，才可在静态合法候选之前增加 typed runtime observer ρ(x)。

启用条件：

- observer 与 profile schema；
- observation/dispatch/switch cost；
- 预构造候选全部静态合法；
- 反抖动、缓存失效和 fallback；
- 可归因；
- 收益覆盖开销；
- 真实 sparse/MoE workload。

当前没有该层，不属于当前必补实验。

## Tests Required

### Formula/legality

- typed inputs 改变时 plan/legal set 的决定性变化；
- unused capability 诚实 no-op/honest-null；
- unknown/unsupported fail-closed；
- formula 与 verifier 不出现第二 authority。

### Selector

- qualified hit；
- no-flip；
- miss→prior；
- stale/unqualified/key-mismatch→prior；
- winner-infeasible→prior/fallback；
- empty legal set→FallbackOrReject。

### Authority

- selected result 在 emission 前成为 final typed body；
- emitter no-redecision；
- measurement 不能增加 candidate；
- metadata/reason 不影响 compute。
- 横向 rebase census 内全部旧 caller、兼容 bridge、第二 selector/dispatcher 为 0；缺 final body 必须拒绝，不得回旧路。
- catalog 中每个 current production formula/constructor 恰有一个 owner；每个 production operator entry 恰进入一个 catalogued construction owner。
- catalog/registry、真实 production entry、decisive dependency 与 semantic boundary
  均由当前代码生成的完整检查保护，不靠手填 census 百分比宣称完成。

### Correctness/performance

- byte-exact 或规定 ULP；
- deployed ggml 回归；
- representative strong opponent；
- 有明确 kernel 增益时选择性 e2e；
- 正负结果均保留。

## 非目标

- 新 Formula dialect；
- 通用表达式 AST；
- giant optional candidate descriptor；
- 每个职责一个强制软件子系统；
- 通用 online cost model；
- runtime sparse/MoE 提前接线；
- 为了公式覆盖率制造伪 c/θ；
- measurement lookup 被包装成新的闭式公式。
