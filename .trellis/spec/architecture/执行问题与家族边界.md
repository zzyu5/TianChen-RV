# 执行问题、Domain Binding、Construction Owner 与 Artifact 边界

本文是 V2 canonical execution problem、target-bound selection/deployment domain、typed
construction owner 及 artifact-neutral 边界的稳定正本。公式/selector 数学语义仍以
[变体流水线](./变体流水线.md) 为唯一正本；本文只定义该公式之前和之后的 compiler
工位，绝不建立第二套公式。

## 【定法】系统边界

Weft 是 post-graph、pre-schedule 的自动 operator-to-kernel compiler：上游已经完成图级
融合、算子识别及必要 shape/layout 传播，Weft 接收语义充分、但尚未决定 family execution
mapping 的 operator problem。

这里 `pre-schedule` 只约束 source problem；family construction 本身负责产生 LMUL、tile、
warp、pipeline 等 execution schedule，artifact lowerer 不再选择这些决定。

```text
graph/model compiler
  → canonical operator problem
  → target/domain binding
  → in-domain owner-local construction + bounded selection
  → final typed execution body
  → owner/domain-compatible artifact/runtime
```

低层 RVV/IME/Scalar/future-GPU body 是 Weft 构造出的内部 execution IR；它可以作为
backend unit test/debug 输入，但不能代替 canonical source-to-body 路径来证明自动编译。

Weft 不接管完整模型图，也不新增通用高层 tensor/tile IR。多个 source adapter 可以接入，
但 adapter 不得决定 LMUL、tile、warp、pipeline、MMA、winner 或 artifact route。

## 【定法】Canonical Execution Problem

\[
P=(S,g,\omega)
\]

- `S`（operator semantics）：数学/离散计算、operand roles 与结果语义；
- `g`（typed representation facts）：format、encoding、packing、layout、shape/geometry 及
  与数据表示相关的事实；
- `ω`（bounded static context）：真实承重的 regime、必要 shape bucket、memory form 与
  静态 policy。

分型纪律：

- `S` 不携带 target schedule；
- `g` 不携带 capability、measurement winner、完整 point leaf id 或 artifact 名；
- `ω` 不包含 runtime data distribution、任意 context bag 或 winner memory；
- owner-local formula 可以把上述事实规范化为自己的 typed input，但不能靠字符串、route
  metadata 或 emitter state 恢复缺失语义。

`S` 补足外部 compiler 问题边界，不改变主公式。进入某个具名 operator formula 时，`S`
已经由 source op 与 formula domain 固定，内部继续使用既有 `g/c/ω` 构造式。

## 【定法】Target/Domain Binding

令 `t` 为显式 target/profile request：

\[
\operatorname{BindDomain}(t)=(d,C_d)
\]

- `d` 是一个 target-bound selection/deployment domain：同一设备、地址空间、部署生命周期
  与可共同成立的 ABI/runtime 边界，不是 artifact kind；
- `C_d` 是该 target/profile 的 typed capability environment；
- binding 依据显式 typed target/profile 与 capability provenance；不能由 emitter、artifact
  kind、某个候选 origin 或 cost 排名反推；
- 正式 source kernel 必须以 exact symbol 指向 module-level target/profile；`d` 与 `C_d`
  必须在一次 binding 中取自这同一个 target 及其显式 composed providers；
- kernel-local `construction_domain` 若存在只能断言与 target 相等，不能成为 authority；
  kernel-local capability 不能注入 target-bound `C_d`；
- targetless direct/pre-realized 输入只能经显式 debug qualification，产生的环境必须标为
  non-target-bound，不能启动 source proposal或冒充 `BindDomain(t)`；
- binding 不产生 candidate、不读取 measurement、不选择逐点 leaf；
- missing、unknown、ambiguous 或 conflicting domain binding 一律 fail closed。

当前一个 RISC-V/X60 domain 可以容纳 RVV、IME 与 Scalar 等 typed construction owner；
这与 future NVIDIA domain 内 SIMT、MMA/tensor-core 等替代机制同构。H100/5090D 是同一
NVIDIA owner/domain 下的不同 capability profile，而非两个复制的 compiler。AMD/ROCm
若地址空间、ABI/runtime 与 artifact 生命周期不同，则属于另一个 domain。

当前 static/AOT 主链先绑定 domain，再只在该 domain 的 owners/candidates 内
construct/legalize/select。本文不定义跨 domain 的 CPU/GPU、NVIDIA/AMD runtime selector；
未来若引入，必须另有 transfer、observer、artifact 共存、dispatch cost 与真实 workload
证据。

## 【定法】Domain-Scoped、Owner-Local Construction

令 `o∈Owners(d)` 为 domain 中注册的 typed construction owner，例如当前 RVV、IME、
Scalar。每个 owner 从 `C_d` 得到自己的 capability projection：

\[
c_o=\pi_o(C_d)
\]

既有主公式在每个 `o` 内原样成立。`o` 拥有自己的：

- typed problem projection；
- mechanisms 与 formula；
- candidate/plan 类型；
- legality/resource model；
- analytic prior 与可选 measurement key；
- final typed body；
- construction-strength classification。

跨 owner 共享 construct → legality → bounded select → final body 的因果顺序，不共享一个
physical Plan、FormulaResult、mechanism AST 或 resource model。domain 层只合并
owner-qualified candidate envelope，不解释 owner 的 compute。

Domain binding 和域内 selector 是两个不同工位：前者建立设备/部署作用域，后者只在该域
各 owner 已构造且合法的有限候选中选择。`origin=o` 只表示 candidate/body owner，不得冒充
domain binding。两者都不得推迟到 artifact lowering。

## 【定法】Construction Completion

construction completion 的判据是：selected owner 已从 typed `P+c_o` 构造或严格资格化完整
final typed body/plan，且 legality/selection 所需结果已经消费，并返回 exact typed
operation/root。它不以任何特定 artifact dialect、`emitc.func`、C symbol、route id 或
metadata 为定义，也不允许公共层随后扫描 module 重新发现“真正的”body。

construction completion 仍不等于 strong reconstruction：依赖完整 point leaf 的结果只能
标为 `ConstructedWeak`；删除 point leaf 后能由 `g/c/ω + reusable mechanisms + formula`
重建同一 body/legal domain 才是 strong construction。

禁止建立 universal verifier/provider 来判定 construction。Owner 产生 typed result，
通用编排只检查 owner 唯一、调用顺序和结果是否存在；IR verifier 只保护结构/类型/ABI，
不重放公式。

## 【定法】Artifact Contract

artifact lowering 只消费 construction-qualified final typed body：

```text
final typed body
  → owner/domain-compatible artifact driver
  → target dialect/toolchain handoff
  → object/device module/header/bundle
  → family ABI/runtime
```

artifact driver 可以是：

- 当前 RISC-V domain 中 RVV/IME/Scalar owners 的 EmitC/C/C++/native-object 路径；
- future NVIDIA domain 的 GPU/NVGPU/NVVM/device-module 路径；
- future AMD domain 的 GPU/AMDGPU/ROCDL/device-module 路径。

公共 artifact orchestration 可以管理 identity、ownership、typed handoff、ABI/provenance 和
fail-closed，但不得解释 owner compute。`emitc.func` 是 EmitC artifact backend 的完成门，
不是全系统 construction 或 artifact 的通用完成门。

原主公式中的 `Emit_v(c)` 不因此被替换：它仍是 owner 构造式内把已确定 mechanisms 与
parameters 机械组成候选实现的投影。最终 object/cubin/hsaco packaging 是其后的
`LowerArtifact_{d,o}`，不能获得第二 compute authority。

## 【定法】Source、Construction 与 Artifact 的唯一 authority

| 对象 | 唯一 owner | 禁止 |
|---|---|---|
| operator semantics `S` | source problem op/adapter | owner emitter 从名字猜 operator |
| representation `g` | typed source/format owner | capability、winner 或 point leaf id |
| context `ω` | bounded static context owner | runtime distribution、任意 bag |
| domain `d` / environment `C_d` | explicit target/profile | artifact kind/origin/cost 反推 binding |
| capability `c_o` | owner capability projection | giant cross-owner optional struct |
| mechanisms/formula | typed construction owner | common provider 或 emitter replay |
| final body/plan | owner typed execution IR | metadata/route id 替代 |
| artifact/runtime | owner/domain artifact driver | 重新选择 mechanism/tile/LMUL/warp |

## 【现状】2026-07-23 · exact-P / exact-root 实现基础与缺口

已经成立：

- 正式 source kernel 绑定 module-level target/profile，不再自行写入 RISC-V domain 或
  kernel-local capability。`TargetDomainBinding` 从 exact target 统一产生 `(d,C_d)`；source
  proposal、legality、selection 与 selected-owner construction 均以该绑定为 authority；
  direct/pre-realized targetless 输入仅由显式 debug mode 接受并标为 non-target-bound；
- current source adapters 通过 target support helper 建立 target/profile 与 module-level
  capability providers；source/front door 中不再硬编码 `riscv-execution`。domain 字符串仍可
  出现在 target profile 与 plugin membership 声明中，这两处分别是 binding authority 与
  owner membership，不是第二计算权威；
- test-only `domain-a/domain-b` owners 已证明 domain B 的同一个 physical P 可完成
  proposal→legality→selection→artifact-neutral typed construction，而 foreign domain A 在
  support/proposal hook 前退出；该见证没有 GPU capability、dialect、body 或 artifact；
- current artifact-neutral lifecycle/caller authority 已进入
  construction-before-artifact；这不表示 physical source 与全部 compute authority 已收敛；
- proposal、legality、cost、selection 与 selected-owner construction 绑定同一个 direct
  canonical problem pointer；public request overload 对 normalized `C_d` 不连续或伪造输入
  fail closed；
- quantize/dequantize 复用 RVV top-level construction cut；
- RVV `flat_*` final computation plan 由 formula 产生，emitter 直接消费；
- selected `origin` 只表示 owner；domain membership 在 owner hook 前验证，不能反向定义
  target binding；
- RVV、IME、Scalar、Demo、Toy、Template 与 TensorExtLite 都显式实现
  `constructFormulaPlans(FamilyConstructionRequest, FamilyConstructionResult)` 并返回 exact
  typed result，base construction fail closed；
- `TypedBackendEmissionDriver` 不再含 construction hook；
  `convertConstructedModuleWithBackendEmitter` 与
  `tryConvertConstructedModuleWithRegisteredBackend` 只做 constructed body 的 artifact
  projection；driver owner 必须匹配 selected variant origin，registry 保留完整 selected
  variant slice并拒绝任何 competing root；
- `emitc.func` 只作为 current EmitC artifact 的完整 legalization gate。

当前 A/B 横向任务已经完成的第一项清理：

- Demo、Toy、Template 与 TensorExtLite 不再维护 construction manifest、typed-role graph、
  route provider、通用 readiness verifier 或 role/status/interface 字符串镜像；
- metadata-only `lowering_boundary` 已删除，family construction 直接返回 typed compute
  body/root；
- common readiness/plan 直接接收该 exact result，只检查 ownership/existence；
- family contract 中的 artifact route/ABI/callee 是 body 之后的机械常量，不参与 legality、
  candidate、completion 或 compute。

随后完成的 RVV exact-body 清场：

- construction 以 `RVVBodyRuntimeControl {sew, lmul, policy, runtimeAVLValue}` 明确拥有
  runtime config/control，artifact 不从 ABI order 或 route metadata 补值；
- 旧 `lib/Plugin/RVV/EmitC` route-provider 栈、`RVVConstructionProtocol`、route identity、
  route-family plan-owner mirrors 与 provider 构建目标已删除；
- segment2 typed-body construction 住回 family realization owner；contraction realization
  直接消费 formula 的 relation/layout/resource plan；
- provider/formula replay validator 已退出。typed dialect verifier 仍保护结构、类型、
  operand/policy 与局部语义关系，但不得重放公式、产生 candidate 或重新选择 compute。

仍需继续收敛但不回退上述边界：

- source/problem `S/g/ω` 已有多类 bounded canonical anchors，IME/Scalar 直接消费 P，RVV
  source adapters 也建立 exact P；但 RVV 仍在 front door 中预构造完整 body，其 P 尚未成为
  forward construction 的充分输入，未覆盖的 source entry 与 loose family facts继续集中；
- 已闭合的 construction-before-artifact caller 与负例必须持续保护；
- Scalar 等路径仍需检查 formula 是否只产生参数字典、而完整算法仍藏在 artifact leaf；
- `ConstructedWeak` leaf 仍需多 topology delete-leaf reconstruction 才能升级 strong
  construction；
- 重构后 current artifact 的 correctness、deployed、strong-opponent 与 e2e 性能必须由 B 线
  重新给出 paired evidence。

这些剩余工作不是 GPU 已实现缺口的另一种说法，也不授权恢复 backend-side
construction。

## 【现状】已落地的 GPU 前置切面与仍未完成的 construction

已经落地并必须继续保持：

1. artifact-neutral owner construction lifecycle；
2. explicit domain identity 与 owner membership gate；
3. 每个 live family 的 construction lifecycle 归 plugin/family typed owner；
4. 默认成功 construction 与 EmitC driver 内的第二 construction authority 已删除；
5. EmitC driver 只消费 construction-qualified final body；
6. source/direct/pass/translate/artifact caller 的 artifact 路径经同一 construction seam；
7. `emitc.func` 完成门只住 EmitC artifact backend；
8. 旧路径原子退役、无 compatibility middle path；
9. target/profile 已同时绑定 `d/C_d`，source adapter 不再写 kernel-local domain；
10. test-only 第二 domain/owner 已验证 common seam，不包含 GPU implementation。

仍未落地、不得由上述切面推出：

1. 每个 source-origin entry 的 physical `S/g/ω` problem 与 owner 实际消费；
2. RVV 从 exact P 正向构造全部 current source body，而不是 adapter 预构造；
3. 多 topology strong reconstruction 与 current-artifact A/B 真硬件证据。

本 cutover 横向覆盖 RVV、IME、Scalar、Demo、Toy、Template、TensorExtLite 与 Offload
explicit unsupported；不创建 GPU dialect、GPU plan、GPU runtime 或 GPU 测量。

## 【定法】禁止结构

- GPU 作为 current EmitC registry 的新 emitter；
- RVV body/`flat_*` plan 转译成 GPU compute；
- family 只在 emission 时才确定；
- source descriptor 携带完整 backend schedule/template；
- universal capability/Plan/FormulaResult/provider/verifier；
- artifact lowerer 从 `kind/format/fold_model`、device 名或 metadata 重选；
- current architecture target 被写成 GPU 已支持事实；
- 为迁移保留旧 direct emitter、compat adapter 或双 construction hook。

- 每个 production source entry 的 physical `S/g/ω` ownership、实际消费与唯一 construction owner；
- domain identity membership gate 与 target/profile `BindDomain(t)` 分开测试；
- target/domain binding missing/unknown/ambiguous/mixed/conflict/unsupported 负例；
- test-only 第二 domain/owner 复用同一 problem、完成 proposal/legality/construction，且不修改
  common family-name control flow；该测试不创建 GPU implementation；
- 每个 live family 的 artifact-neutral construction 正负路径；
- construction completion 不依赖 EmitC 类型的静态/接口测试；
- current EmitC artifact 仍要求完整 legalization 与 `emitc.func`；
- direct/pass/translate/artifact 调用同一 construction seam；
- mixed/unowned/unconstructed body fail closed；
- quant/dequant 对称与 RVV `flat_*` no-redecision 回归；
- 旧 RVV provider/protocol symbol、include 与构建目标不得回流；
- typed verifier/capability check 只验证已构造结果，不成为 formula replay；
- full catalog/registry 与完整 `check-weft`。
