## T-1. 终极目标与定位红线

**[G-0] 终极目标（原样 · 来源 [G-0]）**：交付一个**基于 MLIR 的能力驱动（capability-driven）可扩展执行层软件栈之参考模板（reference template）**——为碎片化硬件生态（RISC-V 是极端案例：VLEN 任意、扩展组合爆炸、厂商专有单元各异）给出一个可复制的**栈组织方式**：以"能力事实"为**唯一决策源**，接入一个新扩展家族 = 一个插件 + 几行表格、核心零改动；kernel 主体由机制构造（强义，见 [L-8]）而非手写；每一次变体选择可归因；每一条结构性主张机器可检验。**RISC-V 量化 LLM 推理是该模板的首个高性能实例**——真硅上打赢手写出货物是模板质量的**证明书**，不是终极目标本身（主角 = 可扩展性；性能 = 证据）。学术上支撑三条贡献（**C1 模板协议本体**：合取存在性 → 可复制扩展接入协议；**C2 模板经济学**：泛化代价 → 边际成本规律；**C3′ 模板产出质量**：能力键控模式库 → 带实测与迁移的模板）；工程上以覆盖率与正确性门槛，使该模板在本负载域内落成**真正可用的编译器**。

**[G-2] 定位红线（原样 · 来源 [G-2]）**：执行层 / 编译后端层（Triton-backend 类比层）之**可扩展软件栈参考模板**。"可扩展"指**栈的组织方式可复制**（能力 schema / 插件五件套 / falsifier / 选择器骨架）、**不承诺接入任意负载域**——**模板 ≠ 通用编译器**（[NG-2] 照旧，输入侧止于 kernel 级接口）。负载域仍锁 ggml/llama.cpp 型量化 LLM 推理 kernel（负载域锁不变）；覆盖率分母**永远是本负载域 kernel 清单**（[COV-1]），防止向 TVM 式端到端框架漂移。

## T-2. C1（头牌）= 模板协议本体

**[C1-1] 主张（原样 · 来源 [C1-1]）**：**一份带关系的能力 schema + 插件协议（接入五件套 [P-2]）+ falsifier 组机检 = 可复制的扩展接入协议**——同一 schema 同时驱动编译期变体生成与 fail-closed 运行期（装载期解析形态起步）调度守卫，**跨计算范式边界（向量 SIMD → 整矩阵 MAC）且跨独立家族（向量缺席的标量家族）**原封复用；零家族分支由 [F-1..F-6] 机检；接入由外部贡献者按文档可复制。这是模板的**本体贡献**：碎片化硬件生态需要的不是又一个手写库，而是"**接入成本可预期 + 正确性机检 + 选择可归因**"的栈组织方式。

**[C1-3] 证据阶梯（原样 · 来源 [C1-3]）**：家族 #1 RVV、#2 IME（跨范式，已有）→ #3 [X-SCALAR]（广度半边）→（条件）#4 AME（矩阵半边，论文不押注）。

**[C1-4] 验收（原样 · 来源 [C1-4]）**：falsifier 组 ≥3 家族下 CI 常绿；schema.def 自 IME 起未被家族接入触及（F-2′ 逐 PR 审计）；六对照面成文；（M4）外部接入实录。

## T-4. C3′ = 模板产出质量

## T-6. [G-1] 双轴组织原则（原样 · 来源 [G-1]）

- **引擎轴**——机制覆盖广、主体由机制构造、可跨家族（N-operand 统一、全 zoo 构造、资源感知选择、真硬件探测、性能击败）。
- **证据轴**——每条结构性主张机器可检验（schema 冻结哈希、归因日志、模式注册表作数据、自动成本账、覆盖率进 CI、硬件探测）。
- **裁定**：成熟度指标**进 CI，不进 slides**。引擎轴让它成为成熟编译器；证据轴让成熟度可被机器证明为论文证据。两轴并列为交付，任何一轴单跑都不构成里程碑。

> 注（标注，非改写）：引擎 / 证据两轴 与 学术贡献 / 工程面 是两条**正交**切分——引擎轴本身即含性能击败、全 zoo 构造等 C1/C3′ 的实体，不要把 C1/C2/C3′ 整体等同于证据轴。
