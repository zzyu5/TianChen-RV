# 【暂定·随论文侧更新】两柱、六律与贡献组织

> 本文件承载当前理想论文的研究表述。它已经由用户裁决取代旧的“C2=边际递减成本曲线、C3′=模式库”主叙事。
> 它仍是暂定研究表述：不能单独判定某个性能数字能否上报；性能与正确性仍服从本层其他 canon 和 measurement。

## T-1 研究问题与范围

### 研究问题

一个面向碎片化执行生态的 MLIR automatic operator-to-kernel compiler，能否在图级处理后接收语义充分但执行未定的 operator problem，让 operator/representation、hardware capability、construction family 与 artifact/runtime 的变化主要落在各自 typed owner，同时由 `g/c/ω` 条件化的 family-local 可执行专家知识构造专化、合法且具有专家级质量或竞争性能的 kernel？

### 系统类别与旗舰实现

- post-graph、pre-schedule 的 operator-to-kernel execution layer，不新增高层 tensor/tile IR；
- canonical problem 写作 `P=(S,g,ω)`；`S` 是 operator semantics，进入具名 family formula 后继续使用既有 `g/c/ω` 主公式；
- 可扩展 plugin/capability/typed construction/backend/ABI/runtime software stack；
- RISC-V ggml/llama.cpp 风格量化推理是当前旗舰 realization 与主要评价压力域，不是系统类别上界；
- GPU 是 V2 明确引入的第二 execution paradigm 目标，必须作为拥有 capability、formula、legality、typed body 与 artifact/runtime 的完整 construction family 接入；当前尚无 GPU implementation/evidence；
- dequantize-row、quantize-row、vec-dot/contraction、GEMV/GEMM、elementwise、product/reduce 等当前 operator domain；
- RVV、IME、Scalar、Offload 等当前 family 实例；
- AOT/static construction 与 offline-qualified selection。

当前不声称：

- 通用高层 tensor compiler；
- 完整模型图 compiler 或要求用户手写 schedule 的 GPU kernel DSL；
- 通用搜索式 autotuning；
- runtime sparse/MoE 自适应或 CPU/GPU 跨设备 runtime selector；
- 自动得到所有硬件上的全局最优代码；
- 普遍击败全部手写或 vendor kernel。

## T-2 两根柱

### P1 柱一：能力驱动、类型化、可复用的扩展模板

一个扩展不是因为“存在插件目录”就成立。理想模板要求：

- 新 operator/format/representation 主要进入 typed source facts 和 family-local plan；
- 新能力/板主要进入 canonical capability；
- 新 family 走插件五件套与 typed body；
- family construction 与 artifact lowering 分层，GPU 不作为 EmitC 末端分支；
- core/common 零 family-name branch；
- 新知识不要求修改旧 emitter；
- 第三方能按公开协议接入净新 extension/sub-extension；
- 接入成本保持局部且可解释，不退化成 g×c 笛卡尔积手写。

### P2 柱二：高性能知识的可执行利用

高性能知识必须成为：

- candidate/typed plan 的构造；
- legality/resource boundary；
- capability/context-conditioned prior；
- 有限合法候选中的 bounded selection；
- final typed body construction；
- mechanical realization；
- fallback、reason、provenance 与负边界。

解析公式是柱二的核心机制。qualified measurement 只能在解析层构造出的合法候选中修正排序；它不能创造 computation、扩大合法域或绕过 capability。runtime profile 当前是 future。

## T-3 贡献组织

两柱是价值命题；贡献编号用于组织论文，不新增第三根柱。

| 贡献 | 内容 | 主要验证 |
|---|---|---|
| **C1** | canonical problem + capability-driven plugin/typed-construction execution template | source/problem reuse、clean-room、Scalar/no-V、core locality、typed construction、family locality |
| **C2** | formula-centered construct–legalize–select 系统 | 公式消费 g/c/ω、legality-first、analytic prior、qualified winner、fallback、消融 |
| **C3** | cross-paradigm realization：碎片化 RISC-V 旗舰实例与 GPU 第二 execution paradigm | 当前 RISC-V 的 deployed ggml、representative strong opponent、e2e、negative boundary；未来 GPU 的 family-local construction、artifact/runtime 与真硬件证据 |

旧的 family marginal-cost ledger 仍可作为 C1 的模块化证据，但不再独占 C2，也不要求用三个不等价接入点拟合普遍递减曲线。C3 是研究目标组织；当前不能把 GPU 架构可表达性写成 GPU realization 已完成。

## T-4 公式贡献的边界

可执行公式与 selector 的工程正本见 [architecture · 变体流水线](../architecture/变体流水线.md)。

论文中应突出：

1. typed g、c 与有限静态上下文 ω；
2. 解析函数构造候选和 typed 参数；
3. legality 在 selection 之前；
4. measurement 只能修正合法候选的排序；
5. miss、stale、unqualified 或 infeasible 时回 analytic prior；
6. 空合法集进入具名 fallback 或 reject；
7. emitter 不重新决策。

公式 novelty 不是普通 argmin。当前 compiled measurement view 保存的是预先计算的 winner token，因此不得使用没有完整代价表支撑的 MemoArgmin 表述。

## T-5 六律

六律是两柱的操作不变量，不是六个平行贡献。

### 律一：变化有唯一 typed owner

- 算子语义 → source problem 中的 S；
- 格式/表示事实 → g；
- 能力/板 → c；
- 静态使用场景 → bounded ω；
- 解析知识 → family-local formula/construction；
- 可复用 execution mechanism → family-local typed mechanism/body owner；
- 经验知识 → governed measurement row；
- 执行结构 → typed body；
- artifact/runtime → family artifact owner；
- 边界 → named negative/fallback。

### 律二：机制源码无经验点；经验点只住受管数据平面

普通 mechanism、emitter 和 core control flow 不得按具体 g×c×ω 点命名赢家。经验点必须具备 schema、provenance、qualification、freshness 和 revalidation。

### 律三：和积律，并对经验点征税

维护成本应随机制、解析规则、事实轴和有限合格 measurement rows 相加增长，而不是按格式×能力×场景笛卡尔积增长。把点表从 C++ 搬进 JSON 不自动满足本律。

### 律四：理由可执行、变量充分

每个承重决定必须列出实际消费的 g/c/ω、知识类型、typed 输出、适用域、reason、fallback 和 falsifier。未消费字段不得伪装成公式输入。

### 律五：构造、合法性、选择、stamping 与 emission 单向专化

target/profile 先绑定 construction family 与 capability projection；随后 formula 构造候选，legality 限定合法域，selector 选择，typed body 承载结果，artifact lowerer 机械实现。后层不得重新解释前层决定。Family binding 不是薄 selector，也不得推迟到 emitter。

### 律六：合格的双向知识积累

win、loss、no-flip、miss、stale、correctness counterexample、compiler/HW wall 和 e2e wash 都是知识。证据应更新公式适用域、measurement key 或 boundary，而不是产生新的 format/board 特判。

## T-6 性能证据的三层角色

### deployed ggml

证明真实路由、生成、编译、调用和多路径集成。

### strong opponent

校准生成 kernel 的专家级质量，避免系统只靠对手缺席获益。

### e2e

检验 kernel 收益是否穿过 dispatch、packing、memory 和系统固定成本。

三者互补，不能互相替代。性能具体判据仍以 [测量判据](./测量判据.md)、[对手与档位](./对手与档位.md) 和 [成色与措辞](./成色与措辞.md) 为准。

## T-7 Evaluation 目标

已有资产可以复用：

- clean-room reuse-emitter 与 own-emitter；
- Scalar 物理 no-V；
- 横向 formula authority、typed quantize leaf 与可扩展 dequant mechanism construction；
- selector flip/no-flip/miss；
- deployed ggml、强对手和既有 e2e；
- 正负结果与物理墙。

项目改造后需要新增：

1. canonical source/problem `S/g/ω`、artifact-neutral family construction 与全部 current production caller 的横向 before/after；
2. catalog、production entry、dependency edge 与 semantic case 的完整覆盖；
3. fixed/default、analytic-only、analytic+qualified measurement、invalid-M 消融；
4. 重构后 correctness/deployed/flagship/e2e 回归；
5. 真实 capability transfer；
6. 在 GPU 前置横向重构完成后，以至少一个 GPU construction family 验证 source reuse、family locality、formula causality、artifact/runtime 与真硬件性能。

真实外部组织复现、三个以上成本曲线点、runtime sparse/MoE、完整 Scalar 高性能后端和普遍 vendor 胜出，只在主动扩大主张时需要。

## T-8 诚实边界

- catalog/entry completeness 不等于所有字段 analytic/c-driven，也不等于 strong reconstruction。
- typed construction 高覆盖不等于论文整体完成。
- deployed PASS 不等于击败强手调 kernel。
- kernel win 不等于 e2e win。
- measurement hit 不等于 formula 失去贡献；它只能补合法残差。
- runtime future 不得写成当前实现。
- 第二 family 协议存在不等于已达到 RVV 同等级性能成熟度。
- V2 architecture 容纳 GPU 不等于已经支持 GPU；GPU 只有在自己的 construction、typed body、artifact/runtime 与硬件证据都存在后才是 realization。
- artifact-neutral construction cutover 只关闭了 family lifecycle 被 EmitC artifact 绑定的架构债；它不等于 strong reconstruction、真实性能闭环或 GPU realization 已完成。
