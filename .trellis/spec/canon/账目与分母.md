# 账目与分母

## 一、分母

1. **单分母制**：每板分母 = 主表【非 N/A-hw ∧ 非 q1_0】全部行。Σ四档 = 分母，机算必过。头条分母冻结为全量口径；pending/挂起是格内状态、分列显示，**不逐出分母**。
2. **"PASS/已测"永不作头条**，降为派生列（已测胜率）。
3. **除 N/A-hw 与 q1_0 外不存在任何"不进头条"类别**。DEQ / quantize / product_reduce 一律计入所属档头条。
4. **每口径数字必附机打行清单工件**；禁无清单出数。
5. **任何"新口径 / 子账 / 不进头条"提议一律必问级、禁自决**——档位是行上的标签，不是开新账本的许可证。
6. **全员有对手**："无对手 / 声明例外"类别废止；ggml 标量参考兜底即对手。唯一例外 = q1_0（内部格式 · 永久域外）。
7. **两板对称法**：双板同分母同规则；板间差异**只**出现在对手档位列与成绩列。对手可得性差异一律落对手档位列，**禁以此立表或改分母**。**禁按板分裂主表**。
8. **N/A-hw（硬件缺席）**：某行能力谓词对某板的 schema 事实实例不可满足时，该板该格自动标 N/A-hw。**机判强制**（谓词 × 板实例），禁手标。N/A-hw ≠ pending ≠ 认输：不计该板任何局数与分母；该 kernel 经其余合法板列仍在全局分母。
9. **any-board 判绿口径**：跨板复刻 / 第二板转绿**永不增加头条格数**，只升成色注记。"因赢加格"违 anti-gate 精神。**板不是 engine**；板键入单元 = 复辟板×格混算，驳回。
10. **全分母声明制**：分母内每格 ∈ {certified | blocked-on-\<具名机制\> | 声明例外}，加域外名单 = 零未定义格，recon 脚本强制机算。**分母修正必须附 anti-gate 自证**（修正理由与胜负无关）。
11. **regime 结构判据**（纯结构、与胜负无关）：判据 = "该格式存在 ≥2 条结构分立的 repack lowering 路（Gemv / Gemm）"→ 命中者一律拆 decode / prefill 双 cell，**输的照拆**。全格式盲扫；分母随 roster recon 机算重出，禁手改；每笔附 anti-gate 自证（拆分依据 = 结构判据命中，非胜负）。

## 二、赛道与行键

12. **四账禁互推**：各赛道各自成立，永不互推——一格可以 kernel 赢而 e2e wash。赛道枚举 = kernel-sym（单分母四档 micro）/ perf-covered（fair-protocol ≥parity）/ certified（构造轴 byte-exact）/ e2e 系统账（传导）/ [SEL-3] 测量记忆。同理：不同框架的两套计数禁混；构造轴数字禁与 perf 轴数字混。**数字巧合（两赛道同值）不构成互推依据。**
13. **落表纪律**：一切测量 / 解析结果只回填既有主表模板与分账行，**禁在新位置另建账本或报告体系**。新指标 = 既有表加列，不是新表。过程工件（casefile、反汇编存档）可存，但**结论数只住主表**。
14. **评价对象与测量行键分开**：评价对象可按 `(算子, 格式[, 形状类])` 识别，但
    formula authority、construction strength、correctness 与 performance 各自判断，不取
    多路径中的“最高六态”互相覆盖。测量行键（性能口径）= `(算子, 格式, 路径,
    arity, 形状类) + 变体 ID + 选中方式 ∈ {mechanism-selected, forced}`。**产品级主张
    只引 mechanism-selected 行**；forced 行只用于消融科学。形状类必入键：
    `{decode-GEMV(M=1), prefill-GEMM(M 扫描), micro-fixed}`。

## 三、覆盖与构造证据

15. **[COV-1] 评价域与系统类别分开**：ggml / llama.cpp 型量化 LLM kernel 是当前
    旗舰评价 roster，不是 Weft operator compiler 的架构上界。需要报告性能覆盖时，
    roster 和测量行键继续服从本文件前述规则；不能用该 roster 反向定义 formula catalog
    或 plugin 系统范围。
16. **[COV-2] 三类事实禁止互推**：

    - formula/catalog coverage：当前 production authority、entry、decisive dependency
      与 semantic boundary 是否进入统一代码路径；
    - strong reconstruction：是否通过 delete-leaf reconstruction；
    - correctness/performance coverage：是否具备对应测试、真板和对手证据。

    旧 `C_dispatch` / `C_construct` / `C_construct+` / `C_attr` 可用于解释历史表，但不再
    是当前研发燃减、task 完成门或论文头条的预设四指标。需要新统计时从当前代码和明确
    研究问题生成，不维护手填百分比。

> 构造强度见 [构造强度、mechanism 与选择归因](./覆盖状态机与选择归因.md) [K-4]；
> 工程 formula coverage 见 [architecture · 公式层与覆盖](../architecture/公式层与覆盖.md)。
