# 构造强度、mechanism 与选择归因

本文保留既有条款 ID，但取消把旧六态、pattern registry 和 task backlog 当成全项目进度
机器。公式 authority、strong reconstruction、correctness 与 performance 是不同问题，
不得压成一个单调阶梯。

## 一、构造强度与 mechanism

本节的 weak/strong 是实现与证据的观察维度，用于防止把 authority 接线冒充为强重建；
它不修改六律原义，也不是新的论文贡献或单调进度状态机。

1. **[K-4] 构造强度分型**：

   - **unsupported/reject**：当前没有合法实现；明确 fail closed。
   - **constructed-weak**：已经由唯一 formula/construction authority 产生 final typed
     body，但算术主体仍依赖完整手写 point leaf。
   - **constructed（strong）**：删除一个完整 point leaf 后，仍能由 typed
     `g/c/ω + reusable mechanisms + family-local formula` 重建同一 typed body/plan 与
     legal domain。

   `emittable`、`dispatch-wired` 是历史排查标签，不是允许保留的 production formula
   状态；`covered`、correctness、deployed 和 performance 由各自测试/证据独立描述，
   不是比 `constructed` 更高的一格。Catalog/front-door completeness 只证明 authority
   收敛，不改变 construction strength。

2. **[PAT-1] Mechanism 是 typed、可复用的最小执行知识**：它可以由 family-local typed
   op、参数化 builder、算法模块或小型只读 registry 表达，不要求进入全局 pattern
   schema。真正新的不可约语义可以增加 mechanism；已有 mechanisms 可表达的组合不应
   继续复制完整 `format × capability × context` 程序答案。

3. **[PAT-3] 迁移性判据**：同一 mechanism/formula 在不同合法 `g/c/ω` 下通过参数和
   组合变化产生相应 typed body，而不是复制 point leaf。是否迁移成功由代码 diff、
   causal test 和必要时的 delete-leaf reconstruction 证明，不以“registry 零条目改写”
   或双板数字单独判定。

## 二、选择与归因

4. **[SEL-1] 构造后薄选择**：formula 先构造完整 candidate、typed `θ`、解析 prior 与
   legality 所需条件；legality 得到有限合法集。Selector 只执行：

   ```text
   qualified/fresh/selection-valid winner token 且 winner 仍合法 → 选它
   否则合法集非空 → analytic prior
   否则 → named fallback or reject
   ```

   当前 compiled measurement view 没有完整候选代价向量，因此不是编译期 memoized
   argmin。Measurement 不创造 candidate、不扩大合法域、不修改 `θ`。

5. **[SEL-2] Capability/context prior 必须在需要竞争时真实存在**：当两个或更多完整
   legal candidate 进入同一选择域时，miss/unqualified/stale 情况必须有 family-local
   analytic prior 或具名 fallback。不能用注册顺序、常量 cost 或第二 family 演示替代
   真实 prior；只有 singleton candidate 时直接构造，不虚构选择。

6. **[SEL-3] Measurement winner memory**：offline measurement row 使用有限 typed key，
   至少绑定 capability instance、operator/regime/必要 shape、candidate set、正确性、
   run lineage、qualification 与 freshness。编译器只消费已资格化 winner token，并在
   当前合法集内重新验证；单点 vs-opponent 结果不能自动成为 selection-valid row。

7. **[D-4] Reason/provenance 只用于解释**：`only_feasible`、`prior`、`measured` 等 reason
   可以帮助解释选择，但不是 compute、formula、measurement 资格或证据 authority。
   归因应能追到 typed inputs、candidate/legal set、winner/prior 和 final typed body；不
   要求每条生产路径写固定 JSONL、达到“100% reason 门”或建立运行期 observer。当前没有
   runtime observer 时，只能报告编译期选择事实。
