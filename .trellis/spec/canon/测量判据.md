## 二、测量纪律

4. **[PERF-2] 测量纪律**：测前跑 3 次重测-重测 sanity（同 kernel 同配置），运行间 IQR ≤ 该基准类历史噪声地板 ×1.5 → 板可用，立即开测；loadavg 与邻居进程快照**降级为记录项**（入环境指纹）；测中 IQR 突劣 ≥3× 自检值 → 该会话作废重跑。**0 样本永不造数**（宁可无数，不可编数）。非计时测量（objdump 计数、字节比对）无窗口约束。
5. **T-N 噪声地板**（一切效应判定的地基）：每板 × 每基准类跑重测-重测得运行间 IQR%；任何 Δ 须 |Δ| > 2× 噪声地板 **且** bootstrap 95%CI 不含 0。**无 T-N = 无判定资格。**
6. **环境指纹 + 配对测量**：指纹 = hash{板 / SoC、CPU、内核、libc、双方编译器与旗标、ggml 版本与构建开关（含 repack）、线程 / 亲和、governor、内存}。SOP = 固频 + 钉核 + 丢预热 + 我方 / 对手同会话 A/B 交替 + N≥10 中位数 + IQR + 降频守卫（触发作废）。
7. **格 schema 二分与 stale 律**：一切进 CI 的证据都落成两型**格**之一；**本条是这两型格与其状态枚举的权威声明**，别处（[evidence](../evidence/index.md)、`experiments/` 模板）按引用对齐，**不重定义**。
   - **测量格** = {值, 单位, 状态, 环境指纹, 快照, 工件指针, 对手指针, 配对会话}。
   - **结构证明格** = {判定 ∈ {pass, fail}, CI 日志, 快照}。

   **状态枚举（闭合）** = `{measured | stale | board-pending | open | n_a}`：

   - `measured` —— 真硬件 `ssh` 证据在案（[核心不变量](./核心不变量.md) I8），且指纹全分量与当前一致。
   - `stale` —— 曾 measured，但环境指纹任一分量（分量列表见本文件第 6 条，**不在此重列**）已变，或发生 refactor 后未重测。〔**摘编**：原条文在此重列指纹全部分量，本处改为指向第 6 条以免副本；规则内容零改。〕
   - `board-pending` —— 待硬件重测（board-pending 期间旧性能格**不得进任何文本**，[L-5]）。
   - `open` —— 未测量（原 `presumed`；含"presumed parity / presumed null"）。
   - `n_a` —— 按构造不适用。

   **三条铁律（机检，不靠自觉）：**

   1. **`open` 永不可被正文引用。** 未测量默认 = 无主张，绝不默认成功态；把 `open` 当结果登记是复发性过度乐观失败模式。
   2. **指纹变即 `stale`。** 指纹任一分量变 → 同指纹的所有格自动降 `stale`；parity/win 是"每次构建重测的目标"，不是可长期结转的银行数字。
   3. **跨会话不比。** 只有同一配对会话（我方/对手同会话 A/B 交替）内的两值可作差；跨会话的两个 `measured` 不得相减成主张。
8. **构建保真三重**（任一未满足 → 该对比判 INVALID）：
   1. **源码保真 + 派发身份保真**——在钉死的 ggml 版本 + 该板默认构建下探测每个 (算子, 格式, 形状类) 实际派发的 kernel，产映射工件；**vs-framework 测量格无探针工件 = INVALID**。
   2. **构建保真**——对手必须用板全能力 march（从 hwprobe / cpuinfo 实测生成，**不得手写残缺 march**）、同一编译器版本 + 同旗标编译，并经 objdump 验证无软浮点 libcall。
   3. **同编译器断言** = 所有 vs-opponent 计时腿的 fail-closed 前置，且测前先查对手出货编译器身份，据 [L-9] 判走 kernel 账（同工具链重建 / REFUSE）或系统账（披露 + 列最强基线）。

   执法 = harness fail-closed preflight 四道门（march 完整性 / 双侧 objdump libcall 扫描 / 同编译器断言 / 指纹-格匹配）。

## 三、账本与传导

9. **[L-9] 双账本（红线）**：每条性能主张必须标注账本。
   - **kernel 账**（源码 / 算法 / 调度质量）= 双方同编译器、同 flags、同 march、同链接。**禁止"我方 clang 编 vs 对手 shipped gcc 编"登记为 kernel win**（此类数字一律撤回）。
   - **系统账**（产品对拼）= 允许各方用各自完整出货栈，但必须披露双方编译器身份 / flags / deployed object 身份 / 集成方式 / baseline 是否 shipped-best，并尽可能列出最强基线。
   - **两账本互不替代**：kernel 账不证"真实系统收益"，系统账不证"算法更优"。
10. **[L-11] Amdahl 同域**：任何性能立项须先给传导预估（目标 kernel 相内时间占比 × 预期改善 = e2e 上限）；**上限低于噪声地板者只能以机制 / 方法学名义立项，不得以性能名义**。预估输入因子必须与目标部署**同域**（同编译器、同 deployed variant、同输入路径）——拿 micro 域因子喂部署域 = garbage-in。
11. **传导会计（micro → e2e Amdahl 四列）**：`相内时间占比% → Amdahl 预测相级Δ → 实测相级Δ → 传导效率`。**核级赢无传导列不得写"传导到 e2e"**。带宽受限内核以 parity 为零假设（**parity 是物理确认，不是失败**）。

> 传导的判别律 [DISCRIMINATOR-OPPONENT-BOUND-TYPE] 住 [部署与构造语义](./部署与构造语义.md)。

## 四、[VERIFY-LADDER] 三级验证阶梯

一切新 kernel / 新 Plan 的默认顺序，**禁跳级**；跳级上板 = 违例登记；**预算检查前置于构造**。

- **G1 静态账（零板时）**：数指令 + 静态寄存器 live set。门 = 指令数 ≤ stock 同路径 1.1×（**仅 compute / throughput-bound regime**）∧ live set ≤ vreg 预算。不过 → 打回重设计，**不上板**。
  - 精化①：绝对 spill / live-set 必须以**部署编译器**测；本地异编译器仅可做同编译器相对排序。live-set 子门判据 = 部署编译器 objdump，非任意本地编译器。
  - 精化②：instruction-count 子门**仅对 compute / throughput-bound regime 有效**；对 memory-latency-bound decode（M=1 · 停顿型 · IPC 崩非指令爆）是**错判别键**——latency-hiding 杠杆（prefetch 软流水）故意 +指令但助，会被该子门误拒。该 regime 的正确门 = register-budget-fit（live-set）单独 + 转 G2 IPC micro（instruction-count 子门豁免，判别键换 IPC / cycles）。
- **G2 同形状 cold micro**：形状类必须与目标 regime 一致（GEVM 变体测 M=1 GEVM 形，**禁用 cold-GEMM 冒充**）；冷态 = 工作集远超 cache 或逐迭代冲刷；对手 = stock 同形状路径、同会话 A/B、N≥10、T-N。**门 = ≥parity 方可获 e2e 资格**。
- **G3 e2e**：仅对 G2 过关格开放，按批量节奏（不逐格穿插）。判据 = parity 底线 + 分相披露 + [PERF-1]。
- **hot/cold 预测器规则**：仅同形状类 cold micro 方可预测对应 regime 的 e2e（cold-GEMM ↛ decode）。

12. **禁继承**：decode 一律 M=1 实测；IME 禁承 native cold；**禁串行继承任何邻格数字**。**板忙只延后【验证】不延后【施工】**（"constructed · 待板端门"是合法状态）。**预注册先于测量。**
13. **近门补充**：仅当比值落在 0.7–1.0 区间，追加一次独立复测确认；离门远的数字不为噪声举行仪式。

## 五、常驻判断规则

14. **规则一（先反汇编认瓶颈）**：修性能前先反汇编认瓶颈——放大倍数由瓶颈形状决定，未击中关键路径 = 小改善。**落败 / 对比结论在反汇编钉死前不得书面引用。**
15. **规则二（键值板测定）**：一切选择键值 **per-format 板测定**。直觉投影（"更宽 = 更快""回卷省 vsetvli""换成理想 gather 形状 = 更快"）不可信，均已被独立证伪。修法失败先查台账是否已证伪，**别重试已证伪的偏方**。
16. **快照 / 纪元**：分母清单 = 版本化工件（钉 ggml 版本）；上游新增格式 → 开新纪元、曲线断点标注；一切导出携 {repo 快照, ggml 版本, 纪元}。
17. **人工转抄数字非法**：报告引用数字 = 引用行字段 + run-id；工具能输出的数字禁止手算重述。

## 六、T-X X-SCALAR 真板 enablement 证据表（**定义 · 与 §二.5 T-N 并列**）

**T-X** 定义 [X-SCALAR] 向量缺席独立家族在真硅上的 **enablement 证据表**（正确性 / 零向量机检 / 独立见证；**enablement 域 · 无性能主张**）。它与 T-N 并列为"证据表定义"，**本节为权威定义**，别处按引用对齐、不重定义。**六列钉死**：

1. **目标身份** —— 真硅 + capability-facts，按 [architecture · 能力模型](../architecture/能力模型.md) §【定法】Target Profiles 命名 profile。X-SCALAR 目标须为**向量缺席实例**：(a) 物理 no-V 真硅，或 (b) 带 V 板**强制 `-march=rv64gc` no-V 构建+运行**的**窄豁免**（(b) **必须显式标 `narrow-exempt: V-board-run-as-noV`**）。指纹全分量含 march（须无 `v`/`zve*`）。
2. **构建** —— 精确工具链 + `-march=rv64gc -mabi=lp64d`（march 无向量扩展）+ `-ffp-contract=off`；双方编译器身份+旗标入案；内核须为 **Weft-RV emitter 产出的 owned `weft_scalar` 内核**，非 fallback 兜底桩（边界见 [architecture · 家族现状](../architecture/家族现状.md) §【定法】与向量缺席独立标量家族的边界）。
3. **零向量指令机检** —— 对产出 `.o`/`.elf` **静态 objdump**：零 RVV opcode（无 `v*`/`vset*`/`vle*`/`vse*` 等）+ 无 `__riscv_` 向量 intrinsic + 无 `weft_rvv` 符号 + 无 XOR-popcount 码本。脚本化（`check_f6_scalar_family_independence.py` emitted-C 独立分类器姊妹）。**板无关（静态）** = PASS/FAIL 结构证明格。

6. **参考路径披露** —— 披露实际走的路径（deployed variant = proven variant · 证书三要件）；披露 enablement（无性能主张）+ 若 (b) 标窄豁免；披露 [F-6] 关系（真硅证词**加强**而非**替换** committed 合成实例）。
