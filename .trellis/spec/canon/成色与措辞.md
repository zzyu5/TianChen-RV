# 成色与措辞

> 与对手档位直接绑定的成色规则（头条三口径 / 便宜档禁称硬赢 / 计数≠强赢 / 输赢同权 / 物理墙收严）住 [对手与档位](./对手与档位.md) §三，本文件不重抄。

1. **[L-1] 措辞门**：无限定的 beat / outperform **全文禁止**。性能主张必须绑定：相（prefill / decode）× 板 × 格式 × 基线 commit × 对手身份 × 门状态 × 账本（kernel / system）× 双方编译器身份 × 该板 shipped-baseline 编译器。
2. **[NG-4]**：[PERF-1] 全绿前，任何"击败"措辞不存在——禁入代码注释、文档、slides 与提交信息。落败 / 对比结论在反汇编钉死前不得书面引用。
3. **[L-6] 成熟度三重区分**（任一混同即越界主张）：
   1. **wiring ≠ construction**：kernel"能被能力调度路由到"（dispatch-wired）**不等于**其主体"由机制构造"（constructed）。
   2. **vs-naive ≠ vs-framework**：击败朴素 / 标量基线**不等于**击败框架自身同-ISA 内核（如 ggml 真 RVV `vec_dot`）。前者只作内部 sanity，**绝不**作贡献倍数（[核心不变量](./核心不变量.md) I8 / I9）。
   3. **export-lit ≠ silicon-sealed**：编译期 / lit 证据**不等于**硅上封存（每板 objdump / 反汇编 + 实测）。本地 build / lit 是工具链证据，不充硬件正确性 / 性能证据（[核心不变量](./核心不变量.md) I8）。
4. **[G-1]/[G-3] 快照纪律**：一切数字携带快照 ID；跨快照比较必须显式声明区间；**规范文档零现值**（规范源住 spec，现状与数字住报告与主表并带锚点，写作口径住研究档）。
5. **定调锁**：全项目状态 = 结构轴收口 ∧ 测量轴大面积欠账。**禁止"实质胜利 / 目标实质达成 / novelty 轴大成"类表述**——结构造得出 ≠ 性能立得住。
6. **[L-12] 性能三层图**：**L1 路径赢**（生成对手不存在的执行路径；大数字唯一来源）/ **L2 调度赢**（按实例选对变体：布局 / LMUL / tile / lane-width / schedule / 数值档）/ **L3 字节赢**（改算法结构少搬字节；常被 Amdahl 稀释）。负面清单：**指令微质量（vsetvli / spill / code size）非赛场**——但此"非赛场"仅在 kernel 账内成立，系统账内后端选择属于系统身份。**对手贴墙 parity = 满分**。
7. **域外段制度**：需真实外部世界主体、执行面内无法自足完成的事项住域外段——不入战役树、不判废、只登记为 future work。**禁以 in-house 冒充第三方**。

> 强/弱义构造措辞（[L-8]）与能力措辞两层拆分住 [部署与构造语义](./部署与构造语义.md)。
