# 能力模型与插件协议

> 能力 schema 的**字段级权威全文**住 [architecture · 能力模型](../architecture/能力模型.md)。本文件收其中构成判断依据的法条。

## 一、能力模型（S-\*）

1. **[S-1] 事实模型**：每条事实含 `id`、`kind ∈ {isa_ext, sub_ext, uarch, policy}`（**闭合枚举**）、`implies:[id]`、`conflicts:[id]`、`params`（命名空间化结构化字段）、`provenance ∈ {hwprobe, cpuinfo, vendor_table, manual}`、`trust ∈ {measured, declared}`。`kind` 新增属 schema 演进（附加式 minor），**不是运行期自由扩展**。
2. **[S-2] 关系语义**：`implies` 传递闭包**一次性物化**，查询走物化闭包，不在每次查询只查一层让调用方补链；`conflicts` 命中即 fail-closed 拒绝；**未知事实 = 假**（缺省拒绝，绝不缺省放行）。"missing status 视为 available"只在事实**已在场**时解释其 status 字段；事实根本缺席时判假。核心代码不解释具体 target-family 的 status 语义（`if (target.hasRVV())` 是错的）。〔闭包时机的两层措辞标注有残留未覆盖点，见 [待裁](./待裁.md)〕
3. **[S-3] 探针只写事实**：hwprobe / cpuinfo / 厂商表适配器只产出事实条目（带 provenance / trust），**绝不携带路由 / 选择决策**。任何"探到 X 就走 Y"属违规（把隐藏分支重新引入探针层）。探针也**不得伪造** SEW / LMUL / tail-mask 这类 plugin-selected 编译期 config。
4. **[S-5] `schema.def` 是声明工件**（可规范序列化、可哈希），shape **恰含六项、不多不少**：① 事实记录字段与类型（含 subclass、provenance / trust 枚举）② `kind` 闭合枚举 ③ 关系类型表（implies / conflicts 及语义标注）④ `params` 命名空间声明 ⑤ 插件接口签名的可序列化形态 ⑥ 路由描述符操作数角色词表。**不入 shape**（改它们不触 `schema.def`）：具体事实行、`params` 取值、插件内部代码、测量库、模式注册表条目。**schema 只答"能不能 / 是什么"，不内置成本模型**（成本住测量库，按 instance-hash 键控）。
   > 六项的**字段级细节**声明一次，以 [architecture · 能力模型](../architecture/能力模型.md) 的 [S-5] 为准；本处为不变量摘要，**勿在两处重写字段列表**以免漂移。
5. **[S-6] 两级门**：**[F-2′] 操作门（逐 PR）** = 家族接入 PR 系列 diff ∩ `schema.def` = ∅；**报告门（逐版本）** = 规范化序列化（排序 JSON）→ SHA256 + RFC 版本日志；附加式演进（新增可选字段 / 新 kind / 新关系型）记 minor 并标注 "extension not modification"。论文主张的精确形态 = "**自第二家族接入起，没有任何家族接入曾【要求】修改 shape**"（逐 PR 可审计）。
6. **[S-8] 家族语义**：家族 = **能力声明 + 所有权边界**，不是指令密度。允许"**能力门家族**"——其 owned 内核主体用基础指令，家族事实充当门与可选加速子事实。子事实粒度对称成立。
7. **[NG-3] per-dispatch 强制检查永禁**：装载期最小解析消费显式 schema 事实实例、算出 declared-instance-hash、落一条解析记录即止（**热路径零逐次检查**）。per-dispatch 强制 = 破零分支（[核心不变量](./核心不变量.md) I3）与 fail-closed 自足门（I7）。

## 二、插件、家族与扩展（F-\* / P-\* / X-\*）

8. **[F-1] 零分支**（C1/N2 头牌证据门）：零核心分支不变量（[核心不变量](./核心不变量.md) I3）由 CI 门机检。**本条是其 manifest 形态与判读规程的权威声明**；每家族的具体正则表与白名单条目住 manifest 工件（指针 → [evidence · 三贡献证据地图](../evidence/三贡献证据地图.md) §2.2），**不住 spec**。
   - **family-regex manifest** —— 版本化表文件，每家族登记其名字 / 助记符正则（如 `rvv`、`ime`/`vmadot`、`scalar.zbb`）。falsifier 对**核心目录**（`lib/Dialect`、`lib/Support`、`lib/Transforms` 等 plugin 外的核心）grep 这些正则；白名单只含**表/数据文件**（如 monolithic op table、schedule descriptor registry）。manifest / 白名单变更走 **RFC 标记的 commit**。
   - **判读规程（真分支 vs 同名假阳性，命中即需裁决）**：一处命中判 **RED（真分支违规）** 当且仅当它是**核心里按家族名做的控制流 / 派发决策**（if/switch/StringSwitch/starts_with 键控 family）。以下为**声明式假阳性类**（manifest 逐条 allow，不判 RED）：
     1. **数据/表文件里的字符串字面量**（family 名作表数据，非分支）；
     2. **身份比较**（如 `candidate.origin == selectedRoute.originPlugin`，按 origin 相等而非按 family 名分支）；
     3. **op 属性名 / 类型助记符里含 family 子串**（如 `target_kind` / `region_kind`、类型助记符 `weft_rvv.*` / `!rvv...`）—— 是**命名不是决策**。
   - **allow-list 精确到 (文件 glob, 正则)**；新假阳性须**显式登记**方可豁免，**不得放宽全局正则**。**命中不在 allow-list = RED。**

   〔**摘编**：原条文末句把"详细每家族正则表 + 白名单文件清单"归为 `E3 pillar 交付物`，并把具体条目权威指向 `docs/科研目标总纲 [F-1]`。按本树「只写现行法」+「`docs/` 归档后不可达」摘掉该 pillar 编号与 `docs/` 指向，改为指向仓内 manifest 工件（经 evidence 层）；**判读规程与 manifest 形态的规则内容逐字零改**。〕
9. **[F-3] 变更收容**：接入 PR 仅触及 `plugins/<family>/` + 表格行 + 文档。
10. **[F-5] fail-closed 模糊测试**：随机删除 / 伪造事实实例下，非法 plan **全部被拒**（非误编译 / 误发射）。
11. **[F-6] 独立家族判据**：声称 independent 的家族，其全部变体的能力谓词 `implies` 传递闭包 ∩ `{rvv.*}` = ∅（脚本化机检）；且存在**向量缺席实例**使其变体 `only_feasible` 并被真实选中。术语用 `independent-attached`，不与 `integrated`（复用向量寄存器堆）混用。[F-6] 的"向量缺席实例"是**能力 schema 实例**（不需要板），与真硅 `rv64gc` 目标同名不同物，**不得互相顶替**。
12. **[P-1..P-4] 插件协议**：`ExtensionPlugin` 为准 ABI，改动需 RFC；**插件不得改核心目录任何文件**。**接入五件套**（一个家族 = 一个 PR 系列，缺一不收）：① 事实 + 关系表行 ② 合法性谓词 ③ 发射模式（或声明复用）④ 测试（lit 字节精确 + 每板 objdump golden）⑤ ledger 条目。接入验收 = **falsifier 组全绿**。外部可接入 = 接入文档完整到"**非核心作者仅凭文档可完成一次家族接入**"。
13. **Family 准入边界**：一个 family 正当进入 ⟺ 其能力可表达为 RISC-V capability 事实，并被同一 core / common pass **零-core-branch** 地消费——判据落在 capability 模型本身的复用，**不在 pipeline 形状的复用**。正当：RVV、IME、RVV0.7 / zve 变体、厂商 RISC-V 矩阵 / DSP 自定义扩展。**明确排除**：独立非-RISC-V 离散加速卡（GPU / TPU / PCIe 设备）——塞进来即背离 RISC-V-centric 设计中心，novelty 稀释成"又一个 MLIR 后端框架"。offload / 厂商加速的判据 = 是否挂在 RISC-V 核上、经 RISC-V 扩展 / 能力暴露。
14. **[X-0] 接入三问**：见 [缺口与认输](./缺口与认输.md) [X-0]（本文件不重抄）。
