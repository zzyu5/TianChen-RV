### ISSUE-031 · F-7 决策住址门判据未定（C9 blocked）
- **实质**：两种判据给出**相反**的重构指令。判据甲「format 名是否进入 if / 三目条件式」：IME 评分 = 0 个 format 决策（机算 `grep -c` = 0），但 wide-tiling legal-decline 决策确实存在（表驱动 + 名字无关比较）⟹ 表化 = 语法层合法规避、决策原封不动；且该判据奖励把七路 if/else 链降为 constexpr 表来刷门 = 门反向激励。判据乙「format 名是否出现在 emitter 翻译单元（含表初始化器）」：IME 表与「降表方案」双双违规，则「板测 registry 该住哪」必须先有答案（= ISSUE-037，尚未定案）。
  **两条决定性新证据（强支持判据丙 = 语义级）**：
  - **(a) 判据甲会给 `lib/Conversion/RVV/RVVToEmitCGridCodebook.cpp` 发满分，而该 TU 恰是重灾区**：该 TU 内 format 名 **23 次全是表符号、零次进条件式** ⟹ 判据甲评分 = 满分；但该 TU **4/5 格式把向量宽度焊死在发射器内，其中 2 格是【假旋钮】**（`coreLmul` 只喂 intrinsic 名、vtype 是**字面量** ⟹ 设 m2 会发出**类型不匹配的 C**）。⟹ **决策以「无条件字面量」的形态存在，根本没有分支可 grep** = **全新的假阴性形态**（判据甲/乙都只看 format 名的语法位置，而这里 format 名清白、犯事的是宽度字面量）⟹ 语法级判据（甲/乙）结构上抓不住它，**强支持判据丙（语义级）**。
  - **(b) `.value_or` 计数不可做 per-TU 门**：GridCodebook 该项 = 0（`grep -c 'value_or' lib/Conversion/RVV/RVVToEmitCGridCodebook.cpp` 实测 = 0）看似完美，实则 self-default **被搬到上游 TU 当参数递进来** ⟹ **按 TU 切文件即可刷绿此门** = 该门对「决策住哪」零分辨力。⟹ `.value_or` 计数只可作**跨 TU 全域**指标，**禁**作 per-TU 门。

- **影响面**：C9 全节 + 主发射器重构方向。
- **卡在**：判据 = canon 级新红线。
- **保守默认**：草案只落目标态 + 三条待裁项、不落可执行判据；C9 节点保持在树内、状态 = blocked。建议执行序 ISSUE-037 → ISSUE-031，且去重先于上门。
- **状态**：待裁
