# 决策权限卡

本文件帮助 GPT 或开发者在不转嫁普通实现决策的前提下，守住用户范围、安全边界和重大设计选择。

## 一、用户范围优先

最新用户指令定义当前任务范围。

- 后来的明确指令可以替代旧 task、goal、简报或历史战役。
- task 与 issue 不产生额外授权。
- spec 提供稳定边界，但用户可以明确裁决并版本化修改 spec。
- 若代码事实与旧文档冲突，先核实代码事实，再修文档；不得要求现实迎合旧文档。

## 二、可自主执行

在用户范围内，以下通常可以直接推进：

- 只读检查和可复跑诊断；
- 局部、可逆的实现与重构；
- 必要的测试、格式化和文档同步；
- 修正与唯一现存事实不一致的说明；
- 精确暂存和提交用户要求的改动；
- 为明确接口补测试、负控和 fail-closed；
- 在既定设计内选择具体实现细节。

执行后报告关键判断、验证结果和剩余风险即可。

## 三、必须请求用户决定

出现下列情况且没有明确用户授权时，应停止相关分支并请求方向：

- 会改变两柱、六律、论文核心主张或公开兼容性；
- 存在两个会实质改变结果的设计方向，当前上下文无法判断用户偏好；
- 需要不可逆删除、重写历史基线或覆盖 sealed 证据；
- 需要购买、发布、向外部组织发送信息或修改外部系统；
- 需要显著扩大当前任务范围；
- 与用户未提交改动发生无法安全绕开的冲突。

可以继续处理不依赖该选择的独立工作，但不得用“保守默认”偷偷完成那个重大选择。

## 四、禁止事项

- 不得把旧 task 当作强制用户继续某条战役的授权。
- 不得因为“队列还有项目”自动扩大当前请求。
- 不得编造事实、性能数字、硬件证据或外部复现。
- 不得让 metadata、报告或 task 状态覆盖代码和实验事实。
- 不得为避免询问而执行破坏性、外部或不可逆动作。
- 不得用无限流程、禁停规则或仪式性 closeout 代替完成用户当前目标。

## 五、合理假设

允许作出帮助推进的局部假设，条件是：

- 可逆；
- 不改变用户目标；
- 不扩张权限；
- 能由代码、测试或现有约定支持；
- 在结果中明确说明重要假设。

如果假设会改变架构、实验问题或论文主张，就不再属于局部假设。

## 六、task 与 issue

- task：可选计划与恢复上下文载体。
- issue：稳定的问题编号与边界记录。
- spec：稳定契约。
- code/tests：实现事实。
- experiments/master 与 runs：测量事实。

四者职责不同，不能互相代替。没有 task 不等于不能施工；没有 issue 也不等于不能修一个已被用户明确要求且范围清楚的问题。

## 七、完成与停止

当前请求完成、验证完成且没有安全的范围内必要工作时，应交付结果。无需为了保持“队列非空”继续生成任务。

遇到真正阻塞时：

1. 说明已确认的事实；
2. 说明阻塞需要什么新选择或权限；
3. 停止受阻分支；
4. 不伪造完成，也不无限循环。
