# 决策权限卡 · 延后裁决制

新 agent 判断「这件事我能不能自己做」的唯一依据。四类穷尽：**自决直行 / 必问 / 禁停 / 灰区**。
**权限卡条目数 = 20**（**判据级/文书级判别式 1** · 自决直行 8 · 必问 5 · 禁停 3 · 检查点 1 · 灰区 2）。

---

## 〇、★判据级 / 文书级 判别式（先过这一关，再查下面的四类）

修 spec、修登记簿、修任何「对不上实况」的东西之前，先问**这一个问题**：

> ### **修复它，需不需要先回答「哪种算对」？**
>
> - **需要** ⟹ **判据级 · 停** —— 登记 + 保守默认续推，**由用户裁**。
> - **不需要**（修复只是**对齐一个已存在的唯一事实**）⟹ **文书级 · 改 + 报备一行**。

**这条判别式取代一切「路径/文件名/字段名 = 文书级」式的枚举。**
枚举会骗人：**同一个字段名，改它可能是文书级，也可能是判据级** —— 取决于「对的那个值」是否唯一且已存在。

### 判例（每条都是真事故，**不是假想**）

| 事项 | 判别 | 为什么 |
|---|---|---|
| 主表行键写成 `(op,format,engine)` | **文书级** | 唯一事实**已存在且可机验**：三元组切 90 组 / 108 行 = 不唯一；四元组 108/108 = 唯一。**没有"哪种算对"可问** |
| 文档指针指向已归档路径 | **文书级** | 新住址唯一且存在，机器可验存活性 |
| `[PERF-1]` 称「八门」而门体实有十项 | **文书级** | **数门体本身**即得唯一答案（八 = v2 期化石，v3 增补 ⑨⑩ 后失效） |
| **`判定` 字段的值域** | **★判据级 · 停** | **「`PASS(decode-M1-GEVM)` 是独立值，还是 `PASS` 加了个括注？」——这个问题必须先有答案**，而它没有。**括注是判定谱系，不是噪音**（用户裁）。选任一读法 = 替用户做判定 |
| harness 该住哪 | **★判据级 · 停** | 门只裁**负向**（禁数据格）；`tools/bench/cells/` 与 `tools/e2e-harness/` **同样过门** ⟹ 门不选址。写死任一 = 替用户否决其余活选项 |
| 行 schema **缺**字段 | **★判据级 · 停** | **缺字段 ≠ 写错字段**。「该补什么字段」需先答，不是对齐既有事实 |

### ★本判别式的来历（教训压缩成规则本身）

一次施工里，主会话把三洞全判「文书级」并授权照改；施工线**三条全判「须停」并拒绝执行** —— **施工线全对**。
其中最锋利的一次自败：主会话在**同一条指令里**写下

> 「禁自行归并/改名/精简（那就是改判据）· **原样记录**」

而它给出的所谓「机算实况值域」**本身就是归并后的产物** —— 一句 `.split('(')[0]`
把 `PASS(decode-M1-GEVM)`(18) 并进了 `PASS`，raw distinct **12** 被压成 **8**。
**⟹ 归并动作可以完全无意识地混进"机算"里，然后戴着"实况"的帽子出场。**

**★而那句 `.split` 不在任何仓内脚本里** —— 它是**一条 shell 命令 heredoc 里现写的一次性 python**：
**不落盘 · 不进版本 · 不留痕 · 跑完即蒸发**。
⟹ **「机算」的可信度 = 那段提取代码的【可复核性】，不是"用了机器"这件事。
即席代码是可复核性最低的形态。** 凡「机算」类断言进交付物 → **必须连提取代码一起给**。

由此立**通用法**（见 [measurement · 流水线与行 schema](../measurement/流水线与行schema.md)）：

> **值域登记只许机算枚举，禁任何预处理归并；归并即判据，判据即裁。**

## 一、权限卡

### 1.1 自决直行（8 条 · 不问 · 做完日志记一行：决定 + 依据 + 可逆性）

1. **已立项战役内的里程碑推进与排序**——立项即授权全程，除非触碰 §1.2。
2. **队列内工作的执行细节 / 测量 / 入表 / triage 归类**。
3. **预注册判读的执行**——判据已写，结果落地照判照走（含「成功 → 自动进下一步」类条款）。
4. **公开可得、仅为复现/测量所需的模型与数据获取**——自行下载 + 校验 + 登记。仅当付费 / 许可证存疑 / 占用 > 板剩余 1/3 才升级为必问。
5. **可逆工程决策**——分支 / worktree / build 配置 / 测试增补。
6. **两条已立项线之间的资源微调**——以触碰集 diff 为证。
7. **预注册判读的【全部后续动作】**——判据满足即直接执行预注册的结果动作（登记 / 升格 / 翻正 / 降级 / 进下一里程碑），事后报备一行，**不回门**。
8. **措辞预注册制**——凡预注册判读涉登记/升格类，写判读时必同时预注册措辞模板（留数字空位）；结果落地填数即用，**措辞不再构成回门理由**。仅模板空缺处标待裁，且只问空缺、不问整体去向。

> **禁止**：把自决直行类事项包装成选择题或「必问」回门 = 转嫁决策，不是谨慎。

### 1.2 必问（5 条 · 登记后按 §二 续推 · **不阻塞**）

1. **新战役 / 新立项**——**仅指队列【外】的全新战役**。既定裁决的执行 / 合并 / 分批 / 里程碑推进 = 自决直行，**非必问**。
2. **canon / 红线级变更**——改定义、改红线、改既有条文。**按预注册模板填数登记【不是】canon 级**（走 §1.1 条 7/8 自决）。
3. **不可逆动作**——删 sealed 证据 / 改历史基线 / 覆盖 Win 登记 / 上游 pin bump。
4. **停机规则触发后的去向**。〔本仓无「停机规则」的 canon 定义站点；现行 = 保守默认：按 §1.3 与 §二 处理——登记 + 保守默认续推，**不停轮**；唯一停轮口子仍只有 [用户检查点](./队列与简报.md#五用户检查点禁停机制的唯一豁免)。待裁项在 [issues](../issues/index.md)。〕
5. **花钱 / 许可证存疑 / 板硬件之外的外部世界动作**。

> **「必问」= 必须登记 + 必须由用户裁定，【不等于】停下等待。** 处置见 §二。

### 1.3 禁停机制

**3 条 · [GOV-6]。**

1. **「会话已长 / 完成了一个里程碑 / 上下文将压缩 / 用户未回复 / 想等用户审视」——永不构成暂停或回门理由。** 里程碑的正确动作 = **报备一行 + 读队列快照 + 续队首**（[队列与简报](./队列与简报.md#四简报快照格式)）。
2. **队列永远非空**（队列 = 测量欠账表 + 排队项）。若真为空，正确动作 = 列出剩余项**请求排序**，而非提议暂停。
3. **「暂停 / 等你审视」永不作为选项出现在任何裁决请求中。**

> 上下文压缩后的恢复动作 = 读队列快照 + 读本权限卡 + 续队首，**不请示**。禁止压缩后「重新发明项目世界」。

### 1.4 用户检查点

**1 条 · 禁停机制的唯一豁免。**

1. **检查点由用户预先指定，agent 不得自 declare。** 到达用户指定检查点时「报告交付即 idle 等裁决」= **合法，非违例**。检查点清单随战役定义住队列节点，**不住 spec**——见 [队列与简报](./队列与简报.md#五用户检查点禁停机制的唯一豁免)。

### 1.5 灰区（2 条）

1. **不确定属哪类** → 选可逆路径先行 + 标记决策点入日志 + 继续，**不 idle 等待**。用户回归批量追认或翻案。
2. **存疑倾向于「可逆 + 登记 + 续推」**，不倾向于「停下问」。

## 二、延后裁决制

**核心：必问级事项不阻塞。**

### 2.1 流程（四步 · 不可省）

1. **登记**入 [issues](../issues/index.md)：{编号 · 问题 · 选项 · agent 建议 · 采用的保守默认 · 状态}。
2. **采保守默认**（§2.2 铁线之内）。
3. **继续推进**——按队列续队首。
4. **用户回归一次清账**——逐条裁定，追认或翻案。

> **禁以「等待裁决 / 请确认 / 待用户拍板」为由停轮。** 登记本身即是履行必问义务；停轮不是。

### 2.2 保守默认铁线（6 条 · 保守默认只能在此线内取值）

1. **不扩分母**。
2. **不改 canon / `$meta` 措辞**。
3. **不增头条口径**（不新开账本、不新开子账）。
4. **不动队列排序**。
5. **不采购**——板 / 硬件 / 付费资源 / 许可证一律不购；需求只登记。
6. **争议格标 `pending`，而非强判**——预判（「某板上限 X」/「约 N 格认输」）**只用于排序，不写状态、不作认输依据、不作结论**。

### 2.3 硬冻结四类（保守默认也不许碰 · 只登记不执行）

**四类的条文本体见 [canon](../canon/index.md) §十四「硬冻结四类」，本层不重抄**——需要知道「哪四类」时点链接过去，不要在本层找副本。

治理侧效力（本层只定这一条）：命中硬冻结的事项 → **登记 + 不执行 + 续推其余**，**不是停轮**。

> **住址分工**：「哪四类被冻结」= canon 问题，住 [canon](../canon/index.md) §十四；「命中了怎么办 / 保守默认取什么值」= 治理问题，住本文件 §2.2 + 本节。

### 2.4 登记条目状态枚举（7 值）

| 状态 | 含义 |
|---|---|
| `OPEN` | 待用户裁 |
| `RESOLVED-BY-RULING` | 已被后续裁决解决 |
| `APPLIED-DEFAULT` | 已按保守默认推进，待追认 |
| `RESOLVED` | 已裁定案 |
| `RESOLVED-AFFIRMED` | 用户追认保守默认 |
| `APPROVED-PENDING-RECON` | 已批准，待 recon 归位 |
| `移交` | 转下游队列 / 主会话执行（非未决，有明确去向） |

**延后裁决登记 = [issues](../issues/index.md) 的一类条目**（带上表 schema 与状态枚举），**不另立第二登记册**——依「ISSUES = 唯一问题登记簿」。〔登记册单一性与本表 schema 的关系待裁项在 [issues](../issues/index.md)；现行 = 上述保守默认。若裁定需独立登记册，则「唯一登记簿」措辞须同步放宽。〕
