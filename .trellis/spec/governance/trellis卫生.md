# Trellis 卫生纪律

spec / 任务 / 报告 / 数据各住哪、怎么维护、什么算僵尸。

---

## 一、spec = 活文档

- **只许原地更新 + 版本号递增，禁副本。**
- **版本号载体 = 层 index 文件头 `> **版本**: vN`。** 每次用户裁决落地导致条文变更 → 版本号 +1。
- **禁副本**：一份规则只有一个住址；别的层需要它 → **相对链接引用，不重抄**。发现两处写同一条 = 缺陷，合并留一。
  - 逐字正确的副本**仍是缺陷**——两处会各自漂移，最终各自宣称自己是权威。
- **跨文件引用禁行号**：只用**相对链接 + 标题锚**或**条目编号**（`ISSUE-NNN` / `[GOV-N]` / `[K-N]` / `I2`）。被引文件一改行号，行号引用就腐坏成**假引文**——它仍指得动、但指向了别的条文，比断链更危险。
- **spec 只写现行法**：零历史叙事、零编号考古、零「某年某月某人裁定」。**教训压缩成规则本身**——规则为什么长这样，不必写；写了就成了考古层。
- **spec 不写现值**（[GOV-1]）：当前数字 / 节点清单 / 状态一律住报告 + 主表 + 任务树，spec 只放指针。

## 二、完结节点归档，禁僵尸节点

- 任务目录：`.trellis/tasks/{MM-DD-name}/`，含 `prd.md` / `implement.jsonl` / `check.jsonl` / `task.json`，可选 `research/` / `info.md`。
- 生命周期：`create` → `start`（写 `.trellis/.current-task`）→ `finish`（清 current）→ `archive`（移入 `archive/{year-month}/`）。
- **完结即归档**，不留在 active 列表冒充在飞。
- **权威子命令表与 `task.json.status` 合法取值 = `python3 ./.trellis/scripts/task.py --help`**，不是任何文档里的清单——[GOV-1] 规范源本体不写现值，**本层一律不抄该枚举**（抄了就会漂）。

## 三、一切测量/施工必须挂任务且预注册范围

- 无任务 = 不许开测、不许施工。
- **强制建 task 的触发词**（不得自我豁免）：重构 / 抽成 / 独立 / 分发 / 拆出来 / 搞一个 / 做成 / 接入 / 集成 / refactor / rewrite / extract / productize / publish / build X / design Y。
- **免 task 仅当三条全满足**：(a) 本轮零文件写入 (b) 答案一条回复装得下、无多轮计划 (c) 除读 1-2 个仓库文件外零研究。**存疑一律建 task**——过度建 task 便宜；建少了会把计划与研究漏进主上下文。
- 预注册的**实体规则**（预注册先于测量、预注册什么）见 [measurement](../measurement/index.md)；本层只管治理位：**预注册必须挂在任务上**。
- **预注册载体 = 该任务 `prd.md` 的【预注册】节**，不新开独立 prereg 文件序列（依 §四 不另开序列同精神）。
  〔`task.py` 无 prereg 子命令，预注册无工具位；现行 = 上述保守默认。载体（prd.md 字段 / task 目录独立文件 / 由 spec 引用的仓库路径）待裁项在 [issues](../issues/index.md)。〕

## 四、报告 = 任务交付物附件

- 报告是**任务的交付物附件**，随任务住 `.trellis/tasks/<task>/`，**不再另开报告文件序列**。
- **禁止在 `docs/` 下新建任何治理/知识文件。**
- 报告**只引编号与字段**：问题引 [issues](../issues/index.md) 编号；数字引主表行字段 + run-id。

## 五、代码与数据的边界

- 代码、测试、测量数据与工件（主表、rowclue、SEALED 登记、runner/oracle/gates 脚本、证据产物）**留在仓库**。spec 引用其路径，**不搬运其内容**。
- **★ 留仓判据 = 可达性根集合成员，【不是】「被脚本消费」**（2026-07-17 用户裁 · 理由置换）。
  「被脚本消费的数据」曾被写作留仓理由，**但它对若干件是假的**：**SEALED 登记零脚本消费**（谓词 `grep -rln SEALED-WIN-REGISTRY tools/ .trellis/scripts/ schema/` = **零命中**；曾唯一与之接触的 `check_docs_canon.py` 只做文件名命名豁免、不读内容，且已入 attic）。
  **正确判据**：**根集合**（六 spec ∪ `experiments/master` ∪ **SEALED 登记** ∪ 现役 runner/oracle/gates ∪ ISSUES ∪ 现役测试套件）**成员本身 = 根，永不入 attic**；**从根可达者留下并标注来源**；**从根引用不到者一律入 attic**。
  ⟹ 引用留仓理由时**禁再抄「被脚本消费」**——它是**充分非必要**，且已有反例。
- **可寻址性铁线**：spec / 登记条目引用的锚点必须对**克隆本仓者**可达。仓库内实体（`lib/` · `schema/` · `tools/` · `experiments/` · `test/` · `.trellis/`，**含 `.trellis/事故档案/`**）是合法锚点；**`_attic/` 是 git-ignored，克隆者拿不到**——它与 `docs/` 归档一样**不是合法锚点**。

## 六、归档纪律（2026-07-17 用户裁追认入册）

### 6.1 三分处置法（归档一棵树时）

按序问三问，**不许凭体裁直觉**：
1. **是根、或从根可达吗**（§五 根集合）→ **留仓**，并标注来源。
2. **是事故档案吗**（§6.2 四条判据）→ **迁 [`.trellis/事故档案/`](../../事故档案/README.md)**，**原样·不去重·不改写**。
3. 其余 → **`_attic/` 按原路径结构移入**（**plain `mv`，禁 `git mv`** —— `git mv` 会让 attic 文件**仍被跟踪**，`.gitignore` 只管未跟踪文件；完事验 `git ls-files _attic` = 1）。

**顺序铁律：先核引用（全仓，非只扫 spec）→ 先迁内容 → 再归档。** 顺序反了会砸东西：先 stub 源文件才发现权威还在里面 / 只扫 spec 漏掉 `schema/`·`tools/`·`lib/`·`include/`·`test/` 的反向指针。
**折行指针陷阱**：注释里的路径可能**跨两行折断**，单行 `grep` 匹不到 —— 判「无引用」前须考虑折行。

### 6.2 事故档案：判据与选址

**判据 = 四条全中**（缺一即非）：
1. **自指** —— 出错的是**我方**（主张 / 诊断 / 数字 / 流程）。★**关于世界的假说被实测证伪 = 正常科学，不是事故。**
2. **翻转** —— 有明确 before→after：曾被相信的我方主张被**撤回 / 推翻 / 改判 / 纠正**。
3. **防复发残留** —— 给出了将来能抓住同类错误的**规则 / 判别键 / 机制**。
4. **★ 体裁测试** —— **文档的主题即「我方的错」本身**：去掉事故内容后该文**失去存在理由**。

**第 4 条是必需的收窄**：本项目的反错文化使「证伪 / 反面教材 / 空心 / 打脸 / 前科」**遍布全树**，**引用教条 ≠ 自己出了事故**。故 **法条 / 模板 / 台账 / 索引 / 地图 / 登记册 / 绿格登记 / 队列流水账**即便**内嵌**教训也**不收** —— 它们的教训按 §一「教训压缩成规则本身」**已进 canon**，本体随树归档。**banner 型**（翻转仅由事后追加的订正 banner 承载、非本文调查所得）**亦不收**。

**选址 = `.trellis/事故档案/`，与 `spec/` 并列，【不进】`spec/`**。三条理由：
- §一「spec 只写现行法·零历史叙事·零编号考古」—— 事故档案本体**就是**编号考古，且要求**原样不改写** ⟹ 进 `spec/` 即违宪。
- 六 spec「只增内容不增份数」—— `spec/` 下开第七目录 = 增份数。
- 归档令原文说的是「**Trellis** 事故区」，非「spec 事故区」。

**分工（勿混）**：**规则**住 canon / governance（压缩后的现行法）· **案卷**住事故区（规则背后那起具体的错）· **问题**住 [issues](../issues/index.md)。事故区**不是**问题登记簿、**不产生**法条、**不得**被引为现行法。

### 6.3 门退役原则（★ 立此存照）

**凡守护对象已不存在的门，一律退役 —— 不许改造续命。旧世界的检查不迁入新世界。**

- **判别式**：先问「**这门守的那个东西还在不在**」，**再**问「它绿不绿」。
- 守护对象已被新法废除 ⟹ **改锚 / 改判据 / fail-closed 化 全部禁止**。那是给尸体续命，会把**已绝育的病种**伪装成活的防线。
- **别把理由搞反**：「它会变空心绿」**不是**退役理由（那会诱人去改成 fail-closed = 续命）；「**它守的东西已经不存在**」才是。
- **退役 = 移除代码与调用**（原址留墓碑注释）+ **ATTIC_INDEX 记一行死因** + **负控实证**（已退役旗标须**报错而非静默绿**）。
- **判例**：`emit_maturity_numbers.py --drift`（死因「数字只活在主表行 + run-id，地图漂移病种已绝育」）· `check_docs_canon.py`（死因「同一主张换词即过门 = 量的是措辞不是事实」）。均住 [`_attic/ATTIC_INDEX.md`](../../../_attic/ATTIC_INDEX.md)。

### 6.4 已归档件的判读

- **`_attic/` 不是合法锚点**（§五 可达性铁线）：**禁**把 spec / 登记条目的权威锚指进 `_attic/`。
- 但**指向 `_attic/` 的 provenance 注记是【对】的、非死指针**（它诚实记「此物已归档于此」）—— 判「死指针」时**须区分权威锚与出处注**。
- **已归档件内部的自述指针刻意不改**（原样纪律）：判读法 = 该名若在事故区即读事故区，否则读 `_attic/` 同路径。
- **「先前即悬空、非本次归档所致」者不在触碰集** —— 修它属另案，**点名登记、不吞**；判定须**对快照复跑谓词**（`git cat-file -e <snapshot>:<path>`），不靠记忆。
