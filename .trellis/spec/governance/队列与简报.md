# 队列与简报

队列纪律 · 并行纪律 · 简报快照格式 · 用户检查点制度。

队列**内容**（节点清单与顺序）住 Trellis task 树，**不住本层**——[GOV-1] 单一权威：规范源本体不写现值（见 [治理通则](./治理通则.md)）。

---

## 一、队列权威制

- **Trellis task 树 = 唯一队列权威**。根 = 母 program 节点；每子节点 = 一个队列节点。
- 子节点身份写在 `task.json.description` **首行**，格式 `ROADMAP=<战役>/<节点ID>`。母 program 为根节点，**不带**该标记。
  〔首行标记的字面前缀保持 `ROADMAP=` 不改——改名触 [GOV-9] 命名冻结且无功能收益。现行 = 该保守默认；待裁项在 [issues](../issues/index.md)。〕
- **队列排序仅用户可变更**（硬冻结 · agent 只登记不执行）。
- **节点 ID 沿用用户令文原编号，不另造编号体系**（[GOV-9] 命名冻结）。

> **队列 ≠ 工作台。** 问题登记簿是 [issues](../issues/index.md)（回答「有哪些问题、卡在哪、状态是什么」），队列是 Trellis 任务树（回答「下一步做哪个节点」）。用 issues 当队列推进 = 违例：产出会退化成「登记条目」而不是「节点 X → Y」。

## 二、树定格

- **除用户裁决外禁增删节点**；**顺序即优先级**。
- 队列迁移时**只许原样搬运**节点及其顺序，**agent 重排 = 违例**。
- 唯一标尺（选什么、不选什么）见 [思维准则 §一 主干纪律](./思维准则.md#一主干纪律)，本文件不重抄。治理侧只补一条：**队列顺序已由用户裁定的，标尺不构成重排理由**——标尺用于「同优先级内怎么选」与「新提案该不该立」，**不用于翻队列**。

## 三、并行纪律 [GOV-7]

- **能并行的一律并行**：每轮先做**触碰集 diff**，不相交即同跑。
- **N=1 必须附串行理由**——无理由的单线 = 违例。
- **触碰集相交的线必须串行**：共享文件（ODS / verifier / emitter 天然跨线共享）的改动先 verify + commit 线①，再起线②。**worktree 不构成隔离**——子代理可用绝对路径直写主树。
- **工程债 = 与主线并行的卫生工作**。凡提议「X 完成后才回主线」，必须附「X 如何具体阻塞主线」的证据，否则默认并行。
- **板批打包制**：需上板的小项合并进主线板批捎带，**禁为单项独占板窗**；板时冲突一律归性能主线。

## 四、简报快照格式

**每份简报第一节 = 队列快照。缺此节 = 简报不合格。**

```
## 一、队列快照（缺此节 = 简报不合格）
**头条三数**：perf-covered <n>/<N> · certified <n>/<N> · 测量欠账表剩余 <n> 行
**黄格分类**：黄-未接线 <n> · 黄-传导稀释 <n> · 黄-物理墙 <n> · 黄-对手更强 <n> · 声明例外 <n>（零未定义格视角）
**当前坐标**：<战役 / 节点 ID>
**在飞**：<节点 ID + 一句话状态>
**队首三项**：① <ID> ② <ID> ③ <ID>
**并行度**：N=<n> · 各线域：<线=触碰集> …（N=1 必附串行理由）
**对账清单指针**：<路径 + snapshot ID>
```

**照抄法**：整块复制上方代码块 → 每个 `<…>` 占位填一个机算出的值或 ID → 填不出的占位写 `未知`，**不留空、不估、不省行**。缺任一行 = 简报不合格。

规则（本节只定简报格式；被引条文不在此重抄）：

1. **头条三数并列**——perf-covered / certified / 测量欠账表剩余行数，**不再单挂 certified**。
2. **黄格分类一行五筐各计数**（零未定义格视角）。
3. **三数与分类计数一律机算出数**：引用 recon 工件字段 + snapshot ID。转抄禁令见 [canon](../canon/index.md) §四.19（人工转抄数字非法），机算宿主与目的地见 [measurement](../measurement/index.md) §3.2 单一目的地法。
   〔头条三数与黄格五分类的机算宿主 = 主表 recon 工件（路径见 [measurement](../measurement/index.md)）；测量欠账表作为队列的一部分随队列住 Trellis task 树。现行 = 该保守默认；待裁项在 [issues](../issues/index.md)。〕
4. 快照纪律见 [GOV-3]；排队顺序变更权见 §一；压缩后的恢复动作见 [决策权限卡 §1.3](./决策权限卡.md#13-禁停机制)。

> **★简报是污染源，也是纠偏点。** 派发给下游 agent 的任务书里，凡未经自己机核的事实一律不写——写进去就会被下游当既成事实继续推理。任务书首节 = 队列快照。

## 五、用户检查点（禁停机制的唯一豁免）

- **检查点由用户预先指定，agent 不得自 declare。**
- 到达用户指定检查点时「报告交付即 idle 等裁决」= **合法，非违例**。
- **检查点清单随战役定义住队列节点，不住 spec**——spec 写制度，节点写现值（[GOV-1]）。
- 除用户预先指定的检查点外，**一切停轮理由均不成立**——包括会话长度、上下文压缩、里程碑达成（[决策权限卡 §1.3](./决策权限卡.md#13-禁停机制)）。
