# 治理通则 [GOV-1]–[GOV-9]

被别处引用时只引编号，不复制正文。

| 编号 | 规则 |
|---|---|
| **[GOV-1]** | **职责分离与单一住址**：spec 住稳定契约；代码/测试住实现；experiments/master 与 runs 住测量；issues 住问题；task 住可选计划。一个事实或规则只有一个主要 authority。 |
| **[GOV-2]** | **task 可选**：task 用于复杂、多阶段、并行或实验预注册；简单、明确、可逆的范围内工作无需 task。task 状态不产生实现或裁决 authority。 |
| **[GOV-3]** | **快照与数字纪律**：数字必须能追溯到 commit、主表、run-id 或可复跑命令；旧文档中的转抄数字不是当前事实。 |
| **[GOV-4]** | **用户范围优先**：最新用户指令可以重排或终止旧 task/goal；旧计划不得扩张当前权限。 |
| **[GOV-5]** | **重大选择显式化**：科研定义、公共接口、不可逆删除、外部动作和实质范围扩张需要用户授权；普通局部实现细节自主完成。 |
| **[GOV-6]** | **完成即交付**：当前请求完成后可以结束；不建立“队列永远非空”或“禁止停止”的代理行为规则。真正阻塞时说明所需选择或权限。 |
| **[GOV-7]** | **并行按收益使用**：独立且 touch set 不相交时可并行；无独立子任务时单线推进；公共 authority 由单一整合者修改。 |
| **[GOV-8]** | **代码事实优先于旧计划**：排期、立项和文档更新前核查当前代码、测试、工具和实验工件；发现旧描述时修文档，不让现实迎合旧计划。 |
| **[GOV-9]** | **命名与概念稳定**：已有概念优先沿用；新名称应解决真实歧义。用户已经裁决的两柱、六律与公式核心可进入现行 spec。 |

## 断言纪律

- “X 不存在”必须用无截断、可复跑的精确谓词。
- 展示输出可以截断，判断依据不能依赖固定窗口。
- 计数必须带生成器或命令。
- 发现相反代码事实时，旧断言立即失效。
