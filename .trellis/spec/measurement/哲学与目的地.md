## 3.0 哲学与稳定性条款

**哲学一句话：实验为主表服务——一次测量 = 主表一行发生一次受控更新；产生不了行更新的活动不是测量。**

**稳定性条款**（作用：使判据在战役全程恒定，杜绝中途改判与结论反转）：

1. 本层版本化；**修改的唯一途径 = 用户裁决**。
2. 执行中发现的新问题一律进 [ISSUES](../issues/index.md)。
3. **禁止热改流水线、禁止临时加门、禁止战役中途换判据。**
4. agent 可以提案，不可以自改。

## 3.2 单一目的地法

（作用：杜绝"跑一次测量、长出一堆新文件与新叙事"。）

1. 测量的持久产出类型固定为：主表行更新、run-id 原始工件、运行台账一行。目的地固定为三处：

   > **【已建·现役】**（2026-07-18·[ISSUE-073](../issues/index.md) 迁移落地）：三目的地**全部就位** —— `experiments/master/`（T3 主表 + rowclue + 板源 CSV `T3_A`/`T3_B`）· `experiments/runs/<run-id>/`（runner 原始工件）· `experiments/runs.log`（耐久台账）。主 runner 与主 recon 已改指 `experiments/master/`；遗留 reader 默认值单独由 ISSUE-108 追踪。旧路径 `experiments/active/result-tables/` 仍保存 T1/T2/T-N 等非 T3 历史/辅助表。

   - `experiments/master/`：T3 主表、板源 CSV 与 rowclue —— **T3 的唯一正式主表住址**；
   - `experiments/runs/<run-id>/`：该次运行的原始产物（计时原档、反汇编、探针输出），内容寻址、行内引用；
   - `experiments/runs.log`：append-only 运行台账，每次调用一行 `{run-id·时间·格·结果|VOID 原因}`。

2. **测量禁止创建目的地以外的任何文件**——不许新开报告、不许新开表、不许新开目录。跑完没有行更新的运行，只留运行台账一行。

3. 报告引用数字 = **引用行字段 + run-id**。**人工转抄数字非法**；工具能输出的数字禁止手算重述。

4. **★住址（代码）与落点（数据）是两件事**（2026-07-17 用户裁）：

   - **测量的可执行物住 `tools/`** —— runner（现址 `tools/bench/bench`）与每格对拍/计时 harness 一律**在 `tools/` 之下**。理由**不在本层发明**：`experiments/` 是**数据格**，`tools/gates/check_experiments_layout.py` 对脚本 / `+x` / `^run_` 命名入内**逐条判 RED**（该门自述「harness lives under tools/, never in the data cell」）。**该门的判据本身不动。**
   - **测量的写入只落本条第 1 项的三目的地** —— **`tools/` 下不落数据格**：计时原档、反汇编、探针输出、任何表或行，**一律不得写在 runner / harness 自己旁边**。runner 侧以 fail-closed 的写入闸兑现（闸外路径 = 中止，不是警告），闸的负控须常驻其 self-test。
   - ⟹ **住 `tools/`、写 `experiments/`。** 「harness 不许住数据格」与「数据不许住 `tools/`」是**同一条法的两面**，不得援引任一面去推翻另一面。

   > **★选址与契约【已裁】**（[ISSUE-090]·《开测篇》§〇.2）：每格/每族 harness 住 **`tools/bench/cells/`**；e2e harness 住 **`tools/e2e-harness/`**。**契约** = harness 由 `bench` **按声明接口调用**，**harness 自身禁写任何文件** —— 一切持久写入经 runner 的 fail-closed 写入闸落三目的地。
