## 三 · 决议（任务 3）

### 3.1 ★(甲) 逐个迁接口 —— **不推荐（范畴错误）**

**否决理由（机核可证，非意见）**：

1. **该接口不在 [K-4] 阶梯上**（机核 §5：ladder 文本中 `TunableScheduleOpInterface` 出现 = `False`）。阶梯 = `absent → emittable → dispatch-wired → constructed-weak → constructed → covered`，其升 `constructed` 的判据是「**body 由模式库原语构造**」= **谁写的 body**。
2. **该接口管的是"形状/调度"，不是"body 出处"**。其自述：「op whose kernel **SHAPE** is selected by the plugin-local capability/resource-aware **schedule autotuner**」，采纳后仅被 `weft-rvv-materialize-schedule` 自动发现，回传一个 kernel key 去查调度描述符（lmul 旋钮）。**它不构造 body**。
3. **B9 自己已立此规**：`[K-4] 调度≠构造·永不标 constructed`。
4. **接口轴与构造轴正交**（机核 §4 · 已负控）：把 17 个 opaque op 全迁完，接口采纳率变 24/24，而 **legacy 24/27（17 wired + 7 weak）纹丝不动、强义 3/27 纹丝不动、roster 101/108 纹丝不动**。

> **结论**：(甲) 在**结构上不可能**推进构造主张。它把工作量投在与论文主张**正交**的轴上——正是 [K-10]「禁把结构级当旋钮」的镜像错误（此处是**把旋钮当结构级**）。
>
> **公道话（不抹杀 (甲) 的价值）**：迁接口**对 C3′ 能力键控优化模式库有独立价值**（更多 op 进入调度自动调优 = 更多 measured 键控点），且**边际成本极低**（每 op 仅两个 family-neutral 方法 + 一条 registry 键）。**但它属于 C3′ 调优队列，不属于 A7/双路收敛**。误挂在 A7 名下 = 会用「17 个 op 迁完了」冒充「双路收敛了」，那是**弱义充强义**（[L-8] 违宪）的组织版本。
>
> **工作量估算（若日后以 C3′ 名义立项·非本决议授权）**：17 op × (2 方法 + 1 registry 键 + 1 lit)；**5 个 orphan key（`iq4_nl/q4_1/q5_0/q5_1/q8_0`）的描述符已存在**、只缺 op 侧采纳 = 这 5 格近乎零成本。**风险**：低（纯增量、不动 body、byte-exact 不受影响）；**但 Amdahl 传导预估缺失**——未给「调优点增加 → e2e 改善」的传导估算前，**不得以性能名义立项**（宪章规则 4）。

### 3.2 ★(乙) 正式收窄承重格集合 —— **推荐 · 本决议采纳**

**明文写死（草案条文见 §五）**：

- **论文的「由机制构造 / mechanically constructed」（强义）主张，只压在**：
  - **机制存在性（C1）**：legacy 轴 **3/27 形状** = N-operand 构造路 4 front door（`q4_0-nibble` / `offset-binary N=3` / `codebook N=3 LUT`）；
  - **覆盖率（C3′ 产出质量）**：roster 轴 **`C_construct 101/108`**（机算·硬冻结·分母声明制）。
- **其余一律**标 **`descriptor-selected composition`**，**禁沾"构造/变换"**：具体 = 平面描述符路 `deriveFlatBlockDotDescriptor` 服务的 **7 个 kind**（`q8_0/q4_0/q4_1/q5_0/q5_1/iq4_nl/mxfp4`）**在 legacy 27 口径下的那一面**。
