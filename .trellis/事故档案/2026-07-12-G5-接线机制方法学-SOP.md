## 0. 一页速览（判别口诀 · cheat sheet）

| 问题 | 判据 | 去向 |
|---|---|---|
| 这一格该走哪一层？ | 上游同格在目标 VLEN 有无「可翻的 repack 全链路」（trait 注册 + case route + arch gemv/gemm body）？ | 全 present → **L-接线①**；仅缺 riscv repack 分支 → **L-接线②**；缺整套 forward 桥（矩阵范式/IQ gather）→ **L-接线③** |
| 翻 gate 就够吗？ | 上游该格 **VLEN128 kernel body 是否破损**（load/acc 硬编码 AVL=16 或 64 = VLEN256 死宽度变体）？ | 不破损 → routing-freebie（correctness 白送，如 q4_0）；**破损/缺失 → 必须部署我方 emitted vl=8 kernel 承载正确性**（correctness-carrier，如 q8_0/q4_K） |
| 翻 gate 得异常高数（>已知 kernel 优势倍数）？ | **默认怀疑上游 VLEN 破损**（跳半列做少工的假快）。查 objdump vl + output coherence。 | 是 MIRAGE → correctness 门未绿一律不入台账 |
| correctness GREEN 就能登记 perf 绿吗？ | **否**。correctness-carrier ≠ perf-green（q4_K carrier GREEN 但 perf<parity yellow）。 | 只有 fair-protocol（八门+双账本+对手探针）≥parity/赢 才入 perf-covered 台账 |
| kernel-axis 有 margin 就会 e2e 传导吗？ | **否**。micro↛e2e 铁律。大 margin（q8_0 4.10×）可能传导；小 margin（q5_0 1.23×）可能 wash。 | 分相实测才判；prefill/decode 永远分开报 |

## 1. 接线三层分类（L-接线①②③）

**唯一决定接线成本的 gate = 上游在目标 VLEN 有无「现成可翻的 repack 全链路」**。三层按此判据切分，工作量级递增。

### L-接线① 链路层（上游全 present · 翻 gate + 3 挂点）

- **判据**：上游 ggml 已注册该格 repack trait（`tensor_traits<block_X,1,16,GGML_TYPE_Y>`）+ 已在**某个** VLEN（通常 case256）route + arch `ggml_gemv/gemm_X_16x1_Y` body 已存；仅目标 VLEN（128/512/1024）的 `case128:{break;}//TODO` gate OFF。
- **工作量级**：**最低**——净改 ≈ 翻一行 gate + 3 挂点 deploy（见 §2）。零新增上游 GEN/ARCH 结构。
- **成员**：`q4_0`、`q8_0`、`q4_K`（★q4_K 实为此层——上游全 present、`case256` 已 route、arch body 已存；`[GAP-Q4K-VLEN128]` 纠偏了「K-quant 缺整条链路」的旧 framing，那一 framing 只适用 q5_K/q6_K/q3_K）。
- **★层内两分（关键·决定是否需部署 emitted kernel）**：
  - **①a routing-freebie**：上游目标-VLEN kernel body **可用** ⇒ 翻 gate 即路由到上游 repack 路径，correctness 白送。**唯一确认例 = q4_0**（VLEN128 body 与我方 emitted 字节等价）。
  - **①b correctness-carrier**：上游目标-VLEN kernel body **破损/缺失**（硬编码 AVL=16/64 死宽度 = VLEN256 变体，在 VLEN128 上钳半列出 garbage）⇒ **翻 gate 单独 = MIRAGE**；必须部署我方 emitted vl=8 kernel **拦截在破损上游 body 之前**承载正确性。**成员 = q8_0、q4_K**（均确证 `[GAP-Q8_0/Q4K-VLEN128-KERNEL]`）。
  - **★别把 q4_0 的 routing-freebie 泛化到 ①b**：VLEN128 上 correctness **不是 free**——`q4-0-e2e-is-routing-not-kernel` 的精化 = routing 或主导 perf 比值，但**破损上游格的 correctness 由 emitted kernel 承载**。

### L-接线② 新建上游 scaffold（上游零 riscv repack 分支 · 净新 GEN trait + case route + ARCH skeleton）

- **判据**：上游该格在**任何** VLEN 都无 riscv repack 分支（trait 未注册、无 case route、无 arch gemv/gemm body）——`get_tensor_traits` 对该格恒返回 nullptr → block-dot。
- **工作量级**：**中**——须先净新建造上游 scaffold（机械但非零）：(1) GEN `tensor_traits<block_q5_0,1,16,GGML_TYPE_Q8_0>` 注册；(2) GEN case256/128 route；(3) ARCH `ggml_gemv/gemm` skeleton；**之后**才套 §2 的 3 挂点 deploy 模板。
- **成员**：`q5_0`、`q5_1`、`q4_1`（三格全绿·2026-07-12·见 §8）。q8_1-activation 家族（q5_1/q4_1）需净新 `block_q8_1x4` + `ggml_quantize_mat_t<1,Q8_1>` sub-scaffold（板 ggml 只 Q8_0/Q8_K）——★`repack-campaign-terrain` 记的 q4_1「int-zero-point ABI 阻塞」**未现**：q8_1 mat-quant sub-scaffold（q5_1 建·q4_1 零改动复用）即解，机械净新。
- **破损上游检查仍适用**：净新 ARCH body 若照抄 VLEN256 死宽度（AVL=16/64）= 自造第 3 个 MIRAGE → 必须发 vl=8 或 carrier 拦截。

### L-接线③ 跨框架 forward bridge（IQ 系 + IME e2e）

- **判据**：kernel 范式与 ggml 的向量 repack 派发链**不同构**——需在 ggml forward 里建一条**新桥**，而非翻既有 gate。两类：
  - **IME（矩阵范式·k1 板）**：`vmadot` 脉动阵列只在 prefill mul_mat（M≥M*，多激活列）有物理收益；decode（M=1 GEVM）阵列跑不起来。接线须在 `mul_mat` 的 **GEMM/prefill 分支**（M≥阈值）挂 tcrv IME `matmul_tile` + 建 tcrv-IME↔ggml block-layout 桥（`[GAP-IME-E2E-INTEGRATION]`）。
  - **IQ 系（vluxei16 gather codebook）**：gather 表 + 符号布局的 forward 消费桥不存在。
- **工作量级**：**最大**——完整 forward 桥、依赖最多。**排 ②之后**。
- **★诚实上限**：即便桥建成，kernel-axis 优势（IME ~2× compute-account）**仍受 micro↛e2e 约束**（Amdahl/内存墙重核·不预设转绿；IME 5.51× kernel → 0.86× decode 是前车）。**L-接线③ 价值 = 机制/N2 结构闭环，非 perf 绿格。**

## 2. 通用 3 挂点 deploy 模板（每格恒 3 处 · 可逆 · 无 git）

一份幂等 `deploy_patch_<fmt>_emitted.py` 恰改 **2 个 tracked 文件**（GEN + ARCH），带 md5 baseline 断言（非 baseline 即 ABORT）+ 改前 `cp *.ORIG` 备份。三挂点：

### 挂点① dispatch gate — GEN `ggml-cpu/repack.cpp`（`get_tensor_traits`）

上游 `case 128: { break; } // TODO` → 翻 gate 路由到 repack trait：
```cpp
case 128: { if (cur->ne[1] % 16 == 0) { return &<fmt>_16x1_<act>; } break; } /* TCRV route */
```
- 返回上游**同一个** `<fmt>_16x1_<act>` trait（case256 已用的那个）。条件 `ne[1]%16==0` = 16-way 交织行数约束；不满足回落 block-dot（部分 tensor 仍走 stock，是稀释来源）。
- 这一步就是 **route**：把该格 `mul_mat` 从 block-dot 切到 repack-GEMM 布局 + 激活量化 + tiled kernel。

### 挂点② ARCH `#include` emitted `.inc` — ARCH `ggml-cpu/arch/riscv/repack.cpp`

```cpp
#include "tcrv_emitted_<fmt>.inc"   // 与既有 q4_0 .inc 并列
```
- **是 in-tree 源码 `#include` + 重编译**（符号进 `libggml-cpu.so`），**不是** LD_PRELOAD、**不是**独立 `.so`。
- 符号进 `.so` 后 `nm -C … | grep tcrv_emitc` 可验；`.so` 只含已接线格的 tcrv 符号（是「仅哪些格 wired」的 `.so` 级实证）。

### 挂点③ ARCH body VLEN128 分支（banner + 调 emitted + return · 拦截破损上游）

在 `ggml_gemv/gemm_<fmt>_16x1_<act>()` 体内 `UNUSED(blocklen);` marker 之后插：
```cpp
#if defined __riscv_v_intrinsic
    if (__riscv_vlenb() * 8 == 128) {
        static volatile int announced = 0; if (!announced) { announced = 1;
            fprintf(stderr, "TCRV EMITTED GEVM(<fmt> VLEN128 compiler-emitted vl=8) ENGAGED …\n"); }
        tcrv_emitc_<funcname>_kernel_<funcname>(/* ABI-mapped args */);
        return;   // ← 拦截：VLEN128 用我方 emitted kernel，不落到下方破损 upstream body
    }
#endif
```
- **banner = engage 探针**：真实 forward 里 ON → banner FIRES；OFF → ABSENT（对照 = 「已路由 vs 回落 block-dot」的直接实证）。
- **`return` 是拦截语义**：①b 格里 emitted 分支必须在**破损上游 body 之前** return，否则落到 AVL=16 死宽度 body = garbage。

### ★ABI 映射注意（emitter REORDERS 参数 · 必须读 signature 不可默记）

- **emitter 会重排参数**，且顺序**随 lowering 演进变**（q4_K GEMM 07-10 seal-proven `90d454da` 的参数序 ≠ current-HEAD `6cbd9c19` 的序）。→ **每次接线必读 emitted `.inc` 的函数签名**，按位对齐 ggml body 的局部变量。
- **实测签名例（供对照 · 不可跨格套用）**：
  - q4_K **GEVM**：`(size_t n, float* s, const uint8_t* vx, const uint8_t* vy, size_t nc)`。
  - q4_K **GEMM**（current-HEAD 重排）：`(size_t nr, size_t bs, size_t n, float* s, const uint8_t* vx, const uint8_t* vy, size_t nc)`；解码 `n/256=nb`、`nr/4=row_groups`、`nc/16=col_groups`、`vx` stride 2304（q4_Kx16）、`vy` stride 1168（q8_Kx4）、store base `s + row*bs + colgrp*16`。
  - q8_0 **GEVM**：`(n, s, nc, vx, vy)`（weight block_q8_0x16 stride544；act plain q8_0 stride34）。
  - q8_0 **GEMM**（7-role）：`(nr, bs, n, s, nc, vx, vy)`（weight stride544；act block_q8_0x4 stride136）。
- **符号命名规律**：`tcrv_emitc_<funcname>_kernel_<funcname>`，`<funcname>` = 该格 emit 的函数名（如 `ggml_repack_gemv_q4_K_q8_K` / `ggml_repack_gemm_q4_K_q8_K`；q8_0 GEVM 历史命名为 `ggml_vec_dot_q8_0_q8_0`）。**以 `.inc` / `nm -C` 实际符号为准**，不默记。
- **GEMM 缺失时的白嫖回退**：若我方无某格 emitted repack GEMM（emitter 清单缺 prefill 侧），prefill 可走**上游 GEMM body**（前提：该格 ①a 上游 GEMM body 不破损，如 q4_0 prefill A==B 字节等价）；①b 格不成立（上游破损）→ 必须补 GEMM emitter 再接。

## 3. correctness-carrier 概念（★G5 核心发现）

- **定义**：**上游该格目标-VLEN kernel body 破损/缺失** ⟺ **我方 compiler-emitted vl=8 kernel 承载 correctness**（拦截在破损上游 body 之前）。此时 routing/dispatch 或主导 perf 比值，但**正确性由 emitted kernel 承担**。
- **判别口诀**：**carrier 成立 ⟺ 上游同格 VLEN128 kernel 破损/缺失**（objdump 见硬编码 AVL=16/64 死宽度）。若上游 VLEN128 body 可用 = routing-freebie（非 carrier），**别泛化回 q4_0**。
- **两格对比（同为 L-接线① 但成色分岔）**：

| 格 | 上游 VLEN128 body | 我方 emitted vl=8 kernel 角色 | correctness | perf（e2e 分相 · rvv VLEN128） | 登记性质 |
|---|---|---|---|---|---|
| **q4_0** | 可用（字节等价） | 冗余（白送） | 白送 GREEN | prefill 5.76× / decode 1.91×（routing 白嫖） | routing 绿格（带「上游本有路径」注记） |
| **q8_0** | **破损**（AVL=16→半列 garbage） | **carrier（必需）** | 我方 kernel 承载 GREEN（M1 无 kernel = "olta" garbage RED ↔ M1b emitted = "Paris." coherent） | **prefill 4.350× / decode 3.812×**（双 DIFFERENCE·CI 排除 1.0）| **carrier + perf 双得**（无星号绿格 · perf-covered 3/84） |
| **q4_K** | **破损**（AVL=16 f16m1/i8mf2 + AVL=64 u8m2） | **carrier（必需）** | 我方 kernel 承载 GREEN（整模型 greedy A==B + PPL 一致，vs 裸翻 gate PPL 822057 garbage） | **全相 < parity**（8B: prefill 0.42× / decode 0.18×；0.5b: 0.84× / 0.79×）| **仅 carrier · perf<parity yellow**（correctness 门绿前不入台账·**维持 3/84**）|

- **★核心教训**：**correctness-carrier ≠ perf-green**。q8_0 是 carrier+perf 双得的**决定性正例**；q4_K 是 carrier-only 的诚实反例（K-quant repack 慢于 stock scalar/generic vec_dot·decode GEVM heavy vsetvli churn·与 `q4-0-e2e-is-routing-not-kernel` 的「q4_K perf 立不住」一致）。**carrier 是 C1 合取存在性证据（全模型路由+repack+激活量化+dispatch 自建集成经 ggml-generic 对照证正确），不自动是 perf 战果。**

## 4. ★correctness-first SOP + MIRAGE 防线（所有接线格强制）

**MIRAGE 教训（G5-M1 f8b8dabb 教科书级正面教材）**：q8_0 裸翻 gate 得 prefill **8.69× / 78.11 t/s** 高数 = MIRAGE——破损上游 vl 钳位跳半列做少工的假快，output = garbage。aggregator 只看吞吐、不知 output 是 garbage。M1b 正确 vl=8 做全工得 39.191 ≈ 78.11 的一半 → 数值确证 mirage「快」= 跳过半数列。

### SOP 四条铁律
1. **correctness-first**：接线的 **perf 数字在正确性门（greedy A==B / byte-exact / PPL sanity）绿之前一律不入台账**。correctness RED ⇒ perf VOID 不判（判 kernel-变体缺陷，非能力缺口）。
2. **破损上游默认怀疑**：翻 gate 得**异常高数（> 已知 kernel 优势倍数）**→ 默认怀疑上游 VLEN 破损（死宽度硬编码），查 objdump vl 宽度 + output coherence + PPL 再论。
3. **破损上游检查（objdump 判据）**：反汇编上游/我方 kernel，看 `vsetivli` 立即数——**必须是 8，NEVER 16 或 64**。源里 `vle*_v_*(...,16)`（f32m2/f16m1/i8mf2 VLMAX=8 @VLEN128）或 `...,64`（u8m2 VLMAX=32）= VLEN256 死宽度变体 = @VLEN128 钳半列破损（同 PPL 822057 / vl=16 病理，`zero-model-adjudication-cert-hardening` 部署变体≠证过变体）。
4. **每接线格套用**（L-接线①b/②/③ 尤其·防第 N 个 MIRAGE）。

### 部署五验（deploy five-verify · SEAL）
| # | 验 | 判据 |
|---|---|---|
| 1 | **nm 符号** | ON `.so` 含 `tcrv_emitc_…<fmt>…_kernel` ≥1；OFF `.so` = 0 |
| 2 | **objdump vl-seal** | emitted 符号内 `vsetivli imm=8` 命中、`imm=16`/`imm=64` **零**（部署变体 == 证过变体） |
| 3 | **banner FIRES** | 真实 forward ON → EMITTED GEVM/GEMM banner FIRE（engage 探针）；OFF → 0 |
| 4 | **A-tree restore byte-exact** | 测后 `board_restore.sh` 从 `.ORIG` 还原 → GEN/ARCH md5 == baseline，源 restore byte-exact + pristine rebuild |
| 5 | **零 stock 永久改动** | 测后 live `.so` md5 == OFF-pristine（tcrv 符号=0、无 stray `.inc`）；测前/测后 md5 比对证零净改动 |

### correctness 门具体协议
- **greedy A==B**：逐 prompt 贪心 token（`--temp 0 --top-k 1 --seed 1`）A(ON emitted) == B(OFF stock) byte-identical + logits sanity（无 NaN/Inf）。
- **PPL sanity**（K-quant 类必加，如 q4_K）：整链路 PPL ≈ stock（q4_K 11.97/12.008 vs stock 12.05 = 整链 route+repack+q8_K 激活+dispatch 经 ggml-generic 对照证正确），区别裸翻 gate 的 PPL 822057 garbage。
- **措辞锁**：不得说「byte-exact vs ggml」（repack GEMM 用向量 FMA = bounded-ULP，非 ULP0）；真正确性基座 = greedy 生成文本字节相同 + PPL 相干。

## 5. selector 接线（张力A 范式 · deployed=proven）

**问题（张力A）**：翻 gate 强制路由 ≠ 我方编译器自洽选择。M1b 前 selector 对 q8_0 返回 `block-dot-decline-q8_0-lean-fallback`（`!blockDotComputeHeavy`：q8_0 8-bit dequant 便宜、block-dot 精简）——与「翻 gate route q8_0→repack」矛盾。若 emitted kernel 不被 **default selector 自然选中**，则只是「强制路由探针」，board 数字不能算作我方 selected path 的传导。

**修法（LANDED · commit 40ac20ca）**：
- 加 `block_dot_memory_bound`（`OptionalAttr<BoolAttr>`·`block_dot_compute_heavy` 的 **roofline dual**）；benefit = `compute_heavy || memory_bound` 双 roofline arm。
- **load-bearing 发现**：selector 单轴 `blockDotComputeHeavy` 是**错轴**——q8_0 结构事实 = 最宽线性量化（stride34）+ lean vec_dot → **DRAM 带宽受限**（不是 compute-heavy）→ repack x16 连续流除冗余内存流量。M1b decode 3.812× 证伪了单轴 lean-decline。
- **★能力键控做主键·非 measured-guard**：fact 从 block 字节布局 + ggml vec_dot roofline 结构读出（`quants.c:435`）；board 数字只 **CONFIRM 不 establish**；reason 枚举 = capability 类（`repack-kept-q8_0-memory-bound-prefill` / `-vlen128-decode`）。

**deployed=proven 达成（范式）**：
- default-compile q8_0（诚实事实·无强制）→ selector **自然**选 repack → emitted `.inc` **字节等于** M1b 证过的 `b5177a4d` → **M1b board 4.35×/3.81× 传导·无需重测板** → **部署变体 == 证过变体**（closes `deployed≠proven` caveat）。
- **★范式口诀**：**emitted kernel 须被 default selector 自然选中，board 数字才 deployed=proven**。判据链 = 能力键控（结构事实非 measured-guard）→ default-compile 选中 → **.inc 字节等于强制探针的证过件** → board 数字传导。

## 6. 预期管理（诚实 · 接线≠自动转绿）

- **micro↛e2e 铁律**（`kernel-wins-dont-transplant-to-e2e`·`[NG-4]`）：接线让格拿到**真实 e2e 分相判决**，**不保证转绿**。
- **margin 传导预判（分相 · prefill/decode 永远分开报）**：
  - **大 margin → 可能传导**：q8_0 kernel 4.10× → e2e prefill 4.35× / decode 3.81×（repack streaming/locality 主导，收窄了「decode 必撞内存墙 parity」的 M0 张力B 边界——但**别默认**）。
  - **小 margin → 可能 wash**：q5_0 kernel-axis 1.23× gcc-symmetric → e2e **可能 washes to yellow**（micro↛e2e）；据实测决定是否续建 q5_1 scaffold。**perf-covered 从 3/84 上升不保证。**
  - **carrier-only → yellow**：q4_K correctness-carrier GREEN 但 perf<parity（repack 慢于 stock vec_dot）→ **kernel-axis yellow · 不入 perf-covered**。
- **登记纪律**：`perf-covered = 已构造格中经公平协议（八门+双账本+对手探针）测得 ≥parity/赢 的格 / 已构造格数`。分子必逐格披露 {账本 · 八门状态 · 登记性质}。**造得出 ≠ 立得住；候选 ≠ 绿格。** 当前 3/84 = {① q4_K kernel-账 Win-K1-VLEN（k1/VLEN256·与本文 VLEN128 carrier 是不同上下文）② q4_0 routing 绿格 ③ q8_0 full-stack correctness-carrier 无星号绿格}。
- **黄格出口三选一**：{GAP 具名待修 / 物理 parity-at-floor / 声明例外}·零未定义黄格。q4_K VLEN128 carrier 出口 = `[GAP-Q4K-VLEN128]`（破损上游确证=C1 供弹第 2 例·手写库 VLEN 不可移植）。
- **★C1 对手侧铁证**：`[GAP-Q8_0/Q4K-VLEN128-KERNEL]` = **手写库的 VLEN 不可移植性**（上游一份死宽度 kernel VLEN256→VLEN128 即 garbage）= 我方「能力驱动发射正确变体（vl=8 VLEN128-correct）」论点的**对手侧铁证** = **模板协议本体（C1）的外部证据**。

### 7.1 Host emit recipe（tcrv-opt + mlir-translate · HEAD `4b617a9d`·host LLVM 20.1.8）
从 test/ 既有 MLIR 产 emitted `.inc`（VERBATIM）：
```bash
# GEMM（prefill · 需 quant-contraction lowering）
./build/bin/tcrv-opt <prefill-vlen128.mlir> \
    --tcrv-rvv-lower-quant-contraction=march=rv64gcv --tcrv-rvv-lower-to-emitc \
  | /usr/lib/llvm-20/bin/mlir-translate --mlir-to-cpp  > tcrv_emitted_gemm_<fmt>.inc
# GEVM（decode · identity-repack 路径通常只需 lower-to-emitc）

    --tcrv-rvv-lower-to-emitc \
  | /usr/lib/llvm-20/bin/mlir-translate --mlir-to-cpp  > tcrv_emitted_gevm_<fmt>.inc
```

(1) `repack.h`: `struct block_<fmt>x16`（不能用 `block<K,N>` 若有 min/qh）+ decls；(2) GEN `make_block_<fmt>x16` **weight interleaver**（★correctness-critical·byte-exact match emitted kernel decoded layout·transposed-qh/m 字段·**MIRAGE trap**·必 board UT vs oracle build 前 de-risk）；(3) GEN repack fn + template 特化 + trait 注册 + dispatch case128=ON + generic scalar fallback；(4) ARCH `ggml_gemv/gemm_<fmt>` skeleton（thin wrapper·body 由 emitted .inc 填·VLEN128 分支 banner+调 emitted+return）；(5) **激活量化 sub-scaffold**（若激活类板缺·如 q8_1：净新 `block_q8_1x4` + inlined `ggml_quantize_mat_t<1,Q8_1>` byte-match stock ref）；(6) 套 §2 三挂点 + §4 correctness-first + §7 可逆。

### 8.2 ★三条实测结论（方法学 canon）
- **C1 template extensibility 实证**：template 从零建 upstream repack scaffold（上游零 riscv 分支）→ correctness-carrier + prefill perf 传导。不止翻 gate/复用（q4_0/q8_0）·能**真净新建链路**。

- **C3′ perf 传导（asymmetric）**：kernel-axis 小 margin（1.23×/1.41×）**确传导 e2e prefill**（GEMM compute-amortization + repack locality·非 wash）·**但 decode 传导不稳**（q5_0/q5_1 wash·q4_1 win）——prefill/decode 传导 asymmetric·decode 受 memory-wall + stock baseline 方差影响。**★weak-stock caveat**（q4_1）：净新格对手 = stock generic block-dot（无 stock repack）·大倍数（3.68×）= path-win（repack vs 未优化 generic·同 q4_0 类）·**非比调优核快**·磁量解读必披露。
