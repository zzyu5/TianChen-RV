## 1. 发现（一句话）

**q4_0 e2e prefill 5.9× = 把 block-dot 换成 repack-GEMM 布局这一步的赢，而那条 repack-GEMM 全链路（repack 布局、
q8_0 激活量化、tiled kernel、甚至 riscv 16x1 kernel body 与 selector 分支）在 ggml 上游 `f3e1828` 里已经完整存在、
且已在 VLEN256 上路由;上游只是把 VLEN128 那一格留成 `// TODO`(gate OFF)。翻开该 gate = 路由到上游自带的 repack 路径。**
我方 q4_0 构造件（front-door-constructed GEMM）经证与该路径**字节等价**（kernel-est 5.045× ≈ routing-era 5.077×），
是**机制构造并路由**、**不是**"我方 GEMM 把对手 GEMM 打赢了 codegen"。

## 3. 归因分解（routing 白嫖 vs 我方净贡献）

证据来自 sealed cell 自身的对账（`experiments/sealed/repack/rvv-vlen128-q4_0-gemm-constructed-sealed/` 的
`MANIFEST.md §6.1` + `NOTES.md`）与 companion routing-era cell（`rvv-SEALED-q4_0-vlen128-fullmarch/`，5.077×）：

| 层 | 数字 | 归属 | 依据 |
|---|---|---|---|
| **routing 白嫖（主导项）** | **~5.0×**（routing-era e2e 5.077× / 本 cell kernel-est 5.045×） | **100% dispatch** — 换到 ggml **自带** repack GEMM 布局 + q8_0 激活 + memory-locality | routing-era cell 对抗-verify：prefill kernel **A(ours) 与 B 字节相同**，"the win is dispatch"（MANIFEST §6.1） |
| routing → 5.92× 的残差 | 5.08 → 5.92 | **非纯 codegen 赢**：session/co-tenant 混淆（stock 基线漂移 3.9→5.24 t/s、SPEC bzip2 co-tenant）+ 声称的 e2e memory-locality 放大 | MANIFEST §6.1「the 5.08→5.92 delta is session/co-tenant-confounded, NOT a demonstrated pure-codegen gain」 |
| **我方构造件净贡献** | kernel-est **5.045× ≈ routing 5.077×** | 构造件与上游路径**字节等价**：**复现**而非**打赢**该路径 | 硅 verdict = FMA-fold bounded-ULP（≥ggml scalar-vs-f64,2/4 shape 更近）;greedy-token 3/3 A==B;`be66c917 typed_repack_gemm_loop_body` |

**结论**：~5× 的绝大部分 = 路由到上游已建 repack 路径（白嫖 dispatch）;我方构造件把该路径以能力键控方式**从抽象
`quant_contraction` 声明前门构造出来并路由**，**字节等价已证** — 净贡献是**机制（构造 + 键控路由）**，不是 kernel 微质量。
q4_0 是"上游具备等效路径但在该 VLEN 关闭、我方键控翻开并字节等价构造"的**唯一格**。

## 4. 为何**不可外推 K-quant**

同一个 selector，K-quant 各格在 **VLEN128** 的状态与 q4_0 根本不同：

| 格 | VLEN128 selector 状态 | 上游有无可翻 gate | 源码 |
|---|---|---|---|
| q4_0 | `case 128: return &q4_0_16x1_q8_0`（我方翻开） | **有**（trait+kernel+量化+VLEN256 已证,仅 128 是 TODO） | `repack.cpp:4592` |
| q4_K | `case 128: { break; } // TODO` | **无 working trait**@128（仅 VLEN256 有 `q4_K_16x1_q8_K`） | `repack.cpp:4619` |
| q2_K | `case 128: { break; } // TODO` | **无 working trait**@128（仅 VLEN256） | `repack.cpp:4636` |
| q5_K / q6_K / q3_K | 连 riscv 分支/repack kernel 都**不存在**（任何 VLEN） | **零**（家族最强 absence：q3_K 全 ggml 无任何 repack kernel） | inventory §二.4 opponent-absence 三证 |

**关键区别**：q4_0 白嫖的是**上游已在 VLEN256 路由、仅 VLEN128 留 TODO 的现成全链路**（一行 gate 翻转即得）。
K-quant 在 VLEN128 **没有任何可翻的 gate** — repack 布局构造器、q8_K 激活量化、kernel body、dispatch 接线**全部缺失**，
必须由编译器**从头全构造**。板上实测印证：K-quant 构造件当前是 **LOSS 0.18–0.21×**（un-pipelined,first-construction
correctness-first emit vs ggml MATURE `_vl128` block-dot），**那个"免费 ~5×"对 K-quant 根本不存在**。
→ **禁止以 q4_0 的 5.9× 外推任何 K-quant 期望。**
