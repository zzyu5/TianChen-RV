### (b) **新查出真缺陷：axis-B 清单缺 2 条（7 vs 9）** — 已登记 · **未执行**

code 侧 role attr 有 **三种声明形态**，形态盲 grep 会漏掉一种：

```bash
# 形态无关抽取（.td 任意 $x_role(s) ∪ header 引号形式）
{ grep -rhoE '\$[a-z0-9_]+_roles?\b' include/Weft/Dialect/RVV/IR/RVVOps.td | tr -d '$';
  grep -rhoE '"[a-z0-9_]+_roles?"' include/Weft/Plugin/ConstructionProtocol.h | tr -d '"'; } | sort -u
# => 9 条：accumulator_role field0_role field1_role mask_role scale_role
#           selected_path_role source_role typed_role widening_product_multiplicand_roles
```

| 形态 | 例 | 出处 |
|---|---|---|
| `StrAttr:$x_role` | `StrAttr:$mask_role` | RVVOps.td |
| `OptionalAttr<StrAttr>:$x_role` | `selected_path_role` | RVVOps.td:323 |
| 引号常量 | `= "source_role"` | ConstructionProtocol.h:146-147 |

**schema 漏列 `field0_role` / `field1_role`**。二者在 RVVOps.td 里与已列的 `scale_role`/`mask_role`
**声明方式完全相同**（`StrAttr:$field0_role`, :2372/:2373 等）。其取值实测：

```bash
grep -rhoE 'field[01]_role\s*=\s*"[^"]*"' test/ lib/ | sort | uniq -c | sort -rn | head -4
#  31 field0_role = "segment-field0-input-buffer"
#  30 field1_role = "segment-field1-input-buffer"
#  25 field0_role = "segment-field0-output-buffer"
#  24 field1_role = "segment-field1-output-buffer"
```

取值与 axis-A slot 拼写重合 —— 但 schema **自己**已就同样情形收录 `accumulator_role`
（"coincides with the axis-A ABI-slot spelling"）→ **重合不是排除理由**，漏列与 schema 自身处置不一致 = **缺陷**，非刻意留白。

**为何不执行**：`capability.schema.v1.json` 是 **[S-6] 受治 schema.def**，
改一个字节即 shape hash 漂移，须配 VERSIONLOG 版本条目（RFC id + additive/breaking 评级）：


→ 已 `git checkout --` **复原受治件**；`check_schema_gate.py report --check` **exit=0**（绿）。

**待裁 · 批准即机械可用**（补丁存 §四；应用后实测 falsifier `exit=0` 绿）：
