## 二、前半句「编译期变体生成」= 已实现（现状）

现状承载在 `lib/Transforms/` 的 12 个 core/common pass（`.trellis/spec/architecture/变体流水线.md:20-22` 列名 + 复核谓词 `find lib/Transforms -maxdepth 1 -name '*.cpp' | sort`）：

| Pass（`lib/Transforms/*.cpp`） | 后半句相关职责 |
|---|---|
| `VariantSelection.cpp` | 编译期 fail-closed 消费**编译期 IR 事实**做选择；发 [D-4]① JSONL 归因（`VariantSelection.cpp:1094-1115` 计算并写 `declared_instance_hash`） |
| `PluginVariantLegality.cpp` | 合法性谓词过滤（[SEL-1] 第一段） |
| `DispatchRuntimeGuard.cpp` | 见下 —— 后半句在编译期的**唯一现有落点** |
| `CheckCapabilityRequires.cpp` | 能力 `requires` 闭包检查 |
| `VariantDispatchSynthesis.cpp` / `VariantMaterialization.cpp` | dispatch case / 变体物化 |

schema 事实驱动的能力宽度选择在**构造期**由 march → 能力事实派生（非手写开关），代表点：
- `lib/Plugin/RVV/RVVCapabilityProfile.cpp:289` `deriveMinimumVLEN(march, hints)`：`rv64gcv`→128，`rv64gcv_zvl256b`→256（`:299`/`:326-327`）。
- `lib/Plugin/RVV/FrontDoor/RVVLowerQuantContraction.cpp:1222` `deriveRepackHalfLanes(vlenBits)`：`half_lanes = min(vlen/16,16)`，128→8、256→16、<128→0（`:1223-1225`）。
- 同套宽度键在 `lib/Plugin/RVV/Schedule/RVVRepackStripWidthMaterialization.cpp:78` 亦定义（`:100` 复用 `deriveMinimumVLEN`）。

⟹ **前半句成立**：schema/能力事实（march→VLEN→half_lanes）在编译/构造期驱动变体（宽窄/范式）生成，且 [D-4]① 编译期归因日志带 `declared_instance_hash` 已产出。

## 三、后半句「fail-closed 运行期（装载期解析）调度守卫」= 目标契约·未实现（缺口）

### 3.1 编译期已落的那一小片（现有唯一落点）

`lib/Transforms/DispatchRuntimeGuard.cpp`（pass `MaterializeDispatchRuntimeGuards`）在**编译期**做三件事：
1. `requiresRuntimeCapabilityGuard()`（`:118-149`）**在 pass 内、over `TargetCapabilitySet`** 判某 dispatch case 的目标变体是否 `requires` 不可得/冲突能力 —— 这是**编译期**判定，不是运行期逐次检查。
2. 对需守卫的 case 接一个 ABI 运行期参数 `dispatch_available`（`ensureDispatchAvailabilityGuardParam`，`:215-228`；spec 名 `DispatchAvailabilityGuard`，`lib/Support/RuntimeABIParam.cpp:155`）。热路径**只读调用方给的 `dispatch_available` 值**，不做能力再检查（`:326-328` 注释明载）。
3. `[D-2a]` 编译期戳：把**展开后规范化事实集**的 declared-instance-hash 戳到 guard param 上（`:324-338`，`support::computeDeclaredInstanceHash(*capabilities)`）—— 注释 `:330-334` 明确：「装载期消费此戳落**每进程一条** `{declared_instance_hash, ts, resolved_variant_set}` 记录……该 live per-process drop 是 [D-2b]/M2，**故意未在此物化**；E4 只发编译期戳 + 该文档化形状。」

### 3.2 缺什么（后半句未实现部分，逐条）

| 缺口 | 权威锚点 | 现状 |
|---|---|---|
| **装载期（部署二进制内、进程启动时）**读能力事实 → 展开 → 算 hash → 落**每进程一条**解析记录 | `变体流水线.md:94-98` [D-2a]；`DispatchRuntimeGuard.cpp:330-334` | 未实现（[D-2b]/M2 deferred）。今日 `computeDeclaredInstanceHash` 只在**编译期** MLIR pass 内被调 |
| **运行期 hwprobe → 事实 → instance-hash 键控调度链** | `变体流水线.md:115` [D-4]③ | 「现系统无此层」。`__riscv_hwprobe` 仅现于板测 shell（`tools/e2e-harness/T3_step3/board_ab.sh`），`lib/` 内无运行期 hwprobe 消费者 |
| **一份二进制运行期分发**（≠ 一板一份预发射 fixture） | ISSUE-105（`.trellis/spec/issues/门与工具.md:389-413`） | 现 GEN_SEAL 一板一份、march 定死于编译期 |

### 3.3 现状正字（禁误描述为已实现）

`变体流水线.md:98`：「★现状不是这样：今日能力解析在**编译期**由 `VariantSelection` fail-closed 消费**编译期 IR 事实**；load-time 展开与 declared-instance-hash 是目标契约、尚未实现，不得描述为现状。」
`架构·能力模型`：`.trellis/spec/architecture/能力模型.md:41` 同义重申。

## 四、一句话结论

前半句（编译期变体生成 + [D-4]① 带 hash 归因）**已实现**；后半句的**编译期骨架**（guard param + declared-instance-hash 戳）已落于 `DispatchRuntimeGuard.cpp`，但**装载期运行时那一环（读事实→落每进程一条记录）与运行期 dispatch 链**均为【目标契约·未实现】，正是 [D-2a]/[D-4]②③ 的施工面。
