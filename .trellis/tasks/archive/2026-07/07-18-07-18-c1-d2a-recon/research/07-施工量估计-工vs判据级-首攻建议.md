## 一、工 vs 判据级划分（[D-2a] 落地的每块归属）

**判据级** = 触 canon / 红线 / 账目 / 分母，须登记（多为待裁），落地前采保守默认。
**工** = 不改判断依据的实现，可自决直行（仍守 pre-dev checklist + 范围预注册）。

| 施工块 | 工 / 判据级 | 依据 |
|---|---|---|
| 装载期解析器（进程启动读能力事实→展开→算 hash→落一条记录） | **工**（复用 `computeDeclaredInstanceHash`、守 [NG-3]/I3/I7） | hash 算法已存在（`DeclaredInstanceHash.*`）；形态已文档化（`变体流水线.md:96`） |
| 每进程一条解析记录的**产物形状 + CI 硬门**（每进程恰 1 条） | **工**（形状已定 `{declared_instance_hash, ts, resolved_variant_set}`）；**门语义**若要进 [PERF-1]/证据门则**判据级** | `DispatchRuntimeGuard.cpp:330-334`；门体定义 `测量判据.md` |
| [D-4]③ 运行期归因链（hwprobe→事实→hash 键控 dispatch） | **工为主**，但**须守 [NG-3] 红线**（不得退化 per-dispatch 检查）= 设计受**判据级约束** | `能力模型与插件协议.md:14` [NG-3]；I3/I7 |
| **一份二进制发多宽度变体 + 装载期选宽**（ISSUE-105 kernel 账通道） | **判据级·待裁**（ISSUE-105 = 「k1 是否发 VLEN256 fixture」re-baseline 所有 k1 gemm_tile 格·热改流水线） | `门与工具.md:391`（状态：待裁·判据级） |
| k1 半宽群逐格翻 deployed PASS | **判据级**（改 master verdict / 账目 / 分母）+ 每格**工**（byte-exact+板测） | ISSUE-105 保守默认 `门与工具.md:406-408`；proven≠deployed |
| GEN_SEAL/harness 改发 per-board fixture | **判据级**（热改测量流水线，re-baseline） | `门与工具.md:407` |
| 能力措辞两层标注（新代码/文档） | **工**（纪律执行，非裁决） | §六.13 `部署与构造语义.md:32-33` |

**核心判据级门槛**：ISSUE-105 待裁（判据级）是 kernel-账正解**部署侧**的前置；[D-2a] 的**编译器侧构造**（装载期解析器 + 记录 + 归因链）大体是**工**，但其**部署到测量流水线、改 master/账目**的那一步是判据级。

|---|---|---|---|

## 三、首攻建议（大构造分步·勘察建议·非立项）

依赖序（每步独立可验、byte-exact 不可绕）：

1. **首攻 = 阶段 A（装载期解析器骨架）+ B（每进程一条记录）**。理由：
   - 依赖最少（hash 算法 + 编译期戳已在，只需把"算一次"搬到运行时消费 + 落一条记录）；
   - 直接兑现 [D-2a] 步①②③④与 [D-4]②「每进程 1 条」硬门；
   - 不触 ISSUE-105 判据级（不改 GEN_SEAL/master/账目），纯编译器侧构造 = 多为**工**；
   - 守法面清晰（05 号文件的守法设计表可直接作施工契约）。
2. **次攻 = 阶段 C（[D-4]③ 运行期归因链）**，但**必须先固化 [NG-3] 守法测试**（防退化 per-dispatch 检查）——此步是整层新建、最大，且红线密集。
3. **ISSUE-105 部署通道（阶段 D）单独走判据裁决**：先推 ISSUE-105 待裁（判据级）→ 裁准后再逐格 byte-exact + k1 板测翻 deployed。**不与 A/B/C 编译器侧构造耦合推进**（保守默认现行有效，`prd.md:29`）。
4. **[SEL-2] 时序约束随行**：`覆盖状态机.md:23` [SEL-2] —— 能力先验层须先于/同于"矩阵范式接管 GEMM 形 prefill"落地；[D-2a] 装载期解析涉及先验层的运行期兑现时须核 [SEL-2] 硬时序，勿把先验层验证误锁在自有 IME GEMM 之后（`变体流水线.md:86`）。

- PRD §四：「勘察后 → [D-2a] 实现立项（研究定形态后·prd 先写）」。本 6+1 份 research 已定形态（4 步链）、守法设计、kernel-账正解、工/判据划分、首攻分步 —— 满足"研究定形态"前置。

## 五、一句话结论

[D-2a] 编译器侧构造（装载期解析器 A + 每进程一条记录 B + 运行期归因链 C）**大体是工**，但 C 受 [NG-3] 红线密集约束、须先固守法测试；**部署侧**（ISSUE-105 一份二进制多宽度分发、k1 半宽群翻 deployed、改 GEN_SEAL/master/账目）是**判据级·待裁**。**首攻 = A+B**（依赖最少、纯工、不触判据级、直接兑现 [D-2a]/[D-4]② 硬门）；ISSUE-105 部署通道单独走判据裁决、不耦合。施工量按相对量级估（A/B 小-中、C 大、D 判据前置 + 每格工），真实 LOC 落地时 cloc 实测（0 造数）。
