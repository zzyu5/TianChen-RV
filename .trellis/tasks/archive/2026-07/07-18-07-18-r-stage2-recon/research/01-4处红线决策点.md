## 四处（ISSUE-033 ①②③④ · 全部机核复验）

### ① 发射器否决 plan 的选择（loop-order veto）—— 「住址倒挂 · 最重」
- **文件**：`lib/Conversion/RVV/RVVToEmitCBlockQuantLinear.cpp`
- **住址**：K-quant sibling GEMM 发射体内，谓词 `weft_rvv.loop_order` + `weft_rvv.loop_order_selection_reason` 读取处（本仓 HEAD 实测在 ~L3259–3283 一段；**按谓词定位**）。
- **机制**（实读代码）：
  - `bool siblingColGroupOuter = false;` 默认 row_outer。
  - `if loopOrder == "col_outer" && loopOrderReason == "measured"` → 才 `siblingColGroupOuter = true`（翻转）。
  - `else if loopOrder == "col_outer"`（即前门选了 col_outer 但 reason 非 measured，如 `prior` / `only_feasible`）→ **不翻转**，realize 成 byte-exact row_outer，并发一条 `// weft_emitc.loop_order_override selector=col_outer/<reason> realized=row_outer gate=measured-gate-blocks-unmeasured` 记录。
- **为何红**：前门（plan 层）已 SELECT col_outer，发射器用 measured-gate **否决**它 → 决策的最终裁定权落在发射器，而非前门。这就是「住址倒挂」。注意：override 记录的落地已缓解「log-vs-realized 背离」，但**决策仍住发射器**。
- **相关**：同域是 `selection_reason` 分派逻辑，跨 `lib/Plugin/RVV/FrontDoor/RVVLowerQuantContraction.cpp`（前门盖章）与 `lib/Plugin/RVV/EmitC/RVVEmitCRouteMetadata.cpp`。

### ② `.value_or("mf2")` 承重（宽度默认补值）
- **文件**：`lib/Conversion/RVV/RVVToEmitCBlockQuantLinear.cpp`（**× 18**）+ `lib/Conversion/RVV/RVVToEmitCKQuant.cpp`（**× 2**）。
- **谓词**：`grep -c 'getIntegerCoreLmul().value_or("mf2")'`。**实测 BQL = 18 · KQuant = 2**（2026-07-18 复验，与 ISSUE-033 一致）。
- **病名（★禁简化，ISSUE-033 已定）**：**不是**「发射器篡夺决策」。前门 `RVVLowerQuantContraction.cpp` 用**沉默**表达「不用 m1」——盖章式三目 `isM1 ? builder.getStringAttr("m1") : mlir::StringAttr();` **实测 = 18 处**同形（`grep -c` 精确串；注：spec 文字写"16 处"，HEAD 实测为 **18**，同 `.value_or("mf2")` 计数一致——已随代码再生漂移，如实报 18）。⟹ 具体的 `"mf2"` 只活在发射器的 18 个常量里。**病名 = 「plan 用缺席当信号，`.value_or` 因此承重」**：发射器是替一个本就没被送达的决策补值，非推翻已送达的决策。
- **修法方向（ISSUE-033 已定）**：**先让前门把「mf2」显式说出来**（缺席不再是信号），attr 才能改 required / fail-closed。若按「篡夺」病名去删发射器 `.value_or` 而上游仍沉默 → 直接 fail-closed 全表（错）。详见 06 号文的「工 vs 判据级」。

### ③ 宽度二点阶梯无设防
- **文件**：同 ②（`.value_or("mf2")` 覆盖域）。
- **实质**：宽度选择只覆盖 `{mf2, m1}` 二档；第三档时静默算成比基更窄的档、**无 assert = 未设防不变量**。今日安全仅靠上游不产该档。
- **为何红**：缺参不 fail-closed，是「兜底掩盖缺陷」的典型 —— 正是 §四.3「缺参 fail-closed 不兜底」要清除的形态。

### ④ GridCodebook 焊死宽度 + 假旋钮
- **文件**：`lib/Conversion/RVV/RVVToEmitCGridCodebook.cpp`
- **实质**（ISSUE-031(a) + 实读代码）：4/5 格式把向量宽度**焊死为字面量**，其中 **2 格是假旋钮**。
- **代码定位**（机核）：
  - 共享体（L59）`llvm::StringRef coreLmul = cx.coreLmul;` = 合法（读自 context / Win-A gearbox anchor，m2 默认 / m1@VLEN256，L40 注释）。
  - **焊死点**：`grep -n 'coreLmul = "'` 实测 **2 处**：L520 `llvm::StringRef coreLmul = "m1";` 与 L1041 `llvm::StringRef coreLmul = "m1";` —— **字面量直写**，不读 IR/context。这两处 = 假旋钮候选（`coreLmul` 只喂 intrinsic 名、vtype 是字面量 ⟹ 设 m2 会发出类型不匹配的 C）。
  - `value_or` / `StringSwitch` 在该 TU **= 0**（`grep -c` 实测）——∴ 该 TU 犯的是「无条件字面量」形态，**没有分支可 grep** = ISSUE-031(a) 所称「全新的假阴性形态」。
- **为何是「红线」而非普通宽度默认**：它是 ISSUE-031 判据丙（语义级）的决定性证据——语法级判据（甲看 if 条件式 / 乙看 format 名出现）**结构上抓不住它**（format 名清白、犯事的是宽度字面量）。

## 域内存在性证明（重构方向的活范本 · ISSUE-033 已给）
- `lib/Conversion/RVV/RVVToEmitCDeferredDequant.cpp` = 1,070 行，`value_or`/`switch`/`StringSwitch` **全 0**（实测），却有完整形状轴（接受 m1/m2/m4/m8）——它把宽度**读自 IR 向量类型**（`accVecType.getLmul()`）而非字符串属性，全部 lmul 引用都是 fail-closed 门。**②④ 的修法有现成范本**（见 03 号文）。

## 4 处的性质划分（工 vs 判据级 · 详见 06）
- ② ③ = **纯工**（沿 DeferredDequant 范本，前门先显式化 → attr required），但 ② 有前置（前门先说出 mf2）。
- ① = 已部分缓解（override 记录已落地），**是否算「清除」取决于 F-7 判据**（住址倒挂本身是否要消解 = 判据级，gated on ISSUE-031）。
- ④ = 焊死宽度部分是**工**（改读 context/IR）；但「假旋钮抓不住」这一事实是 ISSUE-031 判据丙的论据 → **立门判据 gated on ISSUE-031**。
