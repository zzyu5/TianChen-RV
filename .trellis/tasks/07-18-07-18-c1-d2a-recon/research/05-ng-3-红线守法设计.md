# Research: ★[NG-3] 红线（不可破）+ [D-2a] 守 I3 零分支 / I7 fail-closed 的设计

- **Query**: [NG-3] per-dispatch 强制检查永禁；核实现有热路径无 per-dispatch 检查；[D-2a] 设计怎么守 I3 + I7
- **Scope**: internal（canon [NG-3]/I3/I7 + DispatchRuntimeGuard 热路径核）
- **Date**: 2026-07-18

## 一、[NG-3] 红线条文（不可破·多处一致）

- canon 正本：`.trellis/spec/canon/能力模型与插件协议.md:14` [NG-3]：
  「**per-dispatch 强制检查永禁**：装载期最小解析消费显式 schema 事实实例、算出 declared-instance-hash、落一条解析记录即止（**热路径零逐次检查**）。per-dispatch 强制 = 破零分支（I3）与 fail-closed 自足门（I7）。」
- 去向表：`.trellis/spec/canon/核心不变量.md:61`；索引 `.trellis/spec/canon/非目标.md:5`（「不做 per-dispatch 强制检查」）。
- 形态正字：`.trellis/spec/architecture/变体流水线.md:96`「热路径**零逐次**能力检查；**per-dispatch 强制检查永久禁止**（[NG-3]）」。

**红线形态三要素**（PRD §二.5 口径，对齐条文）：
1. 装载期**算一次** declared-instance-hash；
2. **每进程一条**解析记录；
3. **热路径零逐次检查**（per-dispatch 强制检查永禁）。

## 二、核实：现热路径**无** per-dispatch 检查（机核，非截断）

现有"运行期调度守卫"= `lib/Transforms/DispatchRuntimeGuard.cpp`，逐环核其**检查发生在编译期、热路径只读一个 ABI 值**：

1. **能力检查在 pass 内（编译期）**：`requiresRuntimeCapabilityGuard(kernel, variant, capabilities)`（`:118-149`）over `TargetCapabilitySet`（`:120` 参数）判某变体 `requires` 是否含不可得/冲突能力。这是 pass 运行时（= 编译期）的一次性判定，**不在生成代码的热路径**。
2. **热路径只读 caller 给的 `dispatch_available`**：`:326-328` 注释逐字——「Computed ONCE here at compile time (**never per dispatch, [NG-3]**); the hot path still reads only the caller-provided dispatch_available value.」guard 是一个 ABI 运行期参数（`RuntimeABIParameterRole::DispatchAvailabilityGuard`，`lib/Support/RuntimeABIParam.cpp:155-159`），不是一段"每次 dispatch 重算能力"的逻辑。
3. **无运行期 hwprobe 逐次消费**：`lib/` 内无 `__riscv_hwprobe` 消费者（仅板测 shell `tools/e2e-harness/T3_step3/board_ab.sh`）；`lib/Plugin/RVV/Schedule/RVVProbedCapabilityAxesMaterialization.cpp` 等 "probe" 是**编译期**把 probed 能力轴物化进 IR 属性，非运行期逐次。

⟹ **现状已守 [NG-3]**：热路径零逐次能力检查（读一个 int ABI 值），能力判定全在编译期。

## 三、[D-2a] 设计怎么继续守 [NG-3] + I3 + I7

### 3.1 守 [NG-3]（零逐次）—— 结构上"算一次 + 记一条"

- hash helper 已被设计成**算一次**：`include/Weft/Support/DeclaredInstanceHash.h:25`「Computed once at compile time — never per dispatch」。装载期版本须同样**进程启动时算一次**（步③），把 hash + resolved_variant_set 落**一条**记录（步④），此后热路径**查已解析结果、不重算、不逐次校验**。
- 解析记录是 I4 缓存事实/镜像（`变体流水线.md:96`），热路径**读缓存分发结果**而非"每次 dispatch 重跑合法性/能力谓词"。
- 反面禁区：把 [D-4]③ 运行期归因做成"每次 dispatch 记一条 + 校一次能力"——那正是 per-dispatch 强制检查，[NG-3] 禁。运行期归因须挂在**解析那一次**（每进程 1 条，[D-4]②硬门），不挂在每次 dispatch。

### 3.2 守 I3（零 family-name 分支）

- I3 正本：`.trellis/spec/canon/核心不变量.md:18-19`：core/common pass 只经 capability registry / 插件 interface 调用，**绝不**在 common 路径写 `if RVV`/`if IME` family-name 分支。
- [D-2a] 装载期解析须**经能力事实/hash 键控**分发，不得按 family 名 switch。现有键控范式即此：`RVVRepackTilingSelection.h` 全程按 **bottleneck SHAPE / declared_instance_hash** 键控、**从不按格式名/family 名**（`:71-127` `classifyTilingBottleneckShape` 按 fold_model；`:22-24` 注释「NEVER the quant FORMAT NAME」）。
- 变体流水线本工位是 I3 主战场（`变体流水线.md:26`/`:42`）；[D-2a] 落地的装载期解析器必须复用能力 registry，键 = declared-instance-hash（板身份代理），不引入 family 分支。
- 佐证：[NG-3] 条文本身把"per-dispatch 强制 = 破 I3"绑定（能力模型与插件协议.md:14）——即逐次能力检查往往退化成 family 分支，故禁。

### 3.3 守 I7（fail-closed 自足门）

- I7 正本：`.trellis/spec/canon/核心不变量.md:33-35`：无法证明存在合法可执行 route 时 fail closed，禁从 metadata 合成 route。
- [D-1] 编译期门自足：`变体流水线.md:88-92`——拒绝须自足、不靠后置兜底。
- [D-2a] 装载期解析须继承 fail-closed：能力事实缺失/未知 = 假（[S-2] 缺省拒绝，`能力模型与插件协议.md:8`），解析不出合法宽度变体则 fail-closed，**不得**从解析记录（I4 镜像）合成 route/dtype/schedule（`变体流水线.md:96` 明载「解析记录……不是 route/dtype/schedule authority（I4）」）。
- 现有 fail-safe 范式：`RVVRepackTilingSelection.h:143-159` `tilingVariantFeasibleSet` —— 退化板（无 VLEN 事实/无 vreg 预算）返回**空可行集**（`:154-155`），诚实的 no-capability 行为；`:316-331` 空集 → shape 默认 + **诚实标 static_order**（不冒充 prior）。`selectRepackLoopOrder` 同理（`:508-510`）。

## 四、[D-2a] 红线守法设计要点（综合·勘察结论）

| 要点 | 守的规则 | 现有可复用件 |
|---|---|---|
| 装载期**算一次** hash、落**一条**记录，此后热路径查缓存不重算 | [NG-3]、[D-4]② 每进程1条 | `DeclaredInstanceHash.*`（算一次语义）、`DispatchRuntimeGuard.cpp` 编译期戳 |
| 分发**按能力事实/hash 键控**，禁 family-name 分支 | I3 | `RVVRepackTilingSelection.h` shape/hash 键控范式 |
| 缺/未知能力 → fail-closed、不从记录合成 route | I7、[D-1]、[S-2] | 空可行集 fail-safe + static_order 诚实标注 |
| 运行期归因挂在**解析那一次**，不挂每次 dispatch | [NG-3] | [D-4]② 每进程1条硬门 |
| 解析记录 = I4 镜像，不作 route/dtype/schedule authority | I4 | `变体流水线.md:96` 明文 |

## 五、一句话结论

现热路径**已守 [NG-3]**（能力判定全在编译期，热路径只读一个 ABI int `dispatch_available`，无逐次能力检查）。[D-2a] 守法设计 = 把「算一次 hash + 落一条记录」搬到装载期、热路径查缓存分发结果；键控走**declared-instance-hash / 能力事实**（守 I3 零 family 分支）；缺/未知能力 fail-closed 且不从 I4 镜像合成 route（守 I7）；运行期归因绑在**解析那一次**而非每次 dispatch（守 [NG-3] 的"零逐次"）。
