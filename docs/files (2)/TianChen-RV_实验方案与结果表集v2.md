## §1 对 §5 草案的裁决：保留、修正、与十处最可能翻车的 confound

**整体判决**：三层基线、byte-exact 门、六态阶梯、结构格/测量格二分、每格挂工件——**全部保留并制度化**。以下十处是最可能"证不出 / 比错 / 被 confound"的地方，逐一给修正：

1. **对手身份靠手填 → 必翻车**。repack 路由随（板 × 格式 × ggml 版本 × 构建旗标）变，手填列会静默腐烂。**修正**：对手身份列只能由**对手解析探针**（§2.5）的工件填充；缺探针工件的 vs-framework 测量格 CI 直接判 INVALID。
2. **"IME 表"作为第三张板表 = 类别错误**。IME 不是板，是板 B 上的**范式**。**修正**：板表只有 A/B 两张；IME 变体以 path 键出现在板 B 表内；IME 单独立"卷宗"T5（结构 + 范式消融），不立板表。
3. **micro 赢无传导会计 = 冒充**。**修正**：每条声称的赢必须带 Amdahl 传导链四列（§2.6）；无传导列的 micro 赢在导出时自动降级标注"kernel-level only"。
4. **Win-A 翻转主张缺前提**。跨板赢家翻转要成立，必须**双板候选集完全一致、仅事实不同**，且翻转由归因日志证明（chosen + reason），否则只是"两块板各自调了参"。**修正**：Win-A 协议加"候选集哈希相等"前置检查（§5.1）。
5. **弱义冒充强义无机检**。**修正**：发射来源清单（provenance manifest，§2.7）——每个机制构造的 body 携带其模式原语 ID 列表；强义 = 清单内无不透明手写 helper。六态判定从此可脚本化、不可辩解。
6. **presumed 泄漏进叙事**。**修正**：presumed 更名 `open`（开放测量），导出到任何论文表时渲染为 "—(open)"；CI lint：正文引用 open 格 = 违宪。状态枚举补 `STALE`。
7. **选择器消融在先验层落地前不可测**（你们已识别）。**修正**：时序写死（先验层 ← 先于 P7，[SEL-2]）；且选择器评估**不与 autotuner 对标**（[L-4]），改用**自体 oracle 遗憾度**：oracle = 离线穷举本系统变体空间的最优；指标 = top-1 一致率 + 平均遗憾%（§5.2）。
8. **beat 比错 ggml 配置**。上游构建旗标、repack 开关、线程库都会换对手。**修正**：ggml 构建配置进环境指纹（§2.3）；同会话配对测量（我方与对手交替跑，杀热漂移）。
9. **板 C 的诱惑**。RVV0.7.1 工具链贵、性能表价值低。**裁决**：板 C 只进 **T1b 的 conflicts 关系见证**（两个互斥向量家族的 fail-closed 行为，结构性、一次性），**永不进性能表**。
10. **byte-exact 对浮点路径不可达**。**修正**：整数路径字节精确；浮点/含 fp16 scale 折叠路径改 **ULP 上界声明**（[K-5]），oracle 用高精度参考（f64 累加）+ 上界断言；表中"正确性"列自动按路径类型切换判据。

另一处行键级修正（回答 §7"更好的行键"）：**双层键**。
- **分母键（覆盖率口径）** = `(算子, 格式[, 形状类])`——每对只计一次，覆盖态 = 其全部变体行的最佳六态（防止多路径重复计数虚增覆盖率）；
- **测量行键（性能口径）** = `(算子, 格式, 路径, arity, 形状类)` + **变体 ID** + **选中方式 ∈ {mechanism-selected, forced}**——forced 行只用于消融科学，产品级主张只能引 mechanism-selected 行。
- **形状类**必入键：`{decode-GEMV(M=1), prefill-GEMM(M∈扫描集), micro-fixed}`——你们草案缺这一轴，它正是 micro↛e2e 与 IME 交叉点实验的载体。

## §2 实验宪法（八条全局纪律）

### 2.1 格 schema（进 CI 的最小单元）

```json
// 测量格
{"value": null, "unit": "", "status": "measured|stale|board-pending|open|n_a",
 "board_fp": "<环境指纹哈希>", "snapshot": "<repo+ggml commit>",
 "artifact": "<指针>", "opponent_ref": "<探针工件|null>", "session": "<配对会话ID>"}
// 结构证明格
{"verdict": "pass|fail", "ci_log": "<指针>", "snapshot": "<...>"}
```
规则：`open` 永不可被正文引用；任何指纹分量变更 → 同指纹全部格自动置 `stale`；stale 格禁止跨会话与新格同列比较。

### 2.2 环境指纹与配对测量（v2：编译器身份升为一等字段）

指纹 = hash{板/SoC 标识, CPU 型号串, 内核版本, libc, **我方编译器与旗标（含 march/ABI）**, **对手 shipped baseline 的编译器与旗标**, ggml commit 与构建选项（含 repack 相关开关）, **deployed object 身份（符号 + 哈希）**, 线程/亲和配置, governor, 内存配置, **测前/测后 loadavg 与邻居进程快照**}。
> **v2 强制**：**双方编译器身份缺失的性能格一律 INVALID**（不是"待补"，是无效）——历史上曾因"我方 clang vs 对手 gcc"的静默不对称导致一批 kernel win 需整体撤回。**预飞断言**：任何 perf harness 启动前自检双方编译器/flags/march 是否满足所声称账本（[L-9]）的对称要求，不满足即拒绝出数。
**配对 SOP**：固定频率（performance governor + 实测频率日志）、钉核、丢弃预热、**我方/对手同会话 A/B 交替**、N≥10 取中位数 + IQR/bootstrap CI、温度/降频守卫（触发即作废该会话）。

### 2.3 噪声地板 T-N 与**噪声自检**（v2 改革：共享板现实）

每板 × 每基准类（micro-dot / micro-GEMM / e2e-prefill / e2e-decode）跑**重测-重测**（同 kernel 同配置跨会话），产出运行间变异（IQR%）= 噪声地板。
**效应判定规则**：声称任何 Δ 需同时满足 |Δ| > 2×该类噪声地板 且 bootstrap 95% CI 不含 0。T-N 不在 → 任何"赢/输/平"判定无效。
**开测闸门（v2 替代 loadavg 硬闸）**：共享板上不再死等 loadavg——**测前跑 3 次重测-重测 sanity，运行间 IQR ≤ 该类地板 ×1.5 即判板可用、立即开测**；loadavg 与邻居快照降为**记录项**（入指纹，供审计）；**测中** IQR 突劣 ≥3× 自检值 → 该会话作废重跑（防邻居中途醒来）。**0 样本永不造数**（宁可无数不可编数——被污染时中止并如实报 void，是纪律不是失败）。非计时测量（objdump 计数、字节比对）无窗口约束。

### 2.4 对手解析探针（Opponent Resolution）

在钉死的 ggml commit + 该板默认构建下，对每个 `(算子, 格式, 形状类)` 探测**实际派发的 kernel 符号/路径**（perf/符号追踪/ggml 日志），产出映射工件 `opponent_map(board_fp, ggml_commit)`。**对手类枚举**：`{factory-dispatched(出厂路径, 唯一贡献基线), algorithm-matched(同算法诊断), naive-RVV(sanity), scalar-oracle(sanity)}`——每个测量格必须声明对手类；只有 factory-dispatched 计入 beat。ggml commit 每次 bump → 探针必须重跑。

### 2.5 传导会计（micro → e2e 的 Amdahl 链，四列 + v2 前置检查）

`该 kernel 在相内时间占比%（profile 实测）→ Amdahl 预测相级 Δ → 实测相级 Δ → 传导效率 = 实测/预测`。规则：kernel 级赢只有在传导效率列存在且 ≥ 声明阈值时才可写"传导到 e2e"；带宽受限内核（roofline 分类列）以 **parity 为零假设**，parity 不是失败而是物理确认。
> **v2 三条硬规**：
> ① **Amdahl 输入须部署同域**（[L-11]）：预测所用的 kernel 增益因子必须来自与目标部署**同编译器、同 variant、同输入路径**的测量（历史事故：用 clang micro 因子预测 gcc 部署路径的系统收益）。
> ② **传导前先查接线**（[T10]）：e2e 无增益时，**第一嫌疑不是"物理墙"而是"该 kernel 根本没被 forward 消费"**。未在 T10 台账中确认 on-path 的 kernel，其 e2e 结果不得归因为物理/稀释。
> ③ **micro↛e2e 三因分类**（每个非绿格必须落其一）：`{未接线 | 传导稀释（Amdahl/cache 驻留/冷流式内存墙，附证据）| 物理 parity-at-floor}`。**"接线 ≠ 转绿"**：接线后仍须重做 Amdahl 与内存墙核算。

### 2.6 强义构造机检：发射来源清单

每个机制构造的 body 在发射时写出 `provenance = [pattern_id...]`；**强义判据 = 清单存在 ∧ 无不透明手写 helper 条目**；六态脚本据此判 constructed-weak/constructed，人不可辩解。这同时是 T0 的自动化来源和 [L-8] 的执法工具。

### 2.7 快照/纪元协议

分母清单 = 版本化工件（钉 ggml commit）；上游新增格式 → 开新纪元，曲线（T7）跨纪元断点标注。一切导出图表脚注携带 `{repo snapshot, ggml commit, 纪元号}`。

### 2.8 oracle 构造规则与**证书三要件**（v2 重写；由三次反转的正确性误诊案确立）

任何正确性证书必须同时满足三要件，缺一即 **cert 无效（降级 partial）**：
1. **语料完备**——每个算术项被**非退化** exercise（如 `dmin≠0`、满幅 scale、交替符号、次正规/极端指数、边界形状）。*教训：一整批证书的语料令某项恒为零，该项的错误电路"从未通电"，bug 潜伏到真数据才暴露。*
2. **输入路径同源**——oracle 与被测 dispatch **逐环同源**（量化器/交织/布局同一路径），cert 必须**声明其输入路径谱系**。*教训：用 row-quant oracle 去验 mat-quant dispatch，制造出一个不存在的"bug"，引发三次反转。*
3. **oracle 独立**——不与被测物共享读取/解码实现（"**空心证书**"禁令：共享实现会让同错互相抵消，自洽却验不出共同缺陷）；标量 oracle 结构无关；辅以性质测试与变异测试；oracle 入库、有版本。

### 2.9 **ZERO-MODEL 终审法**（正确性争议的最高法院）

争议不靠"kernel vs 某 oracle"多轮互搏（oracle 本身可能是错的那个）。终审程序两步：
① **ZERO-MODEL**：捕获**真实 dispatch 喂给 kernel 的字节**，用**被测系统自身的原语**从该输入重算，与 kernel 中间值**逐位对**（无外部 oracle 假设）；
② **对位终审**：与一个**独立实现**（如对手自身的同路径实现）在同一真实输入下逐位/ULP 对账。
**规则：单证书永不定案；翻案须比定罪更严谨；定案后一次性恢复口径（禁双改）。**全过程证据入 MANIFEST（可第三方复演）。

### 2.10 **双账本与部署身份**（v2 新增；性能表的效度前提）

- **账本列（每个性能格必填）**：`ledger ∈ {kernel, system, internal-A/B}`。
  **kernel 账**：双方**同编译器/flags/march/链接**（预飞断言强制）；**"我方 clang 编 vs 对手 shipped gcc 编"= INVALID**，不得登记为 kernel win。
  **系统账**：允许各用各的完整出货栈，但必须披露双方编译器身份、deployed object 身份、集成方式、baseline 是否 shipped-best，并**尽力增列最强基线**（以我方编译器重编对手）。
  **internal-A/B**：同一系统内两变体对比（如 tiling on/off）——只证机制，不得升级为对手胜利。
- **部署身份五验（e2e/seal 强制）**：符号 / 反汇编形态 / vl·VLEN 形态 / forward banner / **编译器身份**；外加**反向控制**（不加载我方 object 即失败）。出货 = clang 独立 `.o` 经正门链接；**禁止**把 emitted C 注入对手构建链由其编译器重编后仍声称"部署了已验证 kernel"。
- **选择器测量库主键增加"部署工具链"维度**（不同后端下变体排序可能翻转）。

## §3 表集定义

### T0 · Kernel 普查与六态板（成熟编译器·板无关）
- **行** = 分母键全集（钉 commit 定稿清单）。
- **列** = {当前六态（provenance 判定）、各正确性门状态（byte-exact/ULP、lit 矩阵）、每板硅封状态（objdump golden，单列跟踪不并入六态）、变体行索引}。
- **生成** = 状态机脚本 + provenance 清单；**CI** = 每 PR 重算；**里程碑** = M1 起常驻。

### T1 · C1 结构合取表（板无关·全二值）
- **行** = 每次家族接入事件（#1 RVV 基线快照、#2 IME、#3 SCALAR、（条件）#4 AME）。
- **列** = {F-1 家族名分支计数=0、F-2′ schema.def diff=∅、F-3 收容（仅家族目录+表行+文档）、F-6 独立性闭包 ∩ rvv.*=∅（独立家族适用，integrated 标 N/A）、F-5 模糊全过、五件套齐、shape-hash 前后}。
- **判定** = 全 pass 才算一次合法接入；**工件** = CI 日志。

### T1b · fail-closed 运行期表（合取的运行期半边）
- **行** = 事实扰动场景：{删除 rvv.v、删除 zvfh（闭包在/不在两态）、伪造 conflicts、注入未知事实、向量缺席实例、（板 C 一次性）RVV1.0×0.7.1 互斥共存}。
- **列** = {期望行为（拒绝 / only_feasible=标量族 / 冲突拒）、观察行为、装载期解析记录指针、pass/fail}。
- **注**：板 C 只出现在此表的一行，做完即归档。

### T1d · 同 schema 双实例演示表（C1 的"一图流"证据）
- **行** = 板 A 实例、板 B 实例（同一 schema shape，两个 instance-hash）。
- **列** = {instance-hash、合法变体集大小、被选变体集摘要、核心 diff=∅、归因日志样本指针}。
- **叙事** = "同一份 schema、两份事实、两套合法集与选择、核心零改动"——论文 Table 1 候选。

### T1c · 外部复制表（M4）
- **行** = 每次外部接入试验；**列** = {参与者类别、仅凭文档?、耗时、falsifier 结果、偏离清单}。

### T2 · C2 ledger 与边际曲线（板无关·源码）
- **行** = 家族序号；**列** = {代码行(cloc, 不含测试)、测试行、表行数、接口触点、日历天、**成本住址分解 {模式%, 谓词%, 测试%, 胶水%}**（按目录/文件分类自动算）}。
- **派生** = 边际曲线图（LOC vs 家族序号）；**锚** = 外部定性锚引用行 + ggml 逐家族分支代码量/churn 的量化砖行。
- **CI** = ledger 脚本自动生成，首家族数字必须可复算。

### T3 · 双板测量主表（C3′ + 成熟；板 A / 板 B 各一张）
- **行** = 测量行键（§1 双层键）。
- **列**（顺序即读法）=
  1. 六态 + provenance 指针；
