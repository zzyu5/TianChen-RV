# TianChen-RV 性能宪法与测量司法

> 全项目**最容易被失忆做错**的领域。每条规则都由血的教训换来:一批 kernel win 被整体撤回、一个"bug"翻案三次、一个融合优化 e2e 归零。总纲 v3 与实验总纲 v2 里有对应条款([L-9..L-12]/[K-5b,c]/[K-7]/[PERF-1,2]/§2.8-2.10),本文档是它们的**司法解释与操作手册**。

---

## 一、性能三层图(哪种赢是哪种赢)

大数字与小数字来源不同,措辞与账本必须分层:

| 层 | 是什么 | 数量级 | 例 |
|---|---|---|---|
| **L1 路径赢** | 编译器生成**对手清单里不存在**的执行路径 | 大数字唯一来源 | q4_0 路由赢(对手无该 repack 路径) |
| **L2 调度赢** | 同算法下按实例选对变体(布局/LMUL/tile/lane-width/schedule/数值档) | 全表正差底色、sealed 来源 | Win-K1-VLEN(满宽 + 循环序交换) |
| **L3 字节赢** | 改算法结构少搬字节(融合/格式传播) | 贴墙格唯一解药,常被 Amdahl 稀释 | 融合两腿(现为机制展示) |

**负面清单:指令微质量(vsetvli/spill/code size)非赛场**——但这条"非赛场"**仅在 kernel 账内成立**。系统账内,后端选择是系统身份的一部分(我方 L3=clang 出货是设计事实,不是作弊)。

## 二、双账本(红线;最重要的一条)

每条性能主张**必须标账本**:

- **kernel 账**(源码/算法/调度质量):双方**同编译器、同 flags、同 march、同链接**。**禁止"我方 clang 编 vs 对手 shipped gcc 编"登记为 kernel win**——此类历史数字已全部撤回。
- **系统账**(产品对拼):允许各用各的完整出货栈(我方 clang .o 是设计事实,对手用其系统编译器是它的现实;类比 Triton 由 LLVM 栈编译,不为此道歉),但**必须披露**双方编译器身份/flags/deployed object/集成方式/baseline 是否 shipped-best,并**尽力列最强基线**(以我方编译器重编对手——堵"你只是编译器好"这一刀)。
- **internal-A/B**:同系统内两变体对比(tiling on/off 等),只证机制,**不得升级为对手胜利**。
- **绝不混账**:kernel 账不证"真实系统收益",系统账不证"算法更优"。

> **这条怎么来的**:同一份 kernel 源码,clang 编出来赢对手近 2 倍,gcc 编出来输到 0.27×(spill 从 3 次变 742 次)。代码没变、数学没变,变的只是谁把它翻译成机器码。**我们曾把这个编译器差异当成了自己的算法优势。**

## 三、部署身份("部署的 ≠ 证过的",踩过三次)

任何 e2e/seal 主张必须核验**实际部署物**——**五验**:符号 / 反汇编形态 / vl·VLEN 形态 / forward banner / **编译器身份**。加**反向控制**:不加载我方 object 时测试必须失败(证明跑的确是目标 object)。

出货形态 = **clang 独立 .o 经对象导出正门链接**。**禁止**把 emitted C 注入对手构建链、由对手的编译器重编,却仍声称"部署了已验证的 kernel"——那等于**用对手的后端出货我们的 kernel**。

三次踩坑:①部署了错误 VLEN 变体(半宽核上宽板);②standalone 验证物与部署物不一致;③编译器身份(最贵的一次)。

## 四、测量纪律

**噪声自检**(替代 loadavg 硬闸,共享板现实):测前跑 3 次重测-重测 sanity,运行间 IQR ≤ 该基准类历史地板 ×1.5 → **立即开测**;loadavg 与邻居快照降为**记录项**(入指纹,供审计"当时板上有谁");测中 IQR 突劣 ≥3× → 会话作废重跑。

**0 样本永不造数**(红线)。被邻居污染时中止并如实报 void——**这是纪律不是失败**。

**协议全套**:同会话 A/B 交替、N≥10 中位数 + bootstrap CI、对手身份探针(且须确认对手是**该板 as-shipped 出货物**,不是稻草人)、T-N 效应规则、部署五验、byte-exact。

**预飞断言**:任何 perf harness 出数前自检双方编译器/flags/march 是否满足所声称账本的对称要求,不满足即**拒绝出数**。(这条若早立,可省掉一整轮撤回。)

## 五、micro↛e2e 铁律(三种稀释,每种都有实录)

kernel 级赢**不自动**传导到 e2e:

1. **Amdahl 稀释**——被优化的 kernel 在相内占比太小(融合案:占 decode 0.05%,e2e 归零)。
2. **冷流式内存墙**——micro 热缓存掩盖了权重重读代价(rvv 案:浅 token tile 导致权重冷流 4×,e2e 输 24%;循环序交换后翻正)。
3. **未接线**——emitted kernel 根本没被推理框架 forward 消费(当前头号原因:micro 赢得漂亮,e2e 1.05×,因为 forward 没路由到它)。

**归因顺序**:e2e 无增益时,**第一嫌疑永远是"没接线"**,不是"物理墙"。未在接线台账(T10)确认 on-path 的 kernel,其 e2e 数字不得用于任何主张。

**"接线 ≠ 转绿"**:接上线后仍须重做 Amdahl 与内存墙核算。IME 格接线后若不转绿,是预告过的物理/稀释,**不是失败**。

## 六、perf-covered(性能"立住"的定义)

用户要的性能是**覆盖面,不是孤点**:

```
perf-covered = 已构造格中,经公平协议(双账本+对手探针+[PERF-1])
               测得整模型 e2e ≥parity 或赢 的格数 / 已构造格数
```

**三层严格区分**:
- **绿格** = e2e 达标(计入 perf-covered);
- **内核轴候选** = kernel 账赢/平但未接线或未过 e2e 门(**不计入,也不得表述为"加速了 N 个 kernel"**);
- **机制/消融证据** = 模式消融、预测规律、选择器归因(不计格,但撑 C3′)。

**目标态**:T3 表**成片绿** + 每个非绿格**具名归因**,出口四选一 `{未接线 | 传导稀释(附 Amdahl 账) | 物理 parity-at-floor | 声明例外}`,**零含糊格**。单个 sealed Win 是必要不充分条件。

## 七、roofline 三档判读(防"parity=失败"误读)

- **compute-bound 段**(prefill GEMM、大 M):kernel 优势可显现,这是主战场。
- **memory-bound 段**(decode M=1、流式算子、norm):**parity 就是正确结果**——roofline 设计内预测,不是尴尬,不该强找虚假倍数。
- **物理 parity-at-floor**:已到墙,诚实入档。

判读须**预注册**(测之前就写好"什么结果算什么"),防止事后找补。

## 八、正确性司法(三次反转案的遗产)

**证书三要件**(进 CI,缺一即 cert 无效):
1. **语料完备**——每个算术项被非退化 exercise(某项恒为零的语料 = 该项从未通电,bug 潜伏到真数据才炸)。
2. **输入路径同源**——oracle 与被测 dispatch 逐环同源;cert 必须声明输入路径谱系(**用 row-quant oracle 验 mat-quant dispatch,制造出一个不存在的 bug,引发三次反转**)。
3. **oracle 独立**——不与被测物共享读取/解码实现("**空心证书**"禁令:共享实现让同错互相抵消,自洽却验不出共同缺陷)。

**ZERO-MODEL 终审法**:争议不靠"kernel vs 某 oracle"多轮互搏(oracle 自己可能就是错的那个)。终审 = **捕获真实 dispatch 输入 → 用被测系统自身原语从该输入重算 → 与 kernel 中间值逐位对**;再以独立实现对位复核。

**单证书永不定案;翻案须比定罪更严谨;定案后一次性恢复口径(禁双改)。**

## 九、[K-7] 首次发射律(C3′ 核心实证,四例连档)

> **首次发射的 kernel 功能正确但性能不成熟是常态;其成熟杠杆可具名、可由能力事实键控、可族级复制。**

四例:①输出瓦片化(寄存器悬崖);②循环序交换(冷流式内存墙);③满宽 lane-width(VLEN 事实没流进发射器);④叶批处理(逐指令仪式开销吃掉矩阵单元火力)。

每例结构同构:**暴露问题 → 反汇编/计数器归因 → 具名 GAP → 能力键控修复 → 板证**。

**推论(回答"性能覆盖怎么可能")**:每把杠杆都是**族级/范式级**的,所以 perf-covered 可以**按批变绿**,不必逐格硬凿。

## 十、迁移可预测性 [XFER-1](C3′ 最强证据形态)

优化能否迁移**不看格式名,看瓶颈形状**。三分类:

| 类 | 特征 | 瓦片化 |
|---|---|---|
| **register-cliff** | 压力来自可 staging 的 decode strip / 闲置累加器 | **HOLDS** |
| **weight-reconstruction-bound** | 压力来自不可 staging 的多平面权重重建 | **NULL** |
| **already-lean / gather-bound** | 已在悬崖以下,无可释放压力 | **结构性 no-op** |

**规则:预测必须在板测之前落盘**(事后解释不计分)。正例、负例、边界三类齐备,才配称"可预测的迁移规律"——这比"我们有一堆优化"高一个层次。
