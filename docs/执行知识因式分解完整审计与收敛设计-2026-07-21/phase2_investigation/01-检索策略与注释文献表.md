## 1. Search Strategy

### 1.1 Sources

优先检索和核验：

- 原始论文 PDF 与作者主页；
- USENIX、NeurIPS、ACM/IEEE conference page；
- Google Research、Microsoft Research 与项目官方 publication page；
- arXiv 原始预印本；
- DBLP/Crossref/DOI 只用于书目信息交叉核验，不作为技术结论的唯一来源。

没有用 Wikipedia、博客、新闻稿、Reddit 或论文解读支撑 novelty 判断。

### 1.2 Search Concepts

检索围绕六组概念展开：

```text
(program generation OR staged compilation OR multi-stage programming)
AND (typed code OR kernel generation)

(composable primitives OR rewrite rules OR scheduling language)
AND (high-performance kernels OR hardware accelerators)

(construction-based tensor compiler OR recursive construction)
AND (hardware characteristics OR performance model)

(autotuning OR empirical optimization OR learned cost model)
AND (analytic model OR templates OR codelets)

(low-precision OR quantized inference OR nonuniform quantization)
AND (kernel generator OR compiler)

(extensible compiler infrastructure OR dialect OR plugin)
AND (heterogeneous hardware OR domain-specific computation)
```

并对 SPIRAL、FFTW、Halide、TVM、Ansor、Exo、Exo 2、ROLLER、MetaSchedule、TensorIR、MLIR、BuildIt、LIFT、Ladder、Bolt 与 QIGen 做精确标题检索。

### 1.3 Date and Language

- 时间：1997–2026；老文献仅保留奠基性系统。
- 语言：英文。
- 文献类型：peer-reviewed compiler/systems/PL/HPC paper；QIGen 2026 已取得正式出版 PDF，并与官方会议页、DOI 和作者公开 artifact 交叉核验。

### 1.4 Inclusion Criteria

文献至少直接覆盖以下一项：

1. 从静态输入或领域知识生成/特化代码；
2. 用可组合 primitives、rules、codelets 或 scheduling operations 形成实现；
3. 构造候选/program space，并用解析模型或经验测量选择；
4. 支持新的 hardware primitive、custom datatype 或 accelerator；
5. 直接生成量化/低精度推理 kernel；
6. 为 typed、可扩展、多层 compiler 提供架构基础。

### 1.5 Exclusion Criteria

- 只研究量化精度而不研究 kernel/compiler construction；
- 只报告一个手写 kernel 技巧；
- 只做 runtime scheduling；
- 只提供二手总结；
- 与核心文献重复且没有增加新的 construction/knowledge 维度。

### 1.6 Screening Flow

检索接口没有提供稳定的全局命中总数，因此不制造虚假的精确 PRISMA 数字。实际筛选过程为：

```text
搜索结果页：超过 100 条，含大量重复、二手材料和无关结果
→ 标题/摘要高相关候选：24
→ 原始全文或官方论文页详细核验：19
→ 核心纳入：17
→ 核心表排除：2
   - ATLAS：经验自动调优意义明确，但与 FFTW/SPIRAL 在本问题上的证据高度重叠
   - TileLang：可组合 tiled DSL 很相关，但截至本轮主要依赖 2025 预印本，且不如 Exo 2/Ladder/QIGen 接近当前问题
```

## 2. Annotated Bibliography

### Theme A：程序生成、规则与经验反馈的历史先例

#### 1. FFTW

**Frigo, M., & Johnson, S. G. (1998). FFTW: An adaptive software architecture for the FFT. In *Proceedings of the 1998 IEEE International Conference on Acoustics, Speech and Signal Processing* (Vol. 3, pp. 1381–1384). IEEE. https://doi.org/10.1109/ICASSP.1998.681704**

- 原始来源：[FFTW 官方论文 PDF](https://www.fftw.org/fftw-paper-icassp.pdf)
- Relevance：FFTW 把 executor、可组合 codelets、plan、planner 和真实性能测量分开，是 `mechanisms + plan + empirical residual` 的早期强先例。
- Key finding：planner 通过测量不同 codelet compositions 选择 plan；codelets 又由专用 generator 自动产生。
- 对 Weft 的压力：不能声称“可组合机制 + plan + 测量选择”本身新颖。Weft 必须解释 analytic construction、typed change axes、bounded residual 和多格式 execution layer 的新增内容。
- Quality：peer-reviewed 系统论文；跨 40 多种实现和 7 台机器比较，属奠基性证据。

#### 2. SPIRAL

**Püschel, M., Moura, J. M. F., Johnson, J. R., Padua, D., Veloso, M. M., Singer, B. W., Xiong, J., Franchetti, F., Gačić, A., Voronenko, Y., Chen, K., Johnson, R. W., & Rizzolo, N. (2005). SPIRAL: Code generation for DSP transforms. *Proceedings of the IEEE, 93*(2), 232–275. https://doi.org/10.1109/JPROC.2004.840306**

- 原始来源：[作者 PDF](https://www.cs.cmu.edu/~mmv/papers/05SpiralIEEE.pdf)
- Relevance：当前最强概念近邻。SPIRAL 用 transform definitions、breakdown/manipulation rules、applicability、ruletrees、formulas、code mapping 和 feedback search 自动生成整族高性能实现。
- Key finding：领域知识被表示为少量规则；规则递归产生公式空间，经验 search/learning 在结构化空间中找平台适配实现；新增规则可影响整个 transform collection。
- 对 Weft 的压力：不能把“专家知识变成公式并生成实现 family”“解析规则与经验反馈结合”写成首创。Weft 必须在不规则量化格式、typed capability/context、execution-layer extension 与 sparse residual 的具体组织和证据上形成差额。
- Quality：长篇 peer-reviewed invited paper，包含形式、实现与多平台比较；奠基性 A 级来源。

#### 3. PetaBricks

**Ansel, J., Chan, C., Wong, Y. L., Olszewski, M., Zhao, Q., Edelman, A., & Amarasinghe, S. (2009). PetaBricks: A language and compiler for algorithmic choice. In *Proceedings of the 30th ACM SIGPLAN Conference on Programming Language Design and Implementation* (pp. 38–49). ACM. https://doi.org/10.1145/1542476.1542481**

- 原始来源：[MIT 作者 PDF](https://people.csail.mit.edu/jansel/papers/2009pldi-petabricks.pdf)
- Relevance：把多算法选择、组合与 autotuning 变成语言一等概念。
- Key finding：compiler 能在细粒度与算法级选择之间构造 hybrid algorithm，并针对体系结构、问题规模和精度调优。
- 对 Weft 的压力：candidate family 与 empirical selection 并不新；Weft 需要证明 measurement 只是稀疏残差，而不是一个换名后的普遍 autotuner。
- Quality：PLDI peer-reviewed paper，有 compiler 与 benchmark suite。

#### 4. Halide

**Ragan-Kelley, J., Adams, A., Paris, S., Levoy, M., Amarasinghe, S., & Durand, F. (2012). Decoupling algorithms from schedules for easy optimization of image processing pipelines. *ACM Transactions on Graphics, 31*(4), Article 32. https://doi.org/10.1145/2185520.2185528**

- 原始来源：[作者项目页与论文](https://people.csail.mit.edu/jrk/halide12/)
- Relevance：确立 algorithm 与 schedule 分离，schedule 包括 tiling、fusion、storage、vectorization 和 parallelism。
- Key finding：同一 algorithm 可通过不同 schedule 跨 ARM、x86 与 GPU 获得高性能。
- 对 Weft 的压力：把 compute semantics 与 execution choices 分离不是新颖点。Weft 的差额不能只是换成 format/mechanism/plan 术语，而应说明 irregular quantization facts、capability-conditioned mechanism construction 和 residual boundary 如何超出 algorithm/schedule separation。
- Quality：SIGGRAPH/TOG peer-reviewed，跨多 pipeline 与平台验证。

### Theme B：typed staging、可扩展 compiler 与可组合变换

#### 5. LIFT

**Steuwer, M., Remmelg, T., & Dubach, C. (2017). LIFT: A functional data-parallel IR for high-performance GPU code generation. In *2017 IEEE/ACM International Symposium on Code Generation and Optimization* (pp. 74–85). IEEE. https://doi.org/10.1109/CGO.2017.7863730**

- 原始来源：[项目论文 PDF](https://lift-project.github.io/publications/2017/steuwer17LiftIR.pdf)
- Relevance：使用 functional patterns 与 rewrite rules 表示算法和硬件映射选择，并生成接近手工性能的 OpenCL。
- Key finding：高层 pattern semantics 支撑 rewrite-based exploration 和低层 memory/synchronization realization。
- 对 Weft 的压力：`typed mechanisms + rewrite/composition + hardware mapping` 已有直接先例。Weft 必须展示其 mechanisms 并非一般 map/reduce patterns，而是能够跨量化格式与 capability 重建 execution-family 结构。
- Quality：CGO peer-reviewed，受控 benchmark comparison。

#### 6. TVM

**Chen, T., Moreau, T., Jiang, Z., Zheng, L., Yan, E., Shen, H., Cowan, M., Wang, L., Hu, Y., Ceze, L., Guestrin, C., & Krishnamurthy, A. (2018). TVM: An automated end-to-end optimizing compiler for deep learning. In *13th USENIX Symposium on Operating Systems Design and Implementation* (pp. 578–594). USENIX Association.**

- 原始来源：[USENIX 论文页](https://www.usenix.org/conference/osdi18/presentation/chen)
- Relevance：将高层图优化、low-level tensor program、硬件 primitive 映射和 learned cost-model search 结合起来。
- Key finding：跨 CPU、GPU 与 accelerator 生成和调优 tensor operators，性能接近手工库。
- 对 Weft 的压力：跨后端、hardware-aware codegen 与 learned empirical choice 均非新。Weft 应保持在 high-level MLIR 之后的 execution-layer 范围，不与通用 tensor compiler 争夺相同主张。
- Quality：OSDI peer-reviewed，多平台系统评估。

#### 7. MLIR

**Lattner, C., Amini, M., Bondhugula, U., Cohen, A., Davis, A., Pienaar, J. A., Riddle, R., Shpeisman, T., Vasilache, N., & Zinenko, O. (2021). MLIR: Scaling compiler infrastructure for domain specific computation. In *2021 IEEE/ACM International Symposium on Code Generation and Optimization* (pp. 2–14). IEEE. https://doi.org/10.1109/CGO51591.2021.9370308**

- 原始来源：[Google Research 官方页](https://research.google/pubs/mlir-scaling-compiler-infrastructure-for-domain-specific-computation/)
- Relevance：提供 extensible dialect、多层 abstraction 和 heterogeneous compiler infrastructure 的直接架构先例。
- Key finding：通过可扩展 IR/operation/type/pass infrastructure 连接不同领域、硬件与执行环境。
- 对 Weft 的压力：typed dialect、progressive lowering 和 extension infrastructure 不能单独构成 novelty；Weft 的柱一必须由 execution-layer contract、局部变化与真实第二 family 证明。
- Quality：CGO peer-reviewed infrastructure paper；设计证据强，性能因果证据不是其重点。

#### 8. BuildIt

**Brahmakshatriya, A., & Amarasinghe, S. (2021). BuildIt: A type-based multi-stage programming framework for code generation in C++. In *2021 IEEE/ACM International Symposium on Code Generation and Optimization* (pp. 39–51). IEEE. https://doi.org/10.1109/CGO51591.2021.9370333**

- 原始来源：[MIT 作者 PDF](https://commit.csail.mit.edu/papers/2021/ajay-cgo21-buildit.pdf)
- Relevance：展示 typed multi-stage C++ framework 如何从 generation-time inputs 构造下一阶段 AST/control flow。
- Key finding：用类型决定 binding time，并在不修改 host C++ compiler 的情况下提取条件、循环和代码结构。
- 对 Weft 的压力：从静态 typed inputs 构造代码不新；Weft 的贡献必须来自 execution knowledge 的领域分解、compiler integration 与跨组合重建结果，而不是 staging 技术本身。
- Quality：CGO peer-reviewed，并获得 artifact available/evaluated/reproduced badges。

#### 9. Exo

**Ikarashi, Y., Bernstein, G. L., Reinking, A., Genc, H., & Ragan-Kelley, J. (2022). Exocompilation for productive programming of hardware accelerators. In *Proceedings of the 43rd ACM SIGPLAN International Conference on Programming Language Design and Implementation* (pp. 703–718). ACM. https://doi.org/10.1145/3519939.3523446**

- 原始来源：[作者完整论文 PDF](https://people.csail.mit.edu/yuka/pdf/exo_pldi2022_full.pdf)
- Relevance：将 hardware instructions、special memories、configuration state 与 optimization policy 外置到 user code，并用 composable rewrites 构造高性能 kernels。
- Key finding：小型可信 core 加用户可扩展 scheduling/backend，能针对 Gemmini 与 AVX-512 生成接近 state-of-the-art 的 kernels。
- 对 Weft 的压力：可扩展 hardware abstraction、fine-grained rewrites 和 performance-engineer knowledge externalization 已被明确提出。Weft 不能仅凭 plugin/provider 复述这一点；需证明 `g/c/ω` 自动构造 family 实例以及 analytic/residual 分工。
- Quality：PLDI peer-reviewed，含形式 safety analysis 和多硬件 kernel evaluation。

#### 10. Exo 2

**Ikarashi, Y., Qian, K., Droubi, S., Reinking, A., Bernstein, G. L., & Ragan-Kelley, J. (2025). Exo 2: Growing a scheduling language. In *Proceedings of the 30th ACM International Conference on Architectural Support for Programming Languages and Operating Systems, Volume 1* (pp. 426–444). ACM. https://doi.org/10.1145/3669940.3707218**

- 原始来源：[arXiv 完整版](https://arxiv.org/abs/2411.07211)；[Exo 官方 publication 列表](https://exo-lang.dev/)
- Relevance：允许用户从可信细粒度 primitives 组合新的 scheduling operations 和 libraries，直接研究“知识如何跨 kernel 摊薄”。
- Key finding：其 scheduling libraries 覆盖 80 多个高性能 kernel，显著降低 schedule code，并在三类平台保持竞争性能。
- 对 Weft 的压力：rule fan-out、可组合 primitive 与 family-level amortization 已有很强证据。Weft 的 fan-out 实验必须证明不同维度：由 facts/capability/context 自动实例化不规则量化 family，而非人工 scheduling library 的复用。
- Quality：ASPLOS 2025 peer-reviewed；原始全文与 DOI 均可核验。

### Theme C：program-space construction、analytic model 与 empirical search

#### 11. Ansor

**Zheng, L., Jia, C., Sun, M., Wu, Z., Yu, C. H., Haj-Ali, A., Wang, Y., Yang, J., Zhuo, D., Sen, K., Gonzalez, J. E., & Stoica, I. (2020). Ansor: Generating high-performance tensor programs for deep learning. In *14th USENIX Symposium on Operating Systems Design and Implementation* (pp. 863–879). USENIX Association.**

- 原始来源：[USENIX 论文页](https://www.usenix.org/conference/osdi20/presentation/zheng)
- Relevance：从 hierarchical search-space representation 采样 programs，再以 evolutionary search 和 learned cost model 找实现。
- Key finding：能找到旧模板搜索空间之外的高性能 tensor program，并跨 Intel/ARM CPU 与 NVIDIA GPU 提升性能。
- 对 Weft 的压力：自动生成 candidate space 与经验选择已非常成熟。Weft 要强调有限 analytic construction 与 bounded residual，而不是另一个更小的 autoscheduler。
- Quality：OSDI peer-reviewed，多平台受控比较。

#### 12. ROLLER

**Zhu, H., Wu, R., Diao, Y., Ke, S., Li, H., Zhang, C., Xue, J., Ma, L., Xia, Y., Cui, W., Yang, F., Yang, M., Zhou, L., Cidon, A., & Pekhimenko, G. (2022). ROLLER: Fast and efficient tensor compilation for deep learning. In *16th USENIX Symposium on Operating Systems Design and Implementation* (pp. 233–248). USENIX Association.**

- 原始来源：[USENIX 论文页](https://www.usenix.org/conference/osdi22/presentation/zhu)
- Relevance：最直接使用“construction-based approach”的近邻；用与硬件特征对齐的 rTile 递归构造 rProgram，并用 micro-performance model 评价。
- Key finding：限制形状选择后可在数秒内构造高效 kernel，减少巨型经验 search。
- 对 Weft 的压力：`analytic construction instead of broad search` 也不是空白。Weft 必须说明其对象不是 tensor tiling，而是复杂量化 execution mechanisms、capability/context 与边界的因式分解。
- Quality：OSDI peer-reviewed，多 accelerator 对比。

#### 13. MetaSchedule

**Shao, J., Zhou, X., Feng, S., Hou, B., Lai, R., Jin, H., Lin, W., Masuda, M., Yu, C. H., & Chen, T. (2022). Tensor program optimization with probabilistic programs. In *Advances in Neural Information Processing Systems* (Vol. 35, pp. 35783–35796).**

- 原始来源：[NeurIPS 官方论文页](https://proceedings.neurips.cc/paper_files/paper/2022/hash/e894eafae43e68b4c8dfdacf742bcbf3-Abstract-Conference.html)
- Relevance：让领域专家用 probabilistic-programming abstraction 模块化组合 transformations 和 stochastic choices，显式关注可增长的 search space。
- Key finding：模块化覆盖既有 autoscheduler search space，并允许专家增加规则；配合 learning-driven search 获得 end-to-end 增益。
- 对 Weft 的压力：知识模块化与经验选择结合已经存在。Weft 必须用 residual density 证明经验部分有界，并展示 formula 构造的是 execution semantics/plan，而非一般随机 schedule choice。
- Quality：NeurIPS peer-reviewed，官方全文和 supplemental 可得。

#### 14. TensorIR

**Feng, S., Hou, B., Jin, H., Lin, W., Shao, J., Lai, R., Ye, Z., Zheng, L., Yu, C. H., Yu, Y., & Chen, T. (2023). TensorIR: An abstraction for automatic tensorized program optimization. In *Proceedings of the 28th ACM International Conference on Architectural Support for Programming Languages and Operating Systems, Volume 2* (pp. 804–817). ACM. https://doi.org/10.1145/3575693.3576933**

- 原始来源：[TVM 官方 publication metadata](https://mlc.ai/docs/reference/publications.html)；[arXiv 原文](https://arxiv.org/abs/2207.04296)
- Relevance：将 tensor computation primitives、hardware constraints、loop nests 与 transformation primitives 统一到可自动 tensorize 的 IR。
- Key finding：block abstraction 隔离 tensorized computation，并与 loop/thread/memory transformation 联合优化。
- 对 Weft 的压力：typed primitive、hardware constraint 和自动组合已有直接实现。Weft 的 typed mechanisms 必须在 irregular block quant execution layer 中证明不可被普通 tensorized block abstraction吸收。
- Quality：ASPLOS peer-reviewed，跨后端性能比较。

#### 15. Bolt

**Xing, J., Wang, L., Zhang, S., Chen, J., Chen, A., & Zhu, Y. (2022). Bolt: Bridging the gap between auto-tuners and hardware-native performance. *Proceedings of Machine Learning and Systems, 4*。**

- 原始来源：[MLSys 官方论文页](https://proceedings.mlsys.org/paper_files/paper/2022/hash/1f8053a67ec8e0b57455713cefdd8218-Abstract.html)
- Relevance：以 hardware-native templated search 结合可组合 vendor primitives 与轻量 profiling。
- Key finding：指出纯 tensor autoscheduler 可能远落后于专家模板；复用和组合 CUTLASS primitives 后缩短调优并提升生产性能。
- 对 Weft 的压力：`expert mechanisms + templated construction + bounded measurement` 极其接近。Weft 需要证明自己的 analytic knowledge 和 boundary model不只是另一个模板参数搜索层。
- Quality：MLSys peer-reviewed，生产部署与受控比较；作者评估自有系统的 intellectual COI 需由其他来源交叉约束。

### Theme D：低精度与量化 kernel 的最接近工作

#### 16. Ladder

**Wang, L., Ma, L., Cao, S., Zhang, Q., Xue, J., Shi, Y., Zheng, N., Miao, Z., Yang, F., Cao, T., Yang, Y., & Yang, M. (2024). Ladder: Enabling efficient low-precision deep learning computing through hardware-aware tensor transformation. In *18th USENIX Symposium on Operating Systems Design and Implementation* (pp. 307–323). USENIX Association.**

- 原始来源：[USENIX 官方论文页](https://www.usenix.org/conference/osdi24/presentation/wang-lei)
- Relevance：直接面向持续演化的低精度 datatype，以 tType、extended tensor expression、scheduling primitives 和 hardware-aware policy 生成优化 pipeline。
- Key finding：将 custom datatype 作为一等对象，系统支持多种低比特格式和现代 accelerator，而无需修改硬件。
- 对 Weft 的压力：`typed low-precision facts + hardware-aware transformations + systematic format support` 已是已发表系统贡献。Weft 必须收窄到 ggml block-quant execution layer、RISC-V capability、跨 op/family mechanism reconstruction 与 residual/boundary 证据。
- Quality：OSDI peer-reviewed，artifact 可用，跨 NVIDIA/AMD 等平台验证。

#### 17. QIGen 2026

**Pegolotti, T., Alistarh, D., & Püschel, M. (2026). QIGen: A kernel generator for inference on nonuniformly quantized large language models. In *2026 IEEE/ACM International Symposium on Code Generation and Optimization* (pp. 589–602). IEEE. https://doi.org/10.1109/CGO68049.2026.11395231**

- 原始来源：[本地正式论文 PDF](../QIGen_A_Kernel_Generator_for_Inference_on_Nonuniformly_Quantized_Large_Language_Models.pdf)、[CGO 2026 官方论文页](https://2026.cgo.org/details/cgo-2026-papers/7/QIGen-A-Kernel-Generator-for-Inference-on-Nonuniformly-Quantized-Large-Language-Mode)、[公开 artifact](https://zenodo.org/records/16894301)
- Relevance：当前领域最危险的直接近邻。它针对 CPU 上非均匀量化 LLM，给定量化模型与 target CPU characteristics，生成多种 custom MVM kernels 并匹配 storage format。
- Full-text finding：系统把 quantizer 输出翻译为 W/S/Z，枚举 unique `(M,K,g,b)`，由 cache model 和 grid search 生成/调优 GEVM/GEPM LLVM microkernel，再按每层 group 序列组合，合并相邻同类 group。它是真实的 group/microkernel-level construction，不是 whole-matrix leaf lookup。
- Leaf-boundary finding：2/3/4/5/6/8-bit microkernel 的完整 unpack/shift/mask/dot 过程仍由 `switch(bits)` 编码。QIGen 分解到 group/microkernel composition，但正文没有展示更细的 intra-microkernel semantic mechanism construction。
- Evaluation finding：x86→ARM port 包含手工 signedness 语义适配，但性能实验只在 Intel；kernel/layer 评价明确不含完整 end-to-end runtime，TPOT/TTFT 是模拟/推算。
- 对 Weft 的压力：不能声称“首个按量化格式和 CPU 特征生成 LLM kernel”，也不能把非均匀 group composition、GEVM/GEPM、analytic+search 或 CPU retargeting 本身作为首次。剩余假说必须落在完整 microkernel leaf 以下、异质 GGML topology、多 op/backend、受限 residual 与真实 authority-erasure reconstruction。
- Quality：CGO 2026 peer-reviewed；正式全文、DOI、会议页与公开 artifact 已交叉核验，足以进行论文级直接差分。

## 3. Coverage Gaps After Phase 2 Search

1. QIGen 的全文缺口已关闭；它对 group/layer composition、analytic+search 和 CPU retargeting 的覆盖比早期 artifact-only 判断更强。
2. 现有文献很少直接使用 Weft 拟议的 `M/F/B/R` 四角色术语，但功能成分广泛存在；术语空白不能自动等于概念空白。
3. 剩余直接差额只可能位于完整 per-bit/per-format microkernel leaf 以下，并覆盖 QIGen 仿射 group 模型之外的 GGML 语义拓扑。
4. 文献很少同时报告 rule-level causal fan-out、point-authority erasure、residual coverage/intervention 和真实端到端部署。它们是有辨识力的 evaluation design，但指标本身不应包装成独立 novelty。
5. prospective holdout 只在主张 unseen/generalization 时必要；多 topology 的严格删除与因果实验更直接检验当前 system claim。
6. 外部文献不能回答当前 Weft 是否真正构造；该问题仍必须由源码与实验审计回答。
