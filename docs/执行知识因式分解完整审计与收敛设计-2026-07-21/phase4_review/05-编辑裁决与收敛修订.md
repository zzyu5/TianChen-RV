# 05｜ARS 阶段四：编辑裁决与收敛修订

> **Editorial decision**：**Major Revision，方向接受，主张暂不冻结。**
>
> 这不是对两柱、原构造公式或项目价值的否定。它表示：目标架构已经足够清楚，可以指导后续最小重构；但在多 topology 的真实 reconstruction、第二 operation/backend 因果证据、稀疏 residual 与重构后硬件/端到端结果完成前，不能把目标态写成当前已实现或已证明的 novelty。QIGen 全文差分已在 Phase 5 关闭。

## 0. 最终裁决

### 0.1 保留什么

以下内容通过审查，应继续作为后续 method/spec 收敛的基线：

1. 两柱不变；
2. 六律不是六个平行贡献，也不是工程进度门；
3. 原构造公式是柱二的贡献主体；
4. selector 只是构造式外的薄选择；
5. Weft-RV 是完整 execution-layer compiler，不是公式到 emitter 的玩具管线；
6. capability、typed mechanisms、body construction、backend、ABI、runtime 和真实硬件证据都属于 compiler 本体；
7. measurement 只允许修正已构造、已合法候选的残差；
8. provider/verifier 是普通实现技术，不是第一性原理；
9. reconstruction 是未来要做到的目标，不是当前事实或当前代码的准入门；
10. spec 只需小范围去历史、纠错和补目标态，不应再次大修科研主线。

### 0.2 降级什么

以下内容不能独立承担 novelty：

- `M/F/B/R` 的命名；
- knowledge factorization 的抽象口号；
- rule/mechanism composability；
- analytic construction；
- typed plugin compiler；
- legality-first selection；
- bounded measurement；
- code deduplication；
- 达到某个内部 CM 等级。

它们可以共同解释系统，但只有在特定问题、特定构造对象和严格证据上形成的差额才可能成为论文贡献。

### 0.3 当前最准确的研究状态

> **当前 Weft-RV 已有真实而复杂的 capability-driven typed execution-layer compiler，以及若干 stage-local structural construction substrate；但 block-quant 主路径仍以 CM1/CM2 和逐点 compute authority 为主，尚未证明能在删除完整 point implementation 后由 `g/c/ω + mechanisms + formula` 重建实例。后续工作的核心正是把这一目标做成真实 compiler 事实。**

这句话必须同时出现在稳定 method 与后续 spec 更新中，避免把“目标态”误写成“已完成”。

## 1. 最终概念模型：保留公式，明确工程职责

### 1.1 唯一理论中心仍是原构造式

\[
\theta_{i,v}=f^A_{i,v}(g,c,\omega)
\]

\[
K_{v,\omega}(g,c)
=
Emit_v(c)\circ
\bigoplus_i
\left\{
m_{i,v}(g,\omega)
\text{ with }
\theta_{i,v}
\right\}
\]

任何 `Plan`、`Compose`、`P_v`、mechanism graph 或 selected typed body 都只能是上述构造项的工程展开；若无法逐项映射回 `m + θ`，就不能用它替换主公式。

### 1.2 `M/F/B/R` 只作为工程解释

可把目标实现中的知识职责解释为：

- **M · mechanisms**：可复用的 typed 语义变换或资源 idiom；
- **F · analytic knowledge**：从 `g/c/ω` 推导 `θ`、mechanism choice/composition、candidate structure、资源需求与 analytic prior；
- **B · boundaries**：显式判断 applicability、legality、resource admissibility、fallback 与 negative case；
- **R · residual**：只在有限合法候选中保存无法稳定解析判断的经验 winner。

这四者不是四个新贡献，也不是四层必须统一成同一 C++ ABI 的框架。

为避免重新解释原公式，必须保留这一关系：

> 理论上，构造公式及其解析知识定义 candidate 和合法域所需的条件；工程上，F 产生候选、参数和资源要求，B 对这些条件作显式 applicability/legality 判定。B 不是独立于公式的新 compute authority，更不能由 verifier 反向定义算法。

### 1.3 thin selector 的边界

selector 可以：

- 读取合法候选集；
- 使用 analytic prior；
- 在 qualified/fresh/selection-valid 的有限 residual 中选择 winner；
- miss 时回到 prior；
- 空集时 fallback 或 reject。

selector 不可以：

- 由 point identity 创造一份新 body；
- 通过 winner key 携带 decode/scale/offset 语义；
- 绕过 boundary；
- 让 emitter 再次选择；
- 让 runtime observer 进入当前主系统。

## 2. QIGen 追加核验后的 novelty 裁决

### 2.1 全文已经核验的事实

QIGen 2026 的[正式全文](../QIGen_A_Kernel_Generator_for_Inference_on_Nonuniformly_Quantized_Large_Language_Models.pdf)、[官方会议页](https://2026.cgo.org/details/cgo-2026-papers/7/QIGen-A-Kernel-Generator-for-Inference-on-Nonuniformly-Quantized-Large-Language-Mode)与[公开 artifact](https://zenodo.org/records/16894301)已经交叉核验。正文显示：

- 输入是非均匀量化模型和目标 CPU 特征；quantizer 输出由手工 translation layer 转为 W/S/Z；
- 系统枚举 unique `(M,K,g,b)`，为每个 tuple 生成 GEVM/GEPM LLVM microkernel；
- cache model 决定主要 blocking，随后用 grid search 选择寄存器/unroll 参数；
- layer generator 按非均匀 group 序列组合 microkernels，并合并相邻同 `(g,b)` group；
- packing/storage 与 bitwidth/group 协同；
- 具体 2/3/4/5/6/8-bit unpack、shift、mask、dot 算法仍由完整 `switch(bits)` body 编码；
- x86→ARM port 包含手工 signedness 语义适配，但性能实验只在 Intel；TPOT/TTFT 为模拟推算，并非完整端到端运行。

因此已经可以下的结论比“只读到摘要”更强：

> **QIGen 已覆盖由非均匀量化描述、CPU 相关参数和经验搜索生成并组合 CPU kernel 的宽泛命题。Weft-RV 不能把 family composition、cross-combination generation、GEVM/GEPM、analytic+search 或 CPU retargeting 本身作为首次贡献。**

### 2.2 已确认的构造边界

QIGen 已经在 layer/group 粒度完成 family construction，不应被描述成 template lookup。其更深的边界是：完整 per-bit microkernel 算法仍住在 bitwidth-indexed body 中；正文也没有报告 point-leaf deletion、rule-level causal mutation、residual coverage/intervention 或真实 end-to-end runtime。

这只允许下有限结论：QIGen 所展示的因式分解粒度停在完整 microkernel unit。不能把“没有使用我们的术语”写成“没有 boundary/factorization”，也不能把论文未报告某项实验推成系统原则上做不到。

### 2.3 暂定可辩护差额

全文核验后，最窄且仍值得验证的目标是：

> 在 high-level MLIR 之后的 RISC-V execution layer 中，把异质 GGML/llama.cpp block-quant 的编码拓扑、scale/bias/layout 语义、能力条件、静态上下文和可复用 typed mechanisms 放入真实 compiler authority chain；把因式分解推进到完整 per-bit/per-format microkernel leaf 以下，在删除 point compute authority 后仍能跨 topology、operation/backend 重建 typed implementation，并证明 measurement 只修正稀疏的合法性能残差。

这是 **novelty hypothesis**，不是当前已确认的 novelty。若最终只能证明一次 q5_1 代码去重，则应诚实降级为系统工程贡献。

## 3. 对“新六律”候选的语义血缘审查

本轮无权直接修改 canon 中的六律，只给论文 agent/严格评审提供微调建议。

### 3.1 可以保留的意图

六个候选方向与两柱总体相容：

1. 变化归位；
2. 知识因式分解；
3. 族先于点；
4. 公式构成；
5. 解析主导、测量修残；
6. 证据回流。

它们应继续是相互支撑的设计纪律，不应被写成六个平行 novelty 或六道成熟度门。

### 3.2 三处必须微调，防止重新解释

#### 律三：不要把所有逐点知识都叫 empirical residual

“逐点规则只能是 residual”过宽。应区分：

- 完整逐点 implementation 或逐点 performance winner：应被压缩为共享知识或 bounded residual；
- 格式自身不可约的语义事实：可以留在 `g`；
- 真正新增且不可再分的语义 primitive：可以新增 M；
- 安全/ABI/ISA 的 point-specific negative boundary：可以留在 B。

否则新格式的真实新语义会被错误归类为 measurement residual。

#### 律四：formula 构造要求，boundary 作判定

formula 可以输出 mechanism choice、candidate structure、plan 参数、资源要求和 analytic prior。合法域仍属于柱二的解析知识，但工程上应由显式 boundary 根据这些要求和 `c/ω` 作 admissibility 判定。不要让 formula、boundary、provider 和 verifier 四处重复决定同一件事。

#### 律五：解析主导不等于 F 独占所有 legality

可写成：

```text
analytic construction：候选、机制组合、参数、资源要求、prior
explicit boundary：适用性、合法性、资源可容纳性、fallback/negative
measurement residual：合法候选内的有限排序修正
```

这只是明确职责，不是把 boundary 提升成第三柱或新贡献。

### 3.3 当前 headline 必须改成目标态语气

在 reconstruction 尚未实现前，不能写：

> This factorization enables the compiler to reconstruct ...

当前只能写成：

> Weft-RV investigates whether execution-layer expertise can be factorized so that a typed compiler reconstructs ...

或在中文 method 中写“目标是使……能够”。只有完成相应证据后，才把时态改成已实现。

## 4. 后续代码重构的最小因果路线

以下是方法蓝图，不是 task，也不是开工审批系统。

### 4.1 第一项实现里程碑：q5_1 authority erasure

目标不是删除函数数量，而是删除 q5_1 的全部 procedural authority：

```text
q5_1 independent format facts
  → generic low-nibble mechanism
  → generic optional high-bit-plane merge
  → generic affine scale/offset fold
  → capability-conditioned plan parameters
  → typed GEMV/GEMM bodies
  → mechanical RVV realization/emission
```

必须从 treatment path 移出的对象包括：

- `lowerToRepackGemvQ51`；
- `lowerToRepackGemmQ51`；
- 上游 Q51 full-builder dispatch；
- 等价的 provider/registry plan row；
- emitter/fallback 中能恢复完整 q5_1 body 的分支；
- q5_1 专属 winner 对 construction/correctness 的影响。

旧实现可以保留在独立 baseline/oracle 构建中用于对照，但不能链接回 treatment path。

### 4.2 raw identity 到 independent facts 的防火墙

format identity 可以用于解析输入、诊断和错误信息；进入 family construction 后，承重控制流只能读取独立语义 facts，例如：

- block/stride/offset；
- bit width 与 signedness；
- low/high-plane topology；
- scale/offset topology；
- activation layout；
- regime 与 capability facts。

facts 不能包含 body ID、leaf enum、有序 operation script 或只识别 q5_1 的组合指纹。这个边界应主要由数据结构和 production tests体现，不要求建立新的 universal verifier。

### 4.3 第一条实现路线只做 family construction，不大修 compiler

建议按以下范围收敛：

1. 保留当前 dialect、plugin、pass、ABI、runtime 与 bench 体系；
2. 把 flat repack 的 format facts 正交化；
3. 抽出真正跨 q4/q5 复用的 decode/fold mechanisms；
4. 用原公式的工程展开构造 GEMV/GEMM typed body；
5. 删除 Q51 point authority；
6. 让既有 resource decision 在 emission 前承重；
7. emitter 只实现已经选定的 typed structure；
8. 先跑 analytic-only，再加入 bounded residual。

这是一条局部但真实的 compiler 重构，不要求引入大一统 Formula IR、统一所有 family 的 C++ Plan，或重写整个 spec。

### 4.4 第二证据必须跨出 flat affine topology

短期可以把 Codebook 作为不同 topology 的 CM3 pilot，把 IME 作为第二 backend 的 authority-cleanup pilot；但在出现真实 formula-to-typed-body reconstruction 前，二者都不能被计作第二 CM4。

论文级确认不能只增加一个相似的 flat q4/q5 点。q5_1 跑通后，应覆盖至少一种超出 QIGen 仿射 `(g,b,s,z)` group 模型的真实 topology，例如 KQuant 的量化 scale/min superblock、codebook/grid 或 ternary/q1，并让另一 operation/backend 展示真实 `g/c → mechanisms → typed body` 因果链。

若论文只主张定义域内的 family construction，多 topology 的严格 authority erasure 和因果实验即可直接检验；只有要写 unseen/generalization 时，才在 mechanism/formula 冻结后另选 prospective witness。

### 4.5 IME 与 Scalar 的目标边界

- IME 保留自己的 matrix fragment/vmadot mechanisms，不强迫复用 RVV 的物理模型；但 batched/wide deployment 与 per-format compute decision 应在 emission 前进入 typed body。
- Scalar 继续作为 reference/fallback；除非以后出现真实 construction producer，不为形式对称强行升级。

## 5. 评价设计：如何真正击败弱解释

### 5.1 四类因果干预

1. **construction intervention**：删除 point leaf，观察共享 composition 是否仍产生正确 body；
2. **capability intervention**：固定 `g/ω` 改变 `c`，检查合法集或 resource plan 是否按预测改变；
3. **mechanism/boundary intervention**：移除所需 mechanism 或制造非法组合，检查 construction 失败或 boundary fail closed；
4. **residual intervention**：比较 analytic-only 与 analytic+residual，确认只改变合法 winner，不改变 compute semantics。

不要为了消融在真硬件上执行已知非法程序；boundary 用 negative test 验证即可。

### 5.2 q5_1 的正确称谓与成功条件

q5_1 应称：

> **first point-authority-erasure implementation milestone / local reconstruction witness**

成功至少意味着：

- 无任何 Q51 full-body authority；
- 真实前门同时构造 GEMV 与 GEMM；
- analytic-only 正确；
- capability 对合法 plan 有真实影响；
- independent oracle 通过；
- 与旧 point leaf 的同条件性能达到预定门槛；
- residual 只改善合法选择；
- 新硬件 run lineage 完整。

它仍不能单独支持方法超越 QIGen、整个异质 domain 已被因式分解或 unseen generalization。

### 5.3 只有主张 unseen/generalization 时才需要 prospective witness

若论文需要 generalization/transfer 表述，应在第一轮 mechanisms 与 formula 冻结后：

1. 先公布候选空间和选择规则；
2. 再选择不参与规则设计的组合；
3. 冻结允许输入的 independent facts；
4. 首次运行前冻结 correctness/performance 门；
5. 失败后若修改 mechanism/formula，该点转为开发样例，不继续称 prospective holdout。

这不是日常改代码的繁琐纪律，只适用于论文确认性实验。

### 5.4 主张—证据边界

| 主张 | 最低证据 |
|---|---|
| formula 真实构造 | authority trace + mutation +真实 producer |
| family 而非 point | 删除完整 leaf + 无等价 fallback/identity branch |
| capability-driven | 至少两个真实 capability 投影产生不同合法 plan/structure |
| bounded residual | analytic-only 可正确构造 + coverage/intervention/gain 指标 |
| flat-family authority erasure | q5_1 local reconstruction |
| heterogeneous semantic factorization | 至少一个超出 affine `(g,b,s,z)` 的 topology witness |
| unseen/generalization | 冻结后的 prospective witness |
| cross-family knowledge model | 第二 family 的真实 `g/c → mechanism composition → typed body` |
| competitive performance | 重构后的同条件硬件 campaign |

一个 q5_1 witness不能自动验证全部六律；没有直接证据的部分只能保持设计原则或目标。

## 6. 对 method/spec 的最终处理边界

### 6.1 本轮应写入 method 的内容

- 当前事实与目标态的明确区分；
- 原构造公式和 thin selector 主次；
- `M/F/B/R` 的非第三柱、非 novelty 定位；
- reconstruction 的因果定义；
- q5_1 的本地 authority-erasure milestone 定位；
- QIGen 全文带来的 novelty 再降级与 microkernel leaf 边界；
- 后续最小代码路线与确认性证据边界。

### 6.2 后续 spec 只做微创更新

后续可以：

- 删除已经证伪、已经完成或明显历史化的状态；
- 把 current/substrate/target/evidence 分开；
- 明确 formula constructs、boundary bounds、selector selects、emitter realizes；
- 把 provider/verifier 降为普通实现载体；
- 增加 reconstruction 目标和证据要求；
- 保留复杂 compiler 全景。

后续不应：

- 重写两柱；
- 由本轮 agent 直接定稿新六律；
- 用 CM0–CM4 替代贡献结构；
- 用 task、census、verifier 或 evidence schema 约束普通代码修改；
- 把尚未实现的 reconstruction 写成当前事实。

### 6.3 当前冻结状态

在用户与论文 agent 审核本裁决前：

- canon：不改；
- 已确认公式：不改；
- 新六律：只保留上述微调建议；
- architecture spec：暂不大修；
- task：不建立；
- code：尚未开始重构；
- novelty：provisional；
- q5_1：未来第一项 authority-erasure 实现里程碑；
- topology witness：尚未由论文 agent 最终选择；
- prospective witness：只有主张 unseen/generalization 时才需选择；
- QIGen：正式全文与 artifact 已审，直接差分已闭合。

## 7. 一句话收束

> **Weft-RV 现在最需要的不是再定义一套 compiler 理论，而是把已经确认的公式知识从逐点 builder/emitter 中真正解耦出来：先用 q5_1 学会删除完整 authority，再跨出 flat affine q4/q5，让独立 `g/c/ω` facts 与共享 mechanisms 在显式边界内构造多个 topology/op/backend 的 typed body，并用受限 residual、真实 production reconstruction 和重构后硬件/端到端结果证明这不是换名后的 point implementation。**
