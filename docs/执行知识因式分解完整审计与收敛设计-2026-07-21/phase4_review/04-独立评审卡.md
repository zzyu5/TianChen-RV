# 04｜ARS 阶段四：独立评审卡

> **审查对象**：阶段一至阶段三形成的研究问题、外部 prior、当前代码因果审计与目标重构蓝图。
>
> **审查边界**：评审只判断论证是否成立，不修改两柱、六律、canon 或代码。CM0–CM4 仅是本轮内部审计记号，不是论文贡献编号。
>
> **后续状态**：本卡记录全文取得前的独立评审。QIGen 不确定性已由 [06-QIGen 全文差分与最终再收敛](../phase5_reaudit/06-QIGen全文差分与最终再收敛.md)关闭；其中关于 q5_1 与剩余 novelty 的更新结论优先。

## 0. 汇总裁决

三份独立评审的原始裁决为：

| 视角 | 裁决 | 核心判断 |
|---|---|---|
| compiler/domain | Minor Revision | 技术分级与公式主次基本正确；必须收紧 QIGen、IME/Scalar 和 q5_1 的证据边界。 |
| methodology | Major Revision | 方向成立，但“最小”“真实”“held-out”“competitive”尚未完全操作化，泄漏与归因协议不足。 |
| devil's advocate | Hold / Major Revision | novelty、hidden leaf 和第二 family 三处仍可能发生 foundation collapse；必须用因果干预和新证据解除。 |

编辑合并前的多数意见是：

> **研究方向不应推倒重来；当前论证尚不能冻结为完成态科研主张。应保留两柱、原构造公式和完整 compiler 定位，把 q5_1 降为第一项 authority-erasure 实现目标，并用多 topology 重构、第二 operation/backend、稀疏 residual 与重构后硬件/端到端实验完成收敛。**

## 1. 三方一致通过的内容

### 1.1 主公式与 selector 的主次正确

三方都认可继续以原构造式为中心：

\[
\theta_{i,v}=f^A_{i,v}(g,c,\omega)
\]

\[
K_{v,\omega}(g,c)
=
Emit_v(c)\circ
\bigoplus_i
\left\{
m_{i,v}(g,\omega)
\text{ with }
\theta_{i,v}
\right\}
\]

外层 selector 只能在已经构造且合法的候选中选择，不能：

- 创造 mechanism 或完整实现；
- 改变 compute semantics；
- 把非法 candidate 变合法；
- 通过 winner row、provider 或 emitter 恢复被删除的 point leaf。

`typed plan`、`mechanism graph` 或 body fragment 可以是构造项的工程展开，但不能替换这套主公式。

### 1.2 当前代码是复杂 compiler，但主域尚未完成 family construction

评审一致确认：

- Weft-RV 具有真实 dialect、plugin、capability、front door、typed body、realization、conversion、backend、ABI、runtime 与 measurement 链路；
- typed op、Plan、provider 或 verifier 的存在本身不证明 construction；
- RVV selected-body realization 和若干 builder 内部有真实 structural construction；
- block-quant family 仍大量依赖逐格式 builder 或 emitter 内的大算法分支；
- 当前没有删除完整 point implementation 后仍完成 reconstruction 的 CM4 证据。

因此“这是一个复杂 compiler”与“当前 family-level construction 尚未闭合”同时成立。

### 1.3 provider/verifier 不是第一性原理

三方都同意：

- provider 可以是局部实现载体；
- verifier 可以保护真实 IR/ABI/ISA invariant；
- 二者都不是两柱之外的新核心，也不是 novelty；
- source-shape ceremony、planner replay 和重复 authority 不应继续扩张。

### 1.4 novelty 必须大幅收窄

以下宽泛命题已被 prior 覆盖，不能作为 Weft-RV 的独立 novelty：

- 规则/公式驱动的 family generation；
- composable primitives 或 rule fan-out；
- analytic construction 代替大搜索；
- analytic prior 加有限 empirical selection；
- typed extensible compiler/plugin；
- hardware-aware low-precision compiler；
- 由量化描述与 CPU 特征生成 LLM kernel。

潜在差额只能是一个更具体、可失败的系统命题，而不是 `M/F/B/R` 四个名称本身。

## 2. 必须修正的方法学问题

### 2.1 “最小重构”只能作相对定义

当前材料不能证明数学意义上的全局最小。可接受的定义是：

> 相对于当前代码和预先确定的验收条件，找出能够消除 point compute authority 的最小必要干预集合。

建议用嵌套干预判断必要性：

1. 先把决定从 emission 前移；
2. 再删除完整 point builder；
3. 再补足 mechanism composition；
4. 再让 capability 改变合法 plan/resource；
5. 最后才加入 bounded residual。

如果去掉某一步仍能通过 reconstruction、correctness 和预定性能门，则该步不能被宣称为必要。

### 2.2 CM0–CM4 必须可被反证

建议固定为：

| 等级 | 可反证判据 |
|---|---|
| CM0 | 信息只影响 attr、trace、reason 或诊断，不改变 executable plan/graph。 |
| CM1 | raw point identity 选择完整 monolithic leaf；删除 leaf 后实例失败。 |
| CM2 | typed facts 改变参数，但仍依赖 point-specific skeleton/builder；删除 point builder 后失败。 |
| CM3 | raw identity 只投影为独立语义 facts；共享机制与规则生成 compute graph，且不存在该 point 的 executable branch。 |
| CM4 | 冻结 CM3 构造栈后，对没有完整 point implementation 的组合完成 reconstruction，并通过预定 correctness、部署与 performance 评价。 |

CM4 更准确地说是建立在 CM3 上的 **evaluation grade**，不是只靠静态代码形状判定的实现等级。

### 2.3 q5_1 不能冒充 prospective unseen holdout

团队已经看过并维护过 q5_1 完整实现，也已经知道它可解释为：

```text
low nibble
+ high-bit plane
+ affine scale/offset fold
```

所以删除 Q51 builders 后，q5_1 可以证明：

> 在最终 compiler 中没有 q5_1 完整 leaf 时，共享知识仍能重建它。

它不能单独证明：

> 系统能泛化到设计者未见过的组合。

最终应把证据拆成：

1. **authority-erasure implementation pilot**：q5_1；
2. **multi-topology confirmation**：至少一个超出 flat affine q4/q5 的真实编码拓扑；
3. **prospective holdout**：只有论文主张 unseen/generalization 时，才在 mechanism catalog 和 formula 冻结后选定未参与规则设计的正交组合。

若论文不使用 unseen/generalization 表述，第一类证据仍然有价值；若使用，就必须补第二类。

### 2.4 q5_1 必须防止 hidden leaf leakage

允许保留的是不可约格式事实和独立 oracle，例如 block layout、bit width、qh/qs/scale/offset 的物理位置与 signedness。

必须排除的是：

- q5_1/Q51 identity 决定 mechanism sequence；
- 一行只识别 q5_1 的 composition table；
- q5_1 专属 body factory、完整 plan 或 operation script；
- emitter/provider/fallback 中的等价 full-body branch；
- q5_1 专属 winner row参与正确性或 candidate creation；
- 只在测试中手写目标 typed body。

仅靠字符串搜索不够；最终应同时检查真实 producer 链、typed authority trace、删除实验和运行结果。这里要求的是科研因果证据，不要求新增一套 source-shape verifier。

### 2.5 correctness 与 performance 必须预先定义

至少需要：

- 真实 producer 到 runtime 的端到端路径；
- 独立 scalar/ggml oracle；
- 正常块、tail、非对齐、极值 scale/offset、high-bit plane 模式；
- unsupported capability fail closed；
- 事先确定 bit-exact 或数值容差；
- 同 commit、同 toolchain、同板卡比较旧 point leaf、analytic construction 和 analytic+residual；
- correctness gate 先于性能；
- 事先确定 non-inferiority/performance 门与统计方式；
- 重构后的新硬件 campaign，不继承旧 leaf 的数字。

### 2.6 residual 需要测“作用”，不只数行

建议至少报告：

\[
D_{coverage}
=
\frac{\#\{\text{具有 qualified residual 的 eligible keys}\}}
{\#\{\text{至少有两个合法候选的 eligible keys}\}}
\]

\[
D_{intervention}
=
\frac{\#\{\text{residual 实际改变 analytic winner 的 keys}\}}
{\#\{\text{eligible keys}\}}
\]

以及 analytic-only 到 analytic+residual 的性能增益。这样可以避免通过增加大量无选择点来人为稀释 residual density。

## 3. 当前代码分级的合并意见

| 路径 | 合并后的保守结论 |
|---|---|
| RVV dequant nibble | CM2；参数化 plan 与共享 body 存在，但决定靠近 emission。 |
| RVV dequant codebook | 强 CM2；`c` 真实影响 gather/LMUL 合法性，但 emitter 仍持有完整 scale topology。 |
| KQuant | CM1/弱 CM2；provider 主要重包装 facts，`minimumVLEN` 当前不承重。 |
| Grid/Ternary/q1_0 | CM1；typed leaf/monolithic body 仍是 compute authority。 |
| RVV flat repack | family-level 以 CM2 为主；若干 builder/brick 路径只有 stage-local CM3 substrate。 |
| selected-body realization | realization stage 可判 CM3；不能外推为 production block-quant pipeline 已达 CM3。 |
| IME | 是真实第二 compute backend；存在局部 typed region construction，但 family-level 仍是 CM1/CM2，不能计作第二 reconstruction family。 |
| Scalar | fallback/reference/backend integration witness；当前不是 construction-family 证据。 |
| 当前任何路径 | 尚无 CM4。 |

这里的关键是把 **stage-local construction**、**family-level maturity** 和 **end-to-end reconstruction evidence** 分开，不按最大值替整个 family 评级。

## 4. 最强反对论证

独立反方给出的最强版本是：

> Weft-RV 的性能知识目前仍主要保存在逐格式 builder 与 emitter 大函数中。若所谓 knowledge factorization 只是把旧 leaf 拆成若干新名字，或把 q5_1 的答案搬进 facts、plan、provider、composition table 和 winner row，那么它只是一次优秀的代码去重。SPIRAL、Exo 2、ROLLER、Ladder 和 QIGen 已经覆盖规则生成、可组合 primitive、construction 与量化 kernel generation。除非 Weft 在真实 production chain 上展示无完整 point implementation 的因果重建、正交迁移、稀疏 residual、跨 family 的真实知识作用和竞争性能，否则 novelty 仍可能只是领域重命名。

这项反驳目前尚未被证据击败。它不否定后续目标，正好定义了后续实现必须排除的弱解释。

## 5. 进入编辑裁决的必改项

1. q5_1 改称首个 authority-erasure implementation milestone，不称主要 novelty 或 unseen generalization。
2. CM4 明确为 evaluation grade，并加入反证条件。
3. current、substrate、target、confirmed 四类状态分开。
4. IME/Scalar 不作为已完成的第二 construction family。
5. q5_1 删除范围覆盖 builder、dispatch、provider、emitter、fallback 和 winner leakage。
6. 增加超出 flat affine q4/q5 的 topology witness；只有主张 unseen/generalization 时才增加冻结后的 prospective witness。
7. correctness、performance、residual 和四类 causal intervention 预先操作化。
8. QIGen 维持最高危险近邻；全文已确认其覆盖 group/layer construction、analytic+search 与 retargeting，剩余 claim 必须收窄到完整 microkernel leaf 以下。
9. 六律只提交微调建议，不由本轮工程审查直接覆盖 canon。
10. 不把审计量表、verifier、provider、task 或 census 仪式提升为科研贡献。
