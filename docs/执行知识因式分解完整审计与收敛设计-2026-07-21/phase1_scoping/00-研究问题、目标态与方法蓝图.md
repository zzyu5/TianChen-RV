## 0. 阶段一结论

《高级ai思想》提出的方向值得作为下一轮完整审计的中心假说：

> 将点状 execution-layer 专家实现因式分解为可复用 typed mechanisms、由 `g/c/ω` 条件化的 analytic knowledge、明确的 applicability/resource boundaries，以及有限 empirical residual；再由 compiler 将这些知识重建为真实 typed execution plan 与 kernel family。

但应准确区分三件事：

1. **这是理想目标态，不是当前完成状态。** 当前代码已有 typed facts、typed body、mechanism、plan、capability、plugin、lowering、emitter 和 measurement 等基础，但尚未证明能够普遍从因式分解知识重建未逐点实现的组合。
2. **当前做不到不是对该方向的否定。** 审计的任务正是识别现状与目标态之间的差距，并设计最小而真实的代码重构路径。
3. **它还不能直接作为已成立的论文 novelty。** `Knowledge Factorization` 是否超出既有 generative/staged compilation、kernel DSL、模块化 code generation 和 bounded autotuning，需要在下一阶段用原始文献核验；当前代码是否真的 construction，而非包装或选择手写 leaf，也需要逐条因果链审计。

阶段一裁决为：

> **方向成立，可进入完整审计；“定案”对象应是目标与审计准则，而不是当前实现事实或未经文献核验的 novelty 结论。**

两柱保持不变。六律只允许沿既有意图微调和收敛，不能借新术语整体换义。现有 spec 不在本阶段大修；后续只清除错误或历史状态，并补入经审查确认的新哲学、目标与工程边界。

## 1. Research Question Brief

### 1.1 Topic Area

面向 ggml/llama.cpp 风格 RISC-V 量化推理 kernel 的 capability-driven typed execution-layer compiler，研究如何把分散在逐格式、逐能力、逐场景和手工优化实现中的执行知识，组织成能够真实构造 kernel family 的可复用知识单元。

### 1.2 Primary Research Question

> **经过何种最小而真实的 compiler 重构，Execution Knowledge Factorization 才能使 Weft-RV 由 typed `g/c/ω`、可复用 mechanisms、analytic knowledge、显式 boundaries 与有限 empirical residual，重建未被逐点完整编码且具有正确性与竞争性能的 kernel-family 实例？**

这是目标态设计与验证问题，不是在询问“当前 HEAD 是否已经完成”。

### 1.3 FINER Assessment

| 维度 | 评分 | 理由 |
|---|---:|---|
| Feasible | 4/5 | 项目已有完整 compiler、丰富 family、近千项测试、真实部署和实验资产，可做代码因果链、重构和对照实验；工作量较大但边界可控。 |
| Interesting | 5/5 | 它直指项目当前最大矛盾：拥有大量高性能实现知识，却尚未证明这些知识已成为可组合、可迁移、可重建的 compiler knowledge。 |
| Novel | 3/5 | family-level execution knowledge factorization 可能形成有价值的新系统主张，但与既有生成式编译、staging、kernel DSL 和 autotuning 的差额尚未通过文献审计。 |
| Ethical | 5/5 | 不涉及人体、隐私或高风险干预；主要风险是学术 overclaim 和不诚实归因，可由审稿与证据纪律控制。 |
| Relevant | 5/5 | 直接决定论文 novelty、六律表述、代码重构顺序、实验设计，以及项目是否从“实现集合”升级为“知识驱动 compiler”。 |
| **平均** | **4.4/5** | 达到进入后续研究阶段的阈值；Novel 分数必须由阶段二更新。 |

### 1.4 Scope Boundaries

#### In scope

- 两柱不变前提下，审查 Knowledge Factorization 是否适合作为共同核心；
- `g`、`c`、`ω`、mechanism、formula、boundary、residual、typed plan/body 与 emitter 的真实关系；
- 当前 RVV 主 family，以及足以检验跨 family 边界的 IME/Scalar 等现有资产；
- dequantize-row、vec-dot、repack GEMV/GEMM、contraction、product/reduce 等已有 kernel family；
- 当前代码哪些属于强构造、参数构造、弱描述符选择或纯 metadata；
- 为达到理想目标态所需的最小到中等规模重构；
- novelty 差额、规则扇出、跨组合迁移、factorization ablation、residual density、correctness、部署与性能证据；
- 新六律候选与既有六律之间的语义继承关系。

#### Out of scope

- 改变两柱的地位或重新定义项目为另一类 compiler；
- 新建通用高层 tensor/tile IR；
- 建立大一统 Formula IR、通用 AST 或全局深层 provider 类树；
- 把 runtime sparse/MoE observer 写成当前已实现；
- 把 verifier、provider、census、schema、freshness 或治理工具本身包装成论文 novelty；
- 在完整审计前大规模改写现有 spec 或推翻已有代码、测试与实验资产；
- 要求每一个格式都不允许拥有必要的机制 leaf。真正要消除的是**完整逐点 kernel 实现和后端重决策**，不是无法共享的基本语义机制。

#### Key assumptions

1. 两柱是稳定价值命题；本轮只审查共同核心、六律措辞与实现路径。
2. 当前实现是演进起点，不是目标态证明；已有过渡设施可能保留、简化或退役，需按实际作用判断。
3. “可重建”要求知识对代码生成具有因果作用，不能仅由类名、注释或 typed wrapper 宣称。
4. 并非每个 family 都必须消费全部 `g/c/ω`。若某一输入在该 domain 不承重，应明确 honest-null；只有声称 capability-conditioned 时，`c` 才必须产生可观察的反事实差异。
5. performance 来自公式构成的高质量候选与受限 residual 共同作用；measurement 不得创造 compute、mechanism 或合法性。

### 1.5 Sub-questions

1. **概念与 novelty：** Execution Knowledge Factorization 相对既有 compiler 与 kernel-generation 工作的最小、真实差额是什么，哪些表述只是已有思想的新命名？
2. **现状与重构：** 当前各 family 的 `g/c/ω → formula → mechanism/plan/body → lowerer/emitter` 链中，哪些已经真实构造，哪些仍在包装、重建 decision 或选择完整手写 leaf；应怎样以最小改动迁移到目标态？
3. **证据与可证伪性：** 哪些 point-authority erasure、retrospective reconstruction、冻结后的 prospective combination、fan-out、ablation、residual-density、correctness、部署和性能实验，足以证明 compiler 能重建 family，而不是事后整理已有实现？

三个子问题继承相同范围：当前 Weft-RV、ggml 风格量化推理、AOT/static construction、offline bounded residual；不静默扩展到通用 tensor compiler 或 runtime adaptive system。

### 1.6 Candidate Questions Considered

| 候选 | FINER 均分 | 裁决 |
|---|---:|---|
| 当前 Weft-RV 是否已经实现 execution knowledge factorization？ | 3.4 | 过度绑定当前状态，会把“尚未完成”误判成方向失败，无法指导目标态建设。 |
| Knowledge Factorization 能否降低新增格式/板卡的代码成本？ | 4.0 | 有价值，但过窄，容易再次把论文降成改动行数或 onboarding 成本论证。 |
| 经何种最小重构，因式分解知识能够重建未逐点实现且有竞争力的 family 实例？ | **4.4** | 选定；同时约束 construction、可迁移性与性能，并明确这是目标态问题。 |
| 如何建立一个统一 Formula IR？ | 2.2 | 预设了不必要的软件形态，且偏离用户明确边界。 |

## 2. 目标态的第一性原理

### 2.1 两柱不变，一核作为待验证的共同解释

两柱仍是：

1. capability-driven、typed、可扩展的 execution-layer compiler；
2. 高性能来自 compiler 对专家执行知识的可执行利用。

Execution Knowledge Factorization 不是第三柱。它的候选作用是解释两柱怎样同时成立：

- 柱一要求知识按变化维度分开，使新格式、能力、机制、场景与后端能够局部进入；
- 柱二要求这些知识不是注释或档案，而是实际构造高质量实现；
- boundaries 防止把不适用域伪装成成功；
- empirical residual 只补 analytic knowledge 无法可靠排序的有限部分。

一个 family 的知识可暂记为：

\[
\mathcal E_f=\langle \mathcal M_f,\mathcal F_f,\mathcal B_f,\mathcal R_f\rangle
\]

它描述四种知识角色，不要求四个物理模块：

- \(\mathcal M_f\)：可复用 typed mechanisms；
- \(\mathcal F_f\)：由 `g/c/ω` 构造机制参数、候选结构和 typed plan/body 的 analytic knowledge；
- \(\mathcal B_f\)：适用域、合法性、资源边界、fallback 和负结果；
- \(\mathcal R_f\)：analytic knowledge 无法可靠完成的有限经验排序残差。

### 2.2 公式不静默换义：保留唯一构造正本

用户已确认的核心构造语义必须保留：

\[
\theta_{i,v}=f^A_{i,v}(g,c,\omega)
\]

\[
K_{v,\omega}(g,c)
=
Emit_v(c)\circ
\bigoplus_i
\left\{
m_{i,v}(g,\omega)\ \text{with}\ \theta_{i,v}
\right\}
\]

工程实现可以把求和项展开成 typed plan、mechanism graph 或 body fragments，但不再为此引入新的论文主公式。任何中间表示都必须逐项映射回原式中的 `m + θ`，并保持以下主次：

1. formula/mechanisms 构造候选与 typed plan/body；
2. legality 限定合法域；
3. residual selector 只在合法候选中做薄选择；
4. emitter 实现已经构造和选择的结果，不重新决定 compute。

原式继续是唯一公式正本；工程中间量不进入 canon，也不为视觉简洁改变 candidate、capability、selector、emitter 或 fallback 语义。

### 2.3 “真实 construction”不等于“创建了一个 typed op”

审计采用以下层级。它们用于判断差距，不用于贬低现有资产：

| 等级 | 含义 | 能支持的主张 |
|---|---|---|
| CM0 · Metadata only | 只记录 reason、provenance、名称或未承重 attr；删除后代码形态不变 | 不能支持公式构成 |
| CM1 · Typed leaf selection | typed descriptor/plan 选择一个几乎完整的既有手写 leaf，后端仍按 format/leaf identity 展开完整算法 | 支持 typed routing，不支持 family reconstruction |
| CM2 · Parametric construction | 共享机制图已固定，formula 的 typed 输出真实改变 LMUL、strip、布局、循环、资源、合法域或其他承重参数，lowerer 直接消费 | 支持有限的 parameterized construction |
| CM3 · Structural construction | compiler 由共享 typed mechanisms 和 formula 输出构造有序 plan/body 结构；后端只做机械 lowering | 支持 execution knowledge construction |
| CM4 · Reconstructive evaluation grade | 冻结构造栈后，在没有逐点完整 kernel authority 的条件下构造正确、有竞争力的实例 | 支持选定 domain 内的 reconstructability；是否支持 unseen generalization 取决于 prospective protocol |

理想项目不要求所有路径一步达到同一等级，但论文核心至少需要：

- 多个承重路径达到 CM3；
- 至少一个设计严谨的 CM4 retrospective reconstruction witness；若主张 unseen/generalization，再增加规则冻结后的 prospective witness；
- 其他 CM1/CM2 路径如实标注，不把 typed wrapper 写成强构造。

CM4 是建立在 CM3 上的 evaluation grade，不是只靠静态代码形状判定的实现级别。

### 2.4 “去掉 leaf 后重建”的准确含义

这个标准是未来验收目标，不是当前完成门，也不能机械理解为删除所有 leaf：

- 可以保留真正不可再分的基本 mechanism primitive，例如某种独有位解码、load/gather、widening multiply 或 reduction；
- 应移除或 withheld 的是完整的 `format × capability × context` point implementation、完整 kernel leaf 或同等作用的后端 name branch；
- 新实例应主要由既有 mechanisms、facts、formula 和 boundaries 组合产生；
- 若新格式确实引入全新语义机制，增加一个新 primitive 是合理的，但不应复制完整 pipeline；
- reconstruction 设计必须防止通过 format 名、registry row、测试 fixture 或隐藏 emitter switch 泄漏答案；团队已知旧 leaf 后的删除实验属于 retrospective reconstruction，不自动等于 prospective holdout。

所以目标不是“零 leaf”，而是：

> **不为每个完整实现点保存一份不可分解的 kernel；只为真正新的机制增加最小语义 primitive，其余结构由知识重建。**

### 2.5 `c` 必须在声称 capability-driven 时真实承重

对声称由 capability 条件化的路径，应做反事实审计：固定 `g/ω`，改变一个真实 typed capability 字段，观察它是否改变至少一项：

- 合法候选集；
- mechanism/plan 参数；
- typed body 结构；
- 资源边界或 fallback；
- analytic prior。

若 `c` 不改变任何承重结果，该路径只能标为：

- 当前 domain 中 `c` honest-null；
- 结构常量；或
- 尚未完成 capability construction。

不能为了公式外观把未消费的 `minimum_vlen`、board token 或 capability attr 包进 provider。

### 2.6 Provider 与 verifier 不属于第一性原理

| 名称 | 本轮地位 | 保留或删除的判断 |
|---|---|---|
| provider | 普通 family-local 实现手段，可由函数、builder、表或局部对象替代 | 只有在真实消费 typed inputs 并构造承重结果、或确实服务 plugin 生命周期时才有价值；若只是包装常数、转发 leaf 或制造统一外观，应内联、简化或删除。 |
| verifier | 普通 IR/接口防御手段，不是知识模型、六律或 novelty 的组成部分 | 只在确有 malformed IR、类型/region/ABI/ISA/resource invariant 或不可信 pass 边界时保留局部验证；不得用 source-shape verifier 证明科研主张，也不应重新执行 planner 来维护第二份 authority。 |

因此本轮不提出“所有 formula 必须有 provider”“所有 law 必须有 verifier”。真正的第一性标准是：

> **知识是否进入真实 construction 因果链，以及最终实现是否由该知识决定。**

### 2.7 当前一条代表性路径说明了什么

当前 `RVVDequantizeRowConstruction.cpp` 已经做了两件有价值的事：

1. 将多种 format 的布局事实集中为 typed `DequantizeRowStreamFacts`；
2. 创建 `TypedDequantizeRowLoopBodyOp` 和 `DequantizeRowDecodeCoreOp`。

但后续 `RVVToEmitCForwardElementwise.cpp` 中仍可观察到混合状态：

- Nibble 在 emission 附近再次运行 decision；
- KQuant/Grid 等仍由 `decode_model` 映射 scale model/leaf，再调用 provider；
- 多个完整向量 body 由 leaf/model switch 选择。

这不应被二元裁决为“已有 construction 全部无效”或“已经达到理想 construction”。更准确的阶段性判断是：

> typed facts 与 typed body 是重要基础；部分路径已达到参数构造，部分仍接近 typed leaf selection，完整 CM3/CM4 需要在后续逐 family 审计后才能判定。

这也说明未来工作不是推倒 compiler，而是让已有 typed 基础真正承载 mechanism composition，并逐步把后端的完整 leaf 选择和 decision reconstruction 前移或消解。

## 3. 六律只能演进，不能借新名称整体换义

《高级ai思想》的六律候选与当前六律有明显继承关系，但不是逐字等价。后续必须建立语义血缘，而不是宣布旧律失效：

| 当前稳定意图 | 新候选措辞 | 阶段一判断 |
|---|---|---|
| 变化有唯一 typed owner | 变化归位律 | 基本同义，可精炼措辞。 |
| 机制源码无经验点，经验知识与机制分离 | 知识因式分解律 | 可提升为正面知识模型，但不能丢失“经验 residual 不得污染 mechanism/compute”的边界。 |
| 和积增长、逐点知识承担 point tax | 族先于点律 | 目标一致；应改用 fan-out、retrospective reconstruction、prospective transfer 与 residual density 证明，不必保留粗糙渐进式口号。 |
| 理由可执行、变量充分 | 公式构成律 | 可以把中心从 reason/verifier 收回真实 construction；仍须保留 typed inputs 必须承重、输出有 consumer 的因果要求。 |
| 构造→合法性→选择→typed body→emission 单向专化 | 解析主导、测量修残律 | 可以突出 analytic/residual 主次，但不能丢失 emitter 不重决策、measurement 不造 compute 的单向因果约束。 |
| 正负知识双向积累 | 证据回流律 | 基本同义，可改为更直接的知识更新表述。 |

阶段一建议是：

1. 不把“新六律”当作六个新贡献；
2. 不因删除 verifier novelty 就删除真实 construction、单向 authority 和 residual boundary；
3. 允许删掉 Reason Completeness、No Hidden Specialization 等过度形式化包装；
4. 用实际 code/dataflow/experiment falsifier 代替 source-shape 纪律；
5. 完整审计结束前，不在 canon 中直接替换六律。

## 4. Methodology Blueprint

### 4.1 Research Paradigm

**Selected：** Pragmatist、artifact-centered design science。

**理由：** 本研究不是只给概念下定义，也不是只统计已有代码。它要提出可执行知识模型、改造真实 compiler，并用代码因果链与硬件/系统证据判断该模型是否工作。方法必须同时接受负结果：若重构后仍依赖完整逐点 leaf，或 residual 随产品空间近似逐点增长，应收缩 novelty，而不是继续换术语。

### 4.2 Method

**Type：** 混合方法、顺序式 artifact evaluation。

**Specific method：**

1. 原始文献对比与 novelty delta；
2. 当前实现的 compiler dataflow/causal construction 审计；
3. 面向目标态的最小重构设计；
4. counterfactual、retrospective reconstruction、冻结后的 prospective transfer、ablation 与真实性能实验；
5. 独立 reviewer 与 devil's-advocate 复审；
6. 最后才微调 method/spec 与论文主张。

### 4.3 Data Strategy

#### 内部材料

- 当前 code、tests、build/lit 和真实 lowering 输出；
- 当前 canon、architecture、measurement 与 issues；
- `docs/method/README.md` 与 `docs/method/高级ai思想.md`；
- 2026-07-20 两柱六律审计包；
- 已有实验、正确性、部署、强对手与 e2e 资产。

这些材料用于理解现状与历史，不要求每条普通代码判断都附带一套机械化 census 元数据。关键 claim 只需能够回到实际代码、测试或实验事实。

#### 外部材料

阶段二只使用原始论文、正式项目论文或官方设计资料，重点比较：

- generative programming 与 staging/partial evaluation；
- Halide/TVM/Ansor/Exo/MLIR 等系统中的算法、schedule、mechanism 与 search 分工；
- SPIRAL 类知识驱动生成；
- kernel DSL、active libraries 与 modular code generation；
- analytic model 与 empirical autotuning 的组合。

目的不是堆引用，而是回答：Weft 的对象、分解维度、compiler realization 和实验证据究竟有何不可被现有概念完全吸收的差额。

### 4.4 Sampling

采用 maximum-variation purposive sampling，先选能暴露不同成熟度的代表路径：

- flat nibble / q8_0；
- codebook；
- KQuant；
- grid/ternary；
- repack GEMV/GEMM；
- low-precision contraction 与 product/reduce；
- 至少一个非 RVV family 边界。

代表路径完成方法校准后，再决定是否对所有 family 做全量矩阵。这里不以文件行数或 provider 数量替代语义审计。

### 4.5 Analytical Framework

每个承重 slice 沿以下因果链分析：

```text
typed g / c / ω
→ analytic rule
→ candidate/mechanism/θ/boundary/prior
→ typed plan or typed body
→ body realization / lowering
→ emitted implementation
→ correctness / performance / negative boundary
```

核心问题不是“是否存在某个字段”，而是反事实：

> 在其合法 domain 内改变或移除该知识输出，后续 typed structure、code shape、合法域或选择是否按预期改变？

每个 slice 最终归入 CM0–CM4，并记录：

- 当前实际等级；
- 目标等级；
- 保留资产；
- 重复或错误 authority；
- 最小重构动作；
- 需要的 correctness/performance witness。

### 4.6 Target Refactoring Model

本轮不预设统一物理目录。理想逻辑职责为：

```text
family-local typed facts/context
  → reusable mechanisms
  → analytic construction
  → applicability/resource boundary
  → finite legal plans
  → optional bounded residual selection
  → typed selected plan/body
  → mechanical realization/emission
```

代码重构优先级按因果性，而不是按类名：

1. 找到后端仍在重做的 code-affecting decision；
2. 判断它应成为 mechanism、analytic output、boundary 还是 residual；
3. 让真实 typed input 在 construction 阶段生成承重 plan/body；
4. 让 lowerer 直接消费，不再按 format/board 名重建；
5. 删除同一 slice 的旧 decision owner；
6. 保留必要 semantic verifier，删除只为证明架构口号存在的重复检查；
7. 用现有回归和新反事实实验确认语义、ABI 与性能未退化。

### 4.7 Evidence Program

#### A. Construction causality

- 改变一个 typed formula 输出，确认 plan/body/code shape 发生预期变化；
- 删除 reason/provenance 后代码不应变化；
- 删除或绕过承重 θ 后测试应失败或生成不同实现；
- emitter 不得重新恢复被移除的 decision。

#### B. Capability counterfactual

- 固定 `g/ω`，改变真实 `c`；
- 检查合法域、资源边界、θ、结构或 prior 的决定性变化；
- 无变化的路径诚实标为 capability-honest-null。

#### C. Rule fan-out

- 统计一个 mechanism/rule 能生成多少不同实例；
- 区分“同一规则改参数”与“同一名称下隐藏多份 leaf”；
- 观察新增组合是否触碰旧 emitter decision tree。

#### D. Cross-combination reconstruction

- withheld 一个完整 point implementation 或 combination-specific backend branch；
- 保留其必要基本机制 facts；
- 由共享 mechanisms、formula 和 boundary 构造该组合；
- 通过 typed IR、生成代码、byte-exact/correctness、部署与性能验证；
- 检查没有通过 format 名、registry 或 fixture 泄漏完整答案。

这是目标态核心实验。当前尚未达到并不构成否决，而是后续重构要交付的结果。

#### E. Factorization ablation

至少比较：

1. pointwise/full-leaf baseline；
2. mechanisms + fixed/default；
3. mechanisms + analytic construction；
4. mechanisms + analytic construction + bounded residual。

观察 correctness、coverage、代码变化局部性、性能和 residual 数量，而不是只看生成代码是否能编译。

#### F. Residual density

- residual row/key 数；
- 能覆盖的实例组合；
- flip/no-flip/miss；
- 随格式、能力与 context 扩张的增长趋势。

若 residual 近似逐点覆盖产品空间，应降低“factorized family knowledge”主张，或改进 analytic region/key abstraction。

#### G. Performance and deployment

- 重构后 correctness 与已有测试回归；
- 真实 generated bundle/ABI 与板端路径；
- 有代表性的强对手；
- kernel 收益与 e2e 传导/洗掉；
- 正结果、负结果和物理/compiler wall 同时保留。

### 4.8 Validity Criteria

| 风险 | 控制方式 |
|---|---|
| 把重命名当 novelty | 阶段二与原始系统论文逐项比较对象、机制、保证和证据，而非比较术语。 |
| 把 typed wrapper 当 construction | 使用 CM0–CM4 因果等级、mutation 与 downstream consumer 审计。 |
| reconstruction/holdout 泄漏 | 移除完整 point branch，并检查 format switch、registry、fixture 和 generated table；区分 retrospective 与 prospective。 |
| 只选容易成功的 family | maximum-variation sampling，保留一个强例、弱例与失败例。 |
| 把当前缺口误作方向失败 | 所有结论区分 current state、target state 和 transition plan。 |
| 把目标写成现状 | 论文/文档 claim 必须与实现阶段一致；目标态使用 future/required 表述。 |
| measurement 反向定义 compute | residual 只能选择 analytic 层已构造且合法的计划。 |
| 重构伤害复杂 compiler 资产 | 保留 dialect、plugin、ABI、runtime、tests 与实验路径；逐 slice 原子迁移。 |
| 公式换记号时换了语义 | 对 `P_v/Compose` 与既有 `K_{v,ω}` 做显式等价和 code mapping 审查。 |

### 4.9 Limitations by Design

- 初始实证集中于 RISC-V 量化推理 execution layer，不直接外推到所有 accelerator/compiler。
- 一项成功的 retrospective witness 只能证明在选定 family/domain 内可重建，不能证明 unseen generalization 或任意新机制自动出现。
- 规则 fan-out 和代码局部性是柱一证据，不单独证明高性能。
- 真实 performance 可能受 toolchain、memory、ABI 和系统固定成本影响，需分别归因。
- 当前内部 agent clean-room 不能等同真实外部组织复现，除非论文主动扩大该主张。

### 4.10 Ethics, Reporting, Preregistration

- 无人体研究，IRB 不适用。
- 主要伦理要求是避免 novelty、性能、外部性和当前完成度 overclaim。
- 报告方式采用 artifact/design-science case study，并公开负结果和主张边界；无适用的 EQUATOR 医学报告规范。
- 软件重构探索无需预注册；一旦确定 confirmatory prospective witness 与性能比较，可在运行前冻结组合、机制/公式、指标、对手和成功判据，避免事后挑选。

## 5. Devil's Advocate Report — Checkpoint 1

### Verdict: REVISE before design freeze

这里的 `REVISE` 不否定方向，而是说明在进入文献与全面代码审计前，需要确认本阶段已经做出的目标态/现状态区分和公式处理原则。

### Critical Issues

No unfixable critical issue identified.

### Major Issues

1. **后验重命名风险**
   - 问题：现有 compiler 本就包含 typed IR、plans、providers、boundaries 和 measurement；若只是重新分为 M/F/B/R，可能只是 taxonomy。
   - 处理：核心证据必须是 CM3/CM4 construction、cross-combination reconstruction 与 residual sparsity，而不是结构命名。

2. **目标态与当前事实混写风险**
   - 问题：《高级ai思想》的“定案令”容易被读成当前系统已经重建 family。
   - 处理：所有审计文档分开写 `current / target / transition / evidence required`；当前做不到属于重构任务。

3. **公式语义漂移风险**
   - 问题：从既有 `K=Emit∘构造` 改成 `P=Compose; K*=Emit(Select(P))`，可能改变 candidate、capability 与 emitter 的边界。
   - 处理：暂把 `P_v` 作为原构造项的中间命名；只有证明等价才更新正本。

4. **reconstruction/holdout 实验泄漏风险**
   - 问题：即使删除一个显式 leaf，完整实现仍可能藏在 format switch、registry、provider 或 emitter helper 中。
   - 处理：对目标 point 做完整依赖与 mutation 审计；允许最小不可共享 primitive，不允许完整 point implementation；已知旧实现的 q5_1 只称 retrospective reconstruction。

5. **六律重新解释风险**
   - 问题：新六律若直接替换，可能丢失 mechanism/residual 隔离和 emitter 不重决策等既有核心纪律。
   - 处理：建立逐律语义继承矩阵；只微调措辞和证明方式，不以新名词抹去旧意图。

### Minor Issues

- `Knowledge Factorization` 名称可能与数学 factorization 产生过强形式化联想；阶段二应判断是否需要更限定的术语。
- `reconstruct` 必须定义为 compiler 对 typed plan/body 的生成，不能等同“最终能调用一个已有 helper”。
- 不应要求所有路径都有多候选或 residual；单候选 analytic construction 仍可成立。

### Strongest Counter-Argument

> Weft-RV 可能只是一个工程复杂、typed 化良好的插件编译器，其性能仍主要来自逐格式手写 leaf 和后端大函数；所谓 Execution Knowledge Factorization 只是把已有 facts、helpers、legality 和 tuning table 重新命名。除非它能在没有完整逐点实现的条件下重建新组合，并证明规则复用、有限 residual 与竞争性能，否则它没有形成新的 compiler contribution。

这个反驳不是当前应回避的问题，而是后续重构与实验必须正面击败的对象。

### What's Missing

- 与相邻系统的原始文献 novelty matrix；
- 当前每个代表 family 的 CM0–CM4 因果链分类；
- 从现状到 CM3/CM4 的具体代码设计；
- 至少一个无泄漏的 cross-combination reconstruction 实验；
- 重构后的 factorization ablation 与 residual density；
- 完整 reviewer 复审。

### Stress Test Results

| 测试 | 结果 |
|---|---|
| 去掉《高级ai思想》作为权威来源，问题仍成立吗？ | 是。当前代码中的分散 authority 与弱/强 construction 区别独立存在。 |
| 反转问题：“这只是 typed leaf selection”是否可信？ | 是，而且是当前必须排除的强反解释。 |
| 换到非 RVV family 是否自然成立？ | 尚未证明；必须由跨 family 边界审计回答。 |
| “So what?” 是否充分？ | 若达到有真实因果证据的 CM4 且 residual 有界，充分；若只完成重新命名，不充分。 |

## 6. 阶段一冻结建议

建议将以下内容冻结为后续审计准则：

1. 两柱不变；Knowledge Factorization 是待验证的共同核心，不是第三柱。
2. 当前系统未达到理想 reconstruction，审计面向“如何做到”，而非要求现状已经做到。
3. construction 贡献按 CM0–CM4 因果等级判断；创建 typed op、provider 或 verifier 本身不计贡献。
4. `P_v/Compose` 暂作既有构造项的显式中间量，不静默替换已确认公式。
5. 六律必须沿既有意图微调；后续通过 ARS 审查后才更新 canon。
6. 完整代码重构目标是消除完整 point implementation 与后端重决策，保留真正不可共享的最小 mechanism primitive。
7. 后续必须用原始文献、逐 family 代码因果链、retrospective reconstruction、必要时的 prospective transfer、ablation、residual density 和真实性能共同裁决 novelty。

阶段二在用户确认本范围后开始；它首先回答“这是否真有 novelty”，阶段三再把每条代表路径变成从当前状态到理想状态的代码设计。
