## 一、这个项目在做什么（判断所需的最小背景）

**Weft-RV** = 基于 MLIR 的**能力驱动可扩展执行层软件栈之参考模板**。
RISC-V 量化 LLM 推理（ggml 型 kernel）是它的**首个高性能实例**——
**主角是可扩展性，性能是证明书**，不是反过来。

三条论文贡献：
- **C1 模板协议本体**（头牌）：合取存在性 → 可复制的扩展接入协议
- **C2 模板经济学**：泛化代价 → 边际成本规律
- **C3′ 模板产出质量**：能力键控优化模式库（**性能数字是 C3′ 的证词，不另立贡献**）

**对手 = ggml/llama.cpp 的现成 kernel**（非学术 baseline，是真出货代码）。
我方产出 = MLIR 编译栈**发射**出的 C（EmitC），编译后与对手在**同板同编译器**下对测。

**四块真硬件**（全部在线，本役实探）：

| 别名 | 身份 | 核 | 向量 | 备注 |
|---|---|---|---|---|
| rvv | openEuler | 64 | **VLEN128** | 有 cache-miss 硬件计数器 |
| k1 | SpacemiT X60 | 8 | **VLEN256** + IME 矩阵扩展 | **无可用 PMU**（仅指令/周期计数） |
| **scalar（超锐·本役新到）** | Fedora 42 | 8 | **无向量** | **本役已装 clang-18** |
| fedora-rvv07 | RVV 0.7（非标准前身） | 128 | RVV0.7 | **做不做待裁** |

## 二、核心纪律（判断时必须知道，否则会误读数字）

1. **对手三档法**：任一格的对手必须归入 {**手调** | **通用向量** | **标量类**（含编译器自动向量化） | 未定}。
   **赢便宜档（标量类）禁称"硬赢"**——记账可以，措辞不行。
2. **byte-exact 不可绕**：整数路径必须与 oracle 逐字节相同，否则不许计时。
3. **证书三要件**：语料完备 / 输入路径同源 / oracle 独立。**禁空心证书**（门不咬 = 无效）。
4. **部署的 ≠ 证过的**：证过 A 变体不代表部署了 A。要五验（符号/反汇编/向量长度形态/横幅/编译器身份）。
5. **单世界 clang-18**：双方（我方与对手）一律用 clang 18.1.8 编译。**编译器不对称的对比一律作废**
   （历史上有过 1.884× 的战果因此被撤回——那是"我方 clang vs 对手 gcc"的假象）。
6. **cold 唯一**：只认冷启动数，热数不入账。
7. **单分母制**：每板一个分母，四档穷尽互斥且求和 = 分母。头条 = PASS 数 / 全档量。
8. **硬冻结（只登记、永不执行）**：改分母定义、改花名册元数据、改队列顺序、采购、删已封存资产。

## 四、本役实际发生了什么（详细）

### 4.1 我自己造出并修复的一个陷阱（最该被外部判断的一条）

上一轮我中途叫停两个在飞施工后，留下了一个**不会被发现的假绿**：

| 事实 | 如何验证 |
|---|---|
| 施工改动进了 git 暂存（stash），**源码回退到基线** | 列暂存栈 |
| **但先前编译好的编译器二进制没回退**，仍在发射那版代码 | 对二进制取 strings 计数 = 1 |
| 源码中该符号**全片段计数 = 0** | 对源码目录递归 grep 各片段 |
| **判决性实验**：把输入里该符号**全部改名成探针** → 输出里**原名仍出现、探针不出现** | ⟹ 符号烧在二进制里，不来自输入 |
| 而两个未提交的测试**已被改成期望新形态** | ⟹ **跑测试是绿的，绿在一个源码里不存在的发射器上** |

**处置**：把该施工线封成**一条原子暂存**（发射器 + 两个测试一起，不再是"代码在暂存、测试在树上"的裂开态）；
强制重建、亲眼看到编译 + 归档 + 链接三行 → 幽灵符号在二进制/静态库/发射产物中**全部归零**、基线语义回归；
全套测试回到 **952 发现 / 949 通过 / 3 既有失败**。

**为什么这条重要**：本仓已有记忆条目记录"增量构建不可靠"，但它讲的是
**「二进制少了新代码 → 测试变红 → 会被发现」**。这次是**反向**：
**「二进制多了已撤代码 + 测试配合它 → 测试变绿 → 不会被发现」**。
**恶性变种，已入记忆。** 判决法：把可疑符号在输入里改名重跑——原名仍出现即证明它烧在二进制里。

故障注入对照恰好 1 字节差异（反证器就位）· CPU 状态哈希前后一致 · 零游离进程 · 四分位距 ≤1.02% ·
双方均为**板上真 clang 18.1.8**。

| 格式 | rvv vs 通用参考 | rvv vs 向量长度专化对手 | k1 vs 通用参考 | k1 vs 专化对手 |
|---|---|---|---|---|
| iq1_s | 15.27 | **0.67** | 15.99 | **0.59** |
| iq1_m | 9.00 | **0.57** | 10.14 | **0.59** |

### 4.3 ★为什么这 8 格我没落账（本役最需要外部判断的一条）

**我本可以照先例把它们落成"标量类 PASS ×8"，头条直接 +8。** 落表前我查了对手身份，发现：

**表格违反了它自己写下的约定——同一谓词，两套政策：**

| 处境 | K-quant 支 | iq 支 |
|---|---|---|
| 同算子 repack GEMM **是否存在** | **不存在**（同样缺席） | **不存在** |
| 选谁当对手 | **部署的向量长度专化手调核**（标注 cross-op） | **未部署的标量参考** |
| 归档 | **手调** | **标量类** |
| 结果 | **认下惨输**（0.05× / 0.07× / 0.08× / 0.13× / 0.36×，全部具名失败） | **记 PASS** |

**部署事实（反汇编 + ggml 源码类型注册表实证）**：ggml 注册的那个 vec_dot 符号
是一个 **26 条指令、零向量指令的"向量长度分发 thunk"**——它读硬件向量长度寄存器，
在 rvv（VLEN128）跳向量长度 128 专化版、在 k1（VLEN256）跳 256 专化版。
**⟹ 我们两块板上实际执行的，是手调专化核，不是标量参考。**

**决定性判据**：**换对手会翻转结论的符号**（部署对手下 8 格输 6）
⟹ **能决定胜负的对手选择，必须按【部署事实】证成，不能按【可得性】证成。**

**必须说清的公道话（防止外部读者误判为造假）**：
- 三档法里"标量类"**本就包含编译器自动向量化**，"赢便宜档"就是该档的语义，且纪律**早已明禁称硬赢**
  ⟹ **档标本身可辩护，这不是造假。**
- 那个通用参考**也不是幻影**——它是 **515 条向量指令的真代码**、可直接调用，打赢它是**真测量**
  （一个诚实的"vs 可移植参考实现"数字）。
- **真缺陷是**：gemm_tile 的对手列**声称代表"ggml 在这块板上对这个算子实际会做什么"**——
  **K-quant 行做到了，iq 行没做到。** 可达性只是这个不一致的**证据**，不是缺陷本身。

**该发现经过对抗性独立复核，复核逐条打回我 4 处错，我自跑命令复验后全部接受并重写**：
① 我举例的某个向量长度**架构上不存在**（该架构向量长度必为 2 的幂）
② 我把一种分发写法当成 8/8 格通用，**实为 3/8**（另 5 格用另一种写法，**根本没有通用参考出口**，结论反而更强）
③ 我把某条理由定性成"整条事实错"**过重**（其前件为真，仅后件假）——**一个关于精确性的裁决，自己必须精确**
④ **主张立错了位**（见上：可达性是证据不是缺陷）

### 4.4 P2 decode 两格：从"构造阻塞"证伪 → 实出转绿

**净账**：q4_1 / q8_0 的 decode 格 **@rvv 双双转绿**。

| 格 | 比值 | 判读 | 成色（必须跟着数走） |
|---|---:|---|---|
| q4_1 decode @rvv | **1.381** | PASS | 对手是**真原生向量 block-dot、中等强度**·非手调砖·噪声干净 |
| q8_0 decode @rvv | **7.86** | PASS | **★便宜档·禁称硬赢** |

**q8_0 的 7.86× 是【对手病理】，不是我方核质量**（同形状对照实证）：
权重字节比 34:20 = **1.70×**；**我方**耗时随之 **2.14×**（≈1.70×，访存受限下正常）；
**对手** 却 **12.16×**（病理）。与既有记忆"q8_0 在 rvv 上游 VLEN128 路径破损"同构。

**三条诚实备注**：
1. **噪声**：q8_0 我方相对四分位距 10.2%/6.3%，对手仅 1.0–1.4%——与此前被判"噪声作废"的格同型。
   本役仍入账，**仅因**比值 ≈7.9 距 0.8 门约 10 倍、10% 噪声无法翻转；
   **若将来当"近门"数使用，须先复现噪声。**
2. **拒绝对错误布局计时**（设计即失败关闭）：存在一个**未被表格命名的同算子对手**
   （真手调重型核）。把我方打包缓冲喂给它 → oracle 判 **256/512 不匹配** = **布局不兼容**
   （同一缓冲喂我方核则 0/512）⟹ **拒绝计时**。
   **⟹ 7.86× 仅对弱的跨算子对手成立，不得外推为"赢了同算子手调核"。**
3. **k1 两格 = 具名结构缺口（非未攻）**：前门对两格均失败关闭，**且 verifier 正在正确工作**——
   q4_1 的降级路径会构造 q4_0 形态却仍带 q4_1 的"含最小值项"缩放模型，放行将**静默丢弃该项 = 错误编译**；
   q8_0 根本没有对应降级路径。**两条失败关闭契约已固化进测试**。
   ⟹ "降级到 block-dot"这条路**只对 q4_0 可表达**，是结构缺口不是偶发。

**mxfp4 的两格未测（具名理由，非留白）**：前置全部就绪（leaf 双板前门可导出、能力键控已验、
对手 thunk 已反汇编坐实），**缺唯一一件** = 该格专用的 vec_dot 驱动 + 对应 oracle
（现有两个驱动一个是超块族、一个是 GEVM 非 vec_dot，都不适配）。

## 八、外部判断可用的三个抓手

1. **成色 vs 计数**：头条计数（如"标量类 36/51"）与**成色**（是否硬碰硬赢强手调）**是两回事**。
   本项目已封存的"真硬赢手调砖"**只有 2 个**。计数上涨**不等于**成色质变。
2. **"便宜档赢"的信息量**：多数大倍数（9×、15×、7.86×）都是对**弱/非部署/病理**对手。
   判断时请把它们与"对部署强手调对手"的数字**分开读**——后者本役 8 格输 6。
3. **失败关闭是特性不是缺陷**：本役多处"做不了"是 **verifier 正确拒绝了会产生错误编译的路径**
   （例：放行会静默丢弃一个数学项）。这类应读作**结构缺口 + 已固化契约**，不是"未攻"。
