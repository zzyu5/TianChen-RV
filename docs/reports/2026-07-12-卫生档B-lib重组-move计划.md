## 2. 目标 taxonomy + 归类理由

对齐 [TEMPLATE-AUDIT] R2 建议桶 + REPOSITORY-MAP §2「五件套」职责，落在 `lib/Plugin/RVV/` 下：

```
lib/Plugin/RVV/
├── RVVExtensionPlugin.cpp        ← 件①入口（root 保留，对齐 Template/：TemplateExtensionPlugin.cpp 在家族根）
├── RVVCapabilityProfile.cpp      ← 件①能力事实（root 保留）
├── FrontDoor/       (10) ← ③前门:抽象 contraction→in-compiler 构造 typed 区域
├── Selection/       (1)  ← ④选择器:capability 键控 path/algorithm 选择
├── Schedule/        (7)  ← schedule descriptor + materialization（tunable/gearbox）
├── BodyRealization/ (13) ← selected-body realization owners（config/profile→具体 body 结构）
├── Construction/    (已存,2)  ← ③构造协议家族侧（不动）
└── EmitC/           (已存,20) ← ④发射路由（不动）
```

**归类理由**：
- **FrontDoor/** = 命名 `*SourceFrontDoor.cpp`/`*StreamFrontDoor.cpp` 的 9 前门 + `RVVLowerQuantContraction.cpp`。R3 明确要给「靠命名识别」的前门专属目录，消除 ③ 的 LOW-MEDIUM 定位度。
- **Selection/** = `RVVContractionPathSelection.cpp`（纯选择自由函数·3-fact AND）。桶内仅 1 文件（薄），但与 taxonomy 对齐；其先验头 `RVVRepackTilingSelection.h` 在 include/ 侧（后续 include 平行重组时同归 Selection/）。
- **Schedule/** = 全部 `*Schedule*` + `*Materialization` 调度物化件。
- **BodyRealization/** = 全部 `*SelectedBodyRealizationOwner.cpp`（12）+ 基座 `RVVSelectedBodyRealization.cpp`。契约依据 = locality-contract「selected-body realization = plugin-owned 职责」。
- **root 保留 2 件** = 插件入口 + 能力，对齐参考范本 `Template/`。

**⚠️ 两处角色需 attended 裁定（诚实标注·非 build 风险·纯 taxonomy 判断）**：
- **#25 `RVVLowerQuantContraction.cpp`**：是 front-of-pipeline **lowering pass**，非构造 typed 区域的 SourceFrontDoor 本体，且消费 #26 选择结果。可归 FrontDoor 或另设 `Lowering/`。**建议 FrontDoor**（避免 1 文件新桶），执行前请裁。
- **#33 `RVVProbedCapabilityAxesMaterialization.cpp`**：物化 profile→capability 支持轴。命名归 Schedule 但语义偏 capability/profile。**建议 Schedule**（命名族一致），执行前请裁。
