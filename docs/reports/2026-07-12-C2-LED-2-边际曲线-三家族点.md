### 1.3 厘正结论（如实）

裁五.2 的「**RVV（anchor）**」在两个层面同时为真与需修：

1. **RVV = anchor-of-diversity（家族多样性的原点）**：RVV 是模板的**参考家族（N1 substrate）**，IME/X-SCALAR 是从它**泛化出去的**异质家族。「RVV 是 anchor」在「三家族多样性锚点/被泛化的基准」意义上**成立**。
2. **但 2484 ≠ RVV**：**2484 raw 是 IME family 的 founding-slice**（§1.2 逐文件证），**不是 RVV 的数**。RVV 的真实体积 = **163 629 raw**（整栈），把 163 629 当作一个 onboarding「点」与 IME 2484 / X-SCALAR 1501 的 founding slice **同尺放** = apples-to-oranges（substrate 是全项目 accreted，不是一次接入 delta）。

→ **边际-成本曲线上**：anchor 点（base-expensive 首个**实测** onboarding）= **IME 2484**；X-SCALAR 1501 = 第二 onboarding 点；**RVV = substrate 原点（不落为可比 onboarding 数字）**。C2-ledger row 0 现有标注「anchor-IME2484」**是正确的**；裁五.2 的「RVV(anchor 2484)」是**措辞 conflate**，本报告厘正为上述分层，并在 ledger 新增 RVV substrate 行（seq 17，明标「substrate-origin ≠ 2484」）记录三家族多样性 + apples-to-oranges 警示。

**[C2-3]「extension-family 点 ≥3」的诚实拆分**：
- 作 **家族多样性计数**（三异质能力家族：RVV 向量 substrate / IME 矩阵-N2 / X-SCALAR 标量-向量缺席-独立）→ **≥3 满足**。
- 作 **≥3 个 apples-to-apples 数值 onboarding-成本 点** → **只有 2 个**（IME 2484、X-SCALAR 1501）；RVV 是 substrate 原点、非可比 onboarding 数。**曲线仍 2 个真成本点**（与 C2_marginal_cost_ledger.md 附录「1/≥3 曲线未成」一致，不改口径）。

### 2.2 monotone 判读（诚实：**非单调向零递减**）

1. **家族总量层**：2484 → 1501 是**下降**（≈40% 缩减），两点间平凡「单调递减」——**但下降浅、有 ~60% 地板**，**不是**旧「<300 ≈ 12%」直觉所设想的「向零陡降」曲线。旧「<300」= *integrated 子扩展* 预估被误挂到 *independent 家族*，双轨修订（2026-07-11 用户裁）已撤销该单点目标与「超标」定性。
2. **住址层（更锐利）**：分住址看，**emitter 住址反而上升** IME 757 → X-SCALAR 907 raw（**×1.20**；cloc 511→669 **×1.31**）= **非单调**。总量之所以仍降到 ~60%，**完全来自 op-surface 更轻**：dialect ×0.23（804→184）、plugin ×0.38（923→350）。→ **F-6 禁复用的那块（emitter）不缩反涨；缩的是 op 数驱动的 dialect/plugin。**
3. **结论口径**：C2 曲线的正确刻画 **不是**「随家族序号单调递减」，而是**两 regime**：
   - **独立家族 onboarding**（own emitter，F-6 禁复用 RVV EmitC）= **付真 emitter 成本**、总量浅降（~60% 地板，emitter 住址不降）——IME 2484 / X-SCALAR 1501 两点。**= 成本律主张②本身。**
   - **集成子扩展 / 家族内构造**（decode 格式 C3′、IME-forward 复用）= **近零复用**——那才是陡降 regime，但**闭包 ∩ rvv.*≠∅，不进 C2 extension-family 分母**（§四 decode 注记）。

## 三、四列成本住址分解（「成本住在哪」）

住址定义（按实际文件归属，两家族同一套映射）：
- **dialect**：`*Ops.td`（ODS 算子表）+ `*Dialect.cpp` + `*Dialect.h`（IR/verifier）。
- **emitter**：`*BackendEmissionDriver.cpp/.h`（C/EmitC 发射驱动 = 独立家族净新的那块）。
- **plugin(reg+glue)**：`*ExtensionPlugin.cpp/.h`（ExtensionPlugin 注册 + capability 连线 + variant 提议）。
- **route/glue**：`*EmitCRouteProvider.cpp/.h`（发射路由 provider；IME 折进 plugin/driver、故为 0）。

（raw wc-l / cloc-approx；每家族四列求和 = 家族总量，已核 exact。）

| 住址 | IME founding-slice @`54465ee7`（anchor 口径） | X-SCALAR（landed，= 其 founding 成本） | X-SCALAR / IME 比 |
|---|---|---|---|
| **dialect** | 804 / 662 | **184 / 154** | **×0.23** |
| **emitter** | 757 / 511 | **907 / 669** | **×1.20（raw）/ ×1.31（cloc）** |
| **plugin(reg+glue)** | 923 / 693 | 350 / 287 | ×0.38 |
| **route/glue** | 0 / 0 | 60 / 38 | 新增（IME 无独立 route 文件） |
| **TOTAL** | **2484 / 1866** | **1501 / 1148** | **×0.60 / ×0.62** |

**住址级读数（本报告最锐利的 C2 发现）**：
- **X-SCALAR 的 emitter 住址（907 raw / 669 cloc）比 IME founding emitter（757 / 511）还大** ——独立家族**不能**复用 RVV EmitC 发射机器（复用会把 rvv.* 拉进能力闭包、破坏 [F-6] 独立性），主体 = 净新 pure-C emitter（`ScalarBackendEmissionDriver.cpp` = 878 raw 单文件最大头）。
- X-SCALAR 之所以**总量**只到 IME 的 ~60%，**根因 = dialect 住址 ×0.23**（3 op：compute_skeleton + tq2_0 vec_dot + dequantize_row，vs IME 更大 op 家族）+ **plugin ×0.38**，**不是** emitter 省了。
- → **成本住在 emitter**（独立家族），且该住址**不随家族数摊薄**。这是比「家族越接越便宜」更精确、更可辩护的 C2 主张：**独立家族的边际成本律 = 付真 emitter 成本（住址级不降）；总量差异由 op-surface 驱动。**

（对照：IME **live**（非 founding-slice）四列 = dialect 1915/1578 · emitter 1694/1158 · plugin 1653/1201 · route 0 = raw 5262 / cloc 3937；此为家族内 C3′ 扩展后体积，非 onboarding 口径，仅 informational。）
