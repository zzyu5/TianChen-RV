## 三、★ 真发现：四类分**两个执行层**，其中两类是 **pass-conditional**

harness 对每格**额外跑一遍"不挂 pass"**（仅 parse+verify）来归因拒绝层。结果不是均质的：

| 扰动类 | 拒绝层 | 不挂 pass 时 | `pass-conditional` |
|---|---|---|---|
| ① 删事实 | `verifier-op(weft.exec.variant)` | 仍 exit=1 **拒** | **no** |
| ③ 注入未知事实 | `verifier-op(weft.exec.variant)` | 仍 exit=1 **拒** | **no** |
| ② 伪造冲突 | `pass:weft-check-capability-requires` | **exit=0 接受** | **yes** |
| ④ 向量缺席实例 | `pass:weft-check-capability-requires` | **exit=0 接受** | **yes** |

两条**机制事实**（可复跑，见 §四）：

1. **①③ 的 "unknown = false" 由 op 验证器兜底，不靠 pass。** `weft.exec.variant` 验证器在 parse+verify 阶段即拒未声明的 requires 符号。`CheckCapabilityRequires.cpp:157` 的 `RequirementIssue::Kind::Unknown` 分支（其注释自称"self-sufficient ... rejected here as an unknown"）在**文本 IR 输入路径上被验证器遮蔽**、不是该路径的实际拒绝点。二者皆 fail-closed（结论对），但**归因不同于 pass 文档的自述**。该分支对文本 IR 属纵深冗余；是否经其他输入形态（如程序化构造）可达，本轮**未测**。
2. **②④ 的 fail-closed 是"排程依赖"的，不是验证器内禀。** 流水线里**不挂** `--weft-check-capability-requires`，则伪造冲突与向量缺席实例的畸形计划**被直接接受（exit=0）**。即：这两类的默认拒**寄生在 pass 是否被排进流水线**上。

> 论文口径提示：主张"能力事实层默认拒"时，①③ 可说**结构内禀**（验证器恒在）；②④ **只能绑 pass 在场**这个前提说，不可混为一谈。该 `pass-conditional` 位已逐行落进 T1b 表的 `observed_behavior`（沿用既有 `layer=` 约定，未改 schema）。

## 五、harness 自身是 fail-closed 的（三道防空心绿闸 · 全经故障注入实证）

一个 fail-closed harness 必须**对自己也 fail-closed**。三闸**均已注入故障验证真会响**（非装饰）：

| 闸 | 防的空心绿 | 故障注入实证 | 结果 |
|---|---|---|---|
| **G1 种子前置** | **种子若本就非法 → 四格全"拒" → 全绿但绿错原因**（最阴的一种空心绿） | 改种子使其 requires 一个未声明事实 | `FATAL(G1) ... Refusing to report green` **exit=3** |
| **G2 空变异** | find/replace 静默失配 → 实际没扰动 → 判成 pass | 把 `delete_fact` 换成不匹配的字符串 | `FATAL(G2) ... produced NO change vs seed` **exit=3** |
| **G3 反向测试** | harness 是永远报绿的桩 | 喂合法种子 + 反转期望为 reject | `SELF-TEST PASSED — harness correctly reported RED` **exit=0** |

**反向测试证据（任务硬要求"至少一例证明 harness 真能抓"）= G3 + G1 + G2 三例**，且 G1/G2 是在 scratchpad 的**副本**上注入的，仓内文件未受污染。

补充：`--opt /nonexistent` ⇒ **exit=2 BLOCKED**（明写 "NOT reporting green"），无 SKIP-绿路径。

## 七、诚实边界（本轮**没**做到的）

- **不是板上证据**：全部 = host 静态 verify（`board=n/a(host-static-verify)`）。本节点无任何板上/运行时数字，**不得**被引作性能或硅上主张。
- **四格 ≠ 穷尽**：每类扰动**各 1 个代表实例**（种子单一、形态单一）。这是**四类的存在性演示**，**不是**该层的覆盖率主张，更不是模糊测试意义上的搜索。
- **`vector_absent` 只覆盖 `status="unavailable"`**：未覆盖 `disabled` / `missing` / 能力 op 整体缺席等其他"缺席"形态（既有 lit 语料显示 `disabled`/`missing` 亦有分支）。
- **未测 pass 的 Unknown 分支可达性**：§三.1 只证了文本 IR 路径上它被遮蔽，**未证**它不可达（程序化构造路径未探）。
- **未接 CI**：`.github/workflows/` 是 E4 线触碰集，本轮按令**不碰**。故本 harness 目前**只可手动复跑，无门禁棘轮**（F-5 有棘轮、本 harness 没有）。若需入门，属 E4。
- **实况分层是本轮真结论**，但 `pass-conditional=yes` 的两格**是否构成实际风险**取决于真实流水线是否恒挂该 pass —— **本轮未审计**生产流水线的 pass 排程，故不下"存在漏网风险"的判断。
