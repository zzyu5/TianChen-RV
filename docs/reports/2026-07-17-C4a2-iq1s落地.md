## 一、C4a 拒绝的那一步，为什么现在可以做

C4a 把三份手抄闭集（`decodeModel != "iq2_xxs"` 链）收进 `GridDecodePlan` registry，
但**故意不注册 iq1_s**，理由写得很清楚：注册则 verifier 接受、而前门造不出 / emitter
lower 不了 ⟹ 会 ship「verifier 接受但无人能 lower」的不一致。

**这个判断是对的。** C4a-2 不是推翻它，而是满足它的前提：把 registry 行 / 前门 /
emitter leaf / byte-exact oracle **一起**做齐。同理，C4a 拒写 `GridSignPlane::TernaryDelta`
/ `GridFoldArith::DeltaGrid`（「无行使用的 enum = 投机泛化」）也是对的 —— 现在有真行
使用它们了，才写。

**仍然不注册**：`iq1_m` / `iq3_xxs` / `iq3_s`。它们需要的轴值
（`GridEntryWidth::I32x4` / `GridSignPlane::Ksigns128`）**继续不写进 enum**，理由与 C4a 完全相同。
`test/Dialect/RVV/repack-gemv-iq1-s-q8-K-dataflow.mlir` 专门钉住 `iq1_m` 被拒
（它与 iq1_s 共用同一张 2048 grid，是最像「顺手也能用」的一格 —— 它必须红）。

## 二、iq1_s 是什么（不是 iq2 的参数变体）

ggml `ggml_vec_dot_iq1_s_q8_K` 的算术：

```
ls    = 2*((qh[ib] >> 12) & 7) + 1            // 8 档，[1,15]
delta = qh[ib] & 0x8000 ? -1 : 1
idx   = qs[4*ib+l] | (((qh[ib] >> 3*l) & 7) << 8)   // 11-bit，[0,2047]
sumi  += ls * dot32(ib)
sumi1 += ls * delta * (bsums[2*ib] + bsums[2*ib+1])
sumf  += d_x*d_y * (sumi + 0.125f * sumi1)    // IQ1S_DELTA = 0.125f
```

与 iq2 三行的**结构**差异（这是新 leaf、不是 ls-arity 旋钮）：

| 轴 | iq2_xxs/xs/s | iq1_s |
|---|---|---|
| sign plane | signs64 / signs256 表 + vmul 折叠 | **无**。grid 字节本身即有符号 ternary |
| 整数累加器 | 1 个（sumi） | **2 个**（sumi + sumi1） |
| activation bsums | 不读 | **读**（唯一一行） |
| 0.125 位置 | store 侧一次 | **per-block 只乘 sumi1**，store 无尾乘 |

已机器核验：抽出的 2048 项 grid **每个 entry 的 8 字节全部 ∈ {0x00,0x01,0xff}**
（`0 non-ternary entries`）—— 这就是「无 sign plane」的实证，不是推断。

## 三、四样

1. **registry 行**：`lib/Support/GridDecodePlan.cpp` 现 **4 行**（`registry_rows=4`）。
   新轴 `GridFoldArith{SignScaleEighth,DeltaGrid}` + `GridSignPlane::TernaryDelta`。
   `signArrayName` 对 TernaryDelta 行为空（没有表可命名）；verifier 诊断改为渲染
   `ternary-delta` 而非空白。
2. **前门**：`kIq1SDecodeFacts`。GEVM + GEMM 都能造。
3. **emitter**：`emitRepackGemvIq1SQ8K`（:25340）/ `emitRepackGemmIq1SQ8K`（:25820）。
   leaf 由 `plan->foldArith` **先**选（DeltaGrid 优先于 lsArity）。
4. **byte-exact**：`tools/oracle-repack/oracle_repack_iq1_s.cpp`（533 行）。

**repack 布局（本役设计；ggml 原 block_iq1_s 是 50 B 打包 qs/qh，repack 把 qh 一次性
解开成三条 flat strip，kernel 从此不见 qh）**：

```
d[16]          fp16 @ +0     32 B
ls[8][16]      int8 @ +32   128 B
delta[8][16]   int8 @ +160  128 B   ← 借用 sign-plane offset SLOT
gidx[8][4][16] u16  @ +288 1024 B
                     stride 1312
```

activation：block_q8_K 292/quant@4/**bsums@260**；block_q8_Kx4 1168/quant@16/**bsums@1040**（g16*4+c）。

## 四、[K-5b] 三要件 —— 逐条自证

**③ oracle 独立**：reference 读**原始打包** `block_iq1_s`，**运行时**从 qh 字自己推
ls/delta/idx，并用 ggml 自己的 `(const int8_t *)(iq1s_grid + idx)` **uint64 重解释**读
grid；emitter-model **从不见 qh**，读**已 repack** 的 strip，从 **flat int8 表**
`grid_bytes[idx*8+j]` gather。不同布局、不同索引推导、不同表读法。唯一共享的是
`iq1s_grid` 本身 —— 那是**格式常量**，不是解码实现。

**② 输入路径同源**：两条路都喂同一份生成的 `block_iq1_s`；repack 由
`make_block_iq1_sx16` 从它产生。无 capture-replay。

**① 语料完备 —— 前科 P1 的 oracle 漏负 scale 却自称完备。所以本 oracle 不"声称"，
它 MEASURE 并打印，缺一项就 exit 1**（生成器是**系统性 sweep**，不是撞运气）：

```
grid_index : 2048 / 2048 distinct 11-bit indices exercised   COMPLETE
delta      : qh bit15=0 (+1) 28864 blocks, bit15=1 (-1) 28864 blocks  BOTH POLARITIES
ls         : ls=1:7216 ls=3:7216 ls=5:7216 ls=7:7216 ls=9:7216 ls=11:7216 ls=13:7216 ls=15:7216  ALL 8 STEPS
```

**通电的**：11-bit index 全 2048 值 · delta 两极性 · ls 全 8 档 · GEVM + GEMM 双寻址 ·
真实 bsums（按 q8_K 定义算出，非 0；全 0 会让 sumi1 恒 0、整个 delta 机制静默不通电）。

**未通电的（如实列）**：fp16 d 的实际 fp16 舍入（oracle 用 float 建模 d，与 11 份
兄弟 oracle 同一取舍）· 发射出的 RVV C 本身（本机无 `qemu-riscv64`，本线禁上板）·
nb/nc 非整除的尾块（对齐 11 份先例的 shape 集）。

**结果**（`/tmp/oracle_iq1s`，exit 0）：7 shapes + GEMM 全部 `sumi-mismatch=0
sumi1-mismatch=0`，GEMM `0 / 1280`，`WORST_FP_NORM 0.000e+00`，`VERDICT BYTE-EXACT-INTEGER`。

**负控（扰动 reference；dead control 也判 fail）**：

```
GRID   (rotate index +457)      : sumi 1280/1280 (100%)  sumi1 0/1280 (0%)   EXERCISED
QHHIGH (drop qh high 3 idx bits): sumi 1120/1280 (88%)   sumi1 0/1280 (0%)   EXERCISED
LS     (perturb ls +2)          : sumi 1280/1280 (100%)  sumi1 1280/1280     EXERCISED
DELTA  (ignore qh bit15)        : sumi 0/1280 (0%)       sumi1 640/1280 (50%) EXERCISED
BSUMS  (zero the bsums)         : sumi 0/1280 (0%)       sumi1 1280/1280     EXERCISED
```

极性自洽：DELTA 控制恰好 **50%**，与覆盖计数 28864/28864 的 50/50 分裂互相印证。
GRID/QHHIGH 只打 sumi、DELTA/BSUMS 只打 sumi1 —— 正是各自该打的累加器。

**layout pins**：oracle 的 emitter-model 是**按数组下标**寻址的，所以它验的是布局
**语义 + 算术**，**不验 emitter 的字节算术**（其 `float d[16]` 是 64 B，真 kernel 的
fp16 d[16] 是 32 B —— 与 11 份兄弟 oracle 同一建模取舍）。为补这一轴，oracle 独立重算
真实布局并与前门 shipped 的 offset 对钉，10/10 `PIN OK`。

## 九、诚实边界（不许被读成别的）

* **零性能主张**。未上板、未测、iq1_s 能不能赢**未知且不预测**（PR-37 [shape↛score] 已三次撞墙）。
* iq1_s **故意不进** `classifyTilingBottleneckShape` 的 `AlreadyLean`：那句判词断言
  「body 已 ≤ 32-vreg cliff」是**未测的形状主张**。返回 `nullopt`（= 只造了 plain leaf，
  没有 tiled 变体可选），不盖任何 prior 章。已实测：GEMM 构造出的 IR **无** `sp4_tiling` 戳、
  `loop_order` 仍戳（两轴正交，符合既有注释）。
* oracle 是 **x86 原生**、gate 的是 repack 布局 + 算术 **模型**，**不是**发射出的 RVV C
  本身（本机无 `qemu-riscv64`；11 份兄弟 oracle 同一站位）。emitter 与 model 的对应由
  lit（钉 1312/32/160/288/260/1040）+ layout pins 两段论覆盖，**不是单一 artifact**。
* **[L-8]**：iq1_s repack leaf = **强义 constructed**（前门从抽象 request 造出 typed region，
  emitter 发出完整 body）。registry 行本身是 `descriptor-selected composition`。
* 未做：iq1_s 的 tiled GEMM 变体 · e2e/selector 接线 · dequant 路。
