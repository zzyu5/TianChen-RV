## 0. 一句话结论（go/no-go 先行）

**T4 的 e2e 半（门④）= NO-GO 单会话，是多会话独立集成战役（需单独立项）。** 因为 q4_0 先例的 5.9× **白嫖了 ggml 自带的 q4_0 repack 基建**（在线权重 repack + q8_0 激活 + repack trait 入口，上游只是 VLEN-gate OFF），而 **K-quant 在 ggml 侧一切皆无**（repack trait=`nullptr`、无 riscv 分支、整条 repack GEMM 是我方 emitter 构造的），要从零补齐"离线权重 repack + q8_K×4 激活交织 + mul_mat dispatch patch"三件套。**但 T4 的板批半（门②③k1⑤）与 e2e 解耦、便宜、可另起一次板会话完成**——建议把 T4 拆成 **T4a（板批 dual-board，~1 会话）** 与 **T4b（e2e-seal 战役，多会话，单独立项）**。

## 1. ★q4_0 e2e 集成先例（怎么达成 5.9×）

两个 sealed cell，同一集成机理：

| cell | 数字 | 关键事实 |
|---|---|---|
| `experiments/sealed/repack/rvv-vlen128-q4_0-gemm-constructed-sealed` | prefill **5.92×** [5.91,5.93]，decode 1.91× | 我方 front-door **构造**的 q4_0 repack GEMM（`tcrv_rvv.typed_repack_gemm_loop_body`，commit `be66c917`）emit 成 C `.inc`，部署进 A-tree prefill 路径 |
| `experiments/sealed/repack/rvv-SEALED-q4_0-vlen128-fullmarch` | prefill **5.08×**，decode 1.50–1.56× | 全能力 march；★**对抗-verify 修正**：prefill tiled GEMM `ggml_gemm_q4_0_8x8_q8_0` 在 A/B 两树 **byte-identical** → 5× **不是** 我方-vs-他方 codegen，而是**运行时 DISPATCH/ROUTING**（A 在 VLEN128 engage repack；stock 因 ggml repack VLEN-gated/TODO 留在 block-dot） |

**集成机理（可复制路径，接地真脚本）**：

1. **双 build 树 on `ssh rvv`**（`tools/e2e-harness/board/preflight_e2e.sh:6-14`、`run_seal_measure.sh:10-12`）：
   - **A(ours)** = `/home/ubuntu/tcrv-llamacpp/build-gcc15-rv64gcv` —— patched ggml 树，`arch/riscv/repack.cpp` **include/调用我方 emitted `.inc` kernel**，且 dispatch 在 VLEN128 engage repack。
   - **B(stock)** = `/home/ubuntu/llama.cpp-upstream-native/build-gcc15-rv64gcv` —— 未打补丁上游。
   - 两树 **同 compiler + 同 full-march**（唯一差异 = repack patch）。
2. **权重 repack —— q4_0 白嫖 ggml**：ggml 自带 q4_0 在线-repack（`block_q4_0x8`）在模型加载时做、tiled kernel、repack trait 入口都**已存在**，上游只 VLEN-gate OFF@128。→ **q4_0 无需任何自写离线 repacker**。
3. **q8_0 激活胶水 —— 白嫖 ggml**：q4_0 mul_mat 的激活 q8_0 量化 ggml 已自带。
4. **归因**：A 打印运行时 banner `TCRV EMITTED GEMV(q4_0_16x1 VLEN128 compiler-emitted) ENGAGED`；`llvm-objdump --mattr=+v,+zvfh` 指纹确认我方 kernel 真跑（`objdump_fingerprint.txt`）。
5. **全 march 前提**：`fullmarch_rebuild.sh` 覆写 ggml 的 `MARCH_STR`（否则 CMAKE_C_FLAGS 单改是 relabel 不到热路径），A/B **对称**施加。
6. **测量协议**：`run_seal_measure.sh` 一坐做 preflight(4门 fail-closed)→phase_split A/B(prefill pp128 + decode tg32)→3×decode 内存压力快照→objdump 机制封→greedy-token 正确性门(3/3 A==B)。

> **对 K-quant 的第一性教训**：q4_0 是 **routing/dispatch 型集成**（kernel 白嫖 ggml），所以"易"。K-quant 是 **full-construct 型集成**（整条 GEMM 我方 emit，ggml 侧空白）——novelty 更强（整条 repack GEMM 是编译器构造，非 routing），但**集成面更大（ggml 侧零白嫖）**，这是 K-quant 远难于 q4_0 的根因。

## 2. 复制到 K-quant + 选择器 —— 差距件清单

**K-quant 现状 = kernel-轴 micro ONLY**（非 e2e）：`kquant_gemm_paired.sh` + `kquant_gemm_paired_driver.c` 编译我方 exported `.kernel.c` + link `libggml-cpu.so` 取对手 block-dot，在**合成随机 buffer**上计时（权重内容任意、仅 sizes/strides 精确），**不在任何 llama.cpp forward pass 内**。已登记 kernel-轴：q4_K **1.884×**、q5_K **2.193×**（nr=64、VLEN128）。

差距件（vs q4_0 白嫖，逐件）：

| # | 件 | q4_0 状态 | K-quant 状态 | 要补什么 |
|---|---|---|---|---|
| G1 | **离线权重 repack** | 白嫖 ggml `block_q4_0x8` 在线 repack | **无**（ggml repack trait=`nullptr`@q4_K/128、q5_K 无 riscv 分支；`kquant-l1-q4k-q5k-repack-prefill/dispatch_probe_raw.txt`） | 写 GGUF Q4_K/Q5_K 权重 → 交织 `block_q4_Kx16`/`block_q5_Kx16`（stride 2304/2816；nibbles@256、dmin@32、6-bit scales）的 repacker；**byte-exact 校验复用** `tools/e2e-harness/board/kquant_repack_verify_q{2,3,6}K.c`（已证 layout 往返）作 oracle。可 load-time 或离线 GGUF 转换器 |
| G2 | **q8_K×4 激活交织胶水** | 白嫖 ggml q8_0 激活 | **半**（ggml 有 `quantize_row_q8_K`=prefill 0.33%，但只出**plain** q8_K，非 x4 交织） | 把 q8_K 激活交织成 `block_q8_Kx4`（stride 1168：d[4]@0、qs@16(p*4+c)、bsums@1040，见 `RVVLowerQuantContraction.cpp:333/1414`）→ 喂我方 GEMM |
| G3 | **mul_mat dispatch 入口** | 白嫖（上游只 VLEN-gate，翻开即路由） | **无 env-toggle**（不同于 G2 fusion ON/OFF 可同二进制翻） | A-tree patch：repack.cpp include 我方 `.inc` + 加 q4_K/q5_K@128 repack-GEMM/GEVM trait 入口路由 mul_mat；必须做成 **build-flavor A/B 双树**（同 q4_0） |
| G4 | **部署选择器所选 kernel 群** | N/A | SEL-1 T2/T3 已在**编译期**按 capability-hash 选 tiled(S6)/plain（q4_K/q5_K→S6Tiled、q6_K/q3_K→Plain，reason=prior/measured，门⑦ PASS `4624740f`） | emit 选择器-engaged 的 K-quant kernel 群 + 归因 JSONL(`tcrv_rvv.tiling_selection_reason`)，逐格 `.inc` 部署进 A-tree |

> **★选择器语义澄清（诚实）**：SEL-1 选择在**编译期**烘焙（stamp `tcrv_rvv.tiling_variant`→emit 特定 `.inc`），运行时 dispatch 只调已 emit 的 `.inc`。故 T4 e2e 兑现的是"**选择器的编译期选择被部署后产生 projected 增益 + 归因日志披露逐格所选变体**"，**不**演示运行时变体切换。这与设计 §3 一致，须明写进措辞门⑧。
>
> **历史难点旗**：q4_K emitter scaffold 历史上 timed out 2×（memory `kernel-expansion-q8-q4k`）；NOTES 明称热插整套 = "large integration risk — the historical e2e-seal difficulty"。

## 3. 预注册对账计划（llama-bench 同会话配对）

**对账靶**：measured S_prefill vs 传导账 projection 区间 **[1.3, 1.6]**（headline 1.59×、机理天花板 1.84× 纯 q4_K；`transmission_account.md`）。

- **模型**：`DeepSeek-R1-Distill-Llama-8B-Q4_K_M.gguf`（q4_K 79.1% + q6_K 18.2%、**无 q5_K**）。★区间 [1.3,1.6] **绑此混合模型**；measured 必须同模型。q5_K 需另找 q5_K-majority 模型（如 Q5_K_M gguf）另账。
- **已 measured 基线**（`phase_split.json`，pin8-15 -t8 -r10 median+IQR）：stock pp128 = **5.184 t/s**（cv≈0.02%）、tg32 = **2.087 t/s**（cv≈0.13%）。projected prefill ≈ 5.184×1.59 ≈ **8.24 t/s**（档案估计）。
- **预注册规则**（copy `kquant-family-closure/NOTES.md §0`）：measured e2e prefill 显著（T-N：Δ>2×floor **且** >2% **且** IQR 不重叠）→ 登记首个"构造 kernel 群→整模型 prefill 增益"= **第二 e2e headline**。不显著/无 measured → 报 kernel-轴胜 + Amdahl 稀释账 + 归因，不 claim Win。
- **配对协议**：A(patched)/B(stock) 双树、`preflight_e2e.sh` 4门 fail-closed(同 compiler/march-complete/libcall-free/VLEN↔cell)、cold(warmup-dropped)、paired-interleaved、**多 prompt 长度**(pp128/pp256/pp512 覆盖 M-shape)、-r10 median+IQR、passes→T-N floor。复用 `phase_split_ab.sh`/`aggregate_e2e.py`。
- **传导效率列**：measured Δ / projected 上限；逐相绑（prefill 有效、decode NULL）。
- **归因披露**：日志逐格披露选中变体（q4_K→S6Tiled reason=prior/measured；q6_K→Plain reason=prior；…），满足门⑦格式。
- **decode/整模型诚实**：decode = M=1 GEVM memory-bound → 传导效率≈0、projected decode≈×1.00(NULL) → 整模型自回归 tok/s 净增益≈NULL。**headline 严格住 prefill/prompt-processing 相**（措辞门⑧硬约束）。
- **正确性门**：greedy-token 3/3 A==B（**非** bit-exact vs ggml，fp accum order 不同、两侧 IEEE-legal）。logits 无 NaN/Inf。

## 5. ★Session-scoped go/no-go（诚实评估）

**判定：分线。**

### T4a —— 板批 dual-board（门②③k1⑤）= **GO，~1 板会话**（+ 若需则一次小 lib/lit session）
- 载具 = 已存在的 `kquant_gemm_paired.sh` micro（合成 buffer，**不需** e2e 集成 glue），重定向 k1。
- 产出：q4_K+q5_K 在 k1/VLEN256 的 kernel-轴复测 + objdump 封 → 关门③k1半 + ⑤；若 VLEN256 K-quant emit 路径就绪，同批出门② 的 objdump 佐证（lit 落 `test/` 需另开可写 session）。
- **效果**：q4_K 4/8 → **6/8**（kernel-轴 dual-board characterized；剩 ②lit 形式化 + ④e2e）。**不解锁 beat 措辞**（[NG-4] 仍锁，须 8/8）。

### T4b —— e2e-seal 集成（门④ e2e 半）= **NO-GO 单会话；多会话独立战役，需单独立项**
诚实理由：要从零补 §2 的 G1+G2+G3 三件套（q4_0 全部白嫖、K-quant 全部缺），逐格做，正是历史 e2e-seal 难点（scaffold timed out 2×）；且触碰 `lib/`(dispatch/激活交织) + 板上维护 A-tree patch，非本 read-only session、且 build 与线B 共享。里程碑拆分：

- **M1（离线 repacker）**：GGUF Q4_K 权重 → `block_q4_Kx16`，byte-exact vs 参考 dequant（oracle 复用 `kquant_repack_verify_*.c`）。**验收=repack 往返 byte-exact**。
- **M2（激活交织 + dispatch patch + smoke）**：q8_K→`block_q8_Kx4` 交织；A-tree repack.cpp include 我方 `.inc` + q4_K@128 trait 路由 mul_mat；部署选择器所选 S6Tiled `.inc`；**验收=greedy-token 3/3 A==B smoke + banner/objdump 确认我方 kernel engage**。
- **M3（llama-bench 配对 + 对账）**：`ssh rvv` phase-split A/B（多 prompt-len）；measured S_prefill vs [1.3,1.6] 对账、归因披露。**显著→门④ e2e 半 + 第二 e2e headline**（严格 prefill 相；decode/整模型 tok/s NULL 不 claim）。
- **M4（q5_K + VLEN256 收尾）**：q5_K 重复 M1-M3（需 q5_K-majority 模型）；并 fold 门② VLEN256 lit + ⑤ k1（与 T4a 汇合）。**②③④e2e⑤ 全闭 → q4_K sealed 8/8 首个 Win**（此时才解锁 [NG-4] beat 措辞）。

> **过度乐观纠偏**：即便 M3 显著也只挣门④的 **e2e 半**；beat 措辞至 8/8 前一律锁。decode/整模型净增益结构性 NULL（memory `kernel-wins-dont-transplant-to-e2e`）——headline 永远绑 prefill/prompt-processing 相。q4_0 的 5.9× **不可**外推为 K-quant 期望值（q4_0 靠 routing 白嫖 ggml tiled kernel，K-quant projection 上限仅 1.84× 纯格、本混合模型 1.59×）。
